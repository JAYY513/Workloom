# Contributing

Thank you for improving `design-visual-frontend`.

## Good Contributions

- Clarify a rule that agents commonly misinterpret.
- Add a reproducible frontend failure pattern and a structural correction.
- Improve guidance for a specific product domain.
- Strengthen accessibility, responsive, or browser-verification checks.
- Fix Agent Skills compatibility or installation documentation.

Avoid adding visual preferences that are not tied to user tasks, product evidence, implementation constraints, or observable review criteria.

## Workflow

1. Fork the repository and create a focused branch.
2. Keep changes scoped to one problem.
3. Update `README.md` when behavior, installation, or repository structure changes.
4. Check that every path referenced by `SKILL.md` still exists.
5. Open a pull request explaining the problem, the proposed rule, and an example of how agent behavior changes.

## Writing Guidelines

- Use direct, testable instructions.
- Prefer structural diagnosis over style adjectives.
- Distinguish hard failures from optional preferences.
- Do not rely on fake brands, metrics, testimonials, or product evidence in examples.
- Keep references focused so an agent can load only what the current task requires.
