# M6 一致性自检（Symphony SPEC §17）

对齐基准：`openai/symphony` 的 `SPEC.md`（本地克隆 `C:\Source\CodeSource\github-clone\symphony`，commit `be10a1b`）；对齐边界见方案 §10.7（照搬 / 替换 / 扩展）。本清单逐条给出结论与证据，**不粉饰偏离**。

结论口径：**通过**（行为与 SPEC 一致）、**替换**（方案 §10.7 已决定的替换，行为等价但载体不同）、**偏离**（有意不同，附理由与影响）、**不适用**（该条针对外部 tracker 或 app-server 协议，本系统不采用该形态）。

## §17.1 Workflow 与配置解析

| SPEC 条目 | 结论 | 证据 / 说明 |
|---|---|---|
| 工作流文件路径优先级（显式路径 → cwd 默认 `WORKFLOW.md`） | 替换 | 本系统按 id 读 `.devsys/workflows/<id>.md`（`internal/workflow.Resolve`）；工作项声明 `workflow.id`，无「cwd 默认文件」概念。 |
| 文件变更被检测并热重载，无需重启 | 通过 | 每次消费都重新解析（`workflow.Resolve`），不信任 mtime；测试 `TestLastKnownGood*`（internal/cli）。 |
| 非法重载保留 last-known-good 并给操作者可见错误 | 通过 | `Resolution{Source, Issue}`；`claim` fail-closed、`transition` 用 LKG + warning、`next` 增 `invalid_policy` 风险；测试 `TestLastKnownGoodBlocksDispatchKeepsReadsWorking`。 |
| 缺失工作流文件返回类型化错误 | 通过 | `workflow.Resolve` 返回 not-found；`app.errWorkflowPolicy` 分类为 invalid/precondition（`TestDispatchReportsBrokenCandidateAndContinues` 断言 notice 而非崩溃）。 |
| 非法 YAML front matter / 非 map 返回类型化错误 | 通过 | `internal/workflow.Parse` 逐条定位 `文件:行号:字段:原因`；测试 `policy_test.go`。 |
| 缺省值在 OPTIONAL 缺失时生效 | 通过 | 例：hooks 超时缺省 60s、并发缺省 1、退避上限缺省 1h。 |
| `tracker.kind` / `tracker.provider` 校验 | 不适用 | 无外部 tracker：`.devsys/` 工作项即事实来源（方案 §10.7「替换」）。 |
| `$VAR` 解析（密钥/路径）与 `~` 展开 | 替换 | `workflow.ExpandEnv` 支持 `$VAR`/`${VAR}`/`$$` 转义且**不落盘**（方案 §5.3 密钥不落盘）；路径值由 `workspace_root`/`dispatch_command` 承担，未做 `~` 展开（记录为偏离：本系统不解析用户主目录）。 |
| `codex.command` 作为 shell 命令字符串保留 | 偏离 | 由 `dispatch_command`（配置）+ Harness 适配器取代；M6.7 后工作项可声明 `assigned_harness`。 |
| 按状态的并发覆盖 map 归一化并忽略非法值 | 通过 | `concurrency.per_status`；`ResolveCaps` 取最严、非法（≤0）忽略；测试 `TestResolveCapsTakesTheStrictest`。 |
| 提示词模板渲染 issue 与 attempt | 替换 | 变量集 `workitem.{id,title,type,status}`、`project.{id,name}`、`run.id`、`step`（无 issue/attempt 概念）。 |
| 未知变量严格报错（strict mode） | 通过 | `workflow.Render` 缺变量即错误（绝不静默空串）；测试 `TestAssembleFailsOnUnrenderedTemplate`、`TestWorkflowCheckBadTemplate`。 |

## §17.2 工作区管理与安全

| SPEC 条目 | 结论 | 证据 / 说明 |
|---|---|---|
| 每个标识符的确定性工作区路径 | 通过 | `workspace.Key`（净化 + 哈希后缀）+ `Root`；测试 `TestKeyIsStableAndBounded`、`TestEnsureCreatesOnceThenReuses`。 |
| 缺失目录被创建 / 已存在被复用 | 通过 | `workspace.Ensure`；`TestEnsureCreatesOnceThenReuses`。 |
| 位置上是非目录时安全处理 | 通过 | `Ensure` 返回「存在且不是目录」错误；`TestRootRejectsFileAtRootPath`。 |
| 可选的工作区填充/同步错误被暴露 | 通过 | `after_create` 失败 → `HookError` 带退出码/超时/输出尾部。 |
| `after_create` 只在新建时运行 | 通过 | 复用路径不跑钩子（计数文件为证）；`TestEnsureCreatesOnceThenReuses`。 |
| `before_run` 每次尝试前运行，失败/超时中止本次尝试 | 通过 | `app.RunExec` 在 spawn 前执行，失败即中止（无 start 记录、run 终态 failed、事件 `workspace_hook_failed`）；`TestRunExecRunsInTheWorkspaceAndHonoursBeforeRun`。 |
| `after_run` 每次尝试后运行，失败/超时只记录 | 通过 | 失败仅进 warnings + 事件，不影响退出码；评审修复项（事件写失败也不中断收尾）。 |
| `before_remove` 清理时运行，失败/超时忽略 | 通过 | `TestRemoveRecordsHookFailureAndStillRemoves`。 |
| 路径净化、原始标识哈希抗碰撞、根内不变量在启动 agent 前强制 | 通过 | `workspace.Validate`（含符号链接逃逸）+ `RunExec` 启动前校验；`TestValidateRejectsEscapes`、`TestKeyDistinguishesSanitizationCollisions`。 |
| 净化未改动的标识符保持确定性 key；不同标识符净化后相同时 key 必须不同 | 通过 | `a/b` 与 `a_b` → 不同 key；`TestKeyDistinguishesSanitizationCollisions`。 |
| agent 以工作区为 cwd 启动并拒绝越界路径 | 通过 | `RunExec` 的 `cmd.Dir` = 工作区；越界 → 前置条件错误且不 spawn。 |

## §17.3 Issue Tracker 适配

**结论：不适用（记录在案的替换）**。方案 §10.7 明确「一律以外部 tracker 为事实来源」被替换为「`.devsys/` 工作项是事实来源」。对应能力落在本系统的位置：候选集合 = `dispatch.Plan` 的 ready/retry_queued 筛选（§17.4 条目）；规范化 = `domain.WorkItem` 的严格解码（M0.4）；错误映射 = `app.Error` 四分类 + CLI 退出码（M4.5）。**不实现**：分页、标签归一化、`native_ref`、rate-limit 分类——没有对应概念。

## §17.4 编排：派发、对账与重试

| SPEC 条目 | 结论 | 证据 / 说明 |
|---|---|---|
| 派发排序：优先级 → 最早创建 | 通过（+id 决胜） | `dispatch.Plan`：priority 降序 → created_at → 标识符（确定性全序，SPEC 未要求决胜项）；`TestPlanOrdersByPriorityThenAgeThenID`。 |
| `dispatchable=false` 不参与派发 | 替换 | 由 `blocked_by`（dependencies 需 done/cancelled）与状态白名单表达；`TestPlanBlocksOnUnresolvedDependencies`。 |
| 必需标签过滤大小写不敏感 | 不适用 | 无标签概念。 |
| 活跃状态刷新运行中条目状态 | 替换 | 每次 tick 重新读工作项与租约（无外部 tracker 可刷新）；`retrySweep` + 重新规划。 |
| 非活跃状态停止 agent 但不清理工作区 | 替换 | 工作项离开可派发状态后 tick 不再派发；**正在运行的尝试不被 tick 强制停止**（本系统无外部状态推送，停止由 `run cancel`/超时/停滞判定负责）——记录为偏离。 |
| 终态停止 agent 并清理工作区 | 偏离 | 终态（done/cancelled）由工作项流程达成；工作区**不自动删除**（方案 §4.8「跨 Run 复用但不自动删除」），删除只由 `worktree remove` 触发。 |
| 无运行条目时对账是 no-op | 通过 | `reconcile.Recover` 幂等；`TestRecoverIsIdempotentForLeaseRelease`（M2.3）。 |
| 正常退出安排短延迟续跑（attempt 1） | 通过 | 干净轮次写 `continuation_due_at`（缺省 30s），run 保持 running；M6.3 验收。 |
| 异常退出按 10s 基准指数退避重试 | 偏离 | 本系统基准 30s（`retry.DefaultBase`），上限取策略 `limits.backoff_max_seconds`；抖动由标识+尝试派生（可复现，SPEC 要求）。基准不同但语义一致，已记录。 |
| 退避上限来自配置 | 通过 | `limits.backoff_max_seconds`（命名与 SPEC 的 `agent.max_retry_backoff_ms` 不同）。 |
| 重试队列条目含 attempt、到期时间、标识符、错误 | 通过 | 工作项 `next_attempt_at` + 事件 `retry_queued`（含 attempt 与原因）+ `SweptAttempt` 报告；`TestRetrySweepQueuesFailedAttempt`。 |
| 停滞检测杀死会话并安排重试 | 通过 | 流内最后证据超 `stall_threshold_seconds` → 记 `stalled` 终态 + 重排；`TestRetrySweepEndsStalledAttempt`。 |
| 槽位耗尽时以显式错误原因重排重试 | 偏离 | 本系统在计划里报 `cap_global`/`cap_status`（可行动原因）并让项**留在队列**，不写回状态——语义等价（下次 tick 仍可派发），但不产生「重排事件」。已记录。 |
| 若实现快照 API：运行行/重试行/token/rate limit | 偏离 | 只读视图为 `status`/`next`/`doctor`/`dispatch --dry-run`（无 token/rate-limit 聚合，本系统不采集用量）。 |

## §17.5 编码 Agent 客户端

**结论：偏离（记录在案）**。SPEC 以 Codex **app-server 协议**（JSON-RPC over stdio、审批/工具/用量信号）为客户端契约；方案 §9.3 选择**CLI 级适配器**（`codex exec` / `opencode run` / `claude -p`），因此该节的协议条目（framing、thread/turn 身份、审批请求、用户输入请求、客户端工具、provider-native 工具、usage/rate-limit 遥测）**不适用**；其中与本系统对应且已实现的：

| SPEC 条目 | 结论 | 证据 / 说明 |
|---|---|---|
| 启动命令以工作区为 cwd | 通过 | 适配器 `-C/--dir` + `cmd.Dir`；实跑桩验收。 |
| 读/轮超时被强制 | 通过 | `run exec --timeout`（到期终止整棵进程树）；`TestShellTimeoutKillsProcessTree`。 |
| stdio 传输的诊断 stderr 与协议流分离 | 通过 | 适配器为 CLI 形态；流仍按 stdout/stderr 分行标记（`Line.Stream`）。 |
| 审批/沙箱策略按实现文档化 | 通过 | codex `-s workspace-write`、claude `--dangerously-skip-permissions`（尝试已被 worktree 隔离）；README 记录。 |
| 会话身份/`session_started` | 部分 | run 记录 `agent.harness/model` + `run_exec_started` 事件；无 app-server 的 session id（`Request.SessionID` 已预留续跑参数）。 |
| 用量/rate-limit 遥测被提取 | 偏离 | 原始 JSONL 原样入流（可离线解析），未做聚合。 |
| 工具调用/用户输入请求处理 | 不适用 | CLI 形态下由各 CLI 自理。 |

## §17.8 真实集成画像（RECOMMENDED）

- 真实 tracker 冒烟：**不适用**（无外部 tracker）。
- 真实 Harness 冒烟：**已执行，受环境阻塞**——codex 0.144.1 与 opencode 1.18.21 各启动一次（命令行被真实 CLI 接受、JSONL 入 run 事件流），两次均因提供方后端不可用失败（codex 代理 503、opencode 本地网关 socket closed）；claude 本机未安装（探测/拒绝路径已验）。**按 SPEC 要求，未通过的真实集成明确记为未通过/跳过，不静默当作通过**；确定性链路用桩 harness 覆盖（stdin 投递 → 工作区 → 提交 → 完成校验通过）。

## 偏离汇总（需在后续里程碑处理或明确接受）

1. **外部 tracker 全部替换**为 `.devsys/` 事实来源（方案 §10.7 已决定）——§17.3 整节不适用。
2. **客户端形态**：CLI 适配器而非 Codex app-server 协议（§17.5）——协议级信号（审批/工具/用量）不解析。
3. **退避基准 30s**（SPEC 建议 10s 基准）、**槽位耗尽不写重排事件**、**运行中尝试不被状态变化强制停止**、**终态不自动清理工作区**（§17.4）。
4. **日志/证据写失败中止尝试**（§17.6）——有意与 SPEC 的「日志失败不崩编排」不同，因为尝试的证据流不是旁路日志。
5. **CLI 无位置参数与 `WORKFLOW.md` 默认文件**（§17.7）。
6. **未采集 token/rate-limit 遥测**（§17.4/§17.6）——本系统不代理模型调用。
