# Workloom 使用手册（15 分钟上手）

> 基线：`1ac4d56`；二进制 `go build -ldflags "-s -w" -o /tmp/devsys.exe ./cmd/devsys`
> （发布构建加 `-X workloom/internal/version.Version=… -X …/version.Commit=$(git rev-parse --short HEAD)`）。
> 本手册每条命令都在隔离临时 Git 项目亲手跑过；凡写命令都要 `--actor` + `--reason`（审计）。
> Windows：Git Bash 跑 `.sh` 口径，PowerShell 跑 `.ps1` 口径；`bash.exe` 指向 WSL 时用 Git Bash。
> 烟囱测试：`scripts/smoke-m1..m8.{sh,ps1}`（`--keep`/`-Keep` 保留现场并打印 `KEPT_PROJECT`）。

## 0. 准备（2 分钟）

```sh
go build -o bin/devsys.exe ./cmd/devsys   # 或 bin/devsys（按平台）
bin/devsys.exe --version                  # devsys 0.1.0-dev
bin/devsys.exe --help
export DEVSYS_CONFIG_DIR=/tmp/my-cfg      # 隔离用户注册表；冒烟/试用必设
cd /path/to/your/git-repo                 # init 要求 Git 仓库根
```

## 1. 初始化与校验（2 分钟）

```sh
bin/devsys.exe init            # 创建 .devsys/（20 paths），幂等：只补缺失不动已有
bin/devsys.exe config check    # config ok: 4 files checked（exit 0；版本/字段问题 exit 4；未 init exit 3）
bin/devsys.exe --json config check   # 结构化 problems 数组
```

`.devsys/` 即事实来源（YAML/JSON/JSONL，可 diff 可合并）；`local/` 与 `.cache/` 不提交；
clone 到新机器后补一次 `devsys init`（重建 `local/lock`，`created: 12 paths`，不动元数据）。

新项目的 `.devsys/workflows/` 是空的：没有工作流时任务照常推进，但派发给 Agent 的轮次提示词里不会有流程约束。复制一份示例并按项目改写：

```sh
cp docs/examples/workflows/quick-fix.md .devsys/workflows/            # 最简；另有 feature-development / architecture-change
cp docs/examples/workflows/reference-template.md .devsys/workflows/   # 参考级模板：姿态 / 步骤 / 证据 / 停止条件 / 上报协议
bin/devsys.exe workflow check          # workflow ok: N policies checked（校验全部策略文件）
```

## 2. 第一个任务（5 分钟）

```sh
bin/devsys.exe workitem create --title "上手任务" --actor me --reason "first task" \
  --description "- 背景：…" --acceptance "验收点 1,验收点 2"   # 验收标准可在 create 直接给（见下方质量门）
# WLM-1	draft	上手任务 / version: <64-hex>
bin/devsys.exe --json workitem get WLM-1   # 取 version（后写命令的 --expect 凭据）
V=$(bin/devsys.exe --json workitem get WLM-1 | python -c "import json,sys;print(json.load(sys.stdin)['version'])")
bin/devsys.exe workitem transition --id WLM-1 --to ready --actor me --reason go --expect $V
# WLM-1: ready
bin/devsys.exe --json workitem claim --id WLM-1 --owner me --reason start
# {"ok":true,"run_id":"run-<日期>-1","token":"<32hex>","status":"in_progress"}
```

> 门禁与策略绑定的关系：**质量门与阶段门只在工作项绑定了工作流实例后才参与判定**。`workflow start --id WLM-1 --policy quick-fix` 之前 `claim` 不会被质量门拦（也不会有流程约束）；绑上之后同一任务会按策略判定（`quality gate not satisfied: score 0 is below min_score 40` 之类，exit 4）。按 README 顺序（create → ready → claim）跑的人，请先 `workflow start`。

取 token 稳法（Windows Git Bash 下 `$(…)` 抓 JSON 易混 CR 导致 `lease token mismatch`）：

```sh
TOK=$(grep '^token:' .devsys/scheduling/WLM-1.yaml | awk '{print $2}')
bin/devsys.exe workitem release --id WLM-1 --owner me --token $TOK --actor me --reason pause
bin/devsys.exe workitem block --id WLM-1 --actor me --reason blocked
bin/devsys.exe workitem transition --id WLM-1 --to in_progress --actor me --reason resume
# blocked 的恢复：目标状态必须等于工作项里记录的 previous_status（本例 in_progress），无需额外 flag；
# 其它目标会被拒绝并提示 repair。恢复同样要过该阶段的门禁（如 in_progress 需要新的未消费审批）。
bin/devsys.exe workitem transition --id WLM-1 --to review --actor me --reason review
bin/devsys.exe workitem transition --id WLM-1 --to verification --actor me --reason verify
bin/devsys.exe workitem complete --id WLM-1 --actor me --reason done
# WLM-1	done
```

> 租约未释放时 `workitem transition` 会以 `lease token mismatch` 拒绝（该命令没有 `--token`）：先 `workitem release`（需要 owner + token），再改状态。

`--expect` 是旧快照防覆盖：mismatch 即 `version mismatch … rerun workitem get`（exit 4 族）。

## 3. 记录与上下文（3 分钟）

```sh
bin/devsys.exe decision create --title D1 --decision "选用统一方案" --by me --related WLM-1
bin/devsys.exe finding create --title F1 --description "注意点" --related WLM-1
bin/devsys.exe event record --type note --subject WLM-1 --actor me --content "进展"
# subject 传裸 id（--subject-type 缺省 workitem）
bin/devsys.exe artifact register --name "设计稿" --source manual --related WLM-1
# 产物门按**名称**匹配：策略里 require_artifacts: [decision] 需要 --name decision 的产物
# （--type 只是分类，不参与门禁判定；`artifact register --name decision --type decision` 最稳妥）
bin/devsys.exe search 上手            # 1 match(es) in .devsys/
bin/devsys.exe context get --task WLM-1
# task: WLM-1 … / decision://… / finding://… / artifact://… / knowledge: …（无生成器时降级）
bin/devsys.exe next                   # readiness + 下一步建议（只读，exit 恒 0）
bin/devsys.exe project status         # 计数随任务联动
```

## 4. 只读视图（1 分钟）

```sh
bin/devsys.exe workspace view                       # 摘要：蓝图/进度/就绪/运行/记录/知识/来源
bin/devsys.exe workspace build --static --out tmp/site --limit 10   # 离线站 6 页（--out 用项目内相对路径）
bin/devsys.exe workspace serve --port 8080          # 本地只读（缺省 127.0.0.1，Ctrl-C 停）
```

只读保证：`workspace view/build` 不改 `.devsys/`（指纹 `find .devsys -path ./local -prune …sha256sum`
前后 `diff` 一致，见 `docs/M9-验收报告.md §13`）。

## 5. 审批与派发（进阶，5 分钟）

策略示例 `docs/examples/workflows/`（`quick-fix` 最简）。门禁示例（`require_approval`）：

```sh
# .devsys/workflows/approval-flow.md 声明 stages.in_progress.require_approval: true 后：
bin/devsys.exe workflow start --id WLM-1 --policy approval-flow --actor me --reason begin --expect $V
bin/devsys.exe workitem transition --id WLM-1 --to in_progress …   # 无审批即拒绝并定位策略行
bin/devsys.exe approval request --id WLM-1 --stage in_progress --actor me --reason "变更说明"
bin/devsys.exe approval approve --id approval-1 --by reviewer --comment ok
bin/devsys.exe approval list          # 第二列是有效状态：pending / approved / consumed / invalidated / rejected
bin/devsys.exe workitem transition --id WLM-1 --to in_progress --actor me --reason go --expect $V
# 同一事务消费（approval_consumed）；复用/离 status /旧快照一律拒绝
# 离开 requested_status 即作废（§4.9）：审批被 invalidated 后需重新申请，恢复同一阶段也要新审批
```

调度（`dispatch_command` 必须是**字符串**，数组即 exit 4；项目须有 git HEAD）：

```sh
# .devsys/config.yaml: dispatch_command: "echo dispatched"
bin/devsys.exe dispatch --once --actor me --reason tick     # 恢复→计划→启动；tick 不等待尝试结束
bin/devsys.exe dispatch --dry-run --actor me --reason dry   # 只计划，.devsys/ 零变化
bin/devsys.exe dispatch --watch --interval 30s --actor me --reason loop  # 前台循环，Ctrl-C 停
```

完成校验：`run complete` 先比分支是否推进（claim head vs 当前 head），无证据即拒绝
（`completion_refused` + 工作项转 review），`--force` 必须配 `--by <reviewer>` 留名。

## 6. 交接与归档（备查）

```sh
bin/devsys.exe sync status        # 只读接力 verdict；阻塞仍 exit 0，环境失败 exit 3
# 剧本：旧设备停 --watch → recover → 释放领取 → chore(devsys): 提交推送 → 新设备 sync status ready 再接手
bin/devsys.exe archive events --before <YYYY-MM> --actor me --reason r   # 保守归档（不删只移）
bin/devsys.exe archive runs --id <run-id,...> --actor me --reason r      # 仅终态流
```

退出码速查：0 成功 / 1 内部 / 2 用法 / 3 前置条件 / 4 受管状态不可信 / 10 stale / 11 missing
（后两者专属 `knowledge status`）。
