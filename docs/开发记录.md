> 用途：实施过程中出现的问题点、与冻结方案的偏差、spec 阶段拍板决定、留给后续里程碑的事项，统一记在这里。
> 任务系统（http://localhost:3422）与 git 历史是流水账，本文档是长期索引 —— 任务很长，结论不能只留在会话里。
>
> 维护方式：每完成一个里程碑步骤，把该步骤的结论追加到对应小节。条目格式：
> `[类别] 背景/现象 → 处理或决定 → 位置/引用`。类别：`[问题]`（缺陷、坑、环境限制）、
> `[偏差]`（与方案或实施计划不一致且被接受）、`[决策]`（契约与拍板）、`[遗留]`（后续里程碑接手）。
>
> 事实来源顺序：方案与实施计划（`docs/原始文档/`，冻结）> 本文档 > 任务 artifacts。

## M0.3 文本存储基元（提交 2d5db1b）

- [决策] 采用 vendored `gopkg.in/yaml.v3` v3.0.1：本机直连 `proxy.golang.org` 实测超时，vendor 后 `GOPROXY=off` 也能构建；同步删除 `internal/minyaml`。
- [问题] Windows 标准库 `syscall` 不导出 `LockFileEx` → 用 `syscall.NewLazyDLL("kernel32.dll")` 动态调用，不引入锁库 → `internal/storage/lock_windows.go`。
- [问题] Windows 字节区间锁会阻塞其他句柄读取被锁区间，超时诊断读不到持有者 → 锁区间挪到偏移 1 GiB，锁文件头部保持可读 → `internal/storage/lock.go`。
- [问题] Windows `os.Rename` 覆盖被其他句柄打开的文件会 `Access is denied`（Go 的 `os.Open` 不带 `FILE_SHARE_DELETE`）→ 原子写对目标占用做 20–100ms 退避重试 5 次；读路径坚持「读即读即关」。
- [决策] 事务协议：journal（意图 + payload 摘要）→ `commit.yaml` 原子落盘即提交点 → 逐 op 应用 → 清理；恢复按事务 id 排序、幂等重放（Put 比摘要、append 比「前置长度 + 区间摘要」）；恢复失败拒绝读写但允许只读诊断。
- [决策] JSONL 断尾：末字节非 `\n` 即不完整尾部；追加要求「精确前置长度 + 尾部完整」，不完整时阻断追加。
- [问题] 本机无 gcc，`go test -race` 不可用（`cgo: gcc not found`）；并发结论来自多进程测试（4 进程同信号 CAS、跨进程锁超时、8 并发追加不交错）。
- [遗留] 断电持久性未验证且代码与文档均不宣称；仅验收「进程中断 + 单文件原子性」。
- [遗留] macOS/Linux 仅交叉编译通过、未实跑（锁走 `syscall.Flock` 分支）。

## M1.2–M1.6 领域存储与检索

- [决策] ID 分配统一模式：写事务内目录扫描 `max+1` + `PutYAML ExpectAbsent` CAS，冲突重扫重试≤5；WorkItem `<前缀>-<N>`（前缀大写归一）、Run `run-<YYYYMMDD>-<N>`（按日分序）、记录类 `decision|finding|artifact-<N>`（按类分序）。无全局计数器。
- [决策] 乐观更新契约：caller 读快照原始字节传入 Update，写事务内以 `ExpectHash(HashBytes(快照))` 守卫；storage.Tx 新增 `ReadForExpect`（写锁内读当前字节，供 NewArtifactVersion 等推守卫）。教训：写事务内重读后自造守卫永不冲突；st.Read 不可嵌套于 st.Write（锁超时）。
- [历史测量] 当前 Windows 环境曾测得 1000 文件串行扫描约 3.1s，16 worker 并行扫描约 0.6–0.7s；具体系统开销来源未确证，不能仅凭 Node/Go 对比归因于 Defender。每文件独立槽位保证确定性顺序。原 2s 单元测试硬断言已由任务 #130 移除，改为正确性断言与独立 benchmark。
- [决策] 事件流 ID=`ev-<UTC时间戳.微秒>-<4hex>` 无计数器；分片按 ev.Time 的 UTC 年月（12 月事件 1 月写仍落 12 月分片）；`reply_to` 仅限 comment、悬空/二级回复在聚合时报错。
- [决策] 检索排除 `.cache/`、`local/`；`search` 无命中 exit 0（`"total":0`）；缺/多关键字 usage=2。CLI 退出码契约由 TestSearchReportsMatchesAndExcludes 固定。
- [遗留] search 为逐行子串扫描，M5.1 知识页面解析接入时按页面 front matter 增强过滤；性能数字随硬件变化，升级时重测。
- [决策 #130] `TestSearchThousandFilesResponsive` 保留千文件命中数量、路径、行号、文本检查及耗时日志，不按墙钟时间失败，不跳过 Windows，也不增加预热来让单元测试过关。2s 仅作指定环境下的交互性能目标，不是跨机器保证。
- [测量 #130] `BenchmarkSearchThousandFiles/FreshFiles` 每轮新建文件后首次扫描；`RepeatedFiles` 一次不计时扫描后复用同一批文件。建文件、结果校验、清理不计时；不清空 OS 缓存，不能称为冷缓存基准。命令：`go test ./internal/search -run '^$' -bench BenchmarkSearchThousandFiles -benchmem -benchtime=3x -count=1`。本机 Windows/amd64、i7-13700H：FreshFiles 654.009ms/op、1658616 B/op；RepeatedFiles 12.055ms/op、1649922 B/op，各 3 次。固定 Go 版本、文件规模、机器及负载再作比较；当前不据此归因或宣称算法优化。
- [验收 #130] 最终指定测试扫描 754.546ms，正确性通过；`go test ./... -count=1` 全量通过。未改生产搜索实现；相对路径和大小写转换优化须先取得瓶颈证据。

## M2.1–M2.5 状态机、调度态与对账（提交见 `git log`）

- [决策] 九状态保守图（`internal/domain/state.go`）：draft→backlog→ready→in_progress→review/verification→done；允许的前跳（ready→review/verification、in_progress→verification）在图内注释；blocked 经 `PreviousStatus` 恢复原状态，终态仅 repair 可动。
- [决策] 状态写入唯一路径 `workitem.Transition` / `ApplyRepair`；普通 `Update` 拒绝改状态字段，`Create` 初始状态限定 `{draft,backlog,ready,blocked}`；每次转换要求 actor+reason 并写 `status_changed` 事件，与状态同一 `storage.Write`。
- [决策] `ApplyRepair` 要求非空 `Confirmation` 与 `Guard func(*storage.Tx) error`：Guard 在写事务内复核全部证据（文件 sha256 / 缺失断言），CLI/MCP 无法绕过；这是唯一允许降低完成度的路径。
- [决策] 调度态与 §6.4 映射表落 `WorkItem.SchedulingState`，租约独立文件 `.devsys/scheduling/<id>.yaml`（`domain.SchedulingLease`）；每次领取生成新 32-hex token（调用方传 Token 被忽略），后写校验 owner+token+未过期，`ForExpired`/`ForOrphan` 释放不回归状态。
- [决策] 租约活跃时元数据写必须走 `UpdateClaimed`、Run 写必须走 `FenceRunUpdate`（事务内复核租约与快照）；`Start`（blocked/retry_queued→in_progress）与 `QueueRetry`（确定性 next_attempt_at = now + min(base·2^(attempt-1), 1h)）落地调度态其余取值。
- [问题] Claim 初版在事务外创建 Run（失败者残留 Run、同分片二次 append 违反 tx.claim）→ 改为 `run.CreateTx` 事务内创建、领取事件合并为单条 `claimed`。
- [决策] doctor/status 真只读：`storage.Inspect` 不 O_CREATE、不自动恢复，待恢复事务优先报告且不输出业务事实；无锁文件（从未有写者）时退回 `InspectUnlocked` 保守直读并如实标注，不谎报「无活动」。
- [决策] `recover` = 先 `storage.Recover` 确定性恢复，再按策略释放过期/孤儿领取（每次释放同事务写 `lease_recovered` 事件）；幂等：二次运行为空、无重复事件；缺失 workitem 的租约只报告不释放。
- [问题] `reconcile` 目录缺失判定用 `==` 比 `fs.ErrNotExist` 对包装错误恒假 → 改 `errors.Is`（影响「目录不存在=空列表」契约）。
- [问题] 不可解析的调度文件曾被静默丢弃 → `InspectionReport.UnreadableLeases` 显式报告；过期与孤儿同时成立时先归 `expired`（时间确定事实），修复了 `ReleasedExpired=0` 的误归类。
- [决策] repair 摘要 = sha256(按 workitem+kind 排序的提案与证据集)，不含墙钟；`--apply` 重新 dry-run 后校验摘要，逐提案一个写事务并在事务内复核证据，漂移即拒绝且不写文件；一个明确引用的缺失产物即足以提议 done→in_progress。
- [问题] CLI `--expect` 初版把 64-hex 版本当原始字节传给 CAS（必然冲突）→ 改为读快照校验哈希后传原始字节（fail-closed：哈希不符即拒绝），并容忍首尾空白（Git Bash 输出 CR）。
- [决策] M2.5 交付 `scripts/smoke-m2.ps1` / `.sh`（领取 → 模拟崩溃 → doctor → recover → 确认修复）与真实进程中断回归 `internal/workitem/m2_crash_test.go`：子进程经 `storage.TxnStageHookForTest` 在指定阶段 `os.Exit`；按提交点语义断言——journal-durable 崩溃 = 事务丢弃、领取不可见、可重新领取；committed 崩溃 = 决定已定、完整重放、其余领取者被 fencing 拒绝，读者永不观察半提交。
- [问题] M2.5 初测断言把「commit 后崩溃仍可见领取」误判为泄漏；经 `TestCrashRecoveryMatrix` 语义核对后按提交点分支重写，属测试假设错误而非实现缺陷。
- [问题] PowerShell 版剧本初版漏 `git init`，且 Windows 下 `bash` 需显式调用 Git Bash（系统 `bash.exe` 指向 WSL、其中无 Go）；PS1 文件需 UTF-8 BOM，均已在脚本内备注/修复。
- [验收] 两剧本一次通过（含 doctor 不改锁文件哈希断言）；`go test ./... -count=1` 全绿、gofmt/vet 净；`go build ./...` 通过。
- [遗留] repair 推断目前基于持久化记录（workitem/run/artifact/lease）；方案 §15.4 所述「代码与 Git 历史」证据在缺少锚点（如完成提交关联字段、M3 门禁产物）前不实现，避免无证据猜测——设计原则「先推断、再确认」优先。

## M3.1 策略文件格式与解析

- [决策] 策略文件 `.devsys/workflows/<id>.md` = YAML front matter + 提示词正文；front matter 从首行 `---` 到下一个整行 `---`。不设 schema_version（§5.3 示例只有 `version`，视为策略自身版本，必填 ≥1）；`id` 必填且必须等于文件名；BOM/CRLF 容忍。
- [决策] 未知键（任意层级）= warning（记录、加载成功、`workflow check` 仍 exit 0），结构/类型/必填/交叉引用错误 = error（该文件 Policy 为 nil，exit 4）——实施计划 M3.1「未知键按方案策略处理（记录但不崩）」的落点；一次收齐全部 issue 并按行号排序。
- [决策] schema 拍板：`steps[].type` 词表开放（仅形状 `^[a-z][a-z0-9_-]*$`，避免发明规范未定义的枚举）；`steps[].required` 默认 true；`when` 在 M3.1 只要求非空字符串（语法与字段白名单归 M3.6）；gates 键与 `exempt_stages` 取值 = 工作项九状态（`domain.AllStatuses()`）；hooks 名 = §4.8 四类（未知名按未知键记 warning）；`on_reject` ∈ {`block`, `regress:<status>`}，缺省 `block`。
- [决策] CLI `devsys workflow check`（只读：不加锁、不恢复、不写盘）与 `config check` 同族：exit 0/3/4；warning 打印 `warning: <文件:行号: 字段: 原因>` 但退出码仍 0；`--json` 输出 `policies[]`（file/id/name/version）+ `warnings[]`。
- [问题] front matter 内「第二文档」可达：行 `--- # 注释` 不等于闭合行 `---`，但被 YAML 解码器当作文档分隔 → 保留第二文档拒绝路径（测试固定）。
- [验收] gofmt/vet 净；`go test ./... -count=1` 全绿；真实二进制：三份示例 3 policies exit 0；坏策略逐条定位 `workflows/broken.md:2: id: required`、`:3: version: expected integer, got !!str` exit 4；未知键 warning（`warn-demo.md:5 future_key`、`steps[0].extra`）exit 0；非 `.md` 文件 warning `ignored` exit 0。
- [遗留] 示例策略 `when` 引用的字段白名单待 M3.6 条件求值器定稿；若白名单与示例字段不一致，届时同步示例与 README。

## M3.2 模板渲染与变量引用

- [决策] 模板语法 `{{name}}`（点分标识符，括号内允许空白）；无转义、无控制流：孤立 `}}`、未闭合 `{{`、空名、非法名在加载期报 error（field=`body`，行号=文件绝对行，`workflow check` 可观察）。
