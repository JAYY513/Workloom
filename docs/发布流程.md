# 发布流程（Release Runbook）

> 适用：`JAYY513/Workloom`（私有仓库）。产物是 6 平台二进制 + `checksums.txt`，
> 由 `scripts/install.sh` / `scripts/install.ps1` 消费。
> 自动化落点：`.github/workflows/release.yml`（推 `v*` tag 自动触发，或手动 dispatch）。

## 0. 触发方式与成本

| 触发 | 命令 | 说明 |
|---|---|---|
| 自动 | `git push origin v0.1.1` | tag 名匹配 `v*` 即触发；里程碑 tag（`m7`/`m8`/`m9`）不会触发 |
| 手动 | `gh workflow run release.yml -f tag=v0.1.1` | 需要 tag 已存在；可加 `-f draft=true` 先出草稿、`-f notes="…"` 自定义说明 |

- 单个 `ubuntu-latest` runner（Linux ×1 倍率），一次约 2–4 分钟；私有仓库消耗账号免费额度（Free 2,000 分钟/月），公开仓库免费。
- 不要改成 windows/macos runner 矩阵：Go 交叉编译不需要（`scripts/build-release.sh` 就是一个 runner 上循环 `GOOS/GOARCH`）。
- 工作流只在 tag 推送或手动触发时运行，普通 push 不消耗额度。

## 1. 发版前检查（必须）

```bash
go test ./... -count=1          # 全量绿
gofmt -l internal cmd           # 空
go vet ./internal/... ./cmd/... # 净
git status --short              # 干净；按路径提交完成
```

- **tag 指向的树要与文档一致**：`v0.1.0` 的教训是 tag 打在 README 修正之前，发布树里的 README 还写着「Release 未发布」。先把文档改完、提交，再打 tag。
- 仓库尚未提交 `LICENSE`：公开发布前必须选定并提交（私有仓库阶段不受影响）。

## 2. 发版（自动路径，推荐）

```bash
git tag -a v0.1.1 -m "v0.1.1" <commit>
git push origin v0.1.1
gh run watch                    # 观察本次 run
gh release view v0.1.1          # 结束后核对资产
```

工作流做的事：解析版本 → checkout tag → `setup-go`（按 `go.mod`）→ `scripts/build-release.sh --version <tag> --out dist` → 校验（`devsys-linux-amd64 --version` 必须报该 tag；`sha256sum -c checksums.txt`）→ `gh release create --verify-tag`。

## 3. 发版（手动路径）

```bash
gh workflow run release.yml -f tag=v0.1.1 -f draft=true   # 先草稿验证
gh release edit v0.1.1 --draft=false                      # 验证 OK 后转正
gh workflow run release.yml -f tag=v0.1.1 -f notes="…"    # 或直接正式发布
```

## 4. 无 Actions 的等价手工路径

```bash
make release VERSION=v0.1.1        # = bash scripts/build-release.sh --version v0.1.1 --out dist
gh release create v0.1.1 dist/devsys-* dist/checksums.txt \
  --verify-tag --title v0.1.1 --notes "…"
```

CI 与本地走同一个构建脚本，因此两条路径的产物一致。

## 5. 校验与消费

```bash
bash scripts/install.sh --tag v0.1.1                 # Linux/macOS：下载 + sha256 校验 + 安装
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install.ps1 -Tag v0.1.1 -AddToPath
gh release download v0.1.1 --pattern 'devsys-*'      # 私有仓库：资产下载需要鉴权
```

- 私有仓库的资产 URL 需要鉴权：`curl` 裸拉会失败，脚本会自动回退 `git clone --branch <tag> + go build`（需 Go + Git 与仓库访问权限）。
- 手工核对：`cd dist && sha256sum -c checksums.txt`。

## 6. 回退

| 情况 | 处理 |
|---|---|
| tag 指错 commit | `gh release delete v0.1.1 --yes` → `git push --delete origin v0.1.1` → 修正后重打 |
| 资产缺失/损坏 | `gh release upload v0.1.1 dist/devsys-* dist/checksums.txt --clobber` |
| 只改说明 | `gh release edit v0.1.1 --notes "…"` |
| 用户侧回退 | `scripts/install.sh --tag <上一 tag>`；项目状态回退见 `docs/迁移指南.md`（`git checkout <tag> -- .devsys/`） |

## 7. 常见故障

- **403 `Resource not accessible by integration`**：工作流内已声明 `permissions: contents: write`；若仍失败，检查 Settings → Actions → General → Workflow permissions（本仓库当前默认是 read-only，组织策略可能限制工作流提权）。
- **`tag … does not exist`**：`--verify-tag` 主动拦截；先把 tag 推到 origin。
- **release 已存在**：`gh release delete <tag> --yes` 后重跑，或 `gh release upload --clobber`。
- **版本串不符**：看 run 日志的 `Resolve the version` 输出；通常是 tag 名与 checkout 的 ref 不一致（手动 dispatch 时传错 `tag`）。
