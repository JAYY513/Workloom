# 本地多仓库视图 · 第一版

状态：方案，未实现。

界面原型：`docs/hub-v1-prototype.html`（浏览器直接打开；交互结构以此为准，本文第 7 节与原型同步）。

## 1. 要做什么

一个本机进程，登记若干已经初始化的本地仓库，在浏览器里切换查看。正在看的仓库有新任务时，页面自己更新。

事实仍在各仓库的 `.devsys/`。本进程只登记路径、只读装配、只渲染。


一个仓库里能看的东西：

```text
一个仓库
├─ 蓝图（project.yaml，改得少）
│  ├─ 名称、说明、项目状态、当前阶段
│  ├─ 目标
│  ├─ 范围内 / 范围外
│  ├─ 约束
│  └─ 蓝图产物（可以没有；没有不是错误）
├─ 当前状态（state/，随工作推进变）
│  ├─ 摘要
│  ├─ 风险
│  ├─ 阻塞
│  ├─ 下一步重点
│  └─ 里程碑（state/milestones.yaml，open → done 随工作推进）
├─ 任务（主角）
│  ├─ 状态：待办、就绪、进行中、阻塞、评审、验证、完成、取消
│  ├─ 优先级、负责人、依赖、父任务
│  ├─ 领取与租约
│  └─ 工作流（可选，一个任务最多一个）
│     ├─ 用的是哪份流程
│     ├─ 当前步骤
│     └─ 是否暂停
├─ 工作流定义（可被多个任务共用）
│  ├─ 步骤
│  ├─ 步骤之间的条件和分叉
│  ├─ 进入某状态要的产物、评论、批准
│  └─ 质量门
├─ 审批
│  ├─ 申请中
│  ├─ 已批准 / 已拒绝
│  └─ 已消费 / 已失效
├─ 记录
│  ├─ 决策
│  ├─ 发现
│  └─ 产物（含版本）
├─ 运行
│  ├─ 谁跑的、第几次、成功或失败
│  └─ 事件流（现有只读页不展开正文）
├─ 下一步建议
│  └─ 恢复、开始、评审，或先修什么
├─ 知识
│  ├─ 新鲜 / 过期 / 没有 / 判断不了
│  └─ 受影响的页面
└─ 信任
   ├─ 正常
   ├─ 没锁过，只是参考
   └─ 有未完成写入，这时不显示上面的业务内容
```

多个仓库只是这份树的外面再套一层：清单里有哪些路径，路径还在不在。打开一个，才读它的这棵树。

## 2. 不做什么

- 不 `init` 仓库，不改任务、审批、领取、工作流。写入仍走 CLI / MCP。
- 不把多仓状态写入数据库、缓存或汇总文件。
- 不扫描磁盘找仓库。
- 不做跨仓合并看板。每个仓单独装配。
- 不用 WebSocket / SSE，不做文件监听。
- 不替换 `workloom workspace serve` 与 `workspace build`。前者仍是单仓只读站，后者仍是生成那一刻的离线快照。
- 不绑定非环回地址。第一版只听 `127.0.0.1`。

## 3. 现有零件

| 已有 | 第一版怎么用 |
|---|---|
| `view.Build(ctx, root)` | 每个请求按路径现装 `view.Model`。无缓存。 |
| `%AppData%\devsys\registry.yaml` | 仓清单。字段仍是 `id`、`path`、`last_seen_at`。 |
| `registry.Upsert` + `ProjectList` | 添加与列表。列表已标 `exists`。 |
| `workspace serve` | 保持不动。 |

缺口：注册表没有删除；没有按路径选仓的 HTTP 入口；浏览器不会自己再请求。

## 4. 进程

新命令：

```sh
workloom hub serve [--port 18080]
```

只绑定 `127.0.0.1`。`--port 0` 由系统分配，启动时打印实际地址。端口占用退出码 3。缺注册表文件视为空清单，不报错。

静态页随二进制嵌入，由同一进程提供。不引入前端构建，不引入数据库。

## 5. HTTP

只接受 `GET`、`HEAD`、`POST`、`DELETE`。其它方法 `405`。

### `GET /api/projects`

读注册表，不读项目状态。

```json
[
  {
    "id": "testwl",
    "path": "C:/Source/CodeSource/ai/_experiments/TESTWL",
    "last_seen_at": "2026-09-22T00:21:14Z",
    "exists": true
  }
]
```

`exists` = `<path>/.devsys` 是目录。路径消失也不从清单删除。

### `POST /api/projects`

```json
{ "path": "D:/repos/foo" }
```

规则：

1. 必须是本机绝对路径。拒绝相对路径、空路径、非目录。
2. `<path>/.devsys` 必须已存在。否则 `422`，提示先在该目录 `workloom init`。
3. 路径按注册表现有规则归一（清理、slash、Windows 大小写不敏感）。已登记则更新 `last_seen_at`，返回 `200`。
4. 新路径写入注册表，返回 `201`。`id` 取该仓库 `project.yaml` 的项目 id；读不到则用目录名，冲突时加短后缀。注册表不另造一套 id 空间。

成功体与列表元素相同。此调用只写注册表，不写目标仓库。

### `DELETE /api/projects/{id}`

只删除注册表项。不删目录，不改 `.devsys/`。未知 id 返回 `404`。

这是第一版唯一要补的注册表操作：按 id 删除一项并原子保存。

### `GET /api/projects/{id}/view?limit=50`

对登记路径调用 `view.Build`。响应体就是 `view.Model`，外加：

```json
{ "ok": true, "generated_at": "2026-09-23T03:40:00Z", "etag": "<sha256>" }
```

`etag` 是模型 JSON 的 SHA-256，不含 `generated_at`。请求带 `If-None-Match` 且相同则 `304`，无体。

`limit` 只作用于运行、记录、知识页，缺省 50，必须为正。任务和里程碑不截断。

仓库目录没了：`409`，体为 `{ "ok": false, "error": "missing" }`。待恢复事务沿用 `view.Model` 的 `trust.state = pending_transaction`，不另造状态，不渲染业务事实。

### `GET /` 与静态资源

`/` 返回应用页。`/assets/` 只提供嵌入的 CSS 与 JS。无外链、无分析、无字体下载。

## 6. 刷新

浏览器打开一个仓时请求 `/view`。之后每 2 秒带 `If-None-Match` 再请求。`304` 不改 DOM。`200` 替换当前仓视图。

- 只轮询当前打开的仓。
- 仓列表在进入列表、添加、删除时拉一次。不每 2 秒扫全部仓库。
- `document.hidden` 时停止。重新可见立即拉一次，再恢复 2 秒。
- 连续失败保留上一份成功渲染，顶栏显示「无法刷新」。恢复后清掉。
- 详情（蓝图产物、工作流正文、单条运行）第一版不单独拉。这些正文不在 `view.Model` 里，留下一版再加。

新任务写入 `.devsys/workitems/` 后，正在看的页面最迟约 2 秒更新。没打开的仓，下次打开即是新状态。

## 7. 界面

一页应用：左侧导航 + 右侧内容。不按 URL 切页，不新开窗口。交互结构以 `docs/hub-v1-prototype.html` 为准。

**左侧栏**

- 顶部：产品名、当前仓路径（等宽字体，可断行；缺失时路径旁加红点）、仓切换下拉（去原生样式，自定义 chevron）。缺失的仓在下拉里标注「缺失」。
- 「项目」组：蓝图、当前状态。
- 「任务」组：组标题带任务总数；逐条列出任务标题 + 状态，点一条即看该任务详情。任务是这个区的主角，不做汇总表。
- 「其它」组：工作流、审批、记录、运行，各项带计数徽章（圆角 pill）；知识不带计数。
- 选中的导航项：浅底 + 侧缘 3px 指示条；hover/active/current 三层反馈。
- 缺失的仓：路径旁红点提示，不再叠红色标记；能读到的区照常显示，读不到的（任务）标「读不到」。

**右侧内容**

- 顶部常驻刷新条：正常显示「已更新 · N 秒前」（等宽数字防跳动）；连续失败时变红显示「无法刷新 · 显示的是上次成功的内容」。
- 缺失的仓：所有区顶部一条「目录缺失」横幅（图标 + 标题 + 说明，红左边框卡片），内容降级显示注册表残留信息；蓝图全空时只显示横幅加虚线空态框，不渲染四张空卡。
- 蓝图：阶段实心 pill 置于标题上方 + 24px 项目名 + 15px 描述段（限宽 620px）+ 里程碑卡（卡片头右对齐「N 开启 · M 完成」，4px 进度条，状态圆点 + mono id 右对齐）+ 「方向」分区标签 + 2×2 等宽卡（目标/范围内/范围外/约束，范围外和约束的列表点用浅色区分）。空字段不渲染。窄屏折单列。
- 当前状态：摘要突出卡（深色左边框、15px）+ 风险/阻塞警报卡（有内容才渲染，橙/红左边框）+ 下一步重点/建议（普通卡片）。窄屏单列。
- 任务详情：标题行（标题 + mono id 徽章 + 状态点）+ 审批横幅（复用红色警报卡）+ 字段条（无外框，上下细线分隔，hairline 竖分隔，状态用彩色圆点，依赖用 chip 按钮）+ 工作流区（SVG 流水线：已完成段深色实线覆盖；节点 r=16，已走过的实心打勾、当前空心圆环加中心点加浅光晕、未来的空心细线；分叉画灰色虚线弧线带箭头，悬停看走向，不再标注文字；可选步骤和状态要求合并为节点下方一行灰色小字；暂停在 h3 行内标注）。
- 工作流：每份流程一张卡，卡片头右对齐「N 个任务使用 · M 步」，下方用 chip 列出使用中的任务（可点击跳转）。
- 审批/运行：统一列表容器（1px 边框、圆角、行 hover 底色、表头行）；ID 用 mono 徽章左列对齐；任务名 chip 可点跳转到任务详情；状态用彩色圆点加文字（进行中圆点呼吸动画，reduced-motion 时关闭）。
- 记录：单张列表卡内按「决策/发现/产物」分组子标题，ID mono 徽章左列对齐。
- 知识：状态卡（彩色圆点 + 文字 + 右侧 mono 评估时间）+ 受影响页面列表（路径用 mono 徽章右对齐）；「判断不了」改为「无法评估」并附说明。
- 空态：虚线边框圆角框（标题 + 一句说明），替代裸「无」字。

视觉：暖灰底（#efece6）、侧栏用更浅的 rail 层（#f5f2ec）、米色卡片（#fffdf9）一律 1px 边框加极浅阴影；圆角三档（6/8/10px）；状态用彩色圆点加文字，不只靠颜色；链接和依赖一律 chip 按钮，不用蓝色下划线；导航 hover/active/current 三层反馈，当前项用浅底加侧缘 3px 指示条；侧栏宽 236px。800px 以下左侧栏折到顶部并默认收起，chevron 按钮展开，不隐藏路径。

`trust.state != ok` 时内容区顶部常驻说明。`pending_transaction` 时不渲染业务内容，只显示 `workloom recover`。

## 8. 失败

| 情况 | 结果 |
|---|---|
| 注册表损坏 | 启动失败，退出码 1，不静默当空表 |
| 添加路径未 init | `422`，登记表不变 |
| 添加时注册表写入失败 | `500`，不假装已添加 |
| 查看时单仓装配失败 | 该请求 `500`，其它仓不受影响 |
| 端口占用 | 退出码 3 |

## 9. 验收

1. 登记两个已 init 的本地仓，页面可切换，数据来自各自 `.devsys/`。
2. 相对路径、无 `.devsys/` 的目录、删除注册项，行为与第 5 节一致。删除不触碰仓库文件。
3. 打开仓 A 时往 A 写入新工作项，2 秒内任务表出现；仓 B 不被轮询。
4. 模型未变时第二次请求为 `304`。
5. 待恢复事务的仓不显示任务表。
6. `workspace serve` 与 `workspace build` 的命令、页面和退出码不变。
7. 进程运行前后，除注册表外无其它用户级文件被创建。

## 10. 留下一版

- 蓝图产物正文、工作流 `.md`、单条运行事件。
- 列表上的轻量摘要（计数、就绪结论）。要做的话单独一个只读摘要，仍不落盘。
- 文件监听，只作为少调用 `view.Build` 的优化。轮询仍是正确性来源。
- 非环回绑定。要做时沿用 `--allow-remote`，因为响应含本机路径和项目状态。
 
## 11. 原型边界与待实现缺口
 
当前 `docs/hub-v1-prototype.html` 只是交互和视觉原型，允许使用假数据，不要求现在接入真实 API。`DATA`、`FLOWS` 和仓库下拉选项均为演示数据；页面顶部明确标注“静态原型”，刷新条写“演示快照 · 不自动刷新”。打开 HTML 只能验证导航、信息层级、空态、缺失仓和响应式布局，不能证明 Hub 后端已经支持这些功能。
 
以下内容当前不能从 `view.Model` 直接获取，先保留在原型中展示，并记录为后续实现缺口：
 
| 原型内容 | 当前缺口 | 后续实现方向 |
|---|---|---|
| 审批列表、任务审批横幅 | `view.Model` 没有审批节，只有待审批摘要参与就绪判断 | 增加只读审批摘要/列表数据 |
| 工作流步骤、分叉 SVG、流程卡 | `view.Model` 只有任务的流程 ID、当前步骤和暂停状态，没有步骤拓扑 | 增加流程定义的只读投影 |
| 蓝图产物详情 | 当前只读取蓝图产物是否存在，未暴露产物 ID/标题/版本 | 增加蓝图产物引用或详情 |
| 知识“评估于”时间 | 模型没有评估时间字段；`generated_at` 不是评估时间 | 明确时间来源后再接入 |
| Trust、Git 基线、读取问题 | 模型已有；原型已演示 pending transaction 和 Git 基线，其余信任/降级信息待接入 | 接入真实数据时补充完整可信度和降级状态 |
| 任务租约、重试、运行详情 | 模型已有；原型已演示租约持有人/期限、活动运行和运行次数，其余字段未覆盖 | 接入真实数据时补充字段显示 |
 
当前也没有实现以下 Hub 基础设施：`workloom hub serve`、`/api/projects`、按仓读取 view、ETag/304、2 秒轮询和失败重试。它们不是原型阶段的阻塞项，但在原型转实现时必须单独立项。
 
原型阶段的验收只检查：
 
1. 假数据能覆盖正常、空、缺失和 pending transaction 等状态；真实刷新错误与 advisory_unlocked 仍待演示；
2. 导航、任务跳转、工作流图、仓库切换等交互结构可演示；
3. 800px 以下布局、键盘焦点、状态文字和 reduced-motion 行为正常；
4. 不把原型假数据或静态刷新条描述成已接入真实项目。
 
## 12. 原型与当前代码的调研结论
 

### 12.6 项目总览看板（原型新增）

原型增加“项目总览”入口，用于在多个登记仓之间先看全局，再进入单仓详情。看板展示三类信息：

- 项目卡：项目名、登记路径、目录存在性、信任状态，以及任务数、风险/阻塞数、知识状态；缺失目录和待恢复事务只显示降级事实，不把读不到当成零。
- 汇总指标：登记项目数、可读取项目的任务总数、推进中任务数、风险/阻塞数。
- 进入路径：点击项目卡进入该仓的蓝图页；顶部仓库选择器仍可直接切换仓库。

这些统计仍是离线假数据。真实实现需要 `GET /api/projects` 返回登记项目摘要，并在项目卡点击后按项目读取 view；聚合统计应由服务端或同一快照计算，避免不同项目数据时间不一致。看板不替代单仓任务、运行、记录和知识详情。
以下结论基于 `docs/hub-v1-prototype.html`、`internal/view/view.go`、`internal/view/build.go`、`internal/cli/workspace_serve.go` 和 `internal/registry/registry.go` 的对照。调研时只读；随后按第 11 节边界更新了原型，业务代码未修改。
 
### 12.1 当前项目已经有的能力
 
- `view.Build(ctx, root, opts)` 可以按仓库目录读取蓝图、当前状态、任务、运行、记录、知识和 Git 基线。
- `view.Model` 已有 `Trust`，可表达 `ok`、`advisory_unlocked`、`pending_transaction`。
- 任务模型已有优先级、父任务、依赖、负责人、harness、租约、租约到期时间、重试时间、活动运行 ID 等字段。
- 运行模型已有执行人、harness、模型、次数、阶段、工作区、分支、摘要、错误和事件流损坏标记。
- 记录模型已有状态、严重程度、版本和关联任务。
- 知识模型已有状态、原因、基线、索引、生成器、页面、受影响页面、无法验证页面和变更文件数。
- 注册表已有 `Load`、`Upsert`、`Save` 和 `ProjectList`；缺注册表文件时可以按空表读取，项目列表可以标出路径是否存在。
- `workspace serve` 已有单仓只读页面和 `/api/view`，但它不是多仓 Hub。
 
### 12.2 原型目前使用假数据的地方
 
- `DATA` 硬编码 `workloom`、缺失的 `notes`、待恢复的 `recovery` 三种仓库状态及页面数据。
- `FLOWS` 硬编码三份工作流及步骤分叉。
- 仓库下拉框静态列出三个演示仓库。
- 审批列表、运行列表、知识诊断与待恢复事务均是静态演示，不是接口结果。
 
### 12.3 当前没有真实数据来源的原型内容
 
| 原型内容 | 调研结论 |
|---|---|
| 审批列表和任务审批横幅 | `view.Model` 没有审批节；`build.go` 只把待审批摘要用于 readiness。 |
| 工作流流程卡和 SVG 分叉图 | `view.Model` 没有流程定义、步骤和 edges；只有任务的 workflow ID、当前步骤、暂停状态。 |
| 蓝图产物详情 | 当前只读取是否配置蓝图产物，不提供产物 ID、标题、版本正文。 |
| 知识评估时间 | 模型没有 `checkedAt`；生成时间不能冒充知识评估时间。 |
| 多仓列表 HTTP 接口 | 没有 `GET /api/projects`；注册表只有 CLI/MCP 层面的列表能力。 |
| 添加/删除仓库 HTTP 接口 | 没有 `POST /api/projects`；注册表也没有 Delete 方法。 |
| 按仓读取 HTTP 接口 | 没有 `/api/projects/{id}/view`，只有单仓 `/api/view`。 |
| ETag、304、2 秒轮询 | 服务端和原型都没有实现。 |
 
### 12.4 实际已有但原型仍未完整显示的内容
 
- 已补演示：项目状态、readiness 风险和建议、pending transaction 恢复提示、任务调度/租约/活动运行、运行人/次数、记录元数据、知识过期原因、Git 基线。它们仍是**假数据**。
- 尚未演示：`advisory_unlocked`、逐节 `degraded/reason`、读取来源和问题、readiness 的结构化修复命令/可跳转推荐任务、任务前一状态、运行模型/工作区/开始结束时间/事件流损坏、知识逐页状态/无法验证页面/截断标记。
 
### 12.5 原型仍需注意的边界
 
- 原型没有 `fetch`、`setInterval`、`If-None-Match` 或 `document.hidden` 处理；刷新条明确写“不自动刷新”。
- 缺失仓的工作流、审批、记录、运行、知识区现在显示“读不到”，不把无法读取误报为“没有”。
- 任务状态和优先级目前用中文样本；接入真实模型时需从英文枚举/整数做统一映射，不能直接使用样本字段。
 
这些剩余问题不阻塞静态原型，但转真实实现前须逐项处理。
