## Provenance（每节的 sources 字段）

`Provenance`（[view.go:104-106](file://internal/view/view.go#L104-L106)）作为嵌入字段出现在 `Project`、`Progress`、`Runs`、`Records`、`Knowledge` 五节中：

```go
type Provenance struct {
    Sources []string `json:"sources"`
}
```

**关键约定**（[collect.go:96-123](file://internal/view/collect.go#L96-L123)）：

- **路径全部用项目相对 slash 形式**（Windows 也用 `/`），不混用 `\`。
- **`/` 后缀 = 目录**；无 `/` = 文件。例如 `.devsys/runs/`（runs 目录）vs `.devsys/runs/run-1.jsonl`（具体文件）。
- 来源路径为空的字符串一律丢弃（`noteRel/noteRelDir` 都有 `if rel == ""` 早退）。
- 每节 `Sources` 都过 `sortedUnique`，顶层 `Sources` 又过一次——保证「读端记啥就出啥」。

调用方可以通过 `m.Project.Sources`、`m.Knowledge.Sources` 等逐节追溯每一段事实读了哪些文件；顶层 `m.Sources` 是全量并集 + `git` 基线（基线不在 `.devsys/` 下，不进各节 `Provenance.Sources`，但加入顶层）。

#### `Blueprint` 与 `BlueprintWarnings`（本批新增，[view.go:152-161](file://internal/view/view.go#L152-L161)）

```go
type Blueprint struct {
    ID           string `json:"id"`
    Name         string `json:"name,omitempty"`
    Path         string `json:"path,omitempty"`
    Source       string `json:"source,omitempty"`
    Status       string `json:"status,omitempty"`
    Version      int    `json:"version,omitempty"`
    Content      string `json:"content,omitempty"`
    ContentError string `json:"content_error,omitempty"`
}
```

这是本模块**第一次把非 `.devsys/` 的项目正文读进模型**——`Content` 是蓝图文件（通常 `docs/blueprint.md` 之类）的全文。三个关键编码约定：

| 约定 | 说明 |
|---|---|
| **指针而非值** | `Project.Blueprint` 是 `*Blueprint`。未绑定蓝图时是 `nil`，`omitempty` 让整个 `blueprint` 键从 JSON 里**消失**——渲染层用 `{{if .M.Project.Blueprint}}` / `bp ? … : …` 判断，不会有「空对象」歧义 |
| **`Content` 与 `ContentError` 互斥** | 正文读成功给 `content`，失败给 `content_error` 且 `content` 省略。Hub 前端据此二选一渲染（[app.js:280](file://internal/hubstatic/app.js#L280)）；离线的 `sitestatic` 首页只出绑定蓝图**元信息**一行 + 警告列表（[static.go:335-336](file://internal/sitestatic/static.go#L335-L336)） |
| **降级走 `[]string` 不走 error 字段** | 「读不到源文件」「蓝图状态是 draft」等不是硬错误，集中在 `BlueprintWarnings` 逐条呈现。视图层既有惯例就是「非致命问题进字符串列表」（顶层 `Problems`、各节 `Reason`），蓝图警告沿用同一形状 |

正文读取的完整防线（`readBlueprintContent`，[build.go:32-65](file://internal/view/build.go#L32-L65)）：`TrimSpace(rel)` 空 → 报错；`filepath.Clean(filepath.Join(root, rel))` 后用 `Abs` + `Rel` 判**是否逃出项目根**（`relTarget == ".."` 或以 `..`+分隔符开头）→ 拒绝；`os.Stat` 不存在 → 拒绝；是目录 → 拒绝；`info.Size() > maxBlueprintContent`（`256 << 10` = 256 KiB，[build.go:30](file://internal/view/build.go#L30)）→ 拒绝。**任何一步失败都不让 `Build` 失败**，只把原因写进 `ContentError`——蓝图画不出来不该让整份视图挂掉。

`BlueprintWarnings` 已知包含两类：**artifact 声明了 `source` 但源文件读不到**、**蓝图 `status` 是 `draft`**（草稿状态给提醒而非当错误）。

> `sitestatic` 首页本批把原来的 `{{if .M.Project.Goals}}`「目标」块换成蓝图块（[static.go:335-336](file://internal/sitestatic/static.go#L335-L336)），但 `Project.Goals` **字段本身保留且仍由 `mp.Goals` 填充**——`sitestatic` 的蓝图页与 Hub 蓝图页都仍读 `b.goals`，只是首页不再单独列它。

### `ModelJSON` 与 `data/model.json`

func ModelJSON(m *view.Model) ([]byte, error) {
    if m == nil { return nil, fmt.Errorf("sitestatic: nil model") }
    out, err := json.MarshalIndent(m, "", "  ")
    if err != nil { return nil, fmt.Errorf("sitestatic: encode model: %w", err) }

## JSON 编码约定汇总

- **`omitempty` 的统一规则**：所有可选字段（`omitempty` 标签）都是「空时省略」，让 `Problems/Risks/Blockers/...` 这种空集合不出现在 JSON 里。
- **slice 预填为空**（`newModel`）：保证「没找到」是 `[]` 不是 `null`——这是确定性 + JSON 信封稳定的基础。
- **目录以 `/` 结尾**：路径字符串最后是 `/` 表示目录，最后是文件名（或不带 `/`）表示文件；这是 `Sources` 字段的语义约定。
- **时间字段**：`Item.CreatedAt/UpdatedAt` 是 `time.Time`（必有）；`Project.CreatedAt/UpdatedAt`、`RecordRef.CreatedAt`、`RunEntry.FinishedAt` 是 `*time.Time`（零值省略）。
- **指针字段**：`Baseline.Dirty`（`*bool`）、`Item.LeaseUntil`（`*time.Time`）、`Item.NextAttemptAt`（`*time.Time`）、`RunEntry.FinishedAt`（`*time.Time`）、`RunEntry.Advanced`（`*bool`）、`RecordRef.CreatedAt`（`*time.Time`）。
- **map 字段**：`Progress.Counts` 是 `map[string]int`，**有 `omitempty`** 不会生效（Go 的 json 包对 map 不判 nil → 总是输出）——但 `newModel` 预填 `map[string]int{}` 而不是 `nil`，保证输出 `{}` 而非 `null`。
- **枚举值**：所有状态字段是字符串常量，渲染层按字符串分支，不要把字符串哈希为整数。
- **hint 纯渲染：JSON 无 hint 键**：`siteData.ShowFreshness/FreshnessTitle/FreshnessText/FreshnessReason/FreshnessCmd` 是渲染层派生量（`freshnessHint` 纯函数），**不进** `view.Model`；`ModelJSON` 只 marshal 模型自身，`data/model.json` 与 `Build` 落盘字节级一致——JSON 信封里也找不到 `show_freshness/freshness_*` 这类键。
- **蓝图正文是唯一的「非 `.devsys/` 内容」**（本批新增）：`Project.Blueprint.Content` 装的是项目内蓝图文件全文，不进任何 `Provenance.Sources`（它不是状态文件）。`content` 与 `content_error` 互斥，降级事实走 `blueprint_warnings` 字符串列表——与顶层 `problems` 同一形状，不造 error 对象。
- **前端直接消费 snake_case 键**（本批新增）：`internal/hubstatic/app.js` 按 `d().project.blueprint`、`d().workflows`、`d().records.artifacts`、`d().trust.state` 等键名读模型。因此**改任何 JSON tag 都是 Hub 前端的破坏性变更**——它没有类型层、没有 schema 校验，只有一层 578 行的手写访问器。
- **上一批（v0.1.9，ca58d27→19b9149）**：模型字段、JSON tag、`SchemaVersion=1`、`DefaultLimit=50` 与 `Options` 全部不变；`devsys` 成为同一二进制的兼容别名（主命令 `workloom`，入口 `cmd/workloom/main.go`；别名入口 `cmd/devsys/main.go`），渲染层 hint 文案随主命令改名（`workloom knowledge refresh [--full]`，[static.go:177-179](file://internal/sitestatic/static.go#L177-L179)）；Git 成为可选能力后，非 Git 项目对应既有的 `Baseline.Available=false` 与 `Knowledge=unavailable` 两个分支，模型形状不变。
- **本批（d07638c→9d7ed6c，13 commit）**：模型**新增**三处（顶层 `workflows`；`project.blueprint`；`project.blueprint_warnings`）、**收敛**一处（`records.decisions`/`records.findings` 恒空），`SchemaVersion` 仍为 `1`——都是加法与空值化，没有改名或改类型的破坏性变更。确定性不变：新增 `Workflows` 在 `newModel`/`emptyBusiness` 两处预填 `[]`，蓝图正文在 `filepath.Abs`+`filepath.Rel` 判根逃逸后按 256 KiB 封顶，读取顺序固定，`BlueprintWarnings` 按装配顺序追加——两次构建仍逐字节一致。
