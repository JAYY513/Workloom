# 视图层 · 编码规范

视图层的代码风格围绕「只读聚合层 + 确定性 + 错误降级 + 渲染派生下放」四件事收敛。本卡梳理七条规范，每条都标注两处以上源码行号依据，便于在 review 时快速对照。

## 1. 列表先定序后截断（`capList` + 内联切片）

**规范**：任何列表节（**本批起只剩 `Records.Artifacts` 与 `Knowledge.Pages`**；`Model.Workflows` 不截断）必须**先按文档约定排序**（时间倒序再 ID / 路径字典序 / ID 字典序），再用 `capList[T any]` 或等价的 `list[:limit]` 截断；截断后置 `Truncated=true`。

**依据**：
- `capList`（[internal/view/build.go:869-874](file://internal/view/build.go#L869-L874)）：`if len(list) <= limit { return list, false }; return list[:limit], true`——只切末尾，不改顺序，不重排。
- `Records.Artifacts`（[internal/view/build.go:645](file://internal/view/build.go#L645)）：`artifacts, truncated := capList(artifacts, b.limit)`。**本批变化**：原先 `decisions` 与 `findings` 两处 `capList` 调用**已随 `records()` 停止读这两个目录一并删除**（旧锚点 `build.go:566-567` / `591-592` 在 HEAD 已不存在），因此本批只剩 artifacts 一处；`Truncated` 也随之只反映 artifacts。
- `Runs.Entries`（[internal/view/build.go:528-531](file://internal/view/build.go#L528-L531)）：先 `sort.Slice` 按 `StartedAt` 倒序再 `ID` 升序，再 `runs = runs[:b.limit]; r.Truncated = true`（与 `capList` 等价，但内联）。
- `Model.Workflows`（本批新增）**故意不截断**：工作流数量是配置量级不是列表节，按 `ID` 升序后直接返回（[build.go:326](file://internal/view/build.go#L326)），无 `Truncated` 字段。

**反模式**：截断后再排序（结果与 limit 无关，但顺序与 `Truncated` 关系错乱）；用 `map[string]T` 当列表（编码顺序由 Go runtime 决定，不稳定）。

## 3. 非致命问题进 `m.Problems`，只有缺 `project.yaml` 整体报错

**规范**：单文件损坏（YAML 解码失败、git 读失败、知识状态异常、工作项坏）→ 走 `b.problem(err)` / `b.problemf(format, args...)` 追加到 `m.Problems`，并在对应节标 `Degraded=true` + `Reason=...`。**只有**缺 `.devsys/project.yaml`（即 `storage.ErrNotInitialized`）让 `Build` 整体报错；其余失败都降级。

**依据**：
- `b.problem/problemf`（[internal/view/collect.go:142-152](file://internal/view/collect.go#L142-L152)）：`b.problems = append(b.problems, err.Error())`。
- `project()` 单文件失败（[internal/view/build.go:226-240](file://internal/view/build.go#L226-L240)）：YAML 失败 `b.problem(err)` + `p.Degraded=true` + `p.Reason=err.Error()`，但装配继续。
- `progress()` 单工作项失败（[internal/view/build.go:261-265](file://internal/view/build.go#L261-L265)）：`b.problem(err)` + `failed = append(failed, err.Error())`，其他工作项照常解码；最后 `pr.Degraded = true; pr.Reason = strings.Join(failed, "; ")`（[build.go:296-299](file://internal/view/build.go#L296-L299)）。
- `Build` 入口的硬错误只有 `storage.ErrNotInitialized`（[build.go:33, 42-45](file://internal/view/build.go#L33-L45)）：`storage.Open` 失败即返回 `err`。
- `reconcile.Doctor` 失败时**回退** `storage.Diagnose`（[build.go:51-66](file://internal/view/build.go#L51-L66)）——Doctor 为生成修复提议会解码全部工作项，一个坏文件曾让整次聚合失败，改为回退到不看工作项的诊断并把限制写进 `problems`，其余节照常渲染（该修复的原始依据见 git 历史中的 docs/开发记录.md）。

## 4. `Options.Now` 注入而非直接 `time.Now()`

## 5. JSON 契约的 `omitempty` 统一规则

**规范**：视图层 JSON 字段的 `omitempty` 标签遵循「**空值省略**」原则——`""`/`nil`/`0`/`false`/空 slice/空 map 都省略。**slice 字段用 `newModel` 预填 `[]T{}`** 保证「找到 0 项」编码为 `[]` 而非字段消失。指针字段（`*bool`/`*time.Time`）用于「零值 vs 未设置」的区分。

**依据**：
- `Model` 顶层（[view.go:62-80](file://internal/view/view.go#L62-L80)）：`Problems []string \`json:"problems,omitempty"\``，其余字段不带 `omitempty`（必有字段）。
- `Baseline.Dirty *bool`（[view.go:95](file://internal/view/view.go#L95)）：`*bool` 让 `nil` 与 `false` 区分——`Available=false` 时**留 nil**（不假装 false）。
- `Item.LeaseUntil *time.Time` / `NextAttemptAt *time.Time`（[view.go:158-159](file://internal/view/view.go#L158-L159)）：未设值时省略。
- `RunEntry.FinishedAt *time.Time` / `Advanced *bool`（[view.go:190-191](file://internal/view/view.go#L190-L191)）：同上。
- `newModel` 预填（[build.go:117-140](file://internal/view/build.go#L117-L140)）：`Milestones: []domain.Milestone{}`、`Risks: []string{}`、`Items: []Item{}`、`Pages: []PageEntry{}`、`Affected: []string{}`、`Pending: []string{}`、`Entries: []RunEntry{}`。
- `itemFrom` 中 `Dependencies` 空时显式置 `nil`（[build.go:869-871](file://internal/view/build.go#L869-L871)）：让 JSON 里 `dependencies` 字段消失而不是出现 `[]`。
- `runEntry` 中 `Errors` 空时置 `nil`（[build.go:480-482](file://internal/view/build.go#L480-L482)）：同上。


## 6. 测试用「指纹 / 双 marshal / 只读副本」三种断言

**规范**：视图层测试用三类断言保证「零写入 + 确定性 + 只读契约」：
- **指纹断言**（`fingerprint` + `diffFingerprints`）：整树文件 sha256 + 大小 + mtime 三元组比对前后，证明装配不改任何文件。
- **双 marshal 断言**（`json.Marshal` × 2 + `reflect.DeepEqual`）：同一状态两次装配字节级相同。
- **只读副本断言**（`copyTree` + `os.Chmod 0o444`）：整树只读还能装配完整。

**依据**：
- `TestBuildWritesNothing`（[view_test.go:308-318](file://internal/view/view_test.go#L308-L318)）+ `fingerprint`（[view_test.go:486-520](file://internal/view/view_test.go#L486-L520)）+ `diffFingerprints`（[view_test.go:522-537](file://internal/view/view_test.go#L522-L537)）。
- `TestBuildIsDeterministic`（[view_test.go:293-306](file://internal/view/view_test.go#L293-L306)）：`first, _ := json.Marshal(build(t, root)); second, _ := json.Marshal(build(t, root)); reflect.DeepEqual(first, second)`。
- `TestBuildOnAReadOnlyCopy`（[view_test.go:349-378](file://internal/view/view_test.go#L349-L378)）+ `copyTree`（[view_test.go:539-569](file://internal/view/view_test.go#L539-L569)）：复制 + `filepath.WalkDir` + `os.Chmod(path, 0o444)` + `t.Cleanup` 还原。
- `TestBuildWithoutLockFileStaysReadable`（[view_test.go:320-347](file://internal/view/view_test.go#L320-L347)）：fixture 无 lock 文件 → `build` 后 `os.Stat(lock)` 必须 `ErrNotExist` + `fingerprint(before) == fingerprint(after)`。
- `TestBuildPendingTransactionRendersNoBusinessFacts`（[view_test.go:380-412](file://internal/view/view_test.go#L380-L412)）：手工建 `.devsys/local/txn/txn-1/` → `m.Trust.State == TrustPending` + 业务节空 + `Readiness.Verdict == FAIL` + `m.Baseline.Available == true`（基线照常）。
- `TestBuildDegradesOneSectionOnly`（[view_test.go:414-431](file://internal/view/view_test.go#L414-L431)）：写一个坏 YAML 文件 → 仅 `Progress.Degraded == true` + `m.Problems` 含坏路径 + 其他节正常。

## 8. Hub 前端（`internal/hubstatic`）的四条约定（本批新增）

`internal/hubstatic` 是浏览器资源，不适用上面七条 Go 规范，但有四条自己的硬约定：

| 约定 | 依据 |
|---|---|
| **所有插值过 `esc`** | [app.js:23](file://internal/hubstatic/app.js#L23) 的 `esc` 转义 `& < > " '` 五字符。所有 `render*` 函数以模板字符串拼 HTML 后整块赋给 `innerHTML`，**每一个**插入的项目字段都必须过 `esc`；蓝图正文用 `<pre class="blueprint-content">${esc(bp.content)}</pre>`，**不进** Markdown 渲染器 |
| **零构建步骤、零第三方依赖** | 4 个文件直接 `//go:embed`（[assets.go:1-8](file://internal/hubstatic/assets.go#L1-L8)），无 npm/webpack/vite/`node_modules`；改前端只需重跑 `go build` |
| **零外部引用** | `index.html` 只引同源的 `/assets/style.css` 与 `/assets/app.js`；`style.css` 无 `@import`、无 `url()`、无 web font。**不适用** `RenderPage` 与 `Build` 的「逐字节一致」约束——Hub 没有落盘产物 |
| **写路径为零** | 前端唯一的 `apiPost`（[app.js:74-83](file://internal/hubstatic/app.js#L74-L83)）只打 `POST /api/projects`（写**用户级注册表**，不碰项目业务状态）；宿主对其它非 GET/HEAD 一律 `405 read-only` |

反模式：在 `render*` 里用 `${it.title}` 之类不过 `esc` 的插值（`it.title` 来自 `project.yaml`，是用户可写内容）；给 Hub 引入 npm 依赖链；把「离线站的零 JS 性质」与 Hub 混谈——两者是不同渲染面。
