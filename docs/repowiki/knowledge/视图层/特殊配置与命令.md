### flag 行为

#### `--limit N`

#### `--json`（全局，与 `--quiet` 互斥）

- 走 JSON 信封：`{ "ok": true, "model": { ... view.Model ... } }`（[workspace.go:135-140](file://internal/cli/workspace.go#L135-L140)）。
- 信封是 `workspace build --static` / `workspace serve` 的**稳定输入**——`view.Model` 字段名 (`schema_version/project/trust/baseline/progress/runs/records/knowledge/sources/problems`) 是契约，详见 [视图数据模型.md](视图数据模型.md)。

## `workloom workspace build --static [--out DIR] [--limit N]`

`workspace build` 把 `view.Model` 渲染成离线静态站点（M7.2，方案 §17 两种形态之一）。**唯一**的数据入口是 `view.Build`——共享锁从不创建、事务从不恢复——`--out` 之下是该命令仅有的写入。

### flag 行为

#### `--static`（必填）

- 不传 → `errUsage("`workloom workspace build` needs --static (the only site form in M7.2)")`（[workspace.go:53-55](file://internal/cli/workspace.go#L53-L55)），退出码 2。
- M7.2 站点生成**仅**经 `--static`；其它形式（如 `--watch`）不属于 M7.2 范围。

#### `--out DIR`

- 缺省 `""` → `sitestatic.DefaultOutDir(root) = root/.devsys/dist/site`（[internal/sitestatic/static.go:39-44](file://internal/sitestatic/static.go#L39-L44)）。
- 常量 `DefaultOutRel = ".devsys/dist/site"`（[static.go:39](file://internal/sitestatic/static.go#L39)），落在 `.gitignore` 的 `.devsys/dist/` 之内（[.gitignore:9](file://.gitignore#L9)）—— 生成 HTML 不污染 git freshness 信号（`knowledge.Changes` 把未跟踪文件计入）。
- 空路径 → 解析为 `DefaultOutDir`；相对路径 → 相对项目根；绝对路径 → 接受（即使在项目外）。
- `ResolveOut(root, raw)`（[static.go:46-88](file://internal/sitestatic/static.go#L46-L88)）拒绝矩阵（命中即 `errUsage` → exit 2）：

| 输入 | 行为 |
|---|---|
| `""` / 合法相对路径 | 解析到 `<root>/...` 或默认 `.devsys/dist/site` |
| `.`（项目根） | 拒绝：`refusing to build into the project root itself` |
| `.git` 或 `.git/...` | 拒绝：`refusing to build into .git` |
| `.devsys` 或 `.devsys/...`（**除** `.devsys/dist/` 与 `.devsys/dist/...`） | 拒绝：`refusing to build into managed state %q (only .devsys/dist/ is writable output)` |
| 绝对路径或 `../...` 显式逃逸出项目根 | 接受（与项目外绝对路径同等对待） |

> 拒绝矩阵的存在动机：状态（`.devsys/`）不能被站点生成覆写；`.git/` 是 git 元数据，不应混入渲染产物。`.devsys/dist/` 是被故意放行的本地衍生目录。

#### `--limit N`

- 与 `view` 同：缺省 50；仅作用于列表节；`<=0` → `errUsage` exit 2。

## `workloom workspace serve [--host 127.0.0.1] [--port N] [--allow-remote] [--limit N]`

`workspace serve` 是方案 §17 两种形态之二：本地只读 HTTP 服务，**前台进程**（`Ctrl+C` / `SIGTERM` 经 `signal.NotifyContext` 优雅关闭 `srv.Shutdown`，超时 5s；[workspace_serve.go:197-204](file://internal/cli/workspace_serve.go#L197-L204)）。运行期**零写入**——`serveHandler` 不持快照缓存、不写文件、每次请求现装 `view.Build`（[workspace_serve.go:30-37](file://internal/cli/workspace_serve.go#L30-L37)）。

### 调用链

```
runWorkspaceServe (workspace_serve.go:151-208)
  → flag.NewFlagSet("workspace serve")
       --host  str   (默认 serveDefaultHost = "127.0.0.1")
       --port  int   (默认 serveDefaultPort = 8080；0 = OS 分配)
       --allow-remote  bool  (默认 false)
       --limit  int   (默认 view.DefaultLimit = 50)
  → *limit <= 0             → errUsage exit 2
  → *port < 0 || > 65535    → errUsage exit 2
  → opts.json || opts.quiet → errUsage exit 2
  → !isLoopbackHost(*host) && !*allowRemote → errUsage exit 2
  → requireProjectRoot()     (缺 .devsys/ → errPrecondition exit 3)
  → view.Build(...) 预检    (ErrNotInitialized → errPrecondition exit 3；其它 → errInternal exit 1)
  → net.Listen("tcp", host:port)
       (失败 → errInternal exit 1)
  → 打印 banner: "serving http://<addr>/ (read-only) — Ctrl+C to stop"
       --allow-remote 时追加 " [REMOTE ACCESS ENABLED]"
  → srv.Serve(ln)
       非 ErrServerClosed → errInternal exit 1
  → return nil  (graceful shutdown 后)
```

### flag 行为

#### `--host` / `--allow-remote`

- 缺省 `serveDefaultHost = "127.0.0.1"`（[workspace_serve.go:26](file://internal/cli/workspace_serve.go#L26)）。
- `isLoopbackHost(host)`（[workspace_serve.go:131-134](file://internal/cli/workspace_serve.go#L131-L134)）仅识别 `127.0.0.1`、`::1`、`localhost`（小写、剥括号与空白）。**空串、`0.0.0.0`、`LAN IP`、公网地址**均视为非环回。
- 非环回 + 缺 `--allow-remote` → `errUsage("refusing non-loopback bind %q without --allow-remote ...")`，退出码 2（[workspace_serve.go:170-172](file://internal/cli/workspace_serve.go#L170-L172)）。
- `--allow-remote` 显式开启后，banner 追加 `[REMOTE ACCESS ENABLED]`，提示该进程已对网络可见（[workspace_serve.go:192-194](file://internal/cli/workspace_serve.go#L192-L194)）。

#### `--port N`

- 缺省 `serveDefaultPort = 8080`（[workspace_serve.go:27](file://internal/cli/workspace_serve.go#L27)）。
- `0` → 由 OS 分配端口（`net.Listen` 行为）；实际地址从 `ln.Addr()` 取（[workspace_serve.go:190-195](file://internal/cli/workspace_serve.go#L190-L195)）。
- `<0` 或 `>65535` → `errUsage("`--port` must be 0-65535")` exit 2（[workspace_serve.go:164-166](file://internal/cli/workspace_serve.go#L164-L166)）。

#### `--limit N`

- 与 `view` / `build` 同：缺省 50；仅作用于列表节；`<=0` → `errUsage` exit 2。

#### `--json` / `--quiet`（全局）

- 均被拒绝：`errUsage("`workloom workspace serve` does not take --json or --quiet")`（[workspace_serve.go:156-158](file://internal/cli/workspace_serve.go#L156-L158)），退出码 2。Serve 的契约只有一行人类输出（banner）。

### 路由表

`newServeMux` → `serveHandler.serveHTTP`（[workspace_serve.go:44-97](file://internal/cli/workspace_serve.go#L44-L97)）。所有非 `GET`/`HEAD` 一律 `405 Method Not Allowed`：

| Method | 路径 | 行为 |
|---|---|---|
| `GET` / `HEAD` | `/`、`/index.html` | `servePage("index.html")` |
| `GET` / `HEAD` | `/tasks.html`、`/workflows.html`、`/runs.html`、`/records.html`、`/knowledge.html` | `servePage(<path 去前缀>)` |
| `GET` / `HEAD` | `/assets/style.css` | `sitestatic.Stylesheet()`（包内常量 `styleCSS`） |
| `GET` / `HEAD` | `/data/model.json` | `sitestatic.ModelJSON(buildView())` |
| `GET` / `HEAD` | `/api/view` | `view.Model` 内嵌信封 `{ok, generated_at, ...Model}` |
| `GET` / `HEAD` | `/healthz` | `{"ok":true}\n` |
| 其它非 `GET`/`HEAD` | 任意 | `405` + `Allow: GET, HEAD` + `Content-Type: text/plain; charset=utf-8` + `Cache-Control: no-store` + `X-Content-Type-Options: nosniff` + 体 `read-only: <METHOD> not allowed\n`（[workspace_serve.go:44-54](file://internal/cli/workspace_serve.go#L44-L54)） |
| `GET` / `HEAD` | 其它 | `404 not found\n` |

> `405` 路径在 path routing 之前判定，因此没有任何路径接受写方法（注释 [workspace_serve.go:45](file://internal/cli/workspace_serve.go#L45)）。`Cache-Control: no-store` + `X-Content-Type-Options: nosniff` 对全部响应下发（[workspace_serve.go:49-55](file://internal/cli/workspace_serve.go#L49-L55)）。

## `workspace` 与 `worktree` 的概念区分

| 维度 | `workloom workspace`（视图域） | `workloom worktree`（执行工作区） |
|---|---|---|
| 方案章节 | §17（视图） | §4.8（执行） |
| 包 | `internal/view`（+ `internal/sitestatic` 渲染、`internal/knowledge/freshness.go` 判定） | `internal/workspace` |
| M 里程碑 | M7.1（聚合）/ M7.2（静态构建）/ M7.3（serve）/ M7.4（新鲜度提示） | M6.2 |
| 用途 | 把 `.devsys/` + git 状态装配成一份**只读**快照（人类一行一事实 / JSON 信封 / 离线站 / 本地服务） | 为执行任务准备 / 清理 / 列出执行工作区（**可写**）：Git 项目是仓库的 linked worktree（分支前缀 `devsys/<key>`）；非 Git 项目是**目录工作区**（无分支，[internal/workspace/workspace.go:57-66](file://internal/workspace/workspace.go#L57-L66)、[ensureDirectory](file://internal/workspace/workspace.go#L147)） |
| 副作用 | `view` 零写入；`build` 仅写 `--out`（默认 `.devsys/dist/site/`，已 `.gitignore`）；`serve` 零写入 | 创建/删除执行工作区（Git 项目含 worktree 注册与分支，非 Git 项目只建/删目录）、写 `.devsys/workspaces/`；由 `GitProject`（[internal/workspace/git.go:40](file://internal/workspace/git.go#L40)）决定走哪条路 |
| 锁 | 共享锁（`storage.Inspect`）或无锁（advisory）——`build`/`serve` 都不创建共享锁 | 独享锁（执行） |
| CLI 入口 | `workloom workspace view\|build --static\|serve` | `workloom worktree prepare\|remove\|list` |
| 帮助文本 | `workspace     view [--limit N] \| build --static [--out DIR] [--limit N] \| serve [--host 127.0.0.1] [--port N] read-only project view / offline site / local service (方案 §17)`（[cli.go:84](file://internal/cli/cli.go#L84)） | `worktree      prepare \| remove \| list execution workspaces (方案 §4.8)`（[cli.go:80](file://internal/cli/cli.go#L80)） |

帮助文本把两者放在相邻两行，靠子命令前缀 + 注释（`方案 §17` vs `方案 §4.8`）让脚本与人都不混淆。

- **本批（v0.1.9，ca58d27→19b9149）**：① 主命令改名 `workloom`（入口 `cmd/workloom/main.go`），`devsys` 保留为**同一二进制的兼容别名**（入口 `cmd/devsys/main.go`，install 脚本同时装两个名字，[scripts/install.sh:92-98](file://scripts/install.sh#L92-L98)）——`devsys workspace view|build|serve` 与 `workloom …` 等价，本卡示例统一写 `workloom`。② 上表 worktree 行就地修正：`workloom worktree` 在 Git 项目落成仓库的 linked worktree、在非 Git 项目落成**目录工作区**（无分支，[internal/workspace/workspace.go:57-66](file://internal/workspace/workspace.go#L57-L66)、[ensureDirectory](file://internal/workspace/workspace.go#L147)、[GitProject](file://internal/workspace/git.go#L40)）。③ CLI 锚点随 `internal/cli/cli.go` 净增 3 行而下移：`case "workspace"` → [cli.go:315-316](file://internal/cli/cli.go#L315-L316)、`render` 的 JSON 信封 → [cli.go:357-380](file://internal/cli/cli.go#L357-L380)、`--json`/`--jsonl` 互斥 → [cli.go:253-254](file://internal/cli/cli.go#L253-L254)；命令族 flag、退出码 0/2/3、`--out` 拒绝矩阵与 405/Allow 语义都不变。

> 文档约定：「视图域 ≠ 执行工作区」是显式设计约定，在过程文档中显式记录（原始依据见 git 历史中的 docs/开发记录.md）；M7.1 不新增 MCP 工具（§17 未要求），agent 面已有 `agent_session_start`/`context_*` 间接消费视图。
