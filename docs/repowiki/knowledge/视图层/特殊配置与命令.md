# 视图层 · 特殊配置与命令

视图层在 CLI 暴露一个命令族：`devsys workspace view`。本卡梳理它的非显而易见行为（路由、flag、退出码、信封格式），以及「`workspace` 视图域」与 `worktree`（执行工作区）的概念区分。

### flag 行为

#### `--limit N`

- 缺省 `view.DefaultLimit = 50`（[internal/view/view.go:30](file://internal/view/view.go#L30)）。
- 只作用于**列表节**：`Runs.Entries`、`Records.{Decisions,Findings,Artifacts}`、`Knowledge.Pages`。
- **不**作用于 `Progress.Items`、`Project.Milestones`——注释「work items and milestones are never capped — they are the board itself」（[view.go:27-30](file://internal/view/view.go#L27-L30)）。
- `*limit <= 0` → `errUsage("`--limit` must be positive")`（[workspace.go:43-45](file://internal/cli/workspace.go#L43-L45)），退出码 2。
- 截断时对应节 `Truncated=true`；CLI 人类输出在末尾追加「`(truncated; raise --limit for more)`」（`truncatedSuffix`，[workspace.go:148-152](file://internal/cli/workspace.go#L148-L152)）。

#### `--json`（全局，与 `--quiet` 互斥）

- 走 JSON 信封：`{ "ok": true, "model": { ... view.Model ... } }`（[workspace.go:62-66](file://internal/cli/workspace.go#L62-L66)）。
- 信封是 M7.2 静态构建 / M7.3 serve 的**稳定输入**——`view.Model` 字段名 (`schema_version/project/trust/baseline/progress/runs/records/knowledge/sources/problems`) 是契约，详见 [视图数据模型.md](视图数据模型.md)。
- 错误路径同样走 JSON 信封：`{ "ok": false, "error": { "code": 3, "kind": "precondition", "message": "..." } }`（[cli.go:343-357](file://internal/cli/cli.go#L343-L357)）。
- `--json` 与 `--jsonl` 互斥（[cli.go:283-285](file://internal/cli/cli.go#L283-L285)）：M7.1 `view` 不输出 `--jsonl`（`--jsonl` 是 M4 列表族协议）。

### 退出码

M7.1 视图命令族沿用 CLI 既有契约（[cli.go:30-41](file://internal/cli/cli.go#L30-L41)）：

| 退出码 | 触发 | 来源 |
|---|---|---|
| **0** | 成功 | `CodeOK` |
| **1** | 内部错误（如 `view.Build` 返回 `storage` 包的内部错误） | `CodeInternal` / `errInternal` |
| **2** | 用法错误：`workspace` 无子命令 / 未知子命令 / `--limit <= 0` / 解析 flag 失败 | `CodeUsage` / `errUsage` |
| **3** | 前置条件错误：`Build` 报 `storage.ErrNotInitialized`（缺 `.devsys/`） | `CodePrecondition` / `errPrecondition` |
| **4** | 无效 managed state（本命令不直接走 4——`view.Build` 不修改状态，不破坏 schema） | — |

具体调用点：
- 成功：`return nil`（[workspace.go:67](file://internal/cli/workspace.go#L67)）→ `render` 返回 `CodeOK`。
- 缺 `.devsys/`：`view.Build` 返回 `storage.ErrNotInitialized` → `runWorkspaceView` 翻译为 `errPrecondition`（[workspace.go:54-57](file://internal/cli/workspace.go#L54-L57)）→ `render` 返回 `CodePrecondition=3`。
- 用法错误：`fs.NArg() != 0` 或 `*limit <= 0` → `errUsage`（[workspace.go:40-45](file://internal/cli/workspace.go#L40-L45)）→ `render` 返回 `CodeUsage=2`。

> 实跑示例（[README.md:334](file://README.md#L334)）：`bin/devsys.exe workspace view; echo $?` 在缺 `.devsys/` 时输出 3；用法错误输出 2。

### 人类输出格式（`renderWorkspaceView`）

`internal/cli/workspace.go:73-132` 一行一事实：

```text
project: <name> (<id>) — <status>
  phase: <current_phase>                                    # 若非空
  baseline: <short-sha> (<branch>)  dirty: yes|no|unknown   # git 可用时
  baseline: unavailable — <reason>                           # git 不可用时
  state: <summary>                                          # 若非空
  milestone: <id> <status>                                  # 每个里程碑一行
  progress: <n> item(s) — <status counts, sorted>           # countsLine
  readiness: <Verdict>
    risk: <kind> [<workitem-id>]: <detail>                 # 每个 risk 一行
    next: <action> [<workitem-id>] — <reason>               # 一个 next 行
  runs: <n> — <status counts>  (truncated; raise --limit for more)   # 若截断
  records: decisions <d>  findings <f>  artifacts <a>  (truncated; ...)
```

## `workspace` 与 `worktree` 的概念区分

| 维度 | `devsys workspace`（视图域） | `devsys worktree`（执行工作区） |
|---|---|---|
| 方案章节 | §17（视图） | §4.8（执行） |
| 包 | `internal/view` | `internal/workspace` |
| M 里程碑 | M7.1（聚合）/ M7.2（静态构建）/ M7.3（serve） | M6.2 |
| 用途 | 把 `.devsys/` + git 状态装配成一份**只读**快照 | 为执行任务准备 / 清理 / 列出 git worktree（**可写**） |
| 副作用 | 无（零写入契约） | 创建 worktree、删 worktree、写 `.devsys/workspaces/` |
| 锁 | 共享锁（`storage.Inspect`）或无锁（advisory） | 独享锁（执行） |
| CLI 入口 | `devsys workspace view` | `devsys worktree prepare\|remove\|list` |
| 帮助文本 | `workspace     view [--limit N] read-only project view: blueprint, progress, runs, records, knowledge (方案 §17)` | `worktree      prepare \| remove \| list execution workspaces (方案 §4.8)` |

帮助文本（[cli.go:78-81](file://internal/cli/cli.go#L78-L81)）明确把两者放在相邻两行，靠子命令前缀 + 注释（`方案 §17` vs `方案 §4.8`）让脚本与人都不混淆。

> 文档约定：[docs/开发记录.md:360](file://docs/开发记录.md#L360) 显式记了「视图域 ≠ 执行工作区」这一区分；M7.1 不新增 MCP 工具（§17 未要求），agent 面已有 `agent_session_start`/`context_*` 间接消费视图。

## 不暴露的命令

M7.1 视图层**不**暴露：

- `devsys view`（无 `view` 顶层命令；M5.6 已有 `devsys knowledge status` 等命令族，但视图聚合是 `workspace` 域的子能力）。
- `devsys workspace serve` / `devsys workspace build`（M7.2/M7.3 计划中）。
- `devsys workspace inspect` / `devsys workspace ls`：视图命令族当前**只**有 `view` 子命令；未知子命令触发 `errUsage("unknown `devsys workspace` subcommand %q", rest[0])`（[workspace.go:24-28](file://internal/cli/workspace.go#L24-L28)）。
