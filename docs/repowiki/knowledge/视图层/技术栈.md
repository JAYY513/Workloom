## 不引入的依赖

- **不引入** `github.com/go-git/go-git` / `github.com/src-d/go-git` 等 Go git 库——git 状态只读 `HEAD`/`abbrev-ref`/`status --porcelain`/`diff`，系统 `git` 二进制足够；间接调用统一在 `internal/knowledge`（[freshness.go:206](file://internal/knowledge/freshness.go#L206)），视图层只调 `Head/Changes`，不直接 exec。
- **不引入** YAML 库替代品——所有 YAML 走 `domain.DecodeYAML`（M0 沿用 `gopkg.in/yaml.v3`），不引入 `github.com/goccy/go-yaml` / `github.com/ghodss/yaml`。
- **不引入** Go html/template 之外的模板引擎——M7.2 静态构建与 M7.3 实时渲染都用 `html/template`（[static.go:13](file://internal/sitestatic/static.go#L13)）的 `siteTmpl`，不引入 `Masterminds/sprig` / `valyala/fasttemplate` / Pongo2 / Jet 等模板库；模板函数 `short12 / ftime / dirtyStr / join` 全是 Go 标准库或内部小函数（[static.go:257-262](file://internal/sitestatic/static.go#L257-L262)）。

## 关键非默认决策

### 1. 共享锁 vs 裸读

视图层**不**走 `os.ReadFile` 直读 `.devsys/*`——所有读都过 `storage.Inspect`/`InspectUnlocked`。理由：

- `Inspect` 在已有锁文件上取**共享**锁（多读者可并发、写者独享），避免「读到一半被写者改」造成的视图撕裂。
- `InspectUnlocked` 用于锁文件不存在的场景（只读副本 / 新检出），避开「为了读而写锁」破坏只读契约。
- `storage.Reader` 暴露的 `Read` 还承担「目录存在性 + 路径规范化」职责，比裸 `os.Open` 安全。

### 2. git 经 `internal/knowledge` 中转

视图层**不**直接 `exec.Command("git", ...)`——所有 git 调用走 `internal/knowledge.Head/Changes`（[build.go:806-816](file://internal/view/build.go#L806-L816)）。理由：

- 「git 在哪里、git 不可用怎么降级」是知识层的事（M5.3 起就有了 `ErrNoGit` 概念），视图层只消费「commit/branch/changed files」。
- 测试用 `internal/knowledge.freshness_test.go` 的 git 助手（`exec.Command("git", "-C", root, ...)`），视图层自己的 `view_test.go` 仍以相同方式 init/seed（[view_test.go:42-51](file://internal/view/view_test.go#L42-L51)）——但视图层代码**永不**直接 exec git。
- 复用 `internal/knowledge` 让视图层与 `context get --task` 共享同一份基线计算。

### 3. JSONL 断尾检测经 `storage.InspectJSONL`

视图层**不**自己实现「读最后一行看 `\n` 结尾」——直接调 `storage.InspectJSONL`（[build.go:495](file://internal/view/build.go#L495)）。理由：

- `storage.TailStatus.Complete` 是 M5 已建立的语义（`internal/storage/jsonl.go:25-49`）；`true` 表示文件空或末尾有换行，`false` 表示断尾。
- `ErrIncompleteTail` 是写入侧的哨兵（`internal/storage/errors.go:30`），视图层只**消费** `TailStatus`，不消费错误类型——避免与写入路径的语义耦合。
- 复用让「视图报告断尾」与「写入侧拒绝追加」走同一份判断逻辑，不会出现「视图说完整、写入侧说断尾」的不一致。

### 4. `Options.Now` 注入而非全局时钟

`view.Options.Now`（[view.go:54-60](file://internal/view/view.go#L54-L60)）是显式注入点：

- 测试 `Options{Now: fixedClock}` 控制时钟；模型本身不带 `Now`。
- 同一状态两次构建 marshal 出来**逐字节相同**（[view_test.go:293-306](file://internal/view/view_test.go#L293-L306)）；这把确定性保证做到模型层而不是 Build 入口。

### 5. html/template 而非 text/template

渲染层**用** `html/template`（[static.go:13](file://internal/sitestatic/static.go#L13)）**而非** `text/template`。理由：

- `html/template` 对上下文敏感——`{{.Field}}` 在 HTML 文本上下文自动转义 `<` `>` `&` `'` `"`，所以即便模型里出现 `<b>`/`<script>` 这类字面量，输出也只是 `&lt;b&gt;`/`&lt;script&gt;`，不会被浏览器当 markup 解析。`TestBuildEscapesFacts`（[static_test.go:138-147](file://internal/sitestatic/static_test.go#L138-L147)）断言这一点。
- freshnessHint 的命令文本（如 `devsys knowledge refresh` / `devsys knowledge refresh --full`）经 `<code>` 输出——`html/template` 会把 `<` `>` 转义，与 `<code>` 标签相安无事；切到 `text/template` 后整页就是无脑串拼接，转义责任落回模板作者。
- 即使模板里没有 `template.HTML` / `template.JS` 这类原始输出（[freshness_test.go:90](file://internal/sitestatic/freshness_test.go#L90) 的注释也要求「no template.HTML anywhere」），`html/template` 仍是默认——不是优化，是合同。

### 6. 单本地样式 + 零 JS + 零外部引用

站点**不**引入任何外部 CSS / JS / webfont / CDN。理由：

- `styleCSS`（[static.go:266-284](file://internal/sitestatic/static.go#L266-L284)）是 `package sitestatic` 内的 Go 字符串常量：`@import` 计数 0、`url(` 计数 0、外部 host 计数 0；`font-family` 只引系统字体栈（`system-ui,-apple-system,"Segoe UI","Noto Sans SC",sans-serif`）。`Build` 与 serve 共用同一字符串，所以静态构建的 `assets/style.css` 与 serve 的 `/assets/style.css` 路由逐字节一致。
- 零 JS：`TestBuildIsOffline`（[static_test.go:111-135](file://internal/sitestatic/static_test.go#L111-L135)）对全部 8 个落盘文件跑两条断言——`extRef` 正则（`http://` / `https://` / `ftp://` / `ws://` 等）+ `strings.Contains(..., "<script")` 子串检查；任何脚本注入或远程引用都会使单测失败。
- 双重保证：除了单测的正则/子串，渲染层在生产路径上同样没有 JS——所有「展开/折叠/异步加载」都不存在，导航就是 `<a href="*.html">`，CSS 限定 `position:sticky` 顶部 nav 一行就够。
- 这套姿态是为了让 site 在断网/受限环境（CI artifact、内网 review、压缩包分发）下能原样打开。

### 7. 模板 map 在 Go 侧预排序

`html/template` 对 `range` map 的迭代顺序**未定义**——同样的输入两次构建可能渲染出不同顺序的列表，破坏「同输入同 generatedAt 逐字节相同」的确定性。理由：

- `sortedCounts(m map[string]int) []kv`（[static.go:97-104](file://internal/sitestatic/static.go#L97-L104)）在 Go 侧按 key 字典序排序，返回 `[]kv{K,V}`；模板 `{{range .ProgressCounts}}` 直接遍历 slice，不再接触 map。
- `groupWorkflows(items []view.Item) []workflowGroup`（[static.go:112-128](file://internal/sitestatic/static.go#L112-L128)）按模型已给的 item 顺序（item-ID 顺序）把工作流聚合，工作流组内顺序与组间顺序都来自模型本身，模板不参与排序。
- 副作用：模板里没有任何 `range $k, $v := .SomeMap`；这是约定，所有传给模板的关联容器要么是 slice、要么是已排序的 `[]kv`。

### 8. M7.2 Build 与 M7.3 serve 共享同一渲染路径

`workspace build --static`（M7.2）与 `workspace serve`（M7.3）共用 `internal/sitestatic.RenderPage` + `siteTmpl`。理由：

- `sitestatic.Build`（[static.go:442-483](file://internal/sitestatic/static.go#L442-L483)）对每个 `pageMeta` 调 `siteTmpl.ExecuteTemplate(&sb, pm.tmpl, data)` 写 `strings.Builder`，结果字节写入落盘文件。
- `sitestatic.RenderPage`（[render.go:17-33](file://internal/sitestatic/render.go#L17-L33)）对同一 `pageMeta` 调完全相同的 `ExecuteTemplate`，结果字节写入响应体。
- `render_test.go` 的 byte-equality 单测断言：同一 `(model, generatedAt, file)` 在 `Build` 落盘与 `RenderPage` 返回值之间逐字节相同——所以静态构建产物与 serve 路由**永远不会分叉**。
- serve 的 `buildView`（[workspace_serve.go:114-121](file://internal/cli/workspace_serve.go#L114-L121)）每请求现装 `view.Build`，不缓存、不落盘；运行期零文件写入。

### 9. M7.4 freshnessHint 派生在 Go 侧、不进模板

`freshnessHint(k view.Knowledge)`（[static.go:174-185](file://internal/sitestatic/static.go#L174-L185)）按 `k.Status` 枚举返回 `(show, title, text, reason, cmd)`。理由：

- 判定逻辑（fresh 不显示 / stale → `devsys knowledge refresh` / missing → `devsys knowledge refresh --full` / unavailable → 空命令）在 Go 侧；模板只在 `{{if .ShowFreshness}}` 处决定要不要渲染块。
- freshness 复用 `knowledge.Evaluate` 算出的 `Knowledge.Status / Reason`（M5.4 起就有了），不在视图层重新打 git / 算时间——保证 `workspace view` 与 `workspace build --static` 与 `workspace serve` 三处的「新鲜度提示」走同一份事实。
- CLI 文本面：`workspace view` 与 `workspace build --static` 的人脸只加这一行渲染，**不动** `--json` 信封字段、**不动**退出码（trust 之外的状态信号都属 `codedExit` / 退出码 0）。
