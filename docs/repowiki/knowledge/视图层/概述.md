# 视图层 · 概述

本模块是 M7 里程碑**只读聚合层**的 M7.1 部分（实施计划）：把 `.devsys/` 状态文件 + git 状态 + 知识层状态装配成一份**视图快照**（`view.Model`），交给 CLI/MCP 以及后续 M7.2 静态构建、M7.3 `workspace serve` 渲染层作为稳定数据面。**它不写任何文件**，**不渲染页面**，**不起进程**——它是一个聚合读端的纯函数，给视图域 `devsys workspace` 提供「一次装配、所有节都可信」的数据契约。

## 模块定位

- **做什么**：
  - **装配 `view.Model`**（`internal/view/build.go` 的 `Build(ctx, root, opts)`）：读 `.devsys/project.yaml`、`.devsys/state/current.yaml`、`.devsys/state/milestones.yaml`、`.devsys/workitems/*.yaml`、`.devsys/runs/*.yaml`、`.devsys/runs/*.jsonl`、`.devsys/decisions|findings|artifacts/*.yaml`、`.devsys/approvals/*.yaml`、`.devsys/workflows/*.md`、`.devsys/knowledge/{state.json,snapshot.json}` + 项目配置的 page roots + git HEAD/branch/changes，按节填出 `Project/Progress/Runs/Records/Knowledge` 五节 + 顶层 `Trust/Baseline/Sources/Problems`。每节带 `Provenance.Sources`（项目相对路径，目录以 `/` 结尾）；顶层 `Sources` 是各节 sources 的 `sortedUnique` 并集 + git 基线。
  - **信任态分类**（`view.Trust.State` 三态）：`ok`（共享锁下读取）/ `advisory_unlocked`（无锁文件，退回 `storage.InspectUnlocked`，仍渲染业务事实）/ `pending_transaction`（存在待恢复事务，按方案 §15.4 不渲染业务事实，列出事务 ID 并提示 `devsys recover`）。三种状态是视图对「这一份快照能信多少」的明示答案。
  - **§7.4 就绪判定嵌入进度节**（`view.Progress.Readiness`）：通过 `next.Evaluate(next.Input{...})` 复算 `devsys next` 的 verdict/reasons/risks/fixes/next，传入与 `next` 同样的工作项/里程碑/事务/租约/metadata 缺陷/policy 缺陷/审批参数——视图与就绪判定共用一份实现，不会彼此偏离。
  - **git 基线**（`view.Baseline`）：`Available/Commit/Branch/Dirty *bool/ChangedFiles/Reason`；git 不可用时 `Available=false`、脏位 `nil`（不假装 false），原因写 `Reason`。
  - **知识新鲜度嵌入知识节**（`view.Knowledge`）：复用 `internal/knowledge` 的 `Scan/LoadState/Head/Changes/Evaluate/AdapterByName/MergeStates`——状态机裁决 `fresh/stale/missing/unavailable`；其中 `unavailable`（如无 git）是「问题答不出来」而不是「新鲜」（方案 §12.5）。
  - **运行事件流的断尾报告**（`view.RunEntry.StreamTorn`）：通过 `storage.InspectJSONL` 判定「run 的事件流是否未完整闭合」，**只报告不修复**——修复属 M6.1 的 run 写入侧职责。
  - **确定性聚合**：模型无墙钟字段（`Options.Now` 只喂就绪判定，不落 JSON）；列表先定序（runs 按 started_at 倒序再 id、decisions/artifacts 按 created_at 倒序再 id、findings 按 id、pages 按 path、items 按 id）再按 `DefaultLimit=50`（`--limit` 覆盖）截断并置 `Truncated`；同一状态两次构建 marshal 出来**逐字节相同**。
- **不做什么**：
  - **不恢复事务**：即使存在 pending transaction，视图也只 `report` + `pendingReadiness`（FAIL + `devsys recover` 修复项），从不调用 `reconcile.Recover` 或 `storage.RecoverPending`。
  - **不修复断尾事件流**：`streamTorn` 只查 `storage.InspectJSONL` 的 `Complete` 标志位；写入侧的截断（`storage.RepairTornTail`）不归本层。
  - **不写 `.devsys/.cache/`**：`storage.Read` 会建锁并写缓存，本层只走 `storage.Inspect`（在已有锁文件上取共享锁，不创建）与 `storage.InspectUnlocked`（无锁文件时降级）。
  - **不起进程**（不探测生成器）：生成器适配层的 `Probe(ctx)`（如 `repowiki adapter probe`）需要跑进程，本层从不调用——知识层用 `AdapterByName + Import` 读适配器的**已落盘** state 即可。
  - **不渲染页面**：M7.2 的 TypeScript/React 渲染层、M7.3 的 `workspace serve` 才是渲染侧；M7.1 只输出 JSON 信封 + CLI 一行一事实的人类输出。
  - **不接管执行工作区**：执行工作区是 `devsys worktree`（方案 §4.8，包 `internal/workspace`），与 `devsys workspace view`（视图域，方案 §17）是两个不同的概念——CLI 帮助文本（[internal/cli/cli.go:81](file://internal/cli/cli.go#L81)）与本卡都对两者做了区分。
