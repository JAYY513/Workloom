# 视图层 · 概述

本模块是 M7 里程碑**只读视图层**（方案 §17）：把 `.devsys/` 状态文件 + git 状态 + 知识层状态装配成一份**视图快照**（`view.Model`），交给若干渲染形态作为稳定数据面。M7.1 装配、M7.2 离线静态站（`internal/sitestatic.Build` + `workloom workspace build --static`）、M7.3 本地只读服务（`internal/sitestatic.RenderPage` + `workloom workspace serve`）与 M7.4 知识新鲜度提示渲染（`sitestatic.freshnessHint` 派生字段）共同构成「一次装配、所有节都可信」的数据契约。

本批起模块内有**两个互不共享代码的渲染面**，都消费同一份 `view.Model`：

| 渲染面 | 包 | 形态 | 服务对象 |
|---|---|---|---|
| workspace 视图域 | `internal/sitestatic/**` | **离线**静态站，6 页 + `data/model.json`，**零 JavaScript** | `workloom workspace build --static` / `serve` |
| Hub 聚合域 | `internal/hubstatic/**` | **在线**单页应用，`go:embed` 打包，**JS 驱动** | `workloom hub serve`（多项目） |

**不要把两者混为一谈**：形态相反（离线 vs 在线、单项目 vs 多项目、零 JS vs 有 JS）、没有共享代码、各有各的调色板与渲染策略。区别详见 [Hub静态资源](Hub静态资源.md) 卡。

视图域 = `workloom workspace`，与执行工作区 `workloom worktree` 是不同概念。

## 模块定位

- **做什么**：
  - **装配 `view.Model`**（`internal/view/build.go` 的 `Build(ctx, root, opts)`，M7.1）：读 `.devsys/project.yaml`、`.devsys/state/current.yaml`、`.devsys/state/milestones.yaml`、`.devsys/workitems/*.yaml`、`.devsys/runs/*.yaml`、`.devsys/runs/*.jsonl`、`.devsys/artifacts/*.yaml`、`.devsys/approvals/*.yaml`、`.devsys/workflows/*.md`、`.devsys/knowledge/{state.json,snapshot.json}` + 项目配置的 page roots + git HEAD/branch/changes，按节填出 `Project/Progress/Workflows/Runs/Records/Knowledge` + 顶层 `Trust/Baseline/Sources/Problems`。每节带 `Provenance.Sources`（项目相对路径，目录以 `/` 结尾）；顶层 `Sources` 是各节 sources 的 `sortedUnique` 并集 + git 基线。**这是 M7.2/M7.3 与 Hub 的唯一数据入口**。
  - **信任态分类**（`view.Trust.State` 三态，M7.1）：`ok`（共享锁下读取）/ `advisory_unlocked`（无锁文件，退回 `storage.InspectUnlocked`，仍渲染业务事实）/ `pending_transaction`（存在待恢复事务，按方案 §15.4 不渲染业务事实，列出事务 ID 并提示 `workloom recover`）。三种状态是视图对「这一份快照能信多少」的明示答案。
  - **§7.4 就绪判定嵌入进度节**（`view.Progress.Readiness`，M7.1）：通过 `next.Evaluate(next.Input{...})` 复算 `workloom next` 的 verdict/reasons/risks/fixes/next，传入与 `next` 同样的工作项/里程碑/事务/租约/metadata 缺陷/policy 缺陷/审批参数；视图在此基础上多传 `PolicyIDs`（声明的策略 id）+ `DefaultPolicy`（项目级默认策略）+ `QualityBlocks: next.QualityBlocks(items, facts.policyOf(default))`——`QualityBlocks` 让 ready 工作项的质量门判定与 `workitem claim` 同源，视图判放过的事 `claim` 也判放过、`rep.Risks` 里 `RiskQualityBlocked` 出现时即意味着 `claim` 必拒——视图与就绪判定共用一份实现，不会彼此偏离；v0.1.3 起再增传 `HasBlueprint`（project.yaml 是否声明 blueprint artifact，供空项目风险判定）+ `DeadAttempts`/`InFlight`（由 `attemptSignals` 复用 `next.ClassifyAttempts` 对每个工作项最新 run 与事件流行数分类，与 `workloom next` 同一份）——僵死领取（recover_claim 档）与在飞尝试的 CONCERNS 信号在视图与 CLI 间不分叉。
  - **git 基线**（`view.Baseline`，M7.1）：`Available/Commit/Branch/Dirty *bool/ChangedFiles/Reason`；git 不可用时 `Available=false`、脏位 `nil`（不假装 false），原因写 `Reason`。
  - **知识新鲜度嵌入知识节**（`view.Knowledge`，M7.1）：复用 `internal/knowledge` 的 `Scan/LoadState/Head/Changes/Evaluate/AdapterByName/MergeStates`——状态机裁决 `fresh/stale/missing/unavailable`；其中 `unavailable`（如无 git）是「问题答不出来」而不是「新鲜」（方案 §12.5）。
