# 编码规范 · 项目接入与配置

## 命名

- 包名小写：`cli` / `config` / `project` / `registry` / `version` / `domain`。
- 全局开关与 `options` 结构字段：`--json` / `--quiet` / `--actor` / `--reason` / `--expect` / `--confirm` / `--owner` / `--token` / `--to` / `--policy` / `--stage` / `--scope` / `--run` / `--by` / `--comment` / `--status` / `--workitem`。
- 退出码常量：`CodeOK = 0` / `CodeInternal = 1` / `CodeUsage = 2` / `CodePrecondition = 3` / `CodeInvalid = 4`。
- 错误构造器：`errUsage` / `errPrecondition` / `errInvalid` / `errInternal`，统一返回 `*codedError{kind, code}`。
- 类型化错误：`codedError{kind, code, msg, problems}` 与 `config.Problem{File, Line, Field, Reason}`。
- **错误用结构体携带元数据**：`config.Problem` / `domain.TransitionError{From, To, Allowed, Reason}` / `workitem.WorkflowStepError{Step, Reason, Allowed}` / `workflow.RenderError{Kind, Variables, Line, Reason}` / `*app.Error{Kind, Message, Problems}`（M4 起所有业务错误收口到 `internal/app`）。
- **wrap with sentinel**：`fmt.Errorf("%w: <detail>", <sentinel>, <args>)`，调用方 `errors.Is` 取 sentinel。
- **CLI 层转换**（M4 收口到 `toCoded`，[internal/cli/cli.go:156-175](file://internal/cli/cli.go#L156-L175)）：M3 之前的 `workitemError`（M2）/ `approvalError`（M3）/ `mapWorkflowError`（M3）三类工具函数被替换为 `*app.Error` + `toCoded` 单一翻译：
  - `app.KindUsage` → `CodeUsage`（kind=usage, code=2）
  - `app.KindPrecondition` → `CodePrecondition`（kind=precondition, code=3）
  - `app.KindInternal` → `CodeInternal`（kind=internal, code=1）
  - `app.KindInvalid` 及 `KindWorkflow / KindGate / KindQuality / KindWorkitem / KindApproval` → `CodeInvalid`（kind=ae.Kind, code=4）
  - `storage.ErrNotInitialized` / `workitem.ErrNotFound` 等 sentinel 在 `app` 包内被包装为 `*app.Error{Kind: precondition}`，不再由 CLI 单独翻译。

- **未知错误兜底**：`runXxx` 函数遇到未识别的 error 默认 `errInternal`（kind=internal, code=1）。

## 命令分发

- 每个顶层命令对应一个 `runXxx(stdout io.Writer, opts options, rest []string) error`；子命令通过 `switch rest[0]` 在 `runXxx` 内部二次分发。
- 每个子命令对应 `runXxxSub(stdout, opts, rest[1:]) error`；`fs := flag.NewFlagSet(name, flag.ContinueOnError)` 解析 flag，`fs.SetOutput(io.Discard)` 抑制 flag 库自带错误，`fs.NArg() != 0` 视为位置参数过多。
- **全局开关必须前置**：解析器遇到第一个非选项参数即停止收集开关；`init` 与 `config check` 拒绝多余位置参数。
- **位置参数 vs `--flag`**：M2 起 `workitem transition` / `claim` 改用 `--id` 而非位置参数（与 Go `flag` 在首个位置参数处停止解析的行为一致）。

## `--expect` 与 `--confirm` 解析

`expectedSnapshot(ctx, items, id, expect)`：

- 空字符串 → 抛 `version mismatch: <id>` 错误。
- `strings.TrimSpace` 后 `hex.DecodeString`；长度 ≠ 64 hex / 32 字节 → 抛 `version mismatch: <id>`。
- 比对 `items.Get(ctx, id)` 的 `Version` 字段。
- 任意错误 → `bytes = nil`，由 CLI 层升为 `CodePrecondition`。
- 成功 → 返回 `(*domain.WorkItem, rawBytes, nil)`。

`computeConfirmation(plan)` / `compareConfirmation(current, provided)` 复用 `reconcile.ComputeDigest` 与 `reconcile.ErrDigestMismatch`。

## 写命令前置校验

`workloom init` / `workitem create` / `workitem transition` / `workflow start` / `step-complete` 等在动盘前先调：

- `config.Load(root)` 校验受管元数据；`Problems` 非空 → `errInvalid(problems)`。
- `expectedSnapshot(...)` 校验 `--expect`。
- `workflowPolicy(ctx, root, wi, policyID, requirePolicy)` 取策略；`start` 要求非 nil 且当前文件解析成功；`next` / `step-complete` 允许 LKG fallback + `notice`。

## CLI 编码规则（M3 / M4 / M6 / M7.1）

- **workflow 子命令族**（M3）：`check` 只读走 `workflow.Load`；`start` / `next` / `step-complete` / `pause` / `resume` / `cancel` 走 `workflowPolicy` + `items.WorkflowStart/Next/StepComplete/Signal`。`start` 强制 `--policy`；`step-complete` 的 `--to` 可选（缺省取声明序首满足候选）。
- **approval 子命令族**（M3）：`list` / `request` / `approve` / `reject`；`reject` 区分 scope：`scope=stage_gate` 走 `rejectStageGate`（在 `Transition` 的 Guard 内同时 `DecideTx(rejected)` + 状态变更）；`scope=action` 走独立 `Decide(ctx, id, opts{Approve: false})`。
- **next 只读**（M3）：`runNext` 先 `reconcile.Doctor` 收集风险；仅在 `InspectionOK && len(pending) == 0` 时列举 `workitems` 与 `pending approvals`；`workflow.Load` + `config.Diagnose` 收集策略与元数据问题；`next.Evaluate` 输出 `Report`；exit 恒 0。
- **policy 缺失警告**（M3）：`approval request --scope stage_gate` 在声明 `gates.stages[<stage>].require_approval = false` 或未声明时打印 `warning: policy %q declares no require_approval gate for stage %q; nothing will consume this approval`。
- **next 的 invalid_policy 风险**（M3）：`runNext` 在 `workflow.Load` 之外还交叉核对「工作项 `Workflow.ID` 是否对应一份存在的策略文件」，缺失时打印 `work item WLM-N references missing policy "X"` 风险。

- `--json`：成功输出走 stdout（`{ok: true, …}`），错误信封走 stderr（`{ok: false, error: {code, kind, message, problems?}}`）。
- 非 `--json`：成功用人类可读文本（受 `--quiet` 控制），错误走 stderr。
- `--quiet` 仅抑制成功输出；error / warning / 失败详情始终可见。

## 本批（M9 #336/#337 提交 362b637 / 7e08e3d）

- **JSON 空集合**：列表型 `--json` 输出在结果为 `nil` 时**不**输出 `null`，而是显式补 `[]` 后再 encode。`workitem list` / `workflow list` / 任意 `List*` 调用都遵循——调用方按行解析时不需要为「空 vs null」二态做分支。本批在 [internal/cli/cli.go:861-863](file://internal/cli/cli.go#L861-L863) 与 [internal/cli/cli.go:1294-1296](file://internal/cli/cli.go#L1294-L1296) 显式落 `if items == nil { items = []*domain.WorkItem{} }` 与 `if policies == nil { policies = []app.PolicySummary{} }`，保证 JSON 信封 `items` / `policies` 字段稳定为 `[]`。
