# 编码规范

本模块聚焦**接入与配置**特有的编码约束；通用 Go 风格由 `gofmt -l cmd internal` 兜底（[README:53-56](../../../README.md#L53-L56)）。

## 1. 错误分类优先于错误消息

**约定**：所有从底层上报的错误必须经过 `codedError` 重新分类，由 `render` 决定怎么渲染、由退出码决定怎么分支。

**验证**：

- `errUsage` / `errPrecondition` / `errInvalid` / `errInternal` 四种构造器（[`internal/cli/cli.go:77-100`](../../../internal/cli/cli.go#L77-L100)）保证新代码不会绕过 4 个已知类别。
- `render` 在遇到非 `codedError` 时自动升级为 `CodeInternal`（[`internal/cli/cli.go:152-155`](../../../internal/cli/cli.go#L152-L155)），但调用方应主动分类以保留类别信息。

**反模式**：在命令实现里 `fmt.Fprintln(stderr, ...)` 直接打错误——这会让 `--json` 输出丢结构化问题，且退出码始终是 1。

## 2. 错误信息结构化，问题携带位置

**约定**：每个用户可修复的缺陷必须能被定位到具体文件、行列与字段。

**验证**：

- `config.Problem{File, Line, Field, Reason}`（[`internal/config/config.go:46-51`](../../../internal/config/config.go#L46-L51)）是结构化输出与文本渲染的唯一来源。
- `Problem.String()` 渲染为 `file[:line][: field]: reason`（[`internal/config/config.go:54-67`](../../../internal/config/config.go#L54-L67)），与测试期望严格一致（[`internal/cli/cli_test.go:218-226`](../../../internal/cli/cli_test.go#L218-L226)）。
- `Problems` 自身实现 `error`，便于 `errors.As` 在 cli 层取出。
- M1 嵌套结构（`scope` / `current_state` / `milestones`）的 `Field` 形如 `milestones[0].status`，由 `checkMapping` 自动拼出路径（[`internal/config/nested.go:39-64`](../../../internal/config/nested.go#L39-L64)）。

**反模式**：在配置校验里返回 `fmt.Errorf("bad yaml")`——丢失行号与字段名，调用方无法定位。

## 3. 写命令在动盘前必须先 `config.Load`

**约定**：任何会修改 `.devsys/` 的命令在执行写入前都要调用 `config.Load(root)`。存在 `Problems` 即拒绝，并把 `Problems` 透传给 `errInvalid`。

**验证**：

- `project.Init` 在 `gitRoot`/`requireSameDir` 通过后立即调用 `config.Load`（[`internal/project/init.go:67-69`](../../../internal/project/init.go#L67-L69)）。
- 回归测试 `TestInitRefusesUnknownSchemaVersion`（[`internal/cli/cli_test.go:282-331`](../../../internal/cli/cli_test.go#L282-L331)）：把 `schema_version: 1` 改为 `99`，再跑 `init` 必须得到 `CodeInvalid` 且不修改磁盘；`config check` 在同状态下仍能跑出诊断。

**反模式**：写命令自己重新解析受管文件——容易出现两份规则、规则漂移。

## 4. 命令实现只关心业务，`render` 关心呈现

**约定**：命令函数（`runInit` / `runSearch` / `runConfigCheck`）只返回 `error` 或写完 stdout 后返回 `nil`。渲染（人/机两态、错误位置列表展示、退出码）全部交给 `render`。

**验证**：

- `runInit` 在 `opts.json` 时返回 `json.NewEncoder(stdout).Encode(out)` 错误；否则用 `fmt.Fprintf(stdout, ...)` 写人读输出（[`internal/cli/cli.go:213-247`](../../../internal/cli/cli.go#L213-L247)）。
- `runSearch` 同样分支；`--json` 时输出 `{ok, root, query, matches, total}`（[`internal/cli/cli.go:270-282`](../../../internal/cli/cli.go#L270-L282)），人类模式输出 `<相对路径>:<行号>: <行内容>` 与汇总行（[`internal/cli/cli.go:283-289`](../../../internal/cli/cli.go#L283-L289)）。
- `runConfigCheck` 同样分支，但 `--json` 时 `ok` 载荷里多了 `project` 与 `config` 两段解析结果（[`internal/cli/cli.go:319-334`](../../../internal/cli/cli.go#L319-L334)）。

**反模式**：在命令里 `fmt.Fprintln(stderr, "error:", err)`——丢失 `CodeInvalid`/问题列表。

## 5. 稳定序列化：相同输入产生相同字节

**约定**：受管 YAML 文件的字段顺序是 struct 字段顺序；`storage.EncodeYAML` / `domain.EncodeYAML` 保证键序稳定；`storage.AtomicWrite` 保证读者永远看到完整文件。

**验证**：

- 占位 YAML 的 Go struct 字段顺序（[`internal/project/tree.go:56-84`](../../../internal/project/tree.go#L56-L84)）即落盘顺序，且与 `config` 包的白名单字段顺序（[`internal/config/validate.go:41-73`](../../../internal/config/validate.go#L41-L73)）一一对应——这两份顺序**必须**同步演进，否则 init 写出的文件会被 `config check` 自己拒绝。
- `domain.EncodeYAML` 通过 `preserveNulls`（[`internal/domain/serialize.go:32-71`](../../../internal/domain/serialize.go#L32-L71)）把 nil 切片保留为 `!!null`，避免“未记录”与“空列表”被 yaml.v3 默认行为抹平。
- `registry.Save` 在写入前对 `Projects` 按 `normKey` 排序（[`internal/registry/registry.go:124-126`](../../../internal/registry/registry.go#L124-L126)），保证多次 `init` 在不同顺序下产生的注册表字节相同，便于 diff。

**反模式**：`map[string]any` 编码 YAML——`gopkg.in/yaml.v3` 对 map 的键序不保证，相同输入可能产出不同字节，破坏幂等。

## 6. 出口位置守恒：受管文件永远在仓库根

**约定**：`devsys init` 拒绝在子目录运行；CWD 必须与 `git rev-parse --show-toplevel` 同一目录。

**验证**：

- `requireSameDir` 用 `os.SameFile` 比较 inode（[`internal/project/init.go:146-159`](../../../internal/project/init.go#L146-L159)），不依赖字符串比较。
- 触发时返回 `PreconditionError`，cli 把它升级为 `CodePrecondition`（退出码 3）。

**反模式**：在子目录运行 init 时“自动向上找 .git”——会让人困惑 `.devsys/` 落在哪里，且与“状态目录永远在仓库根”的约束冲突。

## 7. 嵌套字段路径用 `[index].child` 形式

**约定**：所有嵌套结构校验错误必须给出从根到叶子节点的完整路径，便于手编辑者直接定位。

**验证**：

- 序列元素：`checkNested` 把 `name := fmt.Sprintf("%s[%d]", path, i)` 作为子节点路径前缀（[`internal/config/nested.go:13`](../../../internal/config/nested.go#L13)）。
- 映射子键：`checkMapping` 把 `name := path + "." + key.Value` 拼到子节点（[`internal/config/nested.go:39`](../../../internal/config/nested.go#L39)）。
- `Problem.Field` 直接取该路径字符串，使输出形如 `milestones[0].status: required`。

**反模式**：仅报 `milestones: invalid`——调用方无法定位到具体的 `id/name/status` 缺失项。

## 8. JSON 路径必须 `DisallowUnknownFields`

**约定**：领域记录的 JSON 反序列化路径必须严格拒绝未声明字段，与 YAML 端的 `projectSpec` 保持对称。

**验证**：

- `domain.DecodeJSON` 在 `json.Decoder` 上调用 `DisallowUnknownFields`（[`internal/domain/serialize.go:96`](../../../internal/domain/serialize.go#L96)）；多余字段直接报错。
- `DecodeJSON` 还会在末尾再用一次 `Decode` 拒绝多文档 JSON（[`internal/domain/serialize.go:100-106`](../../../internal/domain/serialize.go#L100-L106)），与 `parseDoc` 在 YAML 端的行为一致。


## 9. workitem 写命令强制 `--expect` CAS

**约定**：`workitem transition` 与 `workitem claim` 必须把调用方持有的工作项快照哈希透传给底层；`expectedSnapshot` 只接受 64-hex sha256，长度错误、十六进制解码失败、哈希不匹配一律 fail-closed（[`internal/cli/cli.go:493-506`](../../../internal/cli/cli.go#L493-L506)）。

**验证**：

- `workitem get` 在 `--json` 时输出 `version` 字段为 `fmt.Sprintf("%x", storage.HashBytes(raw))`（[`internal/cli/cli.go:381-389`](../../../internal/cli/cli.go#L381-L389)），人类模式末行同样打印 64-hex；调用方把它原样回传给 `--expect` 即可完成 CAS。
- 哈希长度不为 `sha256.Size` 或解码失败时，`expectedSnapshot` 直接返回 `version mismatch` 错误，由 `workitemError` 升为 `CodePrecondition`。
- 哈希匹配时 `expectedSnapshot` 才返回 `raw` 字节给底层 `Transition` / `Claim` 作为 `Expected` 入参；底层 CAS 失败由领域错误继续上浮为 `CodeInvalid`。

**反模式**：调用方跳过 `workitem get` 直接写一个固定字符串进 `--expect`——会被立即拒绝；或写命令自己读文件再算哈希——会与底层 hash 算法漂移。

## 10. 写命令必填 `--actor` 与 `--reason`

**约定**：所有动盘的命令在创建、修改、修复路径上必须记录操作者与原因（审计追溯）。CLI 层直接拒绝缺失的必填参数，**不**走默认占位。

**验证**：

- `workitem create` 用 `flag.NewFlagSet` 解析 `--title` / `--actor` / `--reason` / `--prefix`；任一必填为空或 `NArg != 0` 即返回 `errUsage`（[`internal/cli/cli.go:392-400`](../../../internal/cli/cli.go#L392-L400)）。
- `workitem transition` 强制 `--actor` + `--reason`（[`internal/cli/cli.go:416-425`](../../../internal/cli/cli.go#L416-L425)），`workitem claim` 强制 `--owner` + `--reason`（[`internal/cli/cli.go:441-449`](../../../internal/cli/cli.go#L441-L449)），二者与 `--expect` 共同组成最小必填集合。
- `recover` 与 `repair --apply / --dry-run` 都强制 `--actor` + `--reason`，缺失时 `errUsage`（[`internal/cli/cli.go:559-566`](../../../internal/cli/cli.go#L559-L566)、[`internal/cli/cli.go:598-608`](../../../internal/cli/cli.go#L598-L608)）。

**反模式**：写命令从环境变量、用户名或默认值中自动推断操作者——会丢失审计链；或在底层默认值上补救——绕过 CLI 必填约束。

## 11. JSON 路径必须 `DisallowUnknownFields`

**约定**：领域记录的 JSON 反序列化路径必须严格拒绝未声明字段，与 YAML 端的 `projectSpec` 保持对称。

**验证**：

- `domain.DecodeJSON` 在 `json.Decoder` 上调用 `DisallowUnknownFields`（[`internal/domain/serialize.go:96`](../../../internal/domain/serialize.go#L96)）；多余字段直接报错。
- `DecodeJSON` 还会在末尾再用一次 `Decode` 拒绝多文档 JSON（[`internal/domain/serialize.go:100-106`](../../../internal/domain/serialize.go#L100-L106)），与 `parseDoc` 在 YAML 端的行为一致。

**反模式**：解码时容许 `interface{}` 兜底——会让 schema 演进的漂移悄无声息地落到磁盘上。
