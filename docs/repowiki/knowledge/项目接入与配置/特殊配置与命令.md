# 特殊配置与命令 · 项目接入与配置

## `devsys init`

唯一允许修改受管文件的写命令。它把 `.devsys/` 布局落到 Git 仓库根目录、写入 4 份占位元数据、注册项目路径到用户级注册表，并保证 `.devsys/.gitignore` 至少覆盖 `local/` 与 `.cache/`。子目录不是仓库根时会拒绝执行。

```sh
cd /path/to/your/git-repo
devsys --json init
devsys --quiet init
devsys config check
```

文本模式报告初始化目录、项目名称与 ID、实际创建的路径数量及注册表路径；数量取决于已有布局。JSON 模式返回实际创建路径与登记结果。

幂等行为：

- 缺失的 `.devsys/`、子目录和占位文件会被补建；现存占位元数据不重写。
- `.devsys/.gitignore` 若已存在，只追加缺失的 `local/`、`.cache/` 行，原有内容不变。
- 落盘前先校验现有受管元数据；若已存在的 `project.yaml` / `config.yaml` / `state/*.yaml` 出现未知 `schema_version`、未知键或类型错误，`init` 拒绝改动并报退出码 4。
- 当前目录不在 Git 仓库或 `git` 不可用 → 退出码 3（前置条件），无任何写入。

## `devsys config check`

只读诊断：不加锁、不写盘、不恢复事务。遍历四份受管元数据文件，逐条定位问题，按 `文件:行号: 字段: 原因` 格式化输出。

```sh
devsys config check             # 通过：config ok: 4 files checked
devsys --json config check      # {ok,root,checked,project?,config?}
devsys config check; echo $?    # 0 / 4 / 3
```

四份受管文件（顺序固定）：`project.yaml`、`config.yaml`、`state/current.yaml`、`state/milestones.yaml`。问题示例：

```
project.yaml:5: unknown_field: unknown key
project.yaml:2: schema_version: unsupported version 99 (...)
config.yaml:2: timeout: unknown key
```

`--json` 模式下问题进入 `error.problems` 数组（`code=4`、`kind=invalid`）；通过时返回完整 `project`、`config` 解析结果。`init` 之前的项目目录 → 退出码 3。

## `devsys search <keyword>`

`.devsys/` 下无索引文本扫描：大小写不敏感子串匹配，单文件最多 5 条命中行，行内容截断 200 字节（UTF-8 安全），排除 `.cache/` 与 `local/`。缺少关键字参数或多于一个位置参数 → 退出码 2。

```sh
devsys search 密码
devsys --json search WLM-2
devsys search no-such-keyword; echo $?   # 0（零命中仍成功）
```

文本输出：`<相对路径>:<行号>: <行内容>`，末尾汇总 `<N> match(es) in .devsys/ for "<keyword>"`。

`--json` 字段：`ok`、`root`、`query`、`matches[]`（`path`、`line`、`text`）、`total`。零命中时 `matches` 是空数组、`total=0`，退出码仍为 0。

## M2 工作项与对账命令

`workitem` 读写工作项状态，`doctor` / `recover` / `repair` 负责对账与修复。写命令都要求 `--actor` 与 `--reason`（写入审计事件）；状态转换与领取用 `--expect <64-hex version>` 提交你读到的版本（`workitem get` 输出），旧快照会被拒绝。

```sh
bin/devsys.exe workitem get WLM-1                                   # 打印字段与 version: <64-hex>
bin/devsys.exe workitem create --title 任务标题 --actor me --reason 建任务
bin/devsys.exe workitem transition --id WLM-1 --to ready --actor me --reason 拆分完成 --expect <hash>
bin/devsys.exe workitem claim --id WLM-1 --owner me --reason 开工 [--expect <hash>]
bin/devsys.exe doctor                                               # 只读：过期/孤儿领取、待恢复事务、修复提议
bin/devsys.exe recover --actor me --reason 恢复中断的领取
bin/devsys.exe repair --dry-run --actor me --reason 盘点             # 打印提议表与 digest
bin/devsys.exe repair --apply --confirm <digest> --actor me --reason 确认修复
```

- 非法状态转换（如 `draft → in_progress`）→ 退出码 4，stderr 列出允许的下一步。
- 版本哈希不匹配（旧视图）→ 退出码 4，重新 `workitem get` 后再试。
- `doctor` 是只读对账：不创建锁文件、不触发事务恢复；有待恢复事务时只报告事务、不输出业务事实。
- `recover` 先做确定性事务恢复，再释放过期/孤儿领取（每次释放写 `lease_recovered` 事件）；重复执行不产生重复事件。
- `repair --apply` 需要与当前状态一致的 `--confirm` 摘要；摘要不符或证据漂移 → 退出码 3，不写任何文件。

## M3 工作流命令

```sh
bin/devsys.exe workflow check                                                       # 校验 .devsys/workflows/*.md
bin/devsys.exe workflow start --id WLM-1 --policy quick-fix --actor me --reason begin --expect <hash>
bin/devsys.exe workflow next --id WLM-1                                             # 列出候选与首满足推荐
bin/devsys.exe workflow step-complete --id WLM-1 [--to implement] --actor me --reason go --expect <hash>
bin/devsys.exe workflow pause --id WLM-1 --actor me --reason hold --expect <hash>
bin/devsys.exe workflow resume --id WLM-1 --actor me --reason go --expect <hash>
bin/devsys.exe workflow cancel --id WLM-1 --actor me --reason abort --expect <hash>
```

- 所有实例操作强制 `--actor` / `--reason` / `--expect`；租约活跃时强制 `--owner` / `--token`（与 `workitem claim` / `updateclaimed` 同 fencing 契约）。
- `workflow start` 强制 `--policy`；坏策略（无 LKG）→ exit 4。
- `workflow next` 在 paused 时仍展示候选，但不输出 `next:` 推荐（M3Reviewer5 ⑤）。
- `workflow step-complete --to nope`（未声明目标 / 条件不满足 / 目标 = 当前步骤）→ exit 4，stderr 列出 `allowed next steps`（含 `when` 与 `satisfied`）。
- `workflow check` 缺 `id` / `version` 非法 / `steps[].id` 重复 / `transitions[].from` 未知 / `gates.stages.<status>` 状态非法 → exit 4 + `file[:line][: field]: reason`；未知键 warning 仍 exit 0。
- 实例操作**不**改工作项状态、不动 `scheduling/` 目录；`paused` 实例拒绝推进（exit 4 + `paused`）。

## M3 审批命令

```sh
bin/devsys.exe approval list [--workitem <id>] [--status pending|approved|rejected]
bin/devsys.exe approval request --id <wi> --stage <stage> [--scope stage_gate|action] [--run <run>] --actor <a> --reason <r>
bin/devsys.exe approval approve --id approval-<n> --by <decider> [--comment <c>]
bin/devsys.exe approval reject --id approval-<n> --by <decider> --reason <r>
```

- `request` 同 (work item, stage, requested status) 重复申请 → exit 4；`--scope action` 不能带 `--stage`。
- `request` 在声明的 `gates.stages.<stage>.require_approval = false` 或未声明时打印 `warning: policy %q declares no require_approval gate for stage %q; nothing will consume this approval`。
- `approve` / `reject` 在已 `invalidated` / 已非 `pending` 时 exit 4。
- `reject --scope stage_gate` 通过 `rejectStageGate` 在转换事务的 Guard 内同时完成 `approval_rejected` 与工作项 `blocked`（或 `regress:<status>` 回退）；失败整单回滚，审批保持 pending，错误说明 `nothing was changed`。
- `consume` **不**暴露为 CLI 子命令——只有 `workitem transition` 的 Guard 内消费（M3.7 决策）。

## M3 next 命令

```sh
bin/devsys.exe next            # PASS|CONCERNS|FAIL + reasons + risks + fixes + 推荐动作
bin/devsys.exe --json next     # 完整 Report JSON
```

- exit 恒 0；不可信状态（有待恢复事务或缺锁文件）不输出业务事实。
- FAIL 修复项给出 `devsys recover --actor operator --reason "recover interrupted state"`（`Input.RecoverCommand` 可覆盖）。
- 推荐六优先级（§7.4）：`recover_claim` → `review` → `start` → `start_backlog` → `milestone_review` → `report_done`。
- 风险信号：过期租约 → 孤儿领取 → 不可读调度文件 → 滞留审查 → 阻塞 → 元数据非法 → 策略非法（含「工作项引用缺失策略」）→ 待决审批 → 检查受限。
- `next` 不会自动恢复 / 修复；只读给出建议，由调用脚本或人决策。

## 隔离运行与构建

### `DEVSYS_CONFIG_DIR`

所有冒烟剧本与隔离测试通过该环境变量把「全局注册表」隔离到临时目录，避免污染用户配置：

```sh
# Bash
export DEVSYS_CONFIG_DIR="$workspace/config"

# PowerShell
$env:DEVSYS_CONFIG_DIR = 'C:/Temp/workloom-registry'
```

### 离线构建

`vendor/` 已提交；干净机器设 `GOPROXY=off` 即可离线构建。

```sh
GOFLAGS=-mod=vendor GOPROXY=off go build ./...
```

### 构建版本注入

```sh
go build -mod=vendor -ldflags "-X workloom/internal/version.Version=0.1.0 -X workloom/internal/version.Commit=$(git rev-parse --short HEAD)" -o bin/devsys.exe ./cmd/devsys
```
## M4 记录族命令

`decision` / `finding` / `event` / `artifact` / `run` 五个族共享同一形态：`list`（默认按 ID 升序，支持 `--jsonl`）/ `get <id>`（打印单条记录 + 64-hex version）/ 写入子命令（`create` / `register` / `update` / `record` / `approve` / `resolve` / `heartbeat` / `log`）。

```sh
# decision
bin/devsys.exe decision list [--jsonl]
bin/devsys.exe decision get <id> [--json]
bin/devsys.exe decision create --title T --decision D --by <author> [--context C] [--reasoning R] [--options a,b] [--consequences a,b] [--related WLM-1,WLM-2]
bin/devsys.exe decision approve --id <n> --by <decider> [--expect <hash>]

# finding
bin/devsys.exe finding list [--jsonl]
bin/devsys.exe finding get <id>
bin/devsys.exe finding create --title T --finding D --severity low|medium|high --by <author> [--related WLM-N]
bin/devsys.exe finding resolve --id <n> --by <resolver> [--expect <hash>]

# event
bin/devsys.exe event list [--type <type>] [--subject <id>] [--jsonl]
bin/devsys.exe event record --type <type> --subject <id> --actor <a> [--content <json>]

# artifact
bin/devsys.exe artifact list [--name <name>] [--jsonl]
bin/devsys.exe artifact get <id>
bin/devsys.exe artifact register --name <name> --kind <kind> --by <author> [--content <body>]
bin/devsys.exe artifact update --id <n> --kind <kind> --by <author> --expect <hash>  # ErrSuperseded → exit 4
bin/devsys.exe artifact history --id <head>

# run
bin/devsys.exe run list [--workitem <id>] [--status <status>] [--jsonl]
bin/devsys.exe run get <id>
bin/devsys.exe run create --workitem <id> --by <author>
bin/devsys.exe run update --id <r> --status running|completed|failed --by <updater> --expect <hash>
bin/devsys.exe run heartbeat --id <r> --by <owner>
bin/devsys.exe run log --id <r> [--limit N]
```

所有写命令强制 `--actor` / `--reason` / `--expect`（如 `update` / `heartbeat` 涉及状态变更）；`expect` 不匹配 → exit 3。

## M4 wire 与 mcp serve

```sh
# wire：把 devsys 纪律块注入 AGENTS.md；幂等（三次运行字节一致）
bin/devsys.exe wire
bin/devsys.exe wire --dry-run         # 预览 diff，不写盘
# 块标记：<!-- devsys:begin ... --> / <!-- devsys:end -->

```

## M4 端到端剧本

`scripts/smoke-m4.{sh,ps1}` 是 M4 完整端到端验证入口（与 M1–M3 同款）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke-m4.ps1 -Keep
```

```sh
bash scripts/smoke-m4.sh --keep
```

五段 PASS：

1. **MCP 表面**：`scripts/m4helper.exe` 作为 SDK 客户端连 stdio；验证 `tools/list` 暴露/隐藏（默认 `session + executor` 应含 `health` / `workitem_list` / `decision_get` / `agent_session_start` / `knowledge_status` / `run_heartbeat`，并隐藏 `project_update` / `project_create` / `approval_decide`）；调 `decision_create` 做记录往返。
2. **CLI/MCP 写一致**：MCP 创建的决策 → CLI `--json decision get` 能读到同一个 `version`。
3. **会话接口**：单次 `session start` 返回带推荐动作的视图。
4. **交换协议**：`--jsonl workitem list` / `event list` 各行一条 JSON 记录，字段名与 `--json` 信封内同名数组一致；`scripts/exchange-demo.sh` 演示完整读取流。
5. **wire 幂等**：三次 `devsys wire` 后 AGENTS.md 字节级一致；`--dry-run` 预览 diff 不写盘。
