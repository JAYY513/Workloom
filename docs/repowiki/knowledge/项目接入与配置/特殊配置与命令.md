# 特殊配置与命令

只列**非显而易见**的命令与配置。通用 `go build` / `go test` 流程见 [README:22-56](../../../README.md#L22-L56)。

## 命令清单（README 当前约定）

[README.md:31-67](../../../README.md#L31-L67) 给出三组命令面：

- `init`：仓库根一次性创建 `.devsys/`，幂等。
- `config check`：只读诊断受管元数据文件。
- `search <keyword>`：纯文本扫描 `.devsys/`，排除 `.cache/` 与 `local/`，无索引。

M2 起命令面扩展为七组（[internal/cli/cli.go:46-72](../../../internal/cli/cli.go#L46-L72) 的 `usage`）：

- `workitem create|get|transition|claim`：状态机与租约入口，`--expect` 强制 CAS（见下文 §workitem）。
- `doctor`：只读对账报告，待处理事务存在时只提示不修复（见下文 §doctor）。
- `recover`：`storage.Recover` 后释放过期 / 孤儿租约；`--actor` / `--reason` 必填。
- `repair --dry-run` / `--apply --confirm <digest>`：先 dry-run 出 `Plan + Digest`，`--apply` 重跑干跑并比对摘要，仅一致时落盘；`--actor` / `--reason` 必填。

具体退出码含义与 JSON 输出形状在 [Schema 与错误契约](./Schema与错误契约.md) 中详细说明。

## `devsys init`：幂等 + 前置校验的项目初始化

**前置条件**：

1. 当前目录必须**已经**是 git 仓库根（`git rev-parse --show-toplevel` 与 CWD 一致；[internal/project/init.go:55-61](../../../internal/project/init.go#L55-L61)）。
2. `git` 可执行文件必须在 PATH（[internal/project/init.go:128-142](../../../internal/project/init.go#L128-L142)）。
3. 既有 `.devsys/` 下受管元数据文件必须通过 `config.Load` 校验；否则返回 `CodeInvalid`（[internal/project/init.go:67-69](../../../internal/project/init.go#L67-L69)）。

**幂等保证**：

- `.devsys/` 已存在 → 不删不改（[internal/project/init.go:76-80](../../../internal/project/init.go#L76-L80)）。
- 子目录已存在 → 跳过；缺失 → `os.MkdirAll`（[internal/project/init.go:82-93](../../../internal/project/init.go#L82-L93)）。
- 占位 YAML 已存在 → 跳过；缺失 → 用 `storage.AtomicWrite` 写（[internal/project/init.go:95-110](../../../internal/project/init.go#L95-L110)）。
- `.gitignore` 已存在 → 仅追加缺失条目，原行不动（[internal/project/init.go:164-193](../../../internal/project/init.go#L164-L193)）。

**典型用法**（[README:31-41](../../../README.md#L31-L41)）：

```sh
bin/devsys.exe init           # 人类可读输出
bin/devsys.exe init --json    # 机器可读：root/id/name/created/registry_path/registry_updated
bin/devsys.exe init --quiet   # 静默成功（错误仍写 stderr）
bin/devsys.exe init; echo $?  # 非 Git 目录：3
```

`init` 同时**强制刷新**用户级注册表条目 `registry_path` 与 `registry_updated=true`（[internal/cli/cli.go:208-211](../../../internal/cli/cli.go#L208-L211)），无论 `.devsys/` 是否已存在。

## `devsys config check`：只读诊断

**不**加锁、**不**写盘、**不**触发存储恢复。即使受管文件因未知 `schema_version` 不可信，命令仍然跑完并把缺陷列出来。

```sh
bin/devsys.exe config check             # 0 通过；4 有问题
bin/devsys.exe --json config check      # ok=false 时 error.problems 是结构化数组
bin/devsys.exe config check; echo $?    # 未 init：3
```

**输出形状**（[internal/cli/cli.go:319-334](../../../internal/cli/cli.go#L319-L334)）：

| 模式 | 成功 stdout | 失败 stderr |
|---|---|---|
| 人类 | `config ok: 4 files checked` + `project: <name> (<id>)` | 每条问题一行 `file[:line][: field]: reason` |
| `--json` | `{ok, root, checked[], project?, config?}` | `{ok:false, error:{code:4, kind:"invalid", message, problems:[...]}}` |

M1 起 `--json` 成功载荷里的 `project` 字段是完整 `*domain.Project`（[internal/cli/cli.go:326](../../../internal/cli/cli.go#L326)），其字段顺序与 `internal/project/tree.go:60-66` 写出的 YAML 一致。

## `devsys search <keyword>`：只读文本扫描

`search` 不依赖 schema，也不读写任何状态文件：直接遍历 `.devsys/` 下的文本文件，跳过 `.cache/` 与 `local/` 两个子目录，逐行做大小写不敏感的子串匹配（[internal/cli/cli.go:250-290](../../../internal/cli/cli.go#L250-L290)）。

**前置条件**：当前目录必须已经过 `init`，否则返回 `CodePrecondition`（[internal/cli/cli.go:261-265](../../../internal/cli/cli.go#L261-L265)）。

**用法**（[README:57-67](../../../README.md#L57-L67)）：

```sh
bin/devsys.exe search <keyword>
bin/devsys.exe --json search <keyword>   # {ok, root, query, matches, total}
bin/devsys.exe search; echo $?           # 缺关键字：2（用法错误）
bin/devsys.exe search a b; echo $?       # 多余参数：2
```

**输出**：

| 模式 | stdout |
|---|---|
| 人类（默认） | 每命中一行 `<相对路径>:<行号>: <行内容>`，末行 `<N> match(es) in .devsys/ for "<query>"` |
| `--quiet` | 仅保留命中行，关闭汇总行 |
| `--json` | `{ok, root, query, matches:[{path, line, text}], total}`（`matches` 必为数组，命中为零时为 `[]`） |

行内容单条截断 200 字节（UTF-8 安全），单文件最多报告 5 条命中行（[internal/search](../../..) 实现细节）；`--json` 的 `total` 是总命中行数（含被单文件截断掉的命中）。

## `devsys workitem ...`：工作项状态机与租约入口（M2）

四类子命令统一在 `internal/cli/cli.go:361-475` 的 `runWorkitem` 中分发；它们**不**绕过 `internal/workitem` 的写契约，所有修改经 `expectedSnapshot` 完成 CAS。

### `workitem get <id>`：读工作项 + 版本哈希

```sh
bin/devsys.exe workitem get WLM-0001                       # 人类：id/status/title + version
bin/devsys.exe --json workitem get WLM-0001                 # {ok, item, version}；version 为 64-hex sha256
bin/devsys.exe workitem get WLM-0001; echo $?               # 项目未 init / id 不存在：3
```

人类模式输出形如（[internal/cli/cli.go:387-389](../../../internal/cli/cli.go#L387-L389)）：

```text
WLM-0001  in_progress  sample title
version: 1c2d3e4f...
```

末尾的 `version` 行（与 `--json` 的 `version` 字段）即后续 `--expect` 的输入。

### `workitem create --title <title> --actor <a> --reason <r> [--prefix WLM]`

```sh
bin/devsys.exe workitem create --title "fix schema drift" --actor alice --reason "M2 kickoff"
```

- `--title` / `--actor` / `--reason` 三个参数任一缺失或剩余位置参数 → `CodeUsage`（[internal/cli/cli.go:398-400](../../../internal/cli/cli.go#L398-L400)）。
- 内部先调 `config.Load(root)`，受管文件不可信则 `CodeInvalid`；缺 `.devsys/` 或 `meta.Project == nil` 则 `CodePrecondition`（[internal/cli/cli.go:401-407](../../../internal/cli/cli.go#L401-L407)）。
- 创建成功后立即回放 `workitem get <new id>` 输出新 id 与版本哈希，便于后续直接 chain `--expect`。

### `workitem transition --id <id> --to <status> --actor <a> --reason <r> --expect <hash>`

```sh
VERSION=$(bin/devsys.exe --json workitem get WLM-0001 | jq -r .version)
bin/devsys.exe workitem transition --id WLM-0001 --to in_progress --actor alice --reason "M2 kickoff" --expect "$VERSION"
```

- `--expect` 必须是 64-hex sha256（与 `workitem get` 输出一致），长度错误 / 解码失败 / 哈希不匹配一律 fail-closed，由 `expectedSnapshot` 返回 `version mismatch` 并由 `workitemError` 升为 `CodePrecondition`（[internal/cli/cli.go:493-506](../../../internal/cli/cli.go#L493-L506) 与 [internal/cli/cli.go:477-482](../../../internal/cli/cli.go#L477-L482)）。
- 状态机非法转换（领域错误）→ `CodeInvalid`。
- 缺失任何必填参数 → `CodeUsage`。

### `workitem claim --id <id> --owner <owner> --reason <reason> --expect <hash>`

```sh
VERSION=$(bin/devsys.exe --json workitem get WLM-0001 | jq -r .version)
bin/devsys.exe workitem claim --id WLM-0001 --owner alice --reason "M2 kickoff" --expect "$VERSION"
```

- `--expect` 可选但建议必带；缺 `--owner` 或 `--reason` → `CodeUsage`。
- 成功时 `--json` 输出 `{ok, run_id, token, status}`（[internal/cli/cli.go:460-466](../../../internal/cli/cli.go#L460-L466)）；人类模式输出 `claimed <id>: run=<run_id> token=<token>`。

## `devsys doctor`：只读对账报告（M2）

`doctor` **不**触发恢复、**不**写盘、**不**创建项目锁文件——只通过 `storage.Inspect` 列出待处理事务、过期 / 孤儿租约与可修复项（[internal/cli/cli.go:511-554](../../../internal/cli/cli.go#L511-L554)）。

```sh
bin/devsys.exe doctor                                  # 人类：PENDING / EXPIRED / ORPHAN / PROPOSE
bin/devsys.exe --json doctor                           # {ok, inspection_ok, note?, pending_transactions, expired_leases, orphan_leases, orphans}
bin/devsys.exe doctor; echo $?                        # 0 / 1（执行失败时）
```

人类模式输出（[internal/cli/cli.go:526-552](../../../internal/cli/cli.go#L526-L552)）：

| 段 | 行格式 |
|---|---|
| 待处理事务 | `PENDING  <transaction-id>`（多条），末行 `run `devsys recover` before trusting business state` |
| 过期租约 | `EXPIRED  <workitem-id>  owner=<owner>  lease_until=<RFC3339>` |
| 孤儿租约 | `ORPHAN   <workitem-id>  owner=<owner>  run=<run-id> missing` |
| 修复提案 | `PROPOSE  <kind>  <workitem-id>  <description>`，随后逐条 `         absent  <path>` 或 `         file    <path>  <short-sha256>` |

`InspectionOK = false` 时在所有 PENDING 行之前打印 `inspection limited: <note>`，由 `reconcile.Doctor` 在无法打开锁文件 / 缺 `scheduling/` 时给出（[internal/reconcile/reconcile.go:152-208](../../../internal/reconcile/reconcile.go#L152-L208)）。

## `devsys recover`：事务恢复 + 租约释放（M2）

```sh
bin/devsys.exe recover --actor alice --reason "M2 manual recovery"
bin/devsys.exe --json recover --actor alice --reason "M2 manual recovery"
bin/devsys.exe recover; echo $?                       # 缺 --actor / --reason：2
```

- 缺 `--actor` 或 `--reason` → `CodeUsage`（[internal/cli/cli.go:564-566](../../../internal/cli/cli.go#L564-L566)）。
- 内部顺序：`storage.Recover`（确定性事务恢复）→ 释放所有 `lease_until < now` 的过期租约 → 释放所有 `referenced run file missing` 的孤儿租约；状态字段不动（[internal/cli/cli.go:571](../../../internal/cli/cli.go#L571)）。
- 人类模式输出 `transactions recovered: <replayed> applied, <skipped> skipped, <discarded> discarded`，随后逐条 `released expired lease: <id>` / `released orphan lease: <id>`。

## `devsys repair`：dry-run → confirm → apply（M2）

`repair` 把"推断 → 确认 → 重写"（方案 §15.4）拆成两步，**避免**：
  （1）`--apply` 在没有重新校验证据的情况下覆盖磁盘；
  （2）调用方跳过证据直接落盘。

### `repair --dry-run`：列提案 + 打印 `digest`

```sh
bin/devsys.exe repair --dry-run --actor alice --reason "M2 audit"
bin/devsys.exe --json repair --dry-run --actor alice --reason "M2 audit"
```

- `--actor` / `--reason` 必填；二者同时缺失或多余参数 → `CodeUsage`（[internal/cli/cli.go:606-608](../../../internal/cli/cli.go#L606-L608)）。
- `Plan.Digest` 由 `reconcile.ComputeDigest` 计算，排除墙钟时间，保证相同证据输入产生相同摘要（[internal/reconcile/reconcile.go:319-335](../../../internal/reconcile/reconcile.go#L319-L335)）。
- 人类模式输出与 `doctor` 的 `PROPOSE` 段一致，**末行**固定 `digest: <64-hex>`；`--json` 载荷 `{ok, plan: {note?, proposals[], digest}}`。

### `repair --apply --confirm <digest>`：比对摘要后落盘

```sh
DIGEST=$(bin/devsys.exe --json repair --dry-run --actor alice --reason "M2 audit" | jq -r .plan.digest)
bin/devsys.exe repair --apply --confirm "$DIGEST" --actor alice --reason "M2 audit"
```

- `--confirm` 必须非空，否则 `CodeUsage`（[internal/cli/cli.go:614-617](../../../internal/cli/cli.go#L614-L617)）。
- 内部**先**重跑 `reconcile.RepairDryRun` 取得当前 `Digest`，**再**用调用方提供的 `--confirm` 覆盖 `plan.Digest`，**再**调 `reconcile.RepairApply`；摘要不一致由 `reconcile.ErrDigestMismatch` 上浮，`runRepair` 包装为 `CodePrecondition` 并提示 `run `devsys repair --dry-run` again`（[internal/cli/cli.go:629-635](../../../internal/cli/cli.go#L629-L635)）。
- 没有 `--dry-run` 也没有 `--apply` → `CodeUsage`（[internal/cli/cli.go:652-654](../../../internal/cli/cli.go#L652-L654)）。

## 注册表覆盖：`DEVSYS_CONFIG_DIR`

把 `DEVSYS_CONFIG_DIR` 设为非空路径，`registry.Dir()` 直接返回该值（[internal/registry/registry.go:37-46](../../../internal/registry/registry.go#L37-L46)），跳过 `os.UserConfigDir()`。约定：

- **测试**：`t.Setenv("DEVSYS_CONFIG_DIR", t.TempDir())` 把注册表隔离到临时目录；所有 `cli_test.go` 用例都这么做（[internal/cli/cli_test.go:76-78、192、271、299](../../../internal/cli/cli_test.go#L76-L78)）。
- **便携安装**：用户把整个 `devsys/` 目录放到 U 盘时设此变量，注册表跟着走。
- **空字符串视为未设置**：通过 `strings.TrimSpace` 过滤（[internal/registry/registry.go:38-40](../../../internal/registry/registry.go#L38-L40)），避免误把当前目录当作用户级配置根。

## 构建版本注入：`-ldflags`

开发构建默认 `Version=0.1.0-dev`、`Commit=unknown`（[internal/version/version.go:13-16](../../../internal/version/version.go#L13-L16)）。发布构建注入真实版本（[README:60-62](../../../README.md#L60-L62)）：

```sh
go build -ldflags "-X workloom/internal/version.Version=0.1.0 \
                 -X workloom/internal/version.Commit=$(git rev-parse --short HEAD)" \
        -o bin/devsys.exe ./cmd/devsys
```

`devsys --version` 在 `Commit=="unknown"` 时只输出 `Version`（[internal/version/version.go:20-23](../../../internal/version/version.go#L20-L23)）；注入后格式为 `0.1.0 (47620c7)`。

## 受管目录布局（M1 实际写出的）

`init` 在 `.devsys/` 下创建如下子目录（[internal/project/tree.go:13-29](../../../internal/project/tree.go#L13-L29)）。M1 占位 YAML 文件的形状由 `domain.EncodeYAML` 序列化：

```text
.devsys/
├── project.yaml            # 受管元数据（白名单：完整 Project 模型 + schema_version）
├── config.yaml             # 受管配置（白名单：仅 schema_version）
├── .gitignore              # 排除 local/ 与 .cache/
├── state/
│   ├── current.yaml        # 项目当前状态（M1+）
│   └── milestones.yaml     # 里程碑（M1+）
├── workitems/  specs/  workflows/  runs/  decisions/
├── findings/  approvals/  events/   artifacts/  context/  knowledge/
├── scheduling/             # M2 新增：租约文件目录（doctor / recover / repair 关注）
├── .cache/                 # 本地缓存（被 .gitignore 排除）
└── local/                  # 本地私有（被 .gitignore 排除）
```

注意：`project` 包的 `layoutDirs` 列出的子目录在 init 时被创建，但 `current.yaml` 与 `milestones.yaml` 同时也是受管 YAML 占位文件（[internal/project/tree.go:42-49](../../../internal/project/tree.go#L42-L49)），且 `search` 会跳过 `.cache/` 与 `local/`。
