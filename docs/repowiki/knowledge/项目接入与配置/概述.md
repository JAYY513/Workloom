# 项目接入与配置

## 模块定位

本模块是 Workloom 的**接入与配置层**：用户与 `devsys` 二进制之间唯一的接触面。负责把命令行参数解析成命令、把命令分发给底层存储与领域模块、把结果按人/机两种格式渲染到 stdout/stderr，并用一个固定退出码族把错误类别告诉调用脚本。

实现层覆盖 M0.1–M1.7：

- M0.1：Go 工程骨架 + 构建标识（`workloom/internal/version`）。
- M0.2：`devsys init` 命令骨架与退出码契约。
- M0.3：为 init 写盘提供原子写基元（由 `workloom/internal/storage` 提供，本模块只调用）。
- M0.4：受管元数据文件 `project.yaml` / `config.yaml` / `state/*.yaml` 的**严格解析**与 `schema_version` 校验，附 `devsys config check` 只读诊断命令。
- M1.1：引入 `internal/domain`（`SchemaVersion=1`），`project.yaml` 白名单扩展到完整 `Project` 模型；`config.Load` / `Diagnose` 通过 `domain.DecodeYAML` 解析并返回 `*domain.Project`。
- M1.6：新增 `devsys search <keyword>` 只读文本扫描（调用 `internal/search`）。

本模块**不**承担存储恢复、事务日志、JSONL 追加等内容——这些属于 `可靠文本存储` 模块。配置诊断与存储恢复的边界在本页“读 vs 写”小节明确说明。

## 命令一览（M0.1–M1.7）

`devsys` 当前暴露三个顶层命令：`init`、`search`、`config check`。其余领域命令在后续里程碑补齐，**当前不存在**——脚本文档不应假设它们可调用。

| 命令 | 写盘？ | 失败模式（退出码） |
|---|---|---|
| `devsys --version` / `--help` | 否 | — |
| `devsys init` | 是 | 0 / 1 / 2 / 3 / 4 |
| `devsys search <keyword>` | 否 | 0 / 1 / 2 / 3 |
| `devsys config check` | 否 | 0 / 1 / 2 / 3 / 4 |

全局开关：

- `--json`：把所有成功结果与错误结构渲染为单行 JSON 写到 stdout/stderr。
- `--quiet`：抑制 `init` 与 `search` 的人可读成功输出（错误仍然写 stderr）。

退出码契约在 [`internal/cli/cli.go:26-35`](../../../internal/cli/cli.go#L26-L35) 固定：

```text
0 OK · 1 Internal · 2 Usage · 3 Precondition · 4 Invalid managed state
```

`CodeInvalid`（4）专门表示“受管状态存在但不可信”：解析错误、未知键、类型错误、`schema_version` 不被当前构建识别。**写命令**（目前仅 `init`）会因此拒绝；**只读诊断**（`config check` 与 `search`）仍然跑得通。

## 关键边界：读 vs 写

`internal/config` 同时提供两个读取入口，行为差异是本模块契约的核心：

| 入口 | 用途 | 缺文件视为错误？ | 未知 schema_version 行为 |
|---|---|---|---|
| `config.Load(root)` | 写命令前置校验（`init` 入口处先调用） | 否（缺失文件留待 init 创建） | 报 `Problems`，写命令拒绝并返回退出码 4 |
| `config.Diagnose(root)` | 只读诊断（`config check`） | 是 | 报 `Problems`，命令返回退出码 4 但仍然返回解析结果 |

二者共用同一份 `load(root, reportMissing bool)` 内部函数（[`internal/config/config.go:106-140`](../../../internal/config/config.go#L106-L140)）；选择哪个取决于调用点是否能容忍缺失文件。**写命令从不重新实现校验**，只复用 `config.Load`。

M1 起，`config.Load` 对 `project.yaml` 通过 `domain.DecodeYAML` 解析为 `*domain.Project`（[`internal/config/config.go:142-152`](../../../internal/config/config.go#L142-L152)）；任何未在该包 `projectSpec` 白名单内出现的字段都会被拒绝。
