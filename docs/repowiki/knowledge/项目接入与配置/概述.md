# 项目接入与配置

## 模块定位

本模块是 Workloom 的**接入与配置层**：用户与 `workloom` 二进制之间唯一的接触面（`devsys` 是**同一二进制的兼容别名**，入口分别为 `cmd/workloom/main.go` 与 `cmd/devsys/main.go`，两者都只调 `cli.Run`，[cmd/workloom/main.go:1-14](file://cmd/workloom/main.go#L1-L14)、[cmd/devsys/main.go:1-14](file://cmd/devsys/main.go#L1-L14)）。负责把命令行参数解析成命令、把命令分发给底层存储与领域模块、把结果按人/机两种格式渲染到 stdout/stderr，并用一个固定退出码族把错误类别告诉调用脚本。**更名不触及状态与注册名**：状态目录仍是 `.devsys/`、MCP 注册名仍是 `devsys`（[CHANGELOG.md:17](file://CHANGELOG.md#L17)）。

M4 起 `internal/cli` 薄化为「flag 解析 + 渲染 + 退出码翻译」；所有业务分发迁出到共享应用服务 `internal/app`（详见 [共享应用与 MCP](../共享应用与MCP/概述.md)）。`internal/mcp` 在同一服务之上以官方 Go SDK 暴露工具族。MCP 服务端的约束在 [错误语义](../共享应用与MCP/错误语义.md) 与 [工具与 Profile](../共享应用与MCP/工具与Profile.md) 中描述；CLI/MCP 的双入口一致性来自共享服务 + `*app.Error` 的 `Kind/Class` 统一翻译。

`DEVSYS_PROJECT_ROOT` 决定 `appService()` 绑定哪个项目根——agent 在 workspace（git worktree）内运行时从 `HookEnv` 注入，避免写入 worktree 自带的 `.devsys/`；**P1 起** `appService()` 改走 [`resolveRoot`](file://internal/cli/roots.go#L17-L42)（`DEVSYS_PROJECT_ROOT` 优先，否则从当前工作目录向上找最近的 `.devsys/`），子目录里跑 `devsys ...` 也能找到项目根。配置层 `config.yaml` 增 `workspace_root`（默认 `<project>/.devsys/workspaces`）与 `dispatch_command`（默认 `workloom run exec …`）两个可选字段；**b89ffae 增 `default_policy`**（[internal/config/validate.go:73-76](file://internal/config/validate.go#L73-L76)、[internal/config/config.go:111-114](file://internal/config/config.go#L111-L114)、[internal/app/workitem.go:490-530](file://internal/app/workitem.go#L490-L530)）——未绑定工作流实例的工作项按它判定质量门与阶段门，是「先 claim 再绑策略」绕过的唯一堵点；`config.yaml` 非法或默认策略缺失时 `claim` fail-closed，提示 `workloom config check`。

**M8.1–M8.4** 在 M6 执行层之上又落两条独立子包：`internal/syncstatus`（[internal/syncstatus/syncstatus.go:24-77](file://internal/syncstatus/syncstatus.go#L24-L77)）承载 `sync status` 只读判定（git 头/上游差距/unmerged/merge machinery/未提交/.devsys/未提交/pending 事务/lease 审计 + 10 个稳定 `Blocker.Code`）；`internal/archive`（[internal/archive/archive.go:58-86](file://internal/archive/archive.go#L58-L86)）承载 `archive events|runs` 的 `Plan`/`Apply`/`Report`/`Manifest` 与 read-copy-delete 事务。CLI 侧新增三条顶层：`sync status`（[internal/cli/sync.go:36-126](file://internal/cli/sync.go#L36-L126)）、`archive events|runs`（[internal/cli/archive.go:19-110](file://internal/cli/archive.go#L18-L106)）；`repair --dry-run/--apply` 在 M8.2 扩 `ProposalKind = note_unmerged_paths`（[internal/reconcile/reconcile.go:45-49](file://internal/reconcile/reconcile.go#L45-L49)）+ `Plan.Note` 第三键（[internal/reconcile/reconcile.go:82-87](file://internal/reconcile/reconcile.go#L82-L87)）+ `RepairApply` 总是把冲突项路由到 `Rejected`（[internal/reconcile/reconcile.go:501-505](file://internal/reconcile/reconcile.go#L501-L505)）；`dispatch --once|--watch|--dry-run` 在 `recover` 之前跑 `mergeConflict` 门控（[internal/app/dispatch.go:86-95](file://internal/app/dispatch.go#L86-L95)）输出 `CodePrecondition = 3` + `dispatch blocked: <summary>; resolve the merge with git, then \`workloom repair --dry-run\`` 文本。**M8.4**（`scripts/contrabass/{export,import}.py` + `README.md`）是可选 Contrabass 后端的双向映射脚本，不影响 `devsys` 子命令。

## 命令一览（M0.1–M8）

`workloom`（兼容别名 `devsys`，同一二进制）当前暴露以下顶层命令（M2 起新增 workitem/doctor/recover/repair；M3 起新增 workflow/approval/next；M4 起新增 project / decision / finding / event / artifact / run / context / knowledge / session / wire / mcp；**M6** 起新增 worktree / dispatch / run exec|prompt|verify|complete|fail|cancel；**M7.1–M7.4** 起新增 workspace view / build / serve；**M8.1–M8.4** 起新增 sync status / archive events|runs，并在 repair 与 dispatch 上加 M8.2 冲突标注与门控；**v0.1.9** 起新增 setup 与 mcp install）。其余领域命令在后续里程碑补齐，**当前不存在**——脚本文档不应假设它们可调用。

## 关键边界：读 vs 写

`internal/config` 同时提供两个读取入口，行为差异是本模块契约的核心：

| 入口 | 用途 | 缺文件视为错误？ | 未知 schema_version 行为 |
|---|---|---|---|
| `config.Load(root)` | 写命令前置校验（`init` 入口处先调用；M2 起 `workitem create` 也先调用；M4 起所有 `app.Xxx` 调用前；**M6** 起 `dispatch / run exec / worktree prepare` 等也先调用） | 否（缺失文件留待 init 创建） | 报 `Problems`，写命令拒绝并返回退出码 4 |
| `config.Diagnose(root)` | 只读诊断（`config check`） | 是 | 报 `Problems`，命令返回退出码 4 但仍然返回解析结果 |

二者共用同一份 `load(root, reportMissing bool)` 内部函数（[`internal/config/config.go:106-140`](file://internal/config/config.go#L106-L140)）；选择哪个取决于调用点是否能容忍缺失文件。**写命令从不重新实现校验**，只复用 `config.Load`。

M1 起，`config.Load` 对 `project.yaml` 通过 `domain.DecodeYAML` 解析为 `*domain.Project`（[`internal/config/config.go:142-152`](file://internal/config/config.go#L142-L152)）；任何未在该包 `projectSpec` 白名单内出现的字段都会被拒绝。

M2 在 `config.Load` 之外引入两类**只读检查**入口，由 `internal/reconcile` 通过 `storage.Inspect` 暴露，**不**经过 `config.Load`：

- `doctor`：通过 `storage.Diagnose` + `storage.Inspect` 列举待处理事务与 `scheduling/` 下的租约；待处理事务存在时 `Orphans` 留空并附恢复提示（[`internal/reconcile/reconcile.go:142-208`](file://internal/reconcile/reconcile.go#L142-L208)）。
- `repair --dry-run`：基于只读扫描生成 `Plan{Proposals, Digest}`，`Digest` 不含墙钟时间以保证可重复（[`internal/reconcile/reconcile.go:282-304`](file://internal/reconcile/reconcile.go#L282-L304)）。

M3 又引入三条只读入口：

- `workflow check`：`workflow.Load(root)` 直接解析每份策略文件，输出 issues；不走 `config.Load`、不持锁、不写盘。
- `workflow next`：通过 `workflow.Resolve(ctx, root, id)` 取当前或 LKG 策略，列出候选；与 `storage.Write` 的写入路径隔离。
- `next`：`reconcile.Doctor` + `internal/next.Evaluate` 的组合命令，不创建锁、不触发恢复、不可信状态不输出业务事实。

M4 进一步把「只读上下文」收口到 `internal/app.context.go`：

- `context get|workitem|refresh|compact`：走 `reconcile.Doctor` + `next.Evaluate` + `record.*ListArtifacts / ListDecisions / ListFindings` + `events.Comments` 聚合。
- `session start`：在 `context get` 之上挑选「唯一推荐动作」并给出 `Notices`。
- `knowledge status`：M4 永远返回 `unavailable`（M5 §12.6 达到）。

M6 进一步把**只读执行层诊断**收口到 `internal/app.dispatch.go`：

- `dispatch --dry-run`：调 `Plan(in)` 一次，不 recover、不 claim、不 spawn；输出 `Report{Decisions, Started, Notices}`。
- `run prompt --write`：写 `.devsys/local/runs/<id>/round-<N>.md`（.gitignore 保护区域），不写 `.devsys/runs/<id>.jsonl`。

M7.1–M7.4（fa2a87d 增量）又收口一类**视图域入口**（`workloom workspace view / build / serve`）：

- `workspace view`：通过 `internal/view.Build` 装配 `view.Model`——先 `storage.Inspect`（既有锁上的共享锁，**绝不创建**），拿不到时退回 `storage.InspectUnlocked` 并把该次装配标成 `trust.state = advisory_unlocked`。**不**写 `.devsys/.cache/`、`local/`、`workspaces/`，**不**恢复事务，**不**修断尾事件流，**不**探测生成器（不起进程）。pending 事务存在时按 §15.4 不渲染业务事实，仅给出 `pending_transaction` 信任态与 `next.Evaluate` 输出的 §7.4 修复项。
- `workspace build --static`：调 `sitestatic.Build` 把视图落成 6 页 + 样式 + `data/model.json`（唯一**写盘**视图子命令，且只写 `--out` 下）；缺省 `.devsys/dist/site/`（git 忽略）。
- `workspace serve`：每请求现装 `view.Build` + `RenderPage` 内存渲染，**零写入**；缺省 `127.0.0.1:8080`，非环回无 `--allow-remote` → exit 2（用法错误）；GET/HEAD 外 → 405。

这十五类只读路径**不**创建项目锁文件、**不**触发事务恢复，与写路径刻意分开。
