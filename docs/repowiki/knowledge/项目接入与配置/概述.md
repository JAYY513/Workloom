# 项目接入与配置

## 模块定位

本模块是 Workloom 的**接入与配置层**：用户与 `devsys` 二进制之间唯一的接触面。负责把命令行参数解析成命令、把命令分发给底层存储与领域模块、把结果按人/机两种格式渲染到 stdout/stderr，并用一个固定退出码族把错误类别告诉调用脚本。

实现层覆盖 M0.1–M3：

- M0.1：Go 工程骨架 + 构建标识（`workloom/internal/version`）。
- M0.2：`devsys init` 命令骨架与退出码契约。
- M0.3：为 init 写盘提供原子写基元（由 `workloom/internal/storage` 提供，本模块只调用）。
- M0.4：受管元数据文件 `project.yaml` / `config.yaml` / `state/*.yaml` 的**严格解析**与 `schema_version` 校验，附 `devsys config check` 只读诊断命令。
- M1.1：引入 `internal/domain`（`SchemaVersion=1`），`project.yaml` 白名单扩展到完整 `Project` 模型；`config.Load` / `Diagnose` 通过 `domain.DecodeYAML` 解析并返回 `*domain.Project`。
- M1.6：新增 `devsys search <keyword>` 只读文本扫描（调用 `internal/search`）。
- M2：`devsys workitem` 命令面新增 `create` / `get` / `transition` / `claim` 四个子命令，统一走 `internal/workitem` 的租约与状态机入口；新增 `doctor`（只读检查）/ `recover`（事务恢复 + 释放过期/孤儿租约）/ `repair`（dry-run→confirm→apply 闭环）三个对账命令，统一走 `internal/reconcile`。
- **M3**：`devsys workflow` 命令族（`check` / `start` / `next` / `step-complete` / `pause` / `resume` / `cancel`，统一走 `internal/workflow` + `internal/workitem.workflowWrite`）、`devsys approval`（`list` / `request` / `approve` / `reject`，统一走 `internal/approval`）、`devsys next`（只读判定与推荐，走 `internal/next`）；新增 `.devsys/workflows/` 与 `.devsys/approvals/` 受管目录。

本模块**不**承担存储恢复、事务日志、JSONL 追加等内容——这些属于 `可靠文本存储` 模块。配置诊断与存储恢复的边界在本页"读 vs 写"小节明确说明；M2 起对账恢复改由 `internal/reconcile` 与 `internal/storage.Inspect` 协作承担；M3 起工作流/审批/next 三层也都只走 storage 的事务与锁，自身不引入新的锁类型。

## 命令一览（M0.1–M3）

`devsys` 当前暴露以下顶层命令（M2 起新增 workitem/doctor/recover/repair；M3 起新增 workflow/approval/next）；其余领域命令在后续里程碑补齐，**当前不存在**——脚本文档不应假设它们可调用。

| 命令 | 写盘？ | 职责（一句话） |
|---|---|---|
| `devsys --version` / `--help` | 否 | 输出构建标识或帮助文本 |
| `devsys init` | 是 | 在当前仓库根创建 `.devsys/` 布局与占位文件 |
| `devsys search <keyword>` | 否 | 只读扫描 `.devsys/` 内文本内容（排除 `.cache/` 与 `local/`） |
| `devsys config check` | 否 | 只读诊断受管元数据文件 schema |
| `devsys workitem create` | 是 | 在 `internal/workitem` 创建新工作项，强制 `--actor`/`--reason` |
| `devsys workitem get` | 否 | 读取工作项并打印 64-hex sha256 版本哈希（作为 `--expect` 输入） |
| `devsys workitem transition` | 是 | 在工作项状态机上做一次转换；`--expect` 强制 CAS 校验；可选 `--owner`/`--token` 配合租约；M3 转换事务内可由 Guard 消费审批并广播记录引用 |
| `devsys workitem claim` | 是 | 领取工作项并建立租约；可携带 `--expect`；M3 起被 `Policy.QualityGateBlocks` 拦截低质量 claim |
| `devsys doctor` | 否 | 通过 `internal/reconcile.Doctor` 报告待处理事务、过期/孤儿租约与可修复项；不触发恢复 |
| `devsys recover` | 是 | `storage.Recover` 后释放所有过期租约与孤儿租约；强制 `--actor`/`--reason` |
| `devsys repair --dry-run` | 否 | 列出修复提案并打印确定性 `digest`（不含墙钟时间） |
| `devsys repair --apply --confirm <digest>` | 是 | 重跑 dry-run 并比对 `digest`，仅在一致时执行修复；强制 `--actor`/`--reason` |
| `devsys workflow check` | 否 | 校验 `.devsys/workflows/*.md`，逐文件 issued `warning`/`error`；未知键 warning 不阻断 exit 0；值域（hook 名 / stage）失败 exit 4 |
| `devsys workflow start` | 是 | 在工作项上启动策略实例（首步 + 状态对齐校验）；强制 `--actor`/`--reason`/`--expect`；租约活跃时强制 `--owner`/`--token` |
| `devsys workflow next` | 否 | 列出当前步骤的全部候选与 `satisfied`；返回声明序首个满足候选 |
| `devsys workflow step-complete` | 是 | 推进实例一步；显式 `--to` 必须命中声明转换且条件成立；强制 `--actor`/`--reason`/`--expect` |
| `devsys workflow pause` / `resume` / `cancel` | 是 | 仅动实例字段与事件；强制 `--actor`/`--reason`/`--expect` |
| `devsys approval list` | 否 | 按 ID 升序列出审批；可选 `--workitem` / `--status pending|approved|rejected` |
| `devsys approval request` | 是 | 创建 pending 审批（`--scope stage_gate|action`、`--stage`、`--run` 可选）；强制 `--actor`/`--reason` |
| `devsys approval approve` | 是 | pending → approved；强制 `--by`（`--comment` 可选） |
| `devsys approval reject` | 是 | pending → rejected；`scope=stage_gate` 时按策略 `on_reject` 处置工作项（默认 blocked，`regress:<status>` 回退）；强制 `--by`/`--reason` |
| `devsys next` | 否 | 通过 `reconcile.Doctor` + `internal/next.Evaluate` 给出 PASS/CONCERNS/FAIL 与 §7.4 唯一推荐动作；exit 恒 0 |

全局开关：

- `--json`：把所有成功结果与错误结构渲染为单行 JSON 写到 stdout/stderr。
- `--quiet`：抑制成功输出（错误仍然写 stderr）。

退出码契约在 [`internal/cli/cli.go:33-44`](../../../internal/cli/cli.go#L33-L44) 固定：

```text
0 OK · 1 Internal · 2 Usage · 3 Precondition · 4 Invalid
```

M2 在保留 `CodeInvalid = 4`（受管状态不可信）语义同时，扩展了 `CodePrecondition = 3` 的两类新用法（[internal/cli/cli.go:70](../../../internal/cli/cli.go#L70)）：

- workitem 命令收到与 `workitem get` 输出版本哈希不匹配的 `--expect`（hash 长度错误或文件已变更）→ `CodePrecondition`。
- `repair --apply` 收到的 `--confirm` 摘要与当前干跑摘要不一致 → `CodePrecondition`，错误提示要求重跑 `repair --dry-run`。

M3 在同一退出码下扩展了三族新用法：

- workflow / approval / workitem 的领域错误统一升为 `CodeInvalid = 4`，`kind` 分别取 `"workflow"` / `"approval"` / `"workitem"`。
- `workflow check` 把策略文件的结构/类型/必填/交叉引用错误升为 `CodeInvalid`；未知键 warning 不阻断退出码。
- `devsys next` exit 恒 0；脚本按 `--json next` 输出的 `verdict` 分支（PASS / CONCERNS / FAIL）。

## 关键边界：读 vs 写

`internal/config` 同时提供两个读取入口，行为差异是本模块契约的核心：

| 入口 | 用途 | 缺文件视为错误？ | 未知 schema_version 行为 |
|---|---|---|---|
| `config.Load(root)` | 写命令前置校验（`init` 入口处先调用；M2 起 `workitem create` 也先调用） | 否（缺失文件留待 init 创建） | 报 `Problems`，写命令拒绝并返回退出码 4 |
| `config.Diagnose(root)` | 只读诊断（`config check`） | 是 | 报 `Problems`，命令返回退出码 4 但仍然返回解析结果 |

二者共用同一份 `load(root, reportMissing bool)` 内部函数（[`internal/config/config.go:106-140`](../../../internal/config/config.go#L106-L140)）；选择哪个取决于调用点是否能容忍缺失文件。**写命令从不重新实现校验**，只复用 `config.Load`。

M1 起，`config.Load` 对 `project.yaml` 通过 `domain.DecodeYAML` 解析为 `*domain.Project`（[`internal/config/config.go:142-152`](../../../internal/config/config.go#L142-L152)）；任何未在该包 `projectSpec` 白名单内出现的字段都会被拒绝。

M2 在 `config.Load` 之外引入两类**只读检查**入口，由 `internal/reconcile` 通过 `storage.Inspect` 暴露，**不**经过 `config.Load`：

- `doctor`：通过 `storage.Diagnose` + `storage.Inspect` 列举待处理事务与 `scheduling/` 下的租约；待处理事务存在时 `Orphans` 留空并附恢复提示（[`internal/reconcile/reconcile.go:142-208`](../../../internal/reconcile/reconcile.go#L142-L208)）。
- `repair --dry-run`：基于只读扫描生成 `Plan{Proposals, Digest}`，`Digest` 不含墙钟时间以保证可重复（[`internal/reconcile/reconcile.go:282-304`](../../../internal/reconcile/reconcile.go#L282-L304)）。

M3 又引入三条只读入口：

- `workflow check`：`workflow.Load(root)` 直接解析每份策略文件，输出 issues；不走 `config.Load`、不持锁、不写盘。
- `workflow next`：通过 `workflow.Resolve(ctx, root, id)` 取当前或 LKG 策略，列出候选；与 `storage.Write` 的写入路径隔离。
- `next`：`reconcile.Doctor` + `internal/next.Evaluate` 的组合命令，不创建锁、不触发恢复、不可信状态不输出业务事实。

这五条路径**不**创建项目锁文件、**不**触发事务恢复，与写路径刻意分开。
