## 语言与工具链

- **Go 1.26**（`go.mod: go 1.26`）。M4 仍在该版本下，新增 Go SDK 依赖；M6 在该版本下新增 `golang.org/x/term`。
- M1 起 vendored `gopkg.in/yaml.v3` v3.0.1。
- **M4 新增 vendored** `github.com/modelcontextprotocol/go-sdk` v1.8.0（[internal/mcp/server.go:1-130+](../../../internal/mcp/server.go#L1-L130)）。SDK 拥有 Model Context Protocol 的帧、生命周期、版本协商、`tools/list` / `tools/call` 形态、工具输入校验；本仓库只决定哪些工具暴露与共享错误分类。
- **M6 新增 vendored** `golang.org/x/term`（[go.mod](../../../go.mod)）。`internal/harness.shell.go:Probe` 用 `term.IsTerminal(fd int) bool` 报告 host shell 是否可达 TTY；**不**用于 process tree 终止（POSIX 走 `syscall.Kill(-pid, sig)` + `Setpgid`，Windows 走 `golang.org/x/sys/windows` 的 `CreateJobObject` / `TerminateJobObject`）。
- 平台原生文件锁：POSIX `syscall.Flock`（`internal/storage/lock_unix.go`）；Windows `syscall.NewLazyDLL("kernel32.dll")` 动态调用 `LockFileEx`（`internal/storage/lock_windows.go`）。
- 行尾统一 LF：仓库根 `.gitattributes` 固定；M0.1 决策（[docs/开发记录.md:53-56](../../../docs/开发记录.md#L53-L56)）。

## 平台差异

通过 `//go:build` 标签隔离：

- `internal/storage/fsync_unix.go` / `fsync_windows.go` — Windows 下 `fsyncDir` 为 no-op。
- `internal/storage/lock_unix.go` / `lock_windows.go` — `lockContended` 与 `transientRenameError` 分别识别平台错误码。
- **`internal/harness/proc_unix.go` / `proc_windows.go`**（M6）— 跨平台 `killProcessTree(cmd *exec.Cmd) error` 同签名实现：POSIX 走 `Setpgid + kill -PGID`；Windows 走 `JobObject + TerminateJobObject`。
- `scripts/smoke-m{4,6}.sh` 在 `MINGW*` / `MSYS*` 运行时把 `/c/Program Files/Go/bin` 顶到 `PATH` 头部（与 M1–M3 同款）。

## 验证边界

- `-race` 检测器在本机不可用（无 gcc，[docs/开发记录.md:35](../../../docs/开发记录.md#L35)）；有编译环境时补跑 `CGO_ENABLED=1 go test -race ./...`。
- macOS/Linux 仅交叉编译、未实机运行（[docs/开发记录.md:37](../../../docs/开发记录.md#L37)）。
- 进程中断验收不证明断电持久性（[internal/storage/errors.go](../../../internal/storage/errors.go)）。
- M4 MCP 工具的 `tools/list` 过滤发生在 SDK server 注册期（[internal/mcp/server.go:91-105](../../../internal/mcp/server.go#L91-L105)），未注册工具无法以名称调用——此为权限边界，不是 handler 内的运行时判断。
- **M6** 执行层 `dispatch.Plan` 是纯函数——`-run ^TestPlan` 在 `go test ./internal/dispatch` 下不依赖 git / 任何 I/O；`internal/retry.Delay` 同理。适配器层 `internal/harness/shell_test.go` 与 `internal/workspace/key_test.go` / `path_test.go` 在 `go test ./...` 下覆盖而不需要真实 harness 二进制。
- **M6** 真实集成画像：codex 0.144.1 与 opencode 1.18.21 各启动一次（命令行被真实 CLI 接受、JSONL 入 run 事件流），两次均因提供方后端不可用失败（codex 代理 503、opencode 本地网关 socket closed）；claude 本机未安装（探测/拒绝路径已验）。**按 SPEC 要求，未通过的真实集成明确记为未通过/跳过**，确定性链路用桩 harness 覆盖（stdin 投递 → 工作区 → 提交 → 完成校验通过）。
