## 构建

```sh
# 离线构建
GOFLAGS=-mod=vendor GOPROXY=off go build ./...

# 发布构建（注入版本）
go build -mod=vendor -ldflags "-X workloom/internal/version.Version=0.1.0 -X workloom/internal/version.Commit=$(git rev-parse --short HEAD)" -o bin/devsys.exe ./cmd/devsys

# M4 端到端辅助（构建 m4helper）
go build -mod=vendor -o bin/m4helper.exe ./scripts/m4helper
```

Windows：`$env:GOPROXY='off'`。

## 平台差异

通过 `//go:build` 标签隔离：

- `internal/storage/fsync_unix.go` / `fsync_windows.go` — Windows 下 `fsyncDir` 为 no-op。
- `internal/storage/lock_unix.go` / `lock_windows.go` — `lockContended` 与 `transientRenameError` 分别识别平台错误码。
- `scripts/smoke-m4.sh` 在 `MINGW*` / `MSYS*` 运行时把 `/c/Program Files/Go/bin` 顶到 `PATH` 头部（与 M1–M3 同款）。

## 验证边界

- `-race` 检测器在本机不可用（无 gcc，[docs/开发记录.md:35](../../../docs/开发记录.md#L35)）；有编译环境时补跑 `CGO_ENABLED=1 go test -race ./...`。
- macOS/Linux 仅交叉编译、未实机运行（[docs/开发记录.md:37](../../../docs/开发记录.md#L37)）。
- 进程中断验收不证明断电持久性（[internal/storage/errors.go](../../../internal/storage/errors.go)）。
- M4 MCP 工具的 `tools/list` 过滤发生在 SDK server 注册期（[internal/mcp/server.go:91-105](../../../internal/mcp/server.go#L91-L105)），未注册工具无法以名称调用——此为权限边界，不是 handler 内的运行时判断。
