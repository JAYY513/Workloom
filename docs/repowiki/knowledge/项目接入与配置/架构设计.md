## 渲染层

[internal/cli/cli.go:178-198](file://internal/cli/cli.go#L178-L198) `render` 决定输出形态：

- `--json`：成功 / 错误信封都走单行 JSON（成功 stdout，错误 stderr）。
- 非 `--json`：成功用人类可读文本（受 `--quiet` 控制），错误走 stderr。

`--quiet` 仅抑制成功输出，错误与 warning 仍然写 stderr——这是 `doctor` / `repair --dry-run` / `workflow check` / `dispatch` 等诊断命令可见性约束。**M7.1** `workspace view` 沿用同一约定：人类输出 `renderWorkspaceView`（[internal/cli/workspace.go:149-228](../../../internal/cli/workspace.go#L149-L228)）是「一行一事实」+ 缩进层级（`project`/`phase`/`baseline`/`state`/`milestone`/`progress`/`readiness`/`risk`/`next`/`runs`/`records`/`knowledge`/`trust`/`pending`/`problem`/`sources`）；`--json` 模式下成功 `view.Model` 嵌入 `{ok: true, …Model}` 信封走 stdout。**M7.4** 同 `runWorkspace` 路由下的 `build --static` / `serve` 也走 `--json` 信封：`build` 走 `{ok, out, pages[], generated_at, baseline, trust_state}`（[internal/cli/workspace.go:84-91](../../../internal/cli/workspace.go#L84-L91)），`serve` 仍是 loopback HTTP 路由 + `--json` 错误信封，与人类输出同一约束。

M6 新增 `devsys run exec` 在 `--json` 模式下**强制**把 attempt 的 sink 输出走 stderr，stdout 仅保留 envelope——这是 M4.5 已落地的约定。

## M3 命令族详解

### `devsys workflow`

`runWorkflowCheck`（[internal/cli/cli.go:388-452](file://internal/cli/cli.go#L388-L452)）：

- `workflow.Load(cwd)` 解析所有 `.devsys/workflows/*.md`。
- `error-severity` issue 升为 `config.Problem` 并通过 `errInvalid(problems)` → exit 4。
- `warning-severity` issue 走 `warning:` 行打印，`--quiet` 仍保留。
- `--json` 输出 `{ok, root, policies[], warnings[]}`。

`runWorkflowStart` / `WorkflowNext` / `WorkflowStepComplete` / `WorkflowSignal`（pause/resume/cancel）通过 `workflowPolicy(ctx, root, wi, policyID, requirePolicy)` 取当前或 LKG 策略，要求 `policy != nil`（start 时要求，next/step-complete 时允许 LKG fallback），然后调 `items.WorkflowStart/Next/StepComplete/Signal`。所有实例操作都强制 `--actor` / `--reason` / `--expect`；租约活跃时强制 `--owner` / `--token`。

### `devsys approval`

`runApprovalList` / `runApprovalRequest` / `runApprovalDecide`（approve / reject）：

- `Request` 调 `approval.New(root).Request(ctx, opts)`，含重复请求检查（`findOpenApproval`）。
- `Approve` 走独立事务 `Decide(ctx, id, opts{Approve: true})`。
- `Reject` 区分 scope：`scope=stage_gate` 走 `rejectStageGate`（在 `workitem.Transition` 的 Guard 内同时完成 `DecideTx(rejected)` 与状态变更）；`scope=action` 走独立事务 `Decide(ctx, id, opts{Approve: false})`。

`rejectStageGate`（[internal/cli/cli.go:942-976](file://internal/cli/cli.go#L942-L976)）：

1. 调 `workitem.ReadSnapshot` 取工作项当前字节作为 `--expect`。
2. 按策略 `on_reject` 决定目标状态（默认 `blocked`，`regress:<status>` 回退）。
3. 构造 `TransitionRequest{TargetStatus: target, Guard: <DecisionTx closure>}`。
4. `items.Transition(ctx, wi.ID, req, raw)`：Guard 内 `DecideTx(rejected)` 失败 → 整单回滚，工作项不动，审批保持 pending。

### `devsys next`

`runNext`（[internal/cli/cli.go:1323-1437](file://internal/cli/cli.go#L1323-L1437)）：

1. `reconcile.Doctor` 收集待恢复事务 + 过期/孤儿/不可读租约 + `InspectionOK`。
2. 仅在 `InspectionOK && len(pending) == 0` 时列举 `workitems` 与 `pending approvals`（不可信状态不输出业务事实，§15.4）。
3. `config.Diagnose` 收集元数据问题；`workflow.Load` 收集策略问题与「工作项引用缺失策略」交叉核对。
4. `next.Evaluate(in)` 输出 `Report{Verdict, Reasons, Risks, Fixes, Next}`。
5. exit 恒 0；`--json` 输出完整结构。

### `devsys session start` 与 `devsys context`（M4）

`runSessionStart` 调 `app.SessionStart(ctx, SessionRequest{Harness, AgentID, Workspace, Intent, Compact})`（[internal/app/session.go:89-159](file://internal/app/session.go#L89-L159)）：单次返回 `SessionView`——项目身份 + `CurrentState` + `CurrentWorkitems`（limit 收口）+ `RecommendedNextAction`（与 `next.Evaluate` 同源）+ `Context`（近期 decision/finding/artifact/event 引用）+ `Notices`。不持久化、不改状态。

`runContext get|workitem|refresh|compact` 调 `app.ContextGet / ContextForWorkitem / ContextRefresh / ContextCompact`（[internal/app/context.go:62-127](file://internal/app/context.go#L62-L127)）：全部只读；`compact` 模式裁短 payload（fewer refs + 无 per-item detail）。

### `devsys wire`（M4）

`runWire`（[internal/cli/cli.go:371-408](file://internal/cli/cli.go#L371-L408)）→ `app.Wire(dryRun bool)`（[internal/app/wire.go:44-77](file://internal/app/wire.go#L44-L77)）：把 devsys 纪律块以 `<!-- devsys:begin/end -->` 注入 `AGENTS.md`；幂等（三次运行字节一致）；区段外字节保留（含其它工具的管理块）；`--dry-run` 预览 diff。

### `devsys mcp serve`（M4）

`runMCPServe`（[internal/cli/mcp.go:48-84](file://internal/cli/mcp.go#L48-L84)）：

1. 解析 `--profile`（默认 `session,executor`，未知名字报错）。
2. `requireProjectRoot()` 验证 `.devsys/`。
3. `mcp.Config{Root, Profiles, ServerVersion, Instructions, Log=stderr}` → `mcp.Run(ctx, cfg, nopReadCloser{stdin}, nopWriteCloser{stdout})`。
4. `nopReadCloser` / `nopWriteCloser` 防止 SDK 关闭进程流。

`Instructions` 字段由 CLI 在 `mcpInstructions` 常量中固定——和 `app.Wire` 的纪律块描述一致；agent 的纪律文本由 `devsys wire` 显式注入 `AGENTS.md`，不在 SDK `initialize` 自动推送。

## M6 命令族详解

### `devsys worktree`（[internal/cli/worktree.go](file://internal/cli/worktree.go)）

`runWorktree` 路由 `prepare | remove | list`：

- `prepare --workitem <id> --actor <a> --reason <r> [--run <run-id>] [--branch <b>]`：`app.WorkspacePrepare` 复用或创建 git worktree，跑 `after_create` 钩子；可选 `--run` 把 workspace 绑到 run（同时记 `claim_head`）。
- `remove --workitem <id> | --path <p> --actor <a> --reason <r> [--force]`：`app.WorkspaceRemove` 跑 `before_remove` 后删除 worktree；失败仅记录。`--path` 越界由 `workspace.Validate` 拒绝 → exit 3。
- `list [--workitem <id>]`：只读 `app.WorkspaceList`。

### `devsys dispatch`（[internal/cli/dispatch.go](file://internal/cli/dispatch.go)）

`runDispatch`：

- `--once`（默认）：一次 tick：`storage.Recover` → `retrySweep`（失败/超时/停滞 attempt 收尾）→ `Plan(in)` → `claim` → `prepare workspace` → `spawn` → `mark running`。
- `--watch --interval 30s`：前台循环，每 interval 一次 tick；Ctrl-C 退出 0。
- `--dry-run`：只调 `Plan(in)`，不 recover、不 claim、不创建任何 `.devsys/runs/*.yaml`。
- `--max N`：本 tick 最多启动 N 个 attempt（0 = `ResolveCaps` 决定）。

### `devsys run exec|prompt|verify|complete|fail|cancel`（[internal/cli/records.go:614-769](file://internal/cli/records.go#L614-L769)）

六族新子命令复用既有 `runRun` 路由：

- `run exec --id <run> [--harness <name>] [--model <m>] [--timeout 30s] [--round N] --actor <a> --reason <r> [-- <command...>]`：默认 shell 形态跑 `--` 后命令；声明 `--harness` 走对应 CLI 适配器（codex/opencode/claude）；`--timeout` 终止整棵进程树；Ctrl-C 取消。`--json` 模式 sink 全部进 stderr。
- `run prompt --id <run> [--round N] [--write]`：`app.RunPrompt` 调 `prompt.Assemble`，把 round 文本写到 stdout；`--write` 落 `.devsys/local/runs/<id>/round-<N>.md`。
- `run verify --id <run>`：只读 `app.RunVerify`；claim head vs current head。
- `run complete|fail|cancel --id <run> --actor <a> --reason <r> [--expect <hash>] [--note <text>] [--force --by <reviewer>]`：`complete` 默认走 verify 守卫；`--force --by` 接受 verify 拒绝；`fail` / `cancel` 直接写终态。

## M7.1 命令族详解

### `devsys workspace {view, build, serve}`（[internal/cli/workspace.go](file://internal/cli/workspace.go)）

`runWorkspace` 路由**只读视图域**（方案 §17；与 §4.8 `worktree`（执行工作区）严格分开——前者只读聚合、不恢复事务、不修断尾、不写 `.cache/`；后者跑 hook 与生命周期）：

- 子命令缺失或不在 `{view, build, serve}` → `errUsage` → 退出码 2（[internal/cli/workspace.go:24-38](../../../internal/cli/workspace.go#L24-L38)）。
- `view [--limit N]`：`runWorkspaceView` 调 `view.Build(ctx, root, view.Options{Limit: *limit})`（[internal/cli/workspace.go:114-145](../../../internal/cli/workspace.go#L114-L145)）。
  - `storage.ErrNotInitialized`（缺 `.devsys/`）→ `errPrecondition` → 退出码 3。
  - 其余 `Build` 失败 → `errInternal` → 退出码 1。
  - `--json` 模式：`json.NewEncoder(stdout).Encode(struct{OK bool; view.Model})`——`view.Model` 整型嵌入 `data`，**不**走 `--jsonl` 列表流。
  - 非 `--json` 模式：`renderWorkspaceView` 一行一事实（[internal/cli/workspace.go:149-228](../../../internal/cli/workspace.go#L149-L228)，project / phase / baseline / state / milestones / progress / readiness / risks / next / runs / records / knowledge / trust / pending / problems / sources）；`--quiet` 抑制。
  - 退出码 0：成功（即使 `trust.state = advisory_unlocked` 也算成功——advisory 是事实标签，不是失败）。
- `build --static [--out DIR] [--limit N]`：M7.4 起新增，`runWorkspaceBuild` 调同一 `view.Build` + `sitestatic.ResolveOut` + `sitestatic.Build`（[internal/cli/workspace.go:44-108](../../../internal/cli/workspace.go#L44-L108)）。`--json` 信封含 `ok / out / pages[] / generated_at / baseline / trust_state`（[internal/cli/workspace.go:84-91](../../../internal/cli/workspace.go#L84-L91)）；非 `--json` 模式打印 `site: <rel> (<N> pages) — baseline …` 与可能的 trust 行；唯一写入是 `--out` 指定目录（默认 `.devsys/dist/site/`），其余路径与 `view` 一样不读 `.devsys/local/`、`.devsys/.cache/`、`.devsys/workspaces/`。`storage.ErrNotInitialized` → exit 3，`sitestatic.ResolveOut` / `Build` 失败 → `errUsage` / `errInternal`（exit 2 / 1）；退出码 0 仍允许 `trust.state = advisory_unlocked`。
- `serve [--host 127.0.0.1] [--port N]`：M7.4 起新增，`runWorkspaceServe` 起 loopback HTTP 服务（`net/http`）从同一 `view.Build` 现场拉取，路由与写盘契约与 `build --static` 对齐；不在远端暴露，仍只读聚合视图域。

`view.Build` 的关键契约（[internal/view/build.go:33-113](../../../internal/view/build.go#L33-L113) + [internal/view/collect.go:23-29](../../../internal/view/collect.go#L23-L29)）：

1. `storage.Open(root, storage.Options{Now: nowFn})`；失败 → `Build` 退出（`storage.ErrNotInitialized`）。
2. `reconcile.Doctor` 拿 `InspectionReport`；失败时回退 `storage.Diagnose` 并把提示写进 `Problems`。
3. `doc.PendingTransactions` 非空 → `Trust.State = pending_transaction`，调 `emptyBusiness` 抹掉业务事实，`Progress.Readiness` 走 `pendingReadiness`（`next.Evaluate`）+ `recoverCommand = "devsys recover --actor operator --reason \"recover interrupted state\""`，**不**进入 `inspectSnapshot`。
4. 否则 `inspectSnapshot`：先 `storage.Inspect`（共享锁上的共享锁，**绝不创建**）；`ErrLockUnavailable` 时退 `storage.InspectUnlocked` 并把 `Trust.State = advisory_unlocked`，仍渲染业务事实。
5. `builder.assemble` 走 `project / progress / metadataProblems / policyProblems / pendingApprovals / runs / records / knowledge / knowledgeState / generator / pageRoots`；每节记 `Provenance.Sources`；`m.Sources = collectSources(m)` 是顶层 sorted union。
6. 列表**先定序后截断**（时间倒序后 ID），`capList[T](list, limit)` 标记 `Truncated`；工作项和里程碑不被截断——它们是 board 本身。
7. `view.Model` 不带墙钟字段；`Options.Now` 只用于 readiness 求值，不进模型；两次同一状态构建**逐字节一致**。
8. `.devsys/local/`、`.devsys/.cache/`、`.devsys/workspaces/` 一律**不**读。

`view.Model` 顶层字段（[internal/view/view.go:65-80](../../../internal/view/view.go#L65-L80)）：`schema_version=1` / `project{...degraded+reason}` / `trust{state, inspection_ok, note, pending}` / `baseline{available, commit, branch, dirty, changed_files, reason}` / `progress{counts, items, readiness.next.report, degraded+reason}` / `runs{entries, truncated}` / `records{decisions, findings, artifacts, truncated}` / `knowledge{status, pages, root, baseline, reason, generator, degraded+reason}` / `sources`（sorted union）/ `problems`（locate 后解码缺陷）。`TrustOK = "ok"`、`TrustAdvisory = "advisory_unlocked"`、`TrustPending = "pending_transaction"`；知识常量 `KnowledgeFresh / Stale / Missing / Unavailable`（**仅用作视图状态，不复用 10/11 退出码**——10/11 仍专属 `devsys knowledge status`）。
