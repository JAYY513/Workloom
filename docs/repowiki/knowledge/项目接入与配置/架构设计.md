## 渲染层

[internal/cli/cli.go:178-198](file://internal/cli/cli.go#L178-L198) `render` 决定输出形态：

- `--json`：成功 / 错误信封都走单行 JSON（成功 stdout，错误 stderr）。
- 非 `--json`：成功用人类可读文本（受 `--quiet` 控制），错误走 stderr。

`--quiet` 仅抑制成功输出，错误与 warning 仍然写 stderr——这是 `doctor` / `repair --dry-run` / `workflow check` / `dispatch` 等诊断命令可见性约束。**M7.1** `workspace view` 沿用同一约定：人类输出 `renderWorkspaceView`（[internal/cli/workspace.go:149-228](file://internal/cli/workspace.go#L149-L228)）是「一行一事实」+ 缩进层级（`project`/`phase`/`baseline`/`state`/`milestone`/`progress`/`readiness`/`risk`/`next`/`runs`/`records`/`knowledge`/`trust`/`pending`/`problem`/`sources`）；`--json` 模式下成功 `view.Model` 嵌入 `{ok: true, …Model}` 信封走 stdout。**M7.4** 同 `runWorkspace` 路由下的 `build --static` / `serve` 也走 `--json` 信封：`build` 走 `{ok, out, pages[], generated_at, baseline, trust_state}`（[internal/cli/workspace.go:84-91](file://internal/cli/workspace.go#L84-L91)），`serve` 仍是 loopback HTTP 路由 + `--json` 错误信封，与人类输出同一约束。

M6 新增 `devsys run exec` 在 `--json` 模式下**强制**把 attempt 的 sink 输出走 stderr，stdout 仅保留 envelope——这是 M4.5 已落地的约定。
