## 2. 包级 sentinel 错误集中声明在 `var ( ... )`，结构化错误走 `errors.As`

每个领域包用 `var ( ... )` 块集中暴露 sentinel；调用方用 `errors.Is` 而非字符串匹配。结构化错误（`PendingTxnError` / `TransitionError`）不能用 sentinel 表达，必须以类型 + `Unwrap` 形式定义并在调用方用 `errors.As` 取出。

- `events`：`ErrNotInitialized` / `ErrIncompleteTail` / `ErrReplyNotFound` / `ErrReplyNotOneLevel` / `ErrBadTime`（[internal/events/events.go:25-31](file://internal/events/events.go#L25-L31)）

## 3. ID 验证、目录派生、列表宽容的写前纪律

## 4. CAS 分配 + 乐观并发 + M2 Guard 的统一写事务结构

M1 五模块的 `Create` 与 M2 的 `ApplyRepair` / `Claim` 都共享同一形态：**一个** `storage.Write` 独占锁 + 写锁内重扫 ID + `tx.PutYAML(Expect*)` + 同事务追加事件：

```text
// M1 CAS 分配
for range maxAttempts (5) {
    err = st.Write(ctx, func(tx *storage.Tx) error {
        next := nextNumber(...)              // 写锁内重扫
        id   := fmt.Sprintf("%s-%d", kind, next)
        v.ID = id
        v.SchemaVersion = domain.SchemaVersion // 0 → 1
        return tx.PutYAML(...+".yaml", v, storage.ExpectAbsent())
    })
    if err == nil                          { return id, nil }
    if errors.Is(err, storage.ErrConflict) { continue }
    return "", err
}
return "", fmt.Errorf("...gave up after %d conflicts", maxAttempts)
```

要点：

- `maxAttempts` 是包内 `const`，写死 5（[internal/workitem/workitem.go:55-88](file://internal/workitem/workitem.go#L55-L88)、[internal/run/run.go:51-92](file://internal/run/run.go#L51-L92)、[internal/record/record.go:124-153](file://internal/record/record.go#L124-L153)）。
- 冲突用 `errors.Is(err, storage.ErrConflict)` 判定，**不**用 `==`。
- `SchemaVersion` 零值时由模块注入；调用方传非零值则保留（[internal/workitem/workitem.go:74-76](file://internal/workitem/workitem.go#L74-L76)、[internal/events/events.go:60-62](file://internal/events/events.go#L60-L62)、[internal/run/run.go:71-73](file://internal/run/run.go#L71-L73)、[internal/record/record.go:159,167,262,310](file://internal/record/record.go#L159-L310)）。`domain.SchemaVersion = 1`（[internal/domain/models.go:6](file://internal/domain/models.go#L6)）。
- 失败后由调用方决定是否重试 / 报错。

`ReadSnapshot` + `Update(expected []byte)` 构成乐观并发对：读取路径必须返回**原始字节**而不是仅返回结构体，调用方在写回时把它直接喂给 `storage.ExpectHash(storage.HashBytes(expected))`。一旦字节不匹配，`storage` 直接报 `ErrConflict`，绝不静默覆盖。

- [internal/workitem/workitem.go:166-195](file://internal/workitem/workitem.go#L166-L195)（`ReadSnapshot`）；[workitem.go:156-164](file://internal/workitem/workitem.go#L156-L164)（`Update`）
- [internal/run/run.go:123-202](file://internal/run/run.go#L123-L202)（同形态）
- [internal/storage/txn.go:37,40](file://internal/storage/txn.go#L37-L40)（`ExpectHash` / `HashBytes`）

**M2 严格化：expected 快照必填且 fail-closed**——`len(expected) == 0` 直接拒绝（[internal/workitem/state.go:65-67](file://internal/workitem/state.go#L65-L67)），不能"无快照也能更新"；测试固定这一契约：`run_test.go:140-143` 用旧的 `snapA` 让第二次 `Update` 触发 `storage.ErrConflict`（[internal/run/run_test.go:140-143](file://internal/run/run_test.go#L140-L143)）。

**actor+reason 必填**：`TransitionRequest.Actor` 与 `TransitionRequest.Reason` 非空白校验由 `valid()` 完成（[internal/workitem/state.go:31-36](file://internal/workitem/state.go#L31-L36)）；`Claim` 走 `requiredFields` 同样校验（[internal/workitem/claim.go:1008-1016](file://internal/workitem/claim.go#L1008-L1016)）。CLI 强制把 `actor` / `reason` 做成必填 flag（[internal/cli/cli.go:564-565,605-607](file://internal/cli/cli.go#L564-L607)）。

**Guard 必须在写事务内复核证据**：`ApplyRepair` 要求 `TransitionRequest.Guard` 闭包，由 `changeStatus(repair=true)` 在写事务内、状态变更前调用——任何一条 evidence 缺失或 hash 不符即整体拒绝（[internal/workitem/state.go:53-59,123-127](file://internal/workitem/state.go#L53-L127)）。`reconcile.RepairApply` 把每条 evidence 列表作为 Guard 传入，digest 不匹配时返回 `reconcile.ErrDigestMismatch`（[internal/reconcile/reconcile.go:357-513](file://internal/reconcile/reconcile.go#L357-L513)、[internal/cli/cli.go:631-633](file://internal/cli/cli.go#L631-L633)）。

## 5. 同一写事务追加事件：`events.AppendTx` 与禁止嵌套 `Write`

M2 起所有调度类写（`Claim` / `Heartbeat` / `Release` / `Start` / `QueueRetry`）以及 `Transition` 末尾追加事件必须走 **`events.AppendTx(tx, ev)`**，直接复用外层 `*storage.Tx`，避免 `storage.Write` 内再调 `Append` 引发的事务嵌套：

- `events.AppendTx` 是事件注入到现有事务的唯一入口（[internal/events/events.go:84-93](file://internal/events/events.go#L84-L93)）
- [internal/workitem/claim.go:300,406,534,640,758](file://internal/workitem/claim.go#L300-L758)（M2 调度全部用 `events.AppendTx`）
- [internal/workitem/state.go:156](file://internal/workitem/state.go#L156)（`Transition` / `ApplyRepair` 末尾同样用 `events.AppendTx`）

**禁止嵌套 `Write`**：`workitem.changeStatus` / `Claim` / `Release` 已经持有 `st.Write` 独占锁，函数体里再调 `events.Append`（会再触发 `st.Write`）是 storage 的死锁红线。M1 时代 `events.Append` 仍保留给 CLI 的"非事务内"路径（[internal/events/events.go:53-82](file://internal/events/events.go#L53-L82)），写路径必须用 `AppendTx`。

## 6. 错误包装一律 `fmt.Errorf("%w: ...", sentinel, ...)`，结构化错误用 `errors.As`

跨包错误都用 `%w` 包装，便于上层 `errors.Is` 判定；格式串总是 `"<sentinel message>: <细节>"`，避免把 sentinel 字面量写到错误文本里再单独匹配。结构化错误（`PendingTxnError` / `TransitionError`）不能塞进字符串，必须 `Unwrap` + `errors.As`：
