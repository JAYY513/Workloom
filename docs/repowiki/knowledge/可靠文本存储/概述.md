# 可靠文本存储 · 概述

`internal/storage` 是 `devsys` 全部受管状态写入的底层。包级注释（`errors.go:1-10`）明确：本包提供单文件原子写、进程中断后的日志重放、以及尽力而为的 `fsync`；**断电一致性不在声明范围内**——任何"防失电"的说法都需要另行验证。

## 模块定位

为 `<root>/.devsys/` 之下的受管文件提供三类能力：

1. **基元层**：原子单文件替换、JSONL 追加与断尾检测、稳定键序 YAML/JSON 序列化。
2. **协调层**：项目级共享 / 排他短锁、乐观并发版本校验（`Expect`）。
3. **事务层**：跨文件可恢复事务（commit point + 日志重放）。

受管路径以 `.devsys/` 为根解析；`.devsys/local/` 持有锁文件与事务恢复材料，从不提交（`store.go:18-27`）。

## 职责边界

**做什么**

- 单文件原子写（`AtomicWrite`）：临时文件 + 写 + `fsync` + 关闭 + `chmod` + `rename`（POSIX 下原子；Windows 下重试 5 次处理 `ERROR_ACCESS_DENIED`/`ERROR_SHARING_VIOLATION`，见 `atomic.go:60-77`、`lock_windows.go:60-64`）。
- JSONL 追加（`appendJSONL`）：要求文件以换行结尾、长度严格匹配 `expectSize`，任何越界一律报错而不是覆盖（`jsonl.go:85-119`）。
- 稳定序列化：`EncodeYAML` 强制两空格缩进、单 LF 结尾；`EncodeJSON` 紧凑、`SetEscapeHTML(false)`（`serialize.go:18-66`）。
- 严格解码：`DecodeYAML` 拒绝未知键与多份 YAML 文档（`serialize.go:38-53`）。
- 项目锁：`flock`（POSIX，`lock_unix.go:13-19`）/ `LockFileEx`（Windows，`lock_windows.go:33-44`）；排他者写 holder 描述便于 `ErrLockTimeout` 报错时点名占用者（`lock.go:71-84,96-102`）。
- 事务：写时先落 payloads + journal，再原子地写 commit marker，然后 apply，最后清理事务目录（`txn.go:246-332`）。
- 恢复：commit marker 存在 → 幂等重放；不存在 → `verifyUntouched` 校验未被外部改动后才丢弃（`recover.go:89-141`）。
- 诊断：`Diagnose` 只读枚举事务目录与每个 op 在盘上的状态，不加锁、不变更（`recover.go:331-345`）。

**不做什么**

- 不提供文件系统级断电一致性（`errors.go:6-9`、`atomic.go:17-18` 显式声明）。
- 不解析或校验业务级 YAML schema；这是 `internal/config` 的职责（通过 `CheckSchemaVersion` 做版本门禁，`serialize.go:77-94`）。
- 不调用任何锁库——`README.md:88` 明示"锁与事务恢复材料只依赖标准库系统调用"。
- 不创建 `.devsys`；`Open` 要求目录已存在，否则 `ErrNotInitialized`（`store.go:53-78`）。
