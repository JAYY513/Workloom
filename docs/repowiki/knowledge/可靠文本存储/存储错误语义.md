# 可靠文本存储 · 存储错误语义

> 自定义维度卡：errors.go 暴露七个 sentinel 错误，每个对应一种"调用方需要换一种做法"的状态。语义边界对 CLI 层和上游模块至关重要，五维卡无法充分承载。

## 错误一览（`errors.go:14-41`）

| 错误 | 触发条件 | 调用方应做 |
|---|---|---|
| `ErrConflict` | Put 的 `Expect` 守卫不满足（`txn.go:266-268`） | 重读后重试，或放弃更新；不应静默覆盖 |
| `ErrLockTimeout` | 等待项目锁超过 `LockTimeout`（`lock.go:48-55`） | 报错给用户；可建议排查占用进程（错误消息含 holder 描述） |
| `ErrRecoveryFailed` | 恢复遇到不可确定状态（`recover.go:74-77`）；或 3 次循环仍有事务残留（`store.go:165`） | 拒绝读写；调用 `Diagnose` 取报告并人工介入 |
| `ErrIncompleteTail` | JSONL 文件最后一字节不是 `\n`（`jsonl.go:68-69,95-96`、`recover.go:225-227,242-243`） | 不允许追加；调用方应"修复后再追加" |
| `ErrUnsafePath` | 受管路径含 `\` / `:` / 绝对路径 / `..` / `local/...`（`store.go:91-105`、`txn.go:230-240`） | 检查路径生成逻辑；不应绕开 |
| `ErrSchemaVersion` | `schema_version` 缺失或不等于 supported（`serialize.go:85-93`） | 走迁移路径；不要改写为 supported 值 |
| `ErrNotInitialized` | `Open` 时 `.devsys` 不存在或不是目录（`store.go:63-69`） | 引导用户运行 `devsys init` |

## 错误包装约定

包内统一使用 `fmt.Errorf("%w: <context>", Err*)` 让 `errors.Is` 可识别：

- `store.go:64,68,92,96,99,103,165`
- `lock.go:52,54`
- `jsonl.go:69,95`
- `recover.go:226`
- `serialize.go:86,89,92`
- `txn.go:233,237,256,264`

非 sentinel 错误则用 `"<verb> %s: %w"`（`store.go:66,122`、`atomic.go:38,42,46,50`）。

## 三类状态判别

读取路径经常需要区分"文件不存在"与"其它错误"。本包对"不存在"的处理有两种语义：

1. **业务文件不存在**：通过 `readFileMaybe`（`atomic.go:103-112`）返回 `(nil, false, nil)`；不视为错误，例如 `Reader.Read` 与 `Reader.Expect` 都使用它（`store.go:115-138`）。
2. **基础设施路径不存在**：`.devsys/local/txn` 不存在时 `pendingTxns` 返回空切片（`recover.go:46-48`）；锁文件不存在时 `acquireLock` 会创建（`lock.go:30`）。

## 调用方责任

- **不要忽略 `ErrRecoveryFailed`**：`recover.go:74-77` 的错误消息明确"unfinished transaction logs are recovery material, not cache (方案 §15.2) — resolve before reading or writing valid state"。恢复失败后 `Read` / `Write` 会拒绝服务，必须人工介入。
- **不要在 `ErrIncompleteTail` 上追加**：`txn.go:264` 提示"repair the file before appending"；追加路径会在写入前再校验一次（`txn.go:258-266`）。
- **`ErrUnsafePath` 来自调用方**：路径解析在校验未通过时不返回绝对路径；调用方应修复路径而非捕获后改写。
- **`ErrConflict` 含期望 vs 实际摘要**：`describeCurrent` 截取 sha256 前 12 位（`txn.go:368-374`）；日志足以排查，但冲突解决的策略由调用方决定（重试 / 提示用户）。

## 与上层模块的边界

- `internal/config` 复用 `CheckSchemaVersion` 做 `project.yaml` / `config.yaml` 版本门禁；`ErrSchemaVersion` 因此是 `storage` / `config` 共用 sentinel，调用方用 `errors.Is(err, storage.ErrSchemaVersion)` 即可识别。
- `internal/project`（`init`）是 `Open` 的前置调用方——`init` 成功后 `Open` 不应再返回 `ErrNotInitialized`，但若用户在 init 之后手工删了 `.devsys`，错误仍会重新出现。
