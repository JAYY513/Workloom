# 存储错误语义

本卡描述 storage 的**七个 sentinel 错误**及其处理约定，以及 M3 起 `approval` / `workflow` 错误分类与 CLI 层转换。

## sentinel 错误

[internal/storage/errors.go](file://internal/storage/errors.go) 定义七个 sentinel：

| 错误 | 触发 | 处理 |
|---|---|---|
| `ErrConflict` | `ExpectAbsent` 命中已存在 / `ExpectHash` hash 不匹配 / 事务内 `rel` 已暂存（`claim` 检测） | 写失败；调用方决定重试或升级（CAS 重试上限 5 次） |
| `ErrLockTimeout` | 锁等待超时（共享 / 排他） | `holderInfo` 携带占用者 `pid/mode/since`，可在错误中暴露；调用方一般重试或退出 |
| `ErrRecoveryFailed` | `verifyUntouched` 或 `replayTxn` 任一不满足 `Expect` / 大小不符 / hash 不符；3 次 `Read` 循环后仍有事务 | 拒绝读写但允许只读诊断（`config check` / `doctor`）；调用方应跑 `devsys doctor` 看具体 proposals |
| `ErrIncompleteTail` | JSONL 末字节非 `'\n'` | append 拒绝；事件层透传，不重写或丢弃 |
| `ErrUnsafePath` | 受管路径不在白名单（绝对路径、含 `\` / `:`、`.` / `..` / `local/lock` / `local/txn` / `local/txn/...`） | 写入拒绝；调用方应使用相对路径 |
| `ErrSchemaVersion` | `schema_version` 不等于 `domain.SchemaVersion` | 写命令前置 `domain.CheckSchemaVersion` 拒绝；只读诊断允许继续（`config check`） |
| `ErrNotInitialized` | `.devsys/` 不存在 | 调用方应提示 `run devsys init`；CLI 层升为 `CodePrecondition = 3` |
| `ErrLocked`（M5） | `storage.LockFile` 在指定路径上检测到 OS 级独占锁争用 | 调用方应等待 holder 释放或报告「已有刷新在跑」；M5 被 `internal/knowledge.LockRefresh` 转译为 `Preconditionf("another refresh is already running ...")`（CLI exit 3）；进程死亡 OS 自动释放锁 |

## 错误传递链

```
storage.ErrXxx
   ↓ wrap/类型断言
领域包（workitem / events / run / record / approval / workflow）
   ↓ 暴露为领域错误类型（TransitionError / WorkflowStepError / approval.ErrXxx / workflow.RenderError）
CLI 层（workitemError / approvalError / mapWorkflowError）
   ↓ codedError{kind, code}
render 阶段决定人/机两种输出
   ↓
stderr JSON: {ok:false, error:{code, kind, message, problems?}}
```

## 领域错误类型

### `workitem`（M2）

- `domain.TransitionError{From, To, Allowed, Reason}` — 非法状态转换（[internal/domain/state.go](file://internal/domain/state.go)）

- `workitem.WorkflowStepError{Step, Reason, Allowed}` — 实例操作拒绝（[internal/workitem/workflow_instance.go:32-59](file://internal/workitem/workflow_instance.go#L32-L59)）

### `approval`（M3）

[internal/approval/approval.go:49-58](file://internal/approval/approval.go#L49-L58)：

```go
var (
    ErrNotFound        = errors.New("approval: not found")
    ErrBadID           = errors.New("approval: bad id")
    ErrInvalidInput    = errors.New("approval: invalid input")
    ErrNotPending      = errors.New("approval: not pending")
    ErrNotApproved     = errors.New("approval: not approved")

    ErrInvalidated     = errors.New("approval: invalidated")
    ErrMismatch        = errors.New("approval: does not match the gate")

```

这些错误都是 `fmt.Errorf("%w: ...", <sentinel>, ...)` 形态，调用方 `errors.Is` 取 sentinel。

### `workflow`（M3）

- `workflow.Policy` parse 错误：返回 `[]Issue{Severity, File, Line, Field, Reason}` 而非 Go error，调用方按 `SeverityError` 判定拒绝（[internal/workflow/parse.go:40-128](file://internal/workflow/parse.go#L40-L128)）。
- `workflow.Resolve` 错误：`workflow policy %q is invalid: %s (no last-known-good retained)` / `workflow policy %q: read: %w` / `workflow policy %q not found under .devsys/workflows/`，纯文本。
- `workflow.RenderError{Kind, Variables, Line, Reason}`（[internal/workflow/template.go:26-49](file://internal/workflow/template.go#L26-L49)）：
  - `KindTemplateSyntax` — 模板语法错误（孤立 `}}`、未闭合 `{{`、空名、非法名）
  - `KindUnknownVariable` — 渲染时变量缺失；`Variables` 去重升序
  - `KindEnvUndefined` — `ExpandEnv` 找不到环境变量
- `workflow.ErrInvalidID` — `id` 不匹配 `^[a-z][a-z0-9-]*$` 形状（在 `Resolve` 内部检查）

## CLI 层转换

### `workitemError`（[internal/cli/cli.go:477-482](file://internal/cli/cli.go#L477-L482)）

```go
func workitemError(err error) error {
    switch {
    case errors.Is(err, storage.ErrNotInitialized),
         errors.Is(err, workitem.ErrNotFound):
        return errPrecondition("%v", err)
    default:
        return errInvalid(nil, "%v", err)
    }
}
```

`--expect` 哈希不匹配由 `expectedSnapshot` 返回，向上经 `workitemError` 走 `CodePrecondition`。

### `approvalError`（M3 新增，[internal/cli/cli.go:1218-1232](file://internal/cli/cli.go#L1218-L1232)）

`approval` 域错误统一升为 `codedError{kind: "approval", code: CodeInvalid}`：

```go
func approvalError(err error) error {
    switch {
    case errors.Is(err, approval.ErrInvalidInput):
        return errUsage("%v", err)
    case errors.Is(err, storage.ErrNotInitialized):
        return errPrecondition("%v", err)
    default:
        return &codedError{
            code: CodeInvalid, kind: "approval", msg: err.Error(),
        }
    }
}
```

`--expect` 不匹配走 `errPrecondition`；其余 `ErrNotFound` / `ErrNotPending` / `ErrNotApproved` / `ErrAlreadyConsumed` / `ErrInvalidated` / `ErrMismatch` 都走 `CodeInvalid`。

### `mapWorkflowError`（M3 新增，[internal/cli/cli.go:522-543](file://internal/cli/cli.go#L522-L543)）

`workflow` 操作错误（`WorkflowStepError` / `Resolve` 失败 / `Render` 失败）走 `codedError{kind: "workflow", code: CodeInvalid}`。

## 与 schema_version 的边界

- `domain.SchemaVersion = 1`（[internal/domain/models.go](file://internal/domain/models.go)）。
- `storage.CheckSchemaVersion(b, expected)`（[internal/storage/serialize.go](file://internal/storage/serialize.go)）在写盘前校验版本；不匹配 → `ErrSchemaVersion`。
- `domain.EncodeYAML` / `DecodeYAML` 在编码/解码末尾调用 `storage.CheckSchemaVersion`（[internal/domain/serialize.go](file://internal/domain/serialize.go)）作为最后一道闸门。

## 与中断恢复的边界

`ErrRecoveryFailed` 不是数据丢失——`recover` 与 `doctor` 会枚举未决事务与 proposals；M3 起 `next` 在待恢复事务存在时直接判定 FAIL 并给出 `devsys recover` 修复命令（[internal/next/evaluate.go:158-170](file://internal/next/evaluate.go#L158-L170)）。
