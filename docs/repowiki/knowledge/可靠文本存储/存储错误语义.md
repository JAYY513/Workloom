# 可靠文本存储 · 存储错误语义

> 自定义维度卡：存储基元（`storage`）、调度与租约（`workitem`）、状态机（`domain`）三层共同暴露 sentinel / 包装错误，每个对应一种"调用方需要换一种做法"的状态。语义边界对 CLI 层和上游模块至关重要，五维卡无法充分承载。

## 错误一览（`internal/storage/errors.go:14-41`）

| 错误 | 触发条件 | 调用方应做 |
|---|---|---|
| `ErrConflict` | Put 的 `Expect` 守卫不满足（`txn.go:266-268`） | 重读后重试，或放弃更新；不应静默覆盖 |
| `ErrLockTimeout` | 等待项目锁超过 `LockTimeout`（`lock.go:48-55`） | 报错给用户；可建议排查占用进程（错误消息含 holder 描述） |
| `ErrRecoveryFailed` | 恢复遇到不可确定状态（`recover.go:74-77`）；或 3 次循环仍有事务残留（`store.go:165`） | 拒绝读写；调用 `Diagnose` 取报告并人工介入 |
| `ErrIncompleteTail` | JSONL 文件最后一字节不是 `\n`（`jsonl.go:68-69,95-96`、`recover.go:225-227,242-243`） | 不允许追加；调用方应"修复后再追加" |
| `ErrUnsafePath` | 受管路径含 `\` / `:` / 绝对路径 / `..` / `local/...`（`store.go:91-105`、`txn.go:230-240`） | 检查路径生成逻辑；不应绕开 |
| `ErrSchemaVersion` | `schema_version` 缺失或不等于 supported（`serialize.go:85-93`） | 走迁移路径；不要改写为 supported 值 |
| `ErrNotInitialized` | `Open` 时 `.devsys` 不存在或不是目录（`store.go:63-69`） | 引导用户运行 `devsys init` |

## M2 错误一览

### `storage` 只读检查错误（`internal/storage/inspect.go:20-41`）

| 错误 | 触发条件 | 调用方应做 |
|---|---|---|
| `ErrLockUnavailable` | `Store.Inspect` 检测到 `.devsys/local/lock` 不存在（`inspect.go:58-63`） | 报告"inspection unavailable"而不是伪造"no activity"；让用户先产生一次写操作 |
| `ErrPendingTxn` | `Store.Inspect` / `InspectUnlocked` 在执行 fn 前发现 `local/txn` 下有未决事务（`inspect.go` 拒绝带未决事务返回业务事实） | 提示用户运行 `devsys recover`；调用方不可基于此结果返回业务数据 |
| `PendingTxnError.IDs` | `ErrPendingTxn` 的包装类型，携带未决事务的 ID 列表（`inspect.go:33-39`） | 直接渲染给用户，**不要**重新扫描目录 |

`PendingTxnError.Unwrap()` 返回 `ErrPendingTxn`（`inspect.go:41`），因此 `errors.Is(err, storage.ErrPendingTxn)` 与 `errors.As(err, &pe)` 两种判定都能用。

### `workitem` 调度/租约错误（`internal/workitem/state.go:189-193`、`claim.go` 抛点）

| 错误 | 触发条件 | 调用方应做 |
|---|---|---|
| `ErrInvalidInput` | `TransitionRequest.valid()` 任一字段为空，或 `expected` 为空（`state.go:31-36,65-67`）；`ApplyRepair` 缺 `Confirmation` / `Guard` / `AllowRepair`（`state.go:53-59`） | 补齐 `actor` / `reason` / `expected` / `Confirmation`；不要再用 `Transition` 走 `AllowRepair=true` |
| `ErrLeaseTokenMismatch` | `Transition` / `Heartbeat` / `Release` / `UpdateClaimed` / `FenceRunUpdate` 调用方提供的 `Owner` 或 `Token` 与租约不符；或在没有租约的情况下传入了 `Token`（`state.go:114-122`、`claim.go` 全文） | 重读 lease（`LeaseInspection`）后再决定；不要重试旧的 owner/token |
| `ErrAlreadyClaimed` | `Claim` 时租约文件已存在（`state.go:112,138-140`、`claim.go:189-193` 抛点）；或 `Transition` 仍带 active lease 离开 `in_progress` | 报告该任务已被领取；`Transition` 路径需先 `Release` |
| `ErrNotClaimed` | `Release` / `Heartbeat` / `LeaseInspection` 找不到对应租约文件（`claim.go` 抛点） | 视为已清理；不要伪造 lease 状态 |
| `ErrLeaseExpired` | `Transition` / `Heartbeat` 等检测 `now.Before(lease.LeaseUntil)` 不再成立（`state.go:117-119`） | 让调用方走 `recover` 或重新 `Claim`；不要延长已过期的租约 |

### `domain` 状态机错误（`internal/domain/state.go:176-193`）

| 错误 | 触发条件 | 调用方应做 |
|---|---|---|
| `*domain.TransitionError` | 状态转换在保守图中不合法，或目标要求 `AllowRepair=true`（`state.go:99-101` 抛点） | 用 `errors.As` 取出 `Allowed` 列表渲染 "next: ..." 提示；不要回退到无校验的 `PutYAML` |

`TransitionError` 字段：`From` / `To` / `Allowed`（合法目标列表） / `Reason`（如 `target not allowed; regression requires confirmed repair`）。`Error()` 文本含 `allowed: [...]` 供 CLI 直接显示。

## 错误包装约定

包内统一使用 `fmt.Errorf("%w: <context>", Err*)` 让 `errors.Is` 可识别：

- `store.go:64,68,92,96,99,103,165`
- `lock.go:52,54`
- `jsonl.go:69,95`
- `recover.go:226`
- `serialize.go:86,89,92`
- `txn.go:233,237,256,264`

非 sentinel 错误则用 `"<verb> %s: %w"`（`store.go:66,122`、`atomic.go:38,42,46,50`）。

M2 起补充：

- `inspect.go:24,29` 声明 `ErrLockUnavailable` / `ErrPendingTxn`；`PendingTxnError.Unwrap` 透传（`inspect.go:41`）。
- `workitem/state.go:33,48,55,67,86,100,112,115,118,121,139` 全部以 `%w` 包装 `ErrInvalidInput` / `ErrLeaseTokenMismatch` / `ErrAlreadyClaimed` / `ErrLeaseExpired` / `storage.ErrConflict`。
- `workitem/claim.go` 所有抛点同形态；`reconcile.go:622,632` 用 `%w` 包装 `ErrDigestMismatch`。

`domain.TransitionError` 不通过 `%w` 包装，而是由 `errors.As(&te)` 判定（`workitem/state.go:99-101`），因为它需要把 `Allowed` 列表透传给调用方做 UI。

## 三类状态判别

读取路径经常需要区分"文件不存在"与"其它错误"。本包对"不存在"的处理有两种语义：

1. **业务文件不存在**：通过 `readFileMaybe`（`atomic.go:103-112`）返回 `(nil, false, nil)`；不视为错误，例如 `Reader.Read` 与 `Reader.Expect` 都使用它（`store.go:115-138`）。
2. **基础设施路径不存在**：`.devsys/local/txn` 不存在时 `pendingTxns` 返回空切片（`recover.go:46-48`）；锁文件不存在时 `acquireLock` 会创建（`lock.go:30`）。

M2 增加了第三类语义边界：

3. **只读检查不接受"先创建后读取"**：`Store.Inspect` 显式拒绝创建 `local/lock`——`ErrLockUnavailable`（`inspect.go:58-63`）。Doctor 这类只读命令必须**直接**告诉用户"没有可读快照"，而不是绕过检查去 `InspectUnlocked`。

`workitem` 也有两类"不存在"：

- `ErrNotFound`：`ReadSnapshot` / `Update` 目标 workitem 不存在（`workitem.go`），调用方按 `errors.Is(err, workitem.ErrNotFound)` 判定。
- `ErrNotClaimed`：租约文件缺失，调用方按 `errors.Is(err, workitem.ErrNotClaimed)` 判定，**不要**与 `ErrNotFound` 混用。

## 调用方责任

- **不要忽略 `ErrRecoveryFailed`**：`recover.go:74-77` 的错误消息明确"unfinished transaction logs are recovery material, not cache (方案 §15.2) — resolve before reading or writing valid state"。恢复失败后 `Read` / `Write` 会拒绝服务，必须人工介入。
- **不要在 `ErrIncompleteTail` 上追加**：`txn.go:264` 提示"repair the file before appending"；追加路径会在写入前再校验一次（`txn.go:258-266`）。
- **`ErrUnsafePath` 来自调用方**：路径解析在校验未通过时不返回绝对路径；调用方应修复路径而非捕获后改写。
- **`ErrConflict` 含期望 vs 实际摘要**：`describeCurrent` 截取 sha256 前 12 位（`txn.go:368-374`）；日志足以排查，但冲突解决的策略由调用方决定（重试 / 提示用户）。
- **`ErrLockUnavailable` 不可降级到 `Read`**：reconcile 必须用 `storage.Inspect`（仅在 Doctor 启动期无锁时走 `InspectUnlocked` 兜底），**不能**因为缺锁文件就 `storage.Read`——后者会自动恢复并创建锁文件，破坏只读不变量（[internal/reconcile/reconcile.go:1-20](file://internal/reconcile/reconcile.go#L1-L20)、[internal/storage/inspect.go:43-81](file://internal/storage/inspect.go#L43-L81)）。
- **`ErrPendingTxn` 必须回显 IDs**：`PendingTxnError.IDs` 是设计给出的"避免重新扫描"字段；CLI 应直接打印，不要让用户重跑 `devsys doctor` 才能看到。
- **`ErrAlreadyClaimed` 不可与 `ErrConflict` 混淆**：M1 时代 `Claim` 失败路径上抛 `storage.ErrConflict`（`claim.go:303`），M2 起 `Claim` 在 lease 存在时直接抛 `workitem.ErrAlreadyClaimed`（语义更准确），调用方用 `errors.Is` 分别识别。
- **`ErrLeaseTokenMismatch` / `ErrLeaseExpired` 不可重试**：`Heartbeat` / `Release` / `UpdateClaimed` 遇到即让调用方重读 lease；延长已过期租约会让 `recover` 的"过期=孤儿"判定失效。
- **`*domain.TransitionError` 用 `errors.As` 判定**：因为 `Allowed` 是切片，无法用 sentinel 表达；CLI 取 `Allowed` 直接渲染（[internal/cli/cli.go:478-481](file://internal/cli/cli.go#L478-L481)）。

## 与上层模块的边界

- `internal/config` 复用 `CheckSchemaVersion` 做 `project.yaml` / `config.yaml` 版本门禁；`ErrSchemaVersion` 因此是 `storage` / `config` 共用 sentinel，调用方用 `errors.Is(err, storage.ErrSchemaVersion)` 即可识别。
- `internal/project`（`init`）是 `Open` 的前置调用方——`init` 成功后 `Open` 不应再返回 `ErrNotInitialized`，但若用户在 init 之后手工删了 `.devsys`，错误仍会重新出现。
- M2 起 `internal/reconcile` 用 `storage.Inspect` 走只读；它**不**复抛 `ErrLockUnavailable` / `ErrPendingTxn`，而是把它们透传给 CLI（`internal/cli/cli.go:511-522`）。CLI 把 `ErrPendingTxn` 转为 `CodeInvalid`（4）输出，并把 `PendingTxnError.IDs` 写入 JSON `pending_transactions` 字段（`internal/cli/cli.go:533-534`）。
