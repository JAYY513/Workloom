# 存储错误语义

本卡描述 storage 的**七个 sentinel 错误**及其处理约定，以及 M3 起 `approval` / `workflow` 错误分类与 CLI 层转换。

## sentinel 错误

[internal/storage/errors.go](file://internal/storage/errors.go) 定义七个 sentinel：

| 错误 | 触发 | 处理 |
|---|---|---|
| `ErrConflict` | `ExpectAbsent` 命中已存在 / `ExpectHash` hash 不匹配 / 事务内 `rel` 已暂存（`claim` 检测） | 写失败；调用方决定重试或升级（CAS 重试上限 5 次） |
| `ErrLockTimeout` | 锁等待超时（共享 / 排他） | `holderInfo` 携带占用者 `pid/mode/since`，可在错误中暴露；调用方一般重试或退出 |
| `ErrRecoveryFailed` | `verifyUntouched` 或 `replayTxn` 任一不满足 `Expect` / 大小不符 / hash 不符；3 次 `Read` 循环后仍有事务 | 拒绝读写但允许只读诊断（`config check` / `doctor`）；调用方应跑 `workloom doctor` 看具体 proposals |
| `ErrIncompleteTail` | JSONL 末字节非 `'\n'` | append 拒绝；事件层透传，不重写或丢弃 |
| `ErrUnsafePath` | 受管路径不在白名单（绝对路径、含 `\` / `:`、`.` / `..` / `local/lock` / `local/txn` / `local/txn/...`） | 写入拒绝；调用方应使用相对路径 |
| `ErrSchemaVersion` | `schema_version` 不等于 `domain.SchemaVersion` | 写命令前置 `domain.CheckSchemaVersion` 拒绝；只读诊断允许继续（`config check`） |
| `ErrNotInitialized` | `.devsys/` 不存在 | 调用方应提示 `run workloom init`；CLI 层升为 `CodePrecondition = 3` |
| `ErrLocked`（M5） | `storage.LockFile` 在指定路径上检测到 OS 级独占锁争用 | 调用方应等待 holder 释放或报告「已有刷新在跑」；M5 被 `internal/knowledge.LockRefresh` 转译为 `Preconditionf("another refresh is already running ...")`（CLI exit 3）；进程死亡 OS 自动释放锁 |

## 错误传递链

```
storage.ErrXxx
   ↓ wrap/类型断言
领域包（workitem / events / run / record / approval / workflow）
   ↓ 暴露为领域错误类型（TransitionError / WorkflowStepError / approval.ErrXxx / workflow.RenderError）
`app.storeError`（[internal/app/workitem.go:460-484](file://internal/app/workitem.go#L460-L484)）：按 sentinel 映射到 `app.Error{Kind}` —— `ErrBadID` → `KindUsage`（exit 2）、`ErrNotFound` 类 → `KindPrecondition`、`ErrConflict` → `KindInvalid`、其它 → `KindInternal`
   ↓
CLI 层（[internal/cli/cli.go:127-147](file://internal/cli/cli.go#L127-L147) 的 `errUsage / errPrecondition / errInvalid` 工厂）：把 `app.Error` 升为 `codedError{kind, code}`
   ↓
render 阶段决定人/机两种输出
   ↓
stderr JSON: {ok:false, error:{code, kind, message, problems?}}
```

`storeError` 的关键判定（[internal/app/workitem.go:460-484](file://internal/app/workitem.go#L460-L484)）：

- `workitem.ErrBadID`（d726ed4）→ `Usagef("%v", err)`；CLI 层由 `app.Error` 自身的 `Class()` 方法（[internal/app/app.go:44-54](file://internal/app/app.go#L44-L54)）折叠出 `usage` 类，再在 `internal/cli/cli.go:158-167` 映射为 exit 2。
- `storage.ErrNotInitialized` / `workitem.ErrNotFound` / `approval.ErrNotFound` / `record.ErrNotFound` / `run.ErrNotFound` → `Preconditionf`，exit 3。
- `storage.ErrConflict` → `Invalidf(KindWorkitem, nil, "%v (the file changed after your read: re-read it and retry, or repeat with --latest where the command offers it)", err)`（乐观并发），CLI exit 4（[internal/app/workitem.go:516-519](file://internal/app/workitem.go#L516-L519)）。
- `app.Error` **没有**独立的 `Fixes` 字段——修复建议就写在 `Message` 字符串里（`app.Error{Kind, Message, Problems}`，[internal/app/app.go:37-42](file://internal/app/app.go#L37-L42)）。

## 领域错误类型

### `workitem`（M2）

- `domain.TransitionError{From, To, Allowed, Reason}` — 非法状态转换（[internal/domain/state.go](file://internal/domain/state.go)）

- `workitem.WorkflowStepError{Step, Reason, Allowed}` — 实例操作拒绝（[internal/workitem/workflow_instance.go:32-59](file://internal/workitem/workflow_instance.go#L32-L59)）

### `approval`（M3）

### `workflow`（M3）

- `workflow.Policy` parse 错误：返回 `[]Issue{Severity, File, Line, Field, Reason}` 而非 Go error，调用方按 `SeverityError` 判定拒绝（[internal/workflow/parse.go:40-128](file://internal/workflow/parse.go#L40-L128)）。
- `workflow.Resolve` 错误：`workflow policy %q is invalid: %s (no last-known-good retained)` / `workflow policy %q: read: %w` / `workflow policy %q not found under .devsys/workflows/`，纯文本。
- `workflow.RenderError{Kind, Variables, Line, Reason}`（[internal/workflow/template.go:26-49](file://internal/workflow/template.go#L26-L49)）：
  - `KindTemplateSyntax` — 模板语法错误（孤立 `}}`、未闭合 `{{`、空名、非法名）
  - `KindUnknownVariable` — 渲染时变量缺失；`Variables` 去重升序
  - `KindEnvUndefined` — `ExpandEnv` 找不到环境变量
- `workflow.ErrInvalidID` — `id` 不匹配 `^[a-z][a-z0-9-]*$` 形状（在 `Resolve` 内部检查）
## CLI 层转换

### `app.Error` 与 `codedError`

应用层封装 `app.Error{KindUsage, KindPrecondition, KindInvalid, KindInternal}` + `Problems`（[internal/app/app.go:36-54](file://internal/app/app.go#L36-L54)）；CLI 用 `app.Error.Class()` 把 `Kind` 折叠到四类（`usage` / `precondition` / `internal` / 其余归 `invalid`），再映射到退出码——`KindUsage = 2`、`KindPrecondition = 3`、`KindInvalid = 4`、`KindInternal = 1`（[internal/cli/cli.go:158-167](file://internal/cli/cli.go#L158-L167)）。CLI 层用 `errUsage / errPrecondition / errInvalid` 三个工厂（[internal/cli/cli.go:127-147](file://internal/cli/cli.go#L127-L147)）直接造 `codedError`，render 阶段把 `app.Error.Problems` 序列化进 stderr JSON。

### 命令级参数 / 缺参检测

各命令 handler 自己校验必填参数——`workitem transition --to <status> --actor <a> --reason <r> [--expect <hash> | --latest]` 等缺参时直接 `errUsage(...)`（[internal/cli/cli.go:907-989](file://internal/cli/cli.go#L907-L989)）：缺 `--to` / `--actor` / `--reason` / `--expect | --latest` 都升为 `KindUsage`、exit 2。

### `app.storeError` 统一映射

应用层调 `s.storeError(err)` 把 storage / 领域 sentinel 转成 `app.Error`（[internal/app/workitem.go:460-484](file://internal/app/workitem.go#L460-L484)）：

- `workitem.ErrBadID`（d726ed4）→ `Usagef`（exit 2）；不再落 storage 的 `unsafe managed path` 兜底。
- `storage.ErrNotInitialized` / `workitem.ErrNotFound` / `approval.ErrNotFound` / `record.ErrNotFound` / `run.ErrNotFound` → `Preconditionf`（exit 3）。
- `storage.ErrConflict` → `Invalidf("workitem", nil, ...)`（exit 4）。
- 该 message 自 d726ed4 起附带修复建议：「… (the file changed after your read: re-read it and retry, or repeat with --latest where the command offers it)」——同一分支覆盖 `app.RunUpdate` 等 `--expect` 不匹配的路径（[internal/app/workitem.go:516-519](file://internal/app/workitem.go#L516-L519)）。
- 其它 → `Internalf`（exit 1）。

`--expect` 哈希不匹配由 storage 层 `ExpectHash` 抛 `ErrConflict`，走 `storeError` 升为 `KindInvalid`、exit 4——并不再走 `CodePrecondition`（这是与旧 `workitemError` 的差异）。

## 与中断恢复的边界

`ErrRecoveryFailed` 不是数据丢失——`recover` 与 `doctor` 会枚举未决事务与 proposals；M3 起 `next` 在待恢复事务存在时直接判定 FAIL 并给出 `workloom recover` 修复命令（[internal/next/evaluate.go:265-278](file://internal/next/evaluate.go#L265-L278)）。

## 本批（M#337，commit 362b637）

### reconcile 侧：`InvalidFile` 与 `InspectionReport.InvalidFiles`
