# 可靠文本存储 · 特殊配置与命令

本卡只列**非显然**的运行配置与命令——普通 `devsys init` / `search` / `config check` 不在此处重复。

## `DEVSYS_CONFIG_DIR` 隔离运行

`registry.EnvDir = "DEVSYS_CONFIG_DIR"`（[internal/registry/registry.go:21-22](file://internal/registry/registry.go#L21-L22)）是 CLI 用来定位全局注册表（已初始化项目列表）的环境变量。冒烟剧本与所有 CLI 集成测试都用它把"全局注册表"隔离到临时目录，**不**污染用户主目录：

- `internal/cli/cli_test.go:77,136,154,192,261,289,340`：每个测试用 `t.Setenv("DEVSYS_CONFIG_DIR", t.TempDir())` 隔离。
- `scripts/smoke-m1.ps1:14,23,55`：进入时记 `$originalConfig = $env:DEVSYS_CONFIG_DIR`，写到 `$workspace/config`，退出时还原。
- `scripts/smoke-m1.sh:30`：`export DEVSYS_CONFIG_DIR="$workspace/config"`。

调用约定：

1. 测试 / 脚本必须**保存并还原**原值，不假设它是空——任意用户的开发机可能已经设置过。
2. 隔离路径必须是空目录（`mktemp -d`、`New-Item -ItemType Directory`），不能让两个测试 / 两次冒烟互相覆盖。
3. PowerShell 版本用 `Join-Path $workspace 'config'` 拼到同一层；Bash 版本也写在 `$workspace/config/`。两版本保持等价。

## `smoke-m1.ps1` / `smoke-m1.sh` 用法

两个剧本完整覆盖 M1.7（实施计划）"建仓库 → 建任务 → 记录决策 → 完成 → search → git status"端到端流程；二者功能等价，分别给 Windows PowerShell 与 Git Bash / WSL 用。

### 共同用法

```powershell
powershell -NoProfile -File scripts/smoke-m1.ps1 [-Keep]
```

```bash
bash scripts/smoke-m1.sh [--keep]
```

无参则把临时 workspace（包括 `devsys.exe`、构建产物、demo-project、`config/`）一次性清掉（[scripts/smoke-m1.ps1:61-63](file://scripts/smoke-m1.ps1#L61-L63)、[scripts/smoke-m1.sh:25-27](file://scripts/smoke-m1.sh#L25-L27)）；带 `--keep` 仅删 `devsys.exe` / `smoke-helper.exe` / `config/`，**保留** `$workspace/demo-project`，并打印 `KEPT_PROJECT=<path>` 供开发手动进入（[scripts/smoke-m1.ps1:57-60](file://scripts/smoke-m1.ps1#L57-L60)、[scripts/smoke-m1.sh:20-23](file://scripts/smoke-m1.sh#L20-L23)）。

## `docs/examples/m1-devsys/` 示例快照

13 个文件构成的**完整 M1 终态示例**：

```
.gitignore
artifacts/artifact-1.yaml
artifacts/artifact-2.yaml
artifacts/artifact-3.yaml
config.yaml
decisions/decision-1.yaml
events/2026-09.jsonl
findings/finding-1.yaml
project.yaml
runs/run-20260917-1.yaml
state/current.yaml
state/milestones.yaml
workitems/WLM-1.yaml
```

用途：

- **golden-file**：新实现要保证序列化形状稳定时，可与该目录对比（特别是 `schema_version: 1` 必填、字段顺序稳定、空集合用 `[]` 而非 `null`）。
- **文档 / 测试 fixture**：`project.yaml` 的 `id: demo-project` 即 `smoke-m1-helper.go` 启动时 `loadProjectID` 读到的项目 ID；`config.yaml` 当前只接受 `schema_version`（[docs/examples/m1-devsys/config.yaml:1-2](file://docs/examples/m1-devsys/config.yaml#L1-L2)）。
- **`workitems/WLM-1.yaml`** 故意用中文标题（`title: 协议适配器骨架`）+ 中文描述，便于直接观察 UTF-8 落盘与 git 不被 quote 化。

不要在 CI / 文档里直接 import 该目录——它是参考快照，不是公共 fixture；任何断言"应当长这样"的测试都应自己用 `t.TempDir()` 跑 `devsys init`。

## 搜索正确性与独立性能测量

`TestSearchThousandFilesResponsive` 保留 1000 文件命中的数量、路径、行号、文本检查及耗时日志，不再以 2s 墙钟时间判定通过，也不会跳过 Windows（[internal/search/search_test.go:102-111](file://internal/search/search_test.go#L102-L111)、[internal/search/search_test.go:165-177](file://internal/search/search_test.go#L165-L177)）。

```sh
go test ./internal/search -run '^$' -bench BenchmarkSearchThousandFiles -benchmem -benchtime=3x -count=1
```

benchmark 分 `FreshFiles`（每轮新建 1000 文件后首次搜索）和 `RepeatedFiles`（一次不计时搜索后重复读取同批文件），排除数据构造、结果验证和清理耗时；不清空 OS 缓存，不宣称测量冷缓存。2s 仅作明确机器、负载和数据集下的交互目标，不是普通测试硬门限（[internal/search/search_test.go:113-144](file://internal/search/search_test.go#L113-L144)）。历史 3.44s 全量测试失败不能直接归因为 Defender；`-short` 也不跳过该测试。

## `smoke-m1-helper.go` 不是纯 seed

`scripts/smoke-m1-helper.go` 同时承担两件事（[scripts/smoke-m1-helper.go:1-13](file://scripts/smoke-m1-helper.go#L1-L13)）：

- 不带 `--verify`：seed 模式——按工作流顺序调用 `workitem.Create` → `events.Append` → `record.CreateDecision` / `CreateFinding` / `CreateArtifact` / `NewArtifactVersion` → `run.Create` → `events.Append(comment + reply)`，打印分配到的 ID。
- 带 `--verify`：回读模式——按依赖顺序 `ReadSnapshot` → `GetArtifact` → `ArtifactHistory` 反向 v3→v1 → `Comments` 聚合 → `git ls-files -z -- .devsys` 逐文件 UTF-8 + 非 NUL 校验（[scripts/smoke-m1-helper.go:436-476](file://scripts/smoke-m1-helper.go#L436-L476)）。`local/` 与 `.cache/` 在该检查中直接被拒。

任何 M1 领域层的回归都会先被这两个剧本捕获，不需要再去敲 CLI。
