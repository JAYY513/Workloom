## `DEVSYS_CONFIG_DIR` 隔离运行

`registry.EnvDir = "DEVSYS_CONFIG_DIR"`（[internal/registry/registry.go:21-22](file://internal/registry/registry.go#L21-L22)）是 CLI 用来定位全局注册表（已初始化项目列表）的环境变量。冒烟剧本与所有 CLI 集成测试都用它把"全局注册表"隔离到临时目录，**不**污染用户主目录：

- `internal/cli/cli_test.go:77,136,154,192,261,289,340`：每个测试用 `t.Setenv("DEVSYS_CONFIG_DIR", t.TempDir())` 隔离。
- `scripts/smoke-m1.ps1:14,23,55`：进入时记 `$originalConfig = $env:DEVSYS_CONFIG_DIR`，写到 `$workspace/config`，退出时还原。
- `scripts/smoke-m1.sh:30`：`export DEVSYS_CONFIG_DIR="$workspace/config"`。
- `scripts/smoke-m2.ps1:13,26,111` 与 `scripts/smoke-m2.sh:30`：同样保存并还原。

调用约定：

1. 测试 / 脚本必须**保存并还原**原值，不假设它是空——任意用户的开发机可能已经设置过。
2. 隔离路径必须是空目录（`mktemp -d`、`New-Item -ItemType Directory`），不能让两个测试 / 两次冒烟互相覆盖。
3. PowerShell 版本用 `Join-Path $workspace 'config'` 拼到同一层；Bash 版本也写在 `$workspace/config/`。两版本保持等价。

## `devsys doctor` / `recover` / `repair`（M2 命令面）

CLI 在 M2 阶段新增三条顶层命令，全部落到 `internal/reconcile/` 上（[internal/cli/cli.go:55-58,156-162](file://internal/cli/cli.go#L55-L162)）。`workitem` 子命令保留 `create` / `get` / `transition` / `claim`（[internal/cli/cli.go:362-475](file://internal/cli/cli.go#L362-L475)）。

### 退出码（`internal/cli/cli.go:35-44`）

| 退出码 | 名称 | 何时触发 |
|---|---|---|
| `0` `CodeOK` | 成功 | 命令无错返回；`--json` 模式下结果写到 stdout |
| `1` `CodeInternal` | 内部错误 | 任何未被分类的 `error`（`render` 函数在 `errors.As(&ce)` 失败时回退到 `errInternal`） |
| `2` `CodeUsage` | 用法错误 | 参数缺失 / 未知子命令；CLI 打印 usage 后退出 |
| `3` `CodePrecondition` | 前置条件不满足 | `devsys init` 之前执行命令、`recover` 拿不到 actor/reason、`repair --apply` digest 不匹配（[internal/cli/cli.go:631-633](file://internal/cli/cli.go#L631-L633)） |
| `4` `CodeInvalid` | 受管状态无效但可读 | `config check` 报 `schema_version` 错误；`workitem get` 拿到不存在的 ID；`workitem` 子命令语义错误（[internal/cli/cli.go:478-481](file://internal/cli/cli.go#L478-L481)）。`--json` 模式下 `problems` 列表会一并输出 |

> doctor / recover / repair **不**返回 `4`：doctor 是只读诊断、`recover` 在 `CodeInternal`（1）失败、`repair` 在 digest 不匹配时 `CodePrecondition`（3），无 `4` 路径。

### `devsys doctor`

只读检查（[internal/cli/cli.go:508-553](file://internal/cli/cli.go#L508-L553)）：

```powershell
devsys --json doctor
```

- 不接受任何位置参数。
- 走 `reconcile.Doctor`（[internal/reconcile/reconcile.go:142-208](file://internal/reconcile/reconcile.go#L142-L208)）：先调 `storage.Diagnose` 看 pending transactions，再走 `storage.Inspect` 枚举 `.devsys/scheduling/`，**不**触发事务恢复、**不**创建锁文件。
- 若 `ErrLockUnavailable` 返回（无锁文件且无 `scheduling/` 目录），报告 `inspection_ok=false` + 提示"no lock file"，**不**伪造"no activity"（[internal/reconcile/reconcile.go:152-154](file://internal/reconcile/reconcile.go#L152-L154)）。
- 若存在未决事务，报告 `pending_transactions` + 提示 `run devsys recover before trusting business state`。
- `--json` 输出 `reconcile.InspectionReport` 完整结构（含 `expired_leases` / `orphan_leases` / `repaired_proposals` / `lease_probes`）。

### `devsys recover`

释放过期/孤儿租约（[internal/cli/cli.go:556-592](file://internal/cli/cli.go#L556-L592)）：

```powershell
devsys recover --actor <operator> --reason <text>
```

`--actor` 与 `--reason` 必填；缺失返回 `CodeUsage`（2）。`reconcile.Recover`（[internal/reconcile/reconcile.go:210-280](file://internal/reconcile/reconcile.go#L210-L280)）先跑 `storage.Recover`（确定性事务恢复），再调 `workitem.Release(ForExpired=true)` 释放 `lease_until < now` 的租约、再调 `Release(ForOrphan=true)` 释放 run 文件缺失的租约。状态字段不主动改——recover 是清理，不是状态机转换。

### `devsys repair`

确认式修复（[internal/cli/cli.go:594-665](file://internal/cli/cli.go#L594-L665)）：

```powershell
# 第一步：dry-run，输出 plan + digest
devsys repair --dry-run --actor <operator> --reason <text>

# 第二步：用第一行的 digest 作为确认值；apply 内部会重新跑 dry-run 校验
devsys repair --apply --confirm <digest> --actor <operator> --reason <text>
```

`--actor` / `--reason` 必填；`--apply` 必须有 `--confirm`；仅 `--dry-run` 或仅 `--apply` 缺一返回 `CodeUsage`（2）。

`reconcile.RepairDryRun`（[internal/reconcile/reconcile.go:282-304](file://internal/reconcile/reconcile.go#L282-L304)）输出与时间无关的 `Plan.Digest`（排序后 SHA256）。`RepairApply` 内部**重跑** `RepairDryRun` 并把 `plan.Digest` 与 `--confirm` 比对（[internal/cli/cli.go:618-622](file://internal/cli/cli.go#L618-L622)）：不一致返回 `reconcile.ErrDigestMismatch` → `CodePrecondition`（3）。一致时按 plan 调用 `workitem.ApplyRepair`，把每条 evidence 列表作为 `TransitionRequest.Guard` 传入，由 `changeStatus(repair=true)` 在写事务内重核（[internal/reconcile/reconcile.go:357-513](file://internal/reconcile/reconcile.go#L357-L513)、[internal/workitem/state.go:53-59,123-127](file://internal/workitem/state.go#L53-L127)）。

> `reconcile.ErrDigestMismatch` 的语义是"在你确认的瞬间，状态已经变了"——必须重新 `--dry-run` 拿新 digest。**不要**用旧的 digest 强制重试。

## `storage.TxnStageHookForTest` 进程中断注入

`storage.TxnStageHookForTest` 是 storage 层暴露的**测试专用**钩子，让其他包的测试在指定 stage 后立即 `os.Exit` 来模拟真实进程中断（[internal/storage/txn.go:434-440](file://internal/storage/txn.go#L434-L440)）。生产代码**不可**调用它。

```go
storage.TxnStageHookForTest(func(stage string) {
    if stage == os.Getenv(envWICrashAt) {
        os.Exit(exitCodeCrash)
    }
})
```

已知的调用方：

- [internal/workitem/m2_crash_test.go:36-46](file://internal/workitem/m2_crash_test.go#L36-L46)：按 env `WI_CRASH_AT` 在 `stageJournalDurable` / `stageCommitted` / `stageApplied(0)` 等不同阶段退出，断言"journal-durable 崩溃 = 事务丢弃、领取不可见、可重新领取"与"committed 崩溃 = 决定已定、完整重放、其余领取者被 fencing 拒绝"。

按提交点语义（`txnStage` 顺序见 [架构设计](架构设计.md) 的写路径小节）：崩溃发生在 `stageJournalDurable` 之前 → 整笔事务被丢弃；发生在 `stageCommitted` 之后 → 读者永不观察半提交，`recover` 阶段补齐 `applyPayload`。

> 该钩子**只**在 `_test.go` 文件中合法引用；普通业务代码 / 工具 / smoke 脚本都不应该看到它。
