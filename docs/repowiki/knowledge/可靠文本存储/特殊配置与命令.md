## 隔离运行

### `DEVSYS_CONFIG_DIR`

所有冒烟剧本与隔离测试通过该环境变量把「全局注册表」隔离到临时目录，避免污染用户配置：

```sh
# Bash
export DEVSYS_CONFIG_DIR="$workspace/config"

# PowerShell
$env:DEVSYS_CONFIG_DIR = 'C:/Temp/workloom-registry'
```

### `GOPROXY=off` 离线构建

`vendor/` 已提交；干净机器设 `GOPROXY=off` 即可离线构建（见 README.md 的「③ 源码构建」一节）。

```sh
# Bash / PowerShell / cmd
GOFLAGS=-mod=vendor GOPROXY=off go build ./...
```

PowerShell：`$env:GOPROXY='off'`。

## 构建与发布标识

```sh
go build -mod=vendor -ldflags "-X github.com/JAYY513/Workloom/internal/version.Version=0.1.0 -X github.com/JAYY513/Workloom/internal/version.Commit=$(git rev-parse --short HEAD)" -o bin/devsys.exe ./cmd/devsys
```

未注入 `-ldflags` 的本地构建保留 `Version=0.1.0-dev`（`devMarker`）；`Commit` 自 #338（v0.1.4）起在 `init()` 里经 `debug.ReadBuildInfo()` 的 `vcs.revision` 兜底——README 食谱 / install.sh 回退这类源码构建也能显示提交短号，完全无 VCS 信息时才保持 `unknown`；`devsys --version` 在 `Commit=="unknown"` 时只输出 `Version`（[internal/version/version.go:27-62](file://internal/version/version.go#L27-L62)）。这是构建标识能力，不表示已有自动发布流水线。

### `smoke-m3.{ps1,sh}`（M3 工作流/门禁/审批端到端）

```sh
bash scripts/smoke-m3.sh --keep
```

七段 PASS（[scripts/smoke-m3.sh](file://scripts/smoke-m3.sh)）：

1. 策略就位：`devsys init` + `cp docs/examples/workflows/quick-fix.md .devsys/workflows/` + `m3helper setup`（parent + sibling + child，child 在 verification 步、quick-fix policy、链接 decision + finding）。
2. done 门禁拦截：`workitem transition --to done` 缺 `test-results` artifact 与 comment → exit 4 + `artifact "test-results" is required`。
3. 补 artifact + comment → 推进 done，child 状态 done、父与兄弟 `context_refs` 包含 `decision://<id>` + `finding://<id>` 各 1、`record_propagated` 事件 1 条、父与兄弟 status 不变。
4. 质量门拦截：`m3helper lowq` 创建 thin 任务（标题"fix"、描述"x"）→ `workitem claim` exit 4 + `quality_gate.min_score` 与改进项（标题过短等）；`m3helper improve` 补足后领取成功。
5. last-known-good：成功 claim 落快照 → 注入坏策略（缺 `id` / `version: "x"`）→ claim 拒绝（exit 4 + `is invalid` + `last-known-good`），`next` 报 `invalid_policy` 风险，`workflow next` 含 `last-known-good` 提示；恢复策略后 claim 成功。
6. 工作流实例：创建 thin 策略（`flow.md`：inspect → implement 两条边）→ `workflow start` → `workflow next` 列出 `to=implement` 候选 → `--to nope` exit 4 + `not a declared transition` + `allowed next steps` → `--to implement` 成功 → `workflow pause` → `step-complete` exit 4 + `paused` → `workflow resume` → 推进；`.devsys/scheduling/` 哈希前后一致（实例操作不动调度态）。
7. 审批门禁：thin 策略（`approval-flow.md`：in_progress 阶段 `require_approval: true`）→ `workitem transition --to in_progress` exit 4 + `an approved, unconsumed approval is required` → `approval request --stage in_progress` → `approval approve --id approval-1` → 重提 transition 成功 + `consumed_at` 写入 + `approval_consumed` 事件 → `approval reject --id approval-2` 触发 `workitem.Transition` 的 Guard 把工作项转 `blocked`（`on_reject=block`）+ `status_changed` 内容含 `approval-2 rejected: risk too high`。

### `m3helper`（`scripts/m3helper/main.go`）

为 `smoke-m3.*` 准备的命令 helper，按 KEY=VALUE 打印：

- `setup <root>` — 创建 parent + sibling + child + decision + finding，挂 quick-fix policy。
- `lowq <root>` — 创建 thin 任务，挂在 quick-fix policy 的 implement 步（触发质量门）。
- `evidence <root> <child>` — 创建 `test-results` artifact + 一条 comment（满足 done 门禁）。
- `improve <root> <id>` — 把 thin 任务改成能过质量门的版本（标题 + 描述 + acceptance_criteria）。
- `status <root> <id>` — 打印 `ID=<id> STATUS=<s> REFS=<comma-sep context_refs>`。
- `propagated <root> <id>` — 打印 `PROPAGATED=<n>`（subject=workitem id 的 `record_propagated` 事件数）。

构建：`go run ./scripts/m3helper <subcommand> <root> [args]`。

## 发布脚本（`scripts/build-release.{sh,ps1}` + `install.{sh,ps1}`）

06f2d8e 起发布矩阵由仓库内脚本驱动，`.github/workflows/release.yml` 仅做编排：tag push 或 `workflow_dispatch` 调 `scripts/build-release.sh` 在 ubuntu-latest runner 上跑同一份矩阵（windows/amd64、windows/arm64、linux/amd64、linux/arm64、darwin/amd64、darwin/arm64），产物落到 `dist/`。

构建脚本（[scripts/build-release.sh:1-54](file://scripts/build-release.sh#L1-L54)、[scripts/build-release.ps1:1-34](file://scripts/build-release.ps1#L1-L34)）：

- `--version` 默认取 `git describe --tags --always --dirty`；`--out` 默认 `dist/`。
- `ldflags` 注入 `github.com/JAYY513/Workloom/internal/version.Version=<version>` 与 `Commit=<short sha>`（v0.1.7 起模块路径为 `github.com/JAYY513/Workloom`），所以本地构建不再保留 `0.1.0-dev/unknown` 默认值。
- `sha256sum devsys-* > checksums.txt`；b89ffae 起严格自检：发现 `^[0-9a-f]{64} \*`（macOS `shasum` 的 `*` 二进制标记）就 `exit 1`，要求 GNU 两空格形态——避免 v0.1.0 的 shasum-格式校验和被发出去。
- v0.1.6（318e002，#347）起 install 脚本随 release 资产发布：`cp scripts/install.sh scripts/install.ps1 dist/` 且 `sha256sum devsys-* install.sh install.ps1 > checksums.txt`——「贴提示词给 agent」流程直接从 release 页下载脚本，手工用户也无需 shallow clone。

安装脚本（[scripts/install.sh:1-95](file://scripts/install.sh#L1-L95)、[scripts/install.ps1:1-86](file://scripts/install.ps1#L1-L86)）：

- `--tag <v>` 必填，`--repo` 默认 `JAYY513/Workloom`，`--prefix` 默认 `~/.local/bin`（PowerShell 用 `%LOCALAPPDATA%/devsys`）。
- 自动推导 os/arch 资产名（`devsys-<os>-<arch>`，windows 加 `.exe`）。
- 下载：先试 `gh release download`（鉴权可用时，处理私有仓库资产；d726ed4 起），失败回退到匿名 `curl`/`wget`/`Invoke-WebRequest`；#342 起 install.ps1 显式 `gh auth status 2>$null | Out-Null`（`$ErrorActionPreference="Stop"` 下原生 stderr 会变成 ErrorRecord 绕过 `$LASTEXITCODE` 检查），install.sh 保留 gh 自己的 stderr 作为失败证据（auth / 网络 / 缺失 tag）。
- 校验：`tr -d '\r' < checksums.txt` 容忍 CRLF；`grep -E "[[:space:]]\*?$asset\$"` 容忍 shasum 的 `*` 标记（98adab3 起）；`sha256sum -c -` / `shasum -a 256 -c -` 二者皆可。
- 下载失败 + Go 与 git 可用 → `git clone --branch <tag> --depth 1` 进 `$tmp/src`（98adab3 起：克隆后 `cd` 进入源码目录再 `go build`），按 build-release 同口径注入 `-X github.com/JAYY513/Workloom/internal/version.Version=$tag` 与 `Commit=$(git rev-parse --short HEAD)`（#338 起两条都注入）；#342 起每条失败路径只打印一行可执行建议（显式 `if !` 守卫，`set -e` 在 `||` 上下文里挂起，裸 `git clone` 失败不会穿透到 build 步）。
- 校验通过 → `cp` 到 prefix，`--version` 自检；PowerShell 可选 `-AddToPath` 写用户 PATH（已存在则提示 `already on user PATH`，未加则提示 `add to PATH: <dest> (rerun with -AddToPath …)`）。

`docs/examples/workflows/reference-template.md`（38f5972 + 577299a 起）：参考级流程模板——4 步 `inspect → plan → implement (status: in_progress) → verify`，`plan → implement` 转换条件 `workitem.clarification_needed == false`，`completion_rules: [acceptance_criteria_verified, no_unresolved_blocker]`。可直接 `cp` 到 `.devsys/workflows/` 作为空白项目起手。
