# 领域记录与事件

本卡覆盖 `.devsys/` 内**领域记录**（WorkItem / Run / Artifact / Decision / Finding / Approval）与**事件流**（按月分片 JSONL）的存储路径、ID 规则、并发写路径与不变式。M3 新增 `record.ListArtifacts`（门禁证据收集）、`Approval` 全生命周期、`events.AppendBatchTx`（按 shard 分组一次 append）、`propagateRecordsTx`（完成事务内广播决策/发现引用）。

## WorkItem（`internal/workitem`）

### 路径与 ID

`.devsys/workitems/<id>.yaml`，`<id>` = `<PREFIX>-<N>`，`<PREFIX>` 默认 `WLM`，创建时由 `workitem.Create` 通过 CAS 分配（[internal/workitem/workitem.go:55-88](file://internal/workitem/workitem.go#L55-L88)）。状态字段由 `changeStatus` 唯一改写；`Update` 拒绝状态变更。

### 关键不变式

- **CAS 分配**：写事务内 `nextNumber` 扫目录 `max+1` → `PutYAML(..., ExpectAbsent())`；`ErrConflict` 即 `continue` 重扫，最多 5 次。
- **乐观更新**：`Update` 把 `ReadSnapshot` 返回的原字节传给 `Write`，由 `ExpectHash(HashBytes(expected))` 守卫；并发写抛 `ErrConflict`，**永不**被静默覆盖（[internal/workitem/workitem.go:156-195](file://internal/workitem/workitem.go#L156-L195)）。
- **状态字段**：`Status` / `SchedulingState` / `LeaseOwner` / `LeaseToken` / `LeaseUntil` / `Workflow` 全部由对应写路径改写，普通 `Update` 阻断；租约活跃时仅 `UpdateClaimed` 能改 metadata。
- **M3 Guard**：`TransitionRequest.Guard` 在事务内、状态字段改写之前被调用，返回事件与 `status_changed` 同批提交。
- **M3 审批失效**：离开 `from` 时 `approval.InvalidateForStatusTx` 把同源未消费审批标记为 `invalidated_at`，事件并入同批。
- **M3 记录传播**：进入 `done` 时 `propagateRecordsTx` 把 `decision://<id>` / `finding://<id>` 追加到父与直接兄弟的 `context_refs`；无 parent 不广播；父子自环拒绝并回滚。

## Artifact（`internal/record`）

### 路径与 ID

`.devsys/artifacts/artifact-<N>.yaml`，`<N>` 由 `nextNumber` 扫目录得到。Artifact 是**不可变版本链**：每个版本是独立文件，`previous_id` 指向上一个版本，链由 `ArtifactHistory` 沿 `previous_id` 反查，环检测 `seen[cursor]` → `ErrBadID`。

### 写路径：`NewArtifactVersion`

[internal/record/record.go:280-325](file://internal/record/record.go#L280-L325) 写锁内：

1. `tx.ReadForExpect` 取当前版本字节 → `DecodeYAML` 到 `cur`。
2. `*next = *cur` 浅拷贝所有字段。
3. `next.ID = newID`、`next.Version = cur.Version + 1`、`next.PreviousID = &currentID`。
4. `tx.PutYAML(... newID.yaml ..., ExpectAbsent())` 写新文件。

现有版本文件**永不**被改写。

### M3 门禁证据收集：`ListArtifacts`

[internal/record/record.go:243-258](file://internal/record/record.go#L243-L258) 按 ID 升序列出全部 artifact 版本，门禁从中提取 `Name` 集与 `gate.RequireArtifacts` 做集合包含校验（[internal/cli/cli.go:1209-1224](file://internal/cli/cli.go#L1209-L1224)）。`Name` 是 artifact 的逻辑名称（同一 `Name` 可能多版本），跨版本聚合。

### 生命周期

```
            Request              Decide                ConsumeTx
pending ─────────────────► approved ─────────► consumed (consumed_at)
   │                          ▲
   │                          │
   └─── Decide(reject) ──► rejected
   │
   └─── InvalidateForStatusTx ──► invalidated (invalidated_at)
```

## 事件流（`internal/events`）

### 路径与 ID

`.devsys/events/<YYYY-MM>.jsonl`，按 UTC 年月分片；ID `ev-<UTC时间戳.微秒>-<8hex>`（[internal/events/events.go:150-157](file://internal/events/events.go#L150-L157)），无全局计数器，4 字节随机后缀保证同微秒多事件去重（M3Reviewer2 ①）。

### 关键不变式

- shard 路径由事件自身 `UTC t.Year()/Month()` 派生，12 月事件 1 月写仍落 12 月分片。
- 写路径只校验 `reply_to` 必须是 comment 类型（[internal/events/events.go:69-71](file://internal/events/events.go#L69-L71)）。
- subject 一致性、悬空 reply、二级回复（parent 也是 reply）由 `Comments` 聚合阶段校验（[internal/events/events.go:240-264](file://internal/events/events.go#L240-L264)）。
- `ErrIncompleteTail` 由 `storage/jsonl.go` 的 `InspectJSONL` / `appendJSONL` 透传；事件层不做断尾判定。
- append 用 `tx.AppendJSONL`（单事件）或 `tx.AppendJSONLRaw`（M3 多事件），由事务协议统一中断恢复。

### M3 事务内多事件：`AppendBatchTx`

[internal/events/events.go:108-144](file://internal/events/events.go#L108-L144) 按 shard 分组，把同 shard 事件合并为一次 `AppendJSONLRaw` 调用。典型场景：

- `workitem.changeStatus` 提交批 = `status_changed` + Guard 事件 + 失效事件 + 传播事件
- `approval.ConsumeTx` + `InvalidateForStatusTx` 同事务内提交 `approval_consumed` + `approval_invalidated` + `status_changed`

每个 shard 在事务内只一次 append，违反 `staged twice` 校验的路径（消费 + 失效同文件）由 `Tx.Staged(rel)` 显式跳过。

## M3 记录传播

`workitem.propagateRecordsTx`（[internal/workitem/propagate.go:28-57](file://internal/workitem/propagate.go#L28-L57)）在 `changeStatus` 目标为 `done` 且来自非 `done` 时触发：

1. `relatedRecordRefs` 按文件名字典序扫描 `decisions/` 与 `findings/`，挑出 `RelatedWorkItems` 命中的记录，返回 `decision://<id>` / `finding://<id>` 引用。
2. `propagationTargets` 取父与所有直接兄弟（按 id 排序）。
3. `propagateToTarget` 对每个目标 `tx.ReadForExpect` → `DecodeYAML` → 追加缺失引用 → `PutYAML(ExpectHash)` → 返回 `record_propagated` 事件。
4. 目标已包含全部引用 → 跳过写盘与事件（幂等）。
5. 父子自环（`parent_id == self`）显式拒绝并回滚。
6. 无 `ParentID` / 空字符串 → 不广播。

事件 `record_propagated` 与 `status_changed` / Guard / 失效事件并入 `events.AppendBatchTx` 同批提交。
