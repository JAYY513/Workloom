# 知识层 · 概述

本模块是 M5 里程碑的接入层：把工作项上下文里**第二层**的「代码页与决定」从一句空话（`degraded to records and events`）变成一份**可校、可刷、可校验**的副产物——但仍保持**两层分工**：本系统拥有并重建索引层（`internal/knowledge`），外部生成器（首选 RepoWiki）写入页面层，CLI/MCP 通过 `internal/app` 共享服务与 `internal/mcp` 工具族对外暴露 `status / scan / validate / refresh` 四族命令与 `context get --task` 的任务上下文装配。

## 模块定位

- **做什么**：
  - **索引层**（`internal/knowledge/snapshot.go`）：扫描工作树，写 `.devsys/knowledge/snapshot.json`（含 `FileEntry{Path,Size,Hash,Language}`、`Stats`、`Excluded{Directories,Files,IgnoreFiles,Rules}`）。排除 `DefaultExcludedDirectories = {.git, .devsys, .repowiki, vendor, node_modules}`、`SecretPatterns`（`.env*`、`.pem`/`.key`/`.p12`/`.pfx`/`.keystore`/`.jks`、`id_rsa*`/`id_dsa*`/`id_ecdsa*`/`id_ed25519*`、`credentials*`、`secrets*`、`.npmrc`、`.netrc`、`.htpasswd`）、单文件 > 1 MiB（`DefaultMaxFileSize`）；尊重 `.gitignore`（通过 `git check-ignore`，不实现第二套语义）+ 项目自定义忽略文件 `.devsys/knowledge/ignore`（不支持 `!` 取反）。
  - **页面层**（`internal/knowledge/page.go` + `scan.go`）：解析 Markdown front matter，必填字段 `status`/`type`/`triggers`/`description`/`source_commit`，可选 `dimension`/`sources`/`content_hash`/`generator`/`generated`/`protected`；`AuthoredStatuses = {current, stable, draft, unverified, conflicted, deprecated, archived}`（明确排除手写的 `stale`/`invalid`——这两态是新鲜度与校验器计算得到的）；`KnownTypes` + `KnownKeys` 已知字典作为 warning（外部生成器的扩展字段允许存在）；`sources` 走项目内相对路径（`/` 前缀 / 盘符 / `\\` / `..` / 空段都拒），无声明则 warning 并要求生成器 state 映射补足（方案 §12.5）。
  - **匹配器**（`internal/knowledge/match.go`）：`*` 段内匹配、`?` 单字符、`**` 跨段；无 `/` 的模式在任意深度匹配（`.gitignore` 风格）；尾部 `/` 把模式扩成目录子树。同一实现既给 ignore 又给 page sources 又给 context 的 source 命中。
  - **新鲜度**（`internal/knowledge/freshness.go`）：`Head` + `Changes` 走 git diff；`Evaluate` 对每页做三阶段决策：`source_commit` → 生成器 `State.Mapping(path)` 的 `SourceCommit` → 层基线（`State.Baseline.Commit`）；任一不为空才能下结论。无 sources 或无 baseline 标 `unverifiable`（`Cannot tell` ≠ fresh，仍要走"stale"）。状态机裁决 `fresh` / `stale` / `missing`：0/10/11 退出码是这套裁决的对外契约。
  - **人工保护**（`internal/knowledge/protection.go`）：`protected: true` 永久锁 + `content_hash` 与磁盘 hash 不一致（被手改）拒重生成；两保护仅 `--force` 可覆盖，但 override 仍出现在 `Skipped[]`（含 `Recorded` / `Actual` / `Overridden`）。
  - **生成器契约**（`internal/knowledge/generator.go`）：`Scope{FormatVersion, Project, Mode, Baseline, Head, Pages}` 写到 `.devsys/knowledge/refresh-scope.json`；argv 拼成 `--project <root> --scope-file <rel> --format-version 1`，**不**走 shell（`strings.Fields` + 直接 CreateProcess）。当前契约版本 `FormatVersion = 1`；`Mode ∈ {full, affected}`。
  - **断点续跑**（`internal/knowledge/run.go`）：`Checkpoint{Phase, Pages, Completed, Generator, ScopeFile, StartedAt, UpdatedAt, PID, Host}` 写 `.devsys/knowledge/run.json`；`Phase ∈ {generating, finished, failed}`；`ResumePending` 用已记录 `content_hash` 比对磁盘文件判断页面是否已完成；`LockRefresh` 走 `internal/storage.LockFile`（OS 级独占锁），被中断的进程死时锁自动释放——配合 `run.json` 让下一轮成为 resume 而不是 restart。
  - **共享应用服务接线**（`internal/app/knowledge.go`）：`KnowledgeStatusView`（`{Status,Layer,Reason,Baseline,Head,Branch,IndexReady,IndexFiles,Pages,Generator,ChangedFiles,Affected,Unverifiable,FreshPages}`）+ `KnowledgeScanView`（`{File,GeneratedAt,Files,TotalSize,Languages,Excluded,ExcludedDirectories,IgnoreFiles,Rules}`）+ `KnowledgeValidateView`（`{Roots,Missing,Pages[],Errors,Warnings,Issues[]}`）+ `KnowledgeRefreshView`（`{Scope,Pages,Resumed,Checkpoint,Generator,ScopeFile,Ran,Reason,Output,Missing,Skipped[],Failed,Error,Status}`）。四方法共享一段「候选名单 + 现有根 + state」流水线；`pageRoots(md)` 把 `KnowledgePages` 与 `DefaultRoots` 合并并剔除不存在的目录；explicit roots（来自 CLI 或 MCP）要求存在且位于项目内。
  - **任务上下文装配**（`internal/app/context.go: knowledgeContext`）：为 `context get --task <id>` 在 `workitem` 摘要 + 决策/发现/工件/事件引用之上叠加 `KnowledgeContext{Pages[], Baseline, Degraded, Notice}`——选页规则是 `trigger 命中 → source 命中 → per-page freshness verdict`；无页面层时返回 `Degraded: true` + 提示「`degrade to records and events`」（方案 §12.6）。
- **不做什么**：
  - 不实现生成器本身：RepoWiki 是首选外部生成器，仓库里只放 stub（`scripts/smoke-m5.sh` 用的 `bash` 脚本）。
  - 不接管 `.devsys/knowledge/state.json` 的写入：state 由生成器写（方案 §12.6），层只读它来映射 sources/content_hash/baseline。
  - 不强制 LLM/MCP 加载顺序：`triggers` 只是触发词，匹配靠子串；层不做语义相似度。
  - 不索引符号或语义：snapshots 是文件清单 + sha256 + 语言，不是 AST、不是嵌入。
