# 知识层 · 断点续跑与锁

本卡描述 M5 知识层**断点续跑与并发互斥**（`internal/knowledge/run.go` + 复用的 `internal/storage/lockfile.go`）：刷新过程中被打断时如何**继续**（而不是从头开始），同时保证任意时刻**最多一个**刷新在跑。

## 两件东西

| 文件 | 角色 | 失效方式 |
|---|---|---|
| `.devsys/knowledge/run.json` | 进度（Checkpoint） | 手动 `rm` / 进程不主动清（除非成功） |
| `.devsys/knowledge/run.lock` | 互斥（OS 锁） | 进程死亡 → OS 自动释放 |

两者必须**同时**存在才是一个「正在跑」的刷新——只 run.json 不 run.lock 说明 checkpoint 残留（被中断），下轮 `Refresh` 会**续跑**。

## `Checkpoint` 的字段

[internal/knowledge/run.go:32-47](../知识层/架构设计.md)：

```go
type Checkpoint struct {
    SchemaVersion int       `json:"schema_version"`        // 恒 1
    PID           int       `json:"pid"`                    // 进程 PID
    Host          string    `json:"host,omitempty"`         // hostname（空 = 未知）
    Phase         string    `json:"phase"`                  // "generating"/"finished"/"failed"
    Mode          string    `json:"mode"`                   // "full"/"affected"
    Generator     string    `json:"generator,omitempty"`    // 配置的生成器命令
    ScopeFile     string    `json:"scope_file,omitempty"`   // refresh-scope.json 路径
    StartedAt     time.Time `json:"started_at"`
    UpdatedAt     time.Time `json:"updated_at"`
    Pages         []string  `json:"pages"`                  // 本轮要生成的页面（去重前）
    Completed     []string  `json:"completed,omitempty"`    // 已确认写完的页面
    Error         string    `json:"error,omitempty"`        // 最后一次 generator 失败的 stderr/msg
}
```

三态（[run.go:22-26](../知识层/架构设计.md)）：

| `Phase` | 含义 | 何时写 |
|---|---|---|
| `generating` | 刷新在跑 | Checkpoint 首次创建时 |
| `finished` | generator 退出 0、after-status 写出 | 成功后写一次 |
| `failed` | generator 退出非 0 / ErrLocked / ScopeFile 写失败 | 失败后写一次 |

成功完成后 `ClearCheckpoint`（[run.go:81-87](../知识层/架构设计.md)）会**删** checkpoint——`run.json` 不留痕；只有**失败**才让 checkpoint 留到下一轮。

## `LockRefresh`

[internal/knowledge/run.go:93-99](../知识层/架构设计.md)：

```go
func LockRefresh(root string) (func() error, error) {
    path := filepath.Join(root, filepath.FromSlash(RunLockFile))
    if err := os.MkdirAll(filepath.Dir(path), 0o755); err != nil {
        return nil, fmt.Errorf("create %s: %w", Dir, err)
    }
    return storage.LockFile(path)
}
```

`storage.LockFile`（[internal/storage/lockfile.go:20-39](../可靠文本存储/存储错误语义.md)）：

- 打开 `O_CREATE|O_RDWR`；
- 调 `lockHandle(file, true)`（POSIX `flock` / Windows `LockFileEx`）；
- 失败时若 `lockContended(err)` 返回 `storage.ErrLocked`（共享/排他争用），否则包成错误；
- 返回 `release func()`（unlock + close）。

**关键不变量**：

- 锁是**进程级**的：进程死亡 → OS 释放 → 下次 `LockFile` 直接成功。这是「中断的刷新永远不阻塞下一次」的关键。
- `MkdirAll(filepath.Dir(path), 0o755)`：项目从未刷新过就没有 `.devsys/knowledge/`——一次 mkdir 让首刷新也能取锁。

`Refresh`（[internal/app/knowledge.go:369](../知识层/架构设计.md)）取锁失败时返回：

```text
Preconditionf("knowledge refresh: another refresh is already running%s; wait for it or remove %s if it died",
    refreshHolder(s.Root), knowledge.RunFile)
```

`refreshHolder`（[internal/app/knowledge.go:476-505](../知识层/架构设计.md)）从 `LoadCheckpoint` 抽出信息拼出"holder 提示"：

- 正常：`(pid 12345 on host01 since 2026-09-19T...)`；
- checkpoint 还在写：`(holder unknown: its checkpoint is not written yet)`；
- checkpoint 不可读：`(holder unknown: the checkpoint cannot be read)`；
- checkpoint 无 PID：`(holder unknown: the checkpoint records no pid)`。

退出码是 3（`CodePrecondition`）。

## `ResumePending`

[internal/knowledge/run.go:111-144](../知识层/架构设计.md)：

```text
pending = checkpoint.Pages ∪ candidates
sort + compact
for path in pending:
    page = pages[path]                  // 必须是扫描出来的页面
    if page 不存在:
        skip                            // 已不存在
    recorded = page.ContentHash ?? state.Mapping[path].ContentHash
    if recorded == "":
        remaining.append(path)          // 无 recorded → 一定还要写
    actual = HashFile(path)
    if recorded == actual:
        skip                            // 已完成（hash 与记录一致）
    else:
        remaining.append(path)          // 还要写
return remaining
```

**关键不变量**：

- 「`recorded == actual`」是「自上次扫描以来页面没动过」的判据——这是层不重写已完成页的依据（不依赖生成器自己幂等）。
- 页面**消失**直接剔除：用户已经在刷新间删了它，再生成也是空生成。
- 没有 `recorded`（新页面）一律保留——首次生成 hash 还没回写到 state，无可比对。
- 错误（`HashFile` 失败但非 NotExist）才返回 `error`——`fs.ErrNotExist` 视为「页面没了」，按不存在处理。

`KnowledgeRefreshRequest` 没有 `Full + Resumed` 的语义冲突：

- `Full`：`candidates = report.Pages`（全部页面）；
- `affected`：`candidates = freshness.Affected() ∪ freshness.Unverifiable()`（按 freshness 算）。

Resume 与 candidates 合并后**总是**走一遍 `ResumePending`——`Full` 模式下也用同样的 hash 比对，已写过的页面自然被剔除（实际 `Full` 极少与续跑相遇）。

## 整段流程（refresh）

```mermaid
flowchart TD
    A[Refresh ctx req] --> B{KnowledgeStatus ok?}
    B -- err --> X[原 err]
    B -- ok --> C{status.Pages == 0?}
    C -- 是 --> Y[Missing=true; exit 11]
    C -- 否 --> D[Scan + LoadState]
    D --> E{req.Full?}
    E -- 是 --> F1[candidates = all pages]
    E -- 否 --> F2[candidates = Affected ∪ Unverifiable + sort]
    F1 --> G
    F2 --> G[LoadCheckpoint]
    G -- err not exist --> H[no checkpoint; Resumed=false]
    G -- ok --> I[Resumed=true; pending = checkpoint.Pages ∪ candidates; ResumePending]
    G -- err 其它 --> X2[invalid]
    H --> J
    I --> J[Skips root pages state req.Force]
    J -- err --> X3[internal]
    J -- ok --> K{req.Force?}
    K -- 否 --> L[剔除 Skipped → candidates]
    K -- 是 --> M[Skipped[i].Overridden=true; 保留全部]
    L --> N
    M --> N{len view.Pages == 0?}
    N -- 是 --> O[Reason = nothing to regenerate; 清 checkpoint; return]
    N -- 否 --> P{view.Generator == ""?}
    P -- 是 --> Y2[Missing=true; exit 11]
    P -- 否 --> Q[LockRefresh]
    Q -- err ErrLocked --> X4[precondition: another refresh is running]
    Q -- err 其它 --> X5[internal]
    Q -- ok --> R[argv = GeneratorCommand; scope = Scope; ScopeFile = WriteScope]
    R --> S[Checkpoint Phase=generating; WriteCheckpoint]
    S --> T[runGenerator ctx argv → output]
    T -- err --> U[Phase=failed + err 写入; Failed=true; Error=err.Error; precondition]
    T -- ok --> V[Phase=finished + Completed=view.Pages; WriteCheckpoint]
    V --> W[KnowledgeStatus after → view.Status]
    W --> X[ClearCheckpoint]
    X --> Y3[return view, nil]
```

**注意**：`ClearCheckpoint` 只在 `Phase=finished` 之后调（[internal/app/knowledge.go:434](../知识层/架构设计.md)）；失败的 checkpoint 留着，下一轮续跑。

## 与 CLI 的可见输出

CLI 的 `reportRefresh`（[internal/cli/records.go](../项目接入与配置/CLI渲染与交换协议.md)）：

- `resumed: true` 且 checkpoint 有 `ScopeFile`：`resumed an interrupted run (<rel>)`；
- `resumed: true` 且 checkpoint 没 `ScopeFile`：`resumed an interrupted run`；
- `Reason`（已存在的）原样打印；
- `Skipped[]` 每条 `skipped: <path>  (<reason>)`——**`--quiet` 下仍可见**（保护被覆盖的事实必须留痕）；
- `Output` 原样打印（generator 自己的日志）；
- `Status` 不为空 → 打印"after refresh: <status>"+"still stale: <page>"。

## 边界与不做的事

- **不做进程间信号**：没有 `kill -USR1` 之类的手动推进机制；checkpoint 在 generator 退出后由本进程写。
- **不做 wall-clock 超时**：刷新进程挂起时层不会自动超时——下轮 `refresh` 仍会拿锁失败（持有者是死进程？不，OS 已释放锁）。挂起的判断留给 hook（外部 watch）。
- **不持久化 `StartedAt/UpdatedAt` 的解析**：`time.Time` 序列化为 RFC3339；时区丢失（UTC 序列化后 parse 仍是 UTC）。
- **不实现 checkpoint schema 迁移**：版本不匹配直接拒读（[run.go:59-62](../知识层/架构设计.md)）。
