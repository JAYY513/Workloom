# 知识层 · 索引快照与匹配器

本卡描述 M5 知识层的**索引层**（`internal/knowledge/snapshot.go`）与**匹配器**（`internal/knowledge/match.go`）：一个是「项目里有什么文件」的指纹，另一个是「一个路径模式如何匹配一条路径」。两层都被 [页面契约与校验](页面契约与校验.md) 的 `sources` 字段、[人工保护](人工保护.md) 的 skip 判定、[上下文装配](上下文装配.md) 的 `MatchSources` 流程共用。

## 索引层：`.devsys/knowledge/snapshot.json`

`Snapshot` 是「工作树指纹」：

```go
// internal/knowledge/snapshot.go
type Snapshot struct {
    SchemaVersion int              `json:"schema_version"`     // 恒 1
    GeneratedAt   time.Time        `json:"generated_at"`
    Files         []FileEntry      `json:"files"`              // 排序后写
    Stats         SnapshotStats    `json:"stats"`
    Excluded      SnapshotExcluded `json:"excluded"`
}

type FileEntry struct {
    Path     string `json:"path"`     // 项目内相对，slash
    Size     int64  `json:"size"`
    Hash     string `json:"hash"`     // 整文件 sha256 hex
    Language string `json:"language"`
}

type SnapshotStats struct {
    TotalFiles int            `json:"total_files"`
    TotalSize  int64          `json:"total_size"`
    Languages  map[string]int `json:"languages"`
}

type SnapshotExcluded struct {
    Directories []string    `json:"directories"`
    Files       []Exclusion `json:"files"`           // 排序后写；含 reason
    IgnoreFiles []string    `json:"ignore_files"`    // 自定义 ignore 文件路径
    Rules       []string    `json:"rules"`           // 解释 "为什么这个文件被排除"
}
```

`SnapshotSchemaVersion = 1` 是当前唯一版本；`LoadSnapshot` 拒绝任何其它版本（[snapshot.go:263-266](../知识层/架构设计.md)）。

## 排除优先级

`BuildSnapshot`（[snapshot.go:113-195](../知识层/架构设计.md)）按下列顺序决定一个文件是否入索引：

1. **默认目录**：`DefaultExcludedDirectories = {.git, .devsys, .repowiki, vendor, node_modules}`——目录直接 `fs.SkipDir`，不进 candidates（[snapshot.go:298-302](../知识层/架构设计.md)）；
2. **密钥名模式**：`SecretPatterns`（[snapshot.go:42-48](../知识层/架构设计.md)）——即便同时被 `.gitignore` 排除，reason 仍写「密钥名模式（同时被 .gitignore 排除）」——审计不能被忽略链隐藏；
3. **`.gitignore`**：通过 `git check-ignore --stdin -z`（[snapshot.go:323-366](../知识层/架构设计.md)）；**未跟踪文件**生效，**已提交文件即使命中忽略规则也会入索引**（[snapshot.go:129](../知识层/架构设计.md) 的 Rules 描述）；
4. **自定义忽略文件**：`.devsys/knowledge/ignore`（`CustomIgnoreFile`）；不支持 `!` 取反——理由：项目自己的 `.gitignore` 已经覆盖需要 `!` 的场景；
5. **单文件大小**：`DefaultMaxFileSize = 1 MiB`；超限以 `Exclusion{Reason: "超过 %d 字节上限"}` 列出（[snapshot.go:223-225](../知识层/架构设计.md)）；
6. **非常规文件**：symlink、字符设备、FIFO——以 `Exclusion{Reason: "符号链接"}` 或 `Exclusion{Reason: "非常规文件"}` 列出；
7. **扫描期间被删除**：`os.Lstat` 返回 `fs.ErrNotExist`——以 `Exclusion{Reason: "扫描期间被删除"}` 列出，**不**报错。

每一条规则在 `SnapshotExcluded.Rules[]` 中以人类可读字符串出现：「目录：`xxx`、`xxx`...」、「密钥名模式：`xxx`、`xxx`...」、「单文件 > %d 字节」、「`.gitignore`（git check-ignore；只对未跟踪文件生效，已提交的文件即使命中忽略规则也会入索引）」、「自定义忽略文件：`.devsys/knowledge/ignore`」。

## `git check-ignore` 的语义

`gitIgnored`（[snapshot.go:323-366](../知识层/架构设计.md)）走 `git -C <root> check-ignore --stdin -z`：

- 输入：候选文件相对路径（项目内、`/` 分隔），逐项后跟 `\x00`；
- 输出：被忽略的路径列表；
- 退出码：1 = 无文件被忽略（成功）；其它非 0 = 错误。

`ErrNoGit`（[snapshot.go:26](../知识层/架构设计.md)）由 §12.5 引入：**禁止把"无 git"降级为"无忽略"**。如果 `git` 不可执行或 `check-ignore` 失败，扫描直接返回错误，`KnowledgeScan` 把这个错误映射为 `Preconditionf("knowledge scan: %v", err)`（exit 3）。

候选列表在调用 `git check-ignore` 之前**已经**完成 `collectCandidates`（[snapshot.go:282-317](../知识层/架构设计.md)），输出按字典序排序保证 snapshot 可重现。

## `ErrNoGit` 的强制

§12.5 写明「git 失败必须报错而不是假装无忽略」。代码侧的两个具体形态：

- `git check-ignore` 返回非 1 退出码且 stderr 非空 → `fmt.Errorf("%w: %v: %s", ErrNoGit, err, stderr)`；
- `git` 二进制不可执行 → `fmt.Errorf("%w: %v", ErrNoGit, err)`。

调用方（`internal/app.KnowledgeScan`）把 `errors.Is(err, knowledge.ErrNoGit)` 翻成 `Preconditionf`；其它错误翻成 `Internalf`。

## 匹配器（`internal/knowledge/match.go`）

`Match(pattern, path) bool`（[match.go:22-24](../知识层/架构设计.md)）的语义与 `.gitignore` 同形：

| 模式形态 | 等价正则 | 含义 |
|---|---|---|
| `*` | `[^/]*` | 段内任意长度 |
| `?` | `[^/]` | 段内单字符 |
| `**` | `.*` | 跨任意字符（含 `/`） |
| `**/` | `(?:[^/]*/)*` | 跨任意段（含零段） |
| `[`/`]` | 字面 | 字符类**不**展开；按字面匹配 |
| `.+()|{}^$\` | 转义 | 正则元字符在模式里按字面匹配 |
| `/` | 字面 | 路径分隔符保持字面 |
| 无 `/` | `(?:.*/)?<expr>` | 在任意深度匹配（`.gitignore` 风格） |
| `^/...` | 锚定项目根 | 带前导 `/` 强制从根开始 |
| 尾部 `/` | `<expr>(?:/.*)?` | 把模式扩成子树 |

`compilePattern`（[match.go:52-67](../知识层/架构设计.md)）输出 `^...$` 锚定正则。

### `**` 的两种形态

- `**`（不在 `/` 后）：跨任意字符——`internal/**x` 等价于 `internal/.*x`，匹配 `internal/x` 也匹配 `internal/store/x`；
- `**/`（紧接 `/`）：跨**段**——`internal/**/x` 等价于 `internal/(?:[^/]*/)*x`，**也**匹配 `internal/x`（零段）；
- 这是 `.gitignore` 的标准语义，方案 §12.2 明确选择它而不是更严格的 `**/x` 必跨段。

### 缓存

`matchRegexp`（[match.go:37-49](../知识层/架构设计.md)）走包级 `sync.Mutex` + `map[string]*regexp.Regexp`：

- 上限 `matchCacheSize = 4096`；
- 满时**整张清空**（不是 LRU）——理由：模式来源是项目级文件（ignore / page sources / context 列表），实际集合远小于 4096；满即清空是为了防止外部模式把 map 撑爆。

## 与页面层的边界

| 角色 | 文件 | 用例 |
|---|---|---|
| 索引层构建 | `snapshot.go` | `KnowledgeScan` → `BuildSnapshot` → `WriteSnapshot` |
| 索引层读取 | `snapshot.go` | `KnowledgeStatus` → `LoadSnapshot` → `view.IndexReady/IndexFiles` |
| 索引层排除语义 | `snapshot.go` | `BuildSnapshot` 内的 `collectCandidates` + `gitIgnored` |
| 模式匹配 | `match.go` | `IgnoreFile.Match`、`sources` 命中、`context get --task` 的 source 覆盖 |
| 模式编译 | `match.go` | `compilePattern` + `patternToRegexp` + 缓存 |

`Snapshot` 不存「谁匹配了谁」——那是 `Evaluate`（[新鲜度与基线](新鲜度与基线.md)）的活，由 `Changes(root, commit)` 走 git diff 拿路径后逐条 `Match(pattern, path)`。`Snapshot` 只回答「项目里有什么文件」。

## 边界与不做的事

- **不做内容索引**：`Snapshot` 是路径清单 + sha256 + 语言；不做 AST、不做嵌入、不做全文搜索（那是 `internal/search`）。
- **不做 watch**：`BuildSnapshot` 是「一次扫描」语义；增量（inotify 等）不在范围内——状态变化由 `knowledge refresh` 显式触发。
- **不支持 git 子模块路径规整**：候选路径走 `filepath.ToSlash` 后原样作为 `FileEntry.Path`；子模块内的相对路径不重写到子模块根。
- **不读符号链接目标**：`ModeSymlink` 直接排除（[snapshot.go:220-222](../知识层/架构设计.md)）；不试图把链接文件的目标纳入索引。
