# 知识层 · 页面契约与校验

本卡描述 M5 知识层**页面层**的核心契约：单个 Markdown 知识页（page）必须满足的 front matter 形态、字段语义、`Parse` 流程与 located 校验清单。**索引层**（snapshot.json）不在此卡；生成器契约（argv / Scope）见[生成器契约与适配器](生成器契约与适配器.md)。

## 页面形状

一个知识页由 front matter + Markdown 正文组成：

```markdown
---
status: stable
type: module
dimension: architecture
triggers:
  - 存储层
  - 事务恢复
description: "可靠文本存储的事务协议与中断恢复"
source_commit: cf7b256
sources:
  - internal/storage/**
content_hash: 3a4f...（64-hex）
generator: repowiki
generated: true
protected: false
---

# 卡片标题
... 正文 ...
```

`---` 围栏之间是 YAML；必须以 `---` 单行开始并以 `---` 或 `...` 单行结束。`Parse` 不接受以 `...` 开头（必须 `---`），这是 YAML 文档分隔符的传统用法；不接受 `===` / `***` 等自定义围栏。

## 字段语义

### 必填字段（`RequiredKeys`）

| 字段 | 类型 | 校验 | 含义 |
|---|---|---|---|
| `status` | 字符串 | `AuthoredStatuses` 之一；显式拒绝 `stale` / `invalid`（这两态是计算出来的） | 页面声明的稳定度 |
| `type` | 字符串 | 正则 `^[a-z][a-z0-9_]*$`；`KnownTypes` 内为「已登记」，否则 warning | 页面类型 |
| `triggers` | 字符串列表 | 非空；非空字符串；去重；首尾空白 warning | 触发词，命中即装入任务上下文 |
| `description` | 字符串 | 非空（TrimSpace） | 卡片说明 |
| `source_commit` | 字符串 | 7-40 位小写十六进制；空字符串 warning（视为未基线） | 页面声明的基线提交 |

### 可选字段（`KnownKeys`）

| 字段 | 类型 | 校验 | 含义 |
|---|---|---|---|
| `dimension` | 字符串 | 无格式校验（外部约定） | 五维自定义标记 |
| `sources` | 字符串列表 | 项目内相对路径：拒绝绝对路径、盘符前缀（`^[A-Za-z]:`）、`\\`、`..` 段、空段；非空；非空字符串；去重；首尾空白 warning | 页面覆盖的源模式 |
| `content_hash` | 字符串 | 64 位小写十六进制（可选空） | 生成器记录的整文件 sha256 |
| `generator` | 字符串 | 无格式校验 | 生成器名 |
| `generated` | 布尔 | 必须是 `true` / `false` 标量 | 是否机器生成 |
| `protected` | 布尔 | 必须是 `true` / `false` 标量 | 永久锁 |

### 未知字段

任何不在 `KnownKeys` 的 front matter 顶层 key 都是 **warning**（不是 error）：

- 理由：页面来自**外部生成器**（首选 RepoWiki），生成器有自己的词汇（dimension 名、自定义分类）；
- 一个 warning 是「请确认拼写」的提示，不是拒绝——见 `internal/knowledge/page.go:188-191`。

### 未知 `type`

`type` 不在 `KnownTypes` 的合法 token 也只是 **warning**：

- `KnownTypes = {module, overview, architecture, api, data_model, config, test, process, guide, reference, note}`；
- 类型正则 `^[a-z][a-z0-9_]*$` 是硬约束（生成器扩展名必须走小写蛇形）；
- 这两个检查是**解耦的**：类型不登记但形态合法 → warning；类型形态非法 → error。

## `status` 的特殊处理

`status` 是页面**声明**的状态，而不是**计算**的状态。`AuthoredStatuses = {current, stable, draft, unverified, conflicted, deprecated, archived}` 是生成器与人可以**手写**的值；`stale` / `invalid` 不在列表里——理由：

- 「`stale`」由新鲜度检查（[freshness.go](../知识层/新鲜度与基线.md)）在 `Evaluate` 时计算；
- 「`invalid`」由本卡描述的解析器在 `Parse` 时计算；
- 一个手写的 `stale` 是「谎报」，比「没写」更糟——层无法校验它是否真实。

`checkStatus`（[internal/knowledge/page.go:219-238](../知识层/架构设计.md)）显式拒绝手写的 `stale` / `invalid`，错误信息是「`%q 是计算得出的状态（新鲜度检查、校验器），不能手写；请写 %s`」。

## `sources` 的路径形态

`checkSourcePattern`（[internal/knowledge/page.go:425-439](../知识层/架构设计.md)）按下面规则逐一拒绝：

| 形态 | 错误信息 |
|---|---|
| 以 `/` 开头 | `必须是项目内相对路径，不能以 / 开头` |
| `^[A-Za-z]:`（Windows 盘符） | `必须是项目内相对路径，不能带盘符` |
| 含 `\` | `必须用 / 分隔` |
| 含 `..` 段 | `不能包含 .. 段` |
| 含空段（`a//b`） | `含空路径段` |

路径段以 `/` 分隔——`containsSegment` 走 `strings.Split(pattern, "/")` 后查 `part == segment`。匹配在 `Match(pattern, path)`（[match.go](../知识层/索引快照与匹配器.md)）里展开成正则。

## `Parse` 流程

[internal/knowledge/page.go:127-217](../知识层/架构设计.md) 的执行顺序：

```mermaid
flowchart TD
    A[utf8.Valid? ] -- 否 --> Z1[err: 不是合法 UTF-8]
    A -- 是 --> B{BOM?}
    B -- 是 --> C[warn: UTF-8 BOM]
    B -- 否 --> D[lines[0] == --- ?]
    C --> D
    D -- 否 --> Z2[err: 缺少 front matter]
    D -- 是 --> E[找结束 --- 或 ...]
    E -- 未找到 --> Z3[err: front matter 未闭合]
    E -- 找到 --> F[block = lines 1..end, yaml.Unmarshal]
    F -- err --> Z4[err: front matter 不是合法 YAML]
    F -- ok --> G{empty doc?}
    G -- 是 --> Z5[err: front matter 为空: 缺少 ...]
    G -- 否 --> H{DocumentNode + 单 Content?}
    H -- 是 --> I[doc = Content 0]
    H -- 否 --> J{doc.Kind == MappingNode?}
    I --> J
    J -- 否 --> Z6[err: 必须是键值映射]
    J -- 是 --> K[seen map 收集所有 key; 重复 key → err; 未知 key → warn]
    K --> L[遍历 RequiredKeys; 缺 → err: 缺少必填字段]
    L --> M[checkStatus/checkType/checkTriggers/checkDescription/checkSourceCommit/checkSources/checkHash/checkGenerator/checkProtected]
    M --> N[BodyLine = end+2; Body = lines end+1..]
    N --> O{body 空白?}
    O -- 是 --> Z7[err: 正文为空]
    O -- 否 --> P{有 一级标题?}
    P -- 否 --> Q[warn: 正文缺少一级标题]
    P -- 是 --> R[return Page, problems]
```

**关键不变量**：

- 校验**收集所有问题**再返回（不是 fail-fast）：`problems []config.Problem` 是切片；调用方一次看完整页状态。
- `Severity` 字段区分 warning vs error：warning 由 `warnAt` 构造（[page.go:538-542](../知识层/架构设计.md)），error 由 `errAt` 构造；调用方按 `Severity == ""` 计数 errors。
- `Page` 即使有 error 也返回——持有能解析的字段，调用方按需消费。
- `Hash()`（[page.go:118-121](../知识层/架构设计.md)）只对 `Body` 计算 sha256；`HashFile`（[protection.go:16-27](../知识层/人工保护.md)）对**整文件**计算 sha256——两者口径不同；保护机制走整文件 hash 以匹配生成器记录的 `content_hash`。

## 错误与警告的输出形态

`config.Problem.String()`（[internal/config/config.go:60-76](../项目接入与配置/Schema与错误契约.md)）的格式：

```text
[warning: ]<file>[:<line>][: <field>]: <reason>
```

`Severity == SeverityWarning` 时前缀 `warning: `；否则无前缀。`Line` 是 1-based 行号，从 front matter 起点算；`blockLine`（[page.go:468-482](../知识层/架构设计.md)）从 YAML 错误消息里提取。`Field` 在以下情况为空：

- 文件整体错误（如「缺少 front matter」「正文为空」）；
- 缺陷不归单个字段（如「front matter 为空：缺少 ...」）。

`knowledge validate` 把所有 `Issues` 放进 `KnowledgeValidateView.Issues[]` 字段，按 `Errors = report.Errors()` 计错误数（影响 exit code），`Warnings = report.Warnings()` 计警告数（不影响 exit code）。`knowledge status` 的 `Scan` 步骤也会跑校验，发现错误会拒绝整个 status（`Invalidf(KindKnowledge, report.Problems, ...)`，exit 4）。

## 与 `status` 计算的关系

`Parse` 只校验**声明**的合法性；它**不**判定「该页是否当前 stale」——那是 `Evaluate`（[freshness.go:111-187](../知识层/新鲜度与基线.md)）的活。两个阶段：

| 阶段 | 入口 | 校验内容 | 失败后果 |
|---|---|---|---|
| 解析 | `Parse(path, data)` | front matter + body 形态 | errors 进 `KnowledgeValidateView.Errors`；影响 `validate` exit code 与 `status` 判定 |
| 裁决 | `Evaluate(root, pages, state)` | 内容与工作树的关系 | `affected` / `unverifiable` 进 `KnowledgeStatusView.Affected/Unverifiable`；影响 `status` exit code |

一个 stale 的页面可以有合法的 front matter（`status: stable` 与 `Evaluate` 的 `Stale: true` 并不矛盾）；一个手写的 `stale` 即使在 `Parse` 阶段就被拒（不能写），也会被 `Evaluate` 判定为 stale。

## 边界与不做的事

- **不校验 Markdown 正文语法**：`Body` 的内容是 opaque 文本；解析器不链接、不编号、不解析标题层级（只检查「有一级标题」）。
- **不强制 `sources` 必填**：生成器把 sources 写在 state 里更可靠（方案 §12.5）；页面只声明时 `Parse` 给 warning，但 `Evaluate` 在 sources 为空时**只**用 mapping，缺 mapping 才 unverifiable。
- **不做跨页一致性检查**：`triggers` 重复、同一 `dimension` 多页——这些都不在本卡范围内。
- **不支持别名映射**：`triggers` 是列表，不是 map；如需英文别名，按字符串列表追加即可。
