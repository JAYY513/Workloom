# 知识层 · 上下文快照

本卡描述 M5.6 引入的**上下文快照**（context snapshot，方案 §11.3）：每轮 prompt 装配时把 assembly 读到的版本号、知识基线、工作区 head 一起固化到 round 记录里——事后读取 round 记录就能回答「agent 当下看到了什么」。

## `prompt.Snapshot` 类型

[internal/prompt/prompt.go:58-75]：

```go
type Snapshot struct {
    ProjectStateVersion string   `json:"project_state_version,omitempty"`
    WorkitemVersion     string   `json:"workitem_version,omitempty"`
    ArtifactVersions    []string `json:"artifact_versions,omitempty"`
    KnowledgeRevision   string   `json:"knowledge_revision,omitempty"`
    KnowledgePages      []string `json:"knowledge_pages,omitempty"`
    DecisionIDs         []string `json:"decision_ids,omitempty"`
    WorkspaceHead       string   `json:"workspace_head,omitempty"`
    KnowledgeBehind     bool     `json:"knowledge_behind,omitempty"`
    KnowledgeDegraded   bool     `json:"knowledge_degraded,omitempty"`
}
```

字段语义：

| 字段 | 来源 | 何时为空 |
|---|---|---|
| `ProjectStateVersion` | `md.Project.UpdatedAt.UTC().RFC3339` | 项目元数据无 `UpdatedAt`（理论上不存在） |
| `WorkitemVersion` | `wi.Version`（64-hex） | `WorkitemGet` 未返回 Version |
| `ArtifactVersions` | `[ref.Ref for ref in wctx.Artifacts]` | 任务未关联工件 |
| `KnowledgeRevision` | `wctx.Knowledge.Baseline` | 知识层无 baseline 或层未生成 |
| `KnowledgePages` | `[ref.Path for ref in wctx.Knowledge.Pages]` | 知识页列表为空 |
| `DecisionIDs` | `[ref.Ref for ref in wctx.Decisions]` | 任务未关联决策 |
| `WorkspaceHead` | `r.Claim.HeadSHA` | run 未 claim 工作区（首轮调试 / 上下文装配） |
| `KnowledgeBehind` | `workspaceHead != knowledgeRevision` 且两者都不空 | 单边为空 |
| `KnowledgeDegraded` | `wctx.Knowledge.Degraded` | 知识层未生成 |

**字段独立**：每字段单独判空；不强制任何组合。**`Snapshot.Empty()`**（[prompt.go:51-56]）返回所有字段都「无意义」——这种快照**不**写进 round 记录，避免 json 流被无意义的 `{}` 撑大。

## `Prompt.Snapshot` 字段

`Prompt`（[prompt.go:39-49]）新增 `Snapshot Snapshot` 字段：assembled 之后序列化时一并写入 `.devsys/runs/<id>.prompt.json`。`RunPromptView.Snapshot`（[internal/app/prompt.go:44-46]）也从组装结果透传给调用方——CLI 与 MCP 客户端拿到的视图里就有 `snapshot`。

## `knowledgeSection` —— 提示词中的「知识基线」小节

[internal/prompt/prompt.go:337-348] 的 `knowledgeSection(snapshot)` 按 Snapshot 状态返回 3 态文本：

```go
func knowledgeSection(snapshot Snapshot) string {
    switch {
    case snapshot.KnowledgeDegraded:
        return "本项目尚未生成知识页面层（方案 §12.6 降级）：上下文只含记录与事件，按需查阅代码。"
    case snapshot.KnowledgeBehind:
        return fmt.Sprintf("知识基线 %s 落后于工作区 HEAD %s：本页描述的是较早的代码，涉及细节时以代码为准。",
            shortCommit(snapshot.KnowledgeRevision), shortCommit(snapshot.WorkspaceHead))
    default:
        return ""
    }
}
```

装配到 prompt 的 `[上下文引用]` 与 `[汇报协议]` 之间（[prompt.go:203-208]）；空文本时不插入该小节——保持简洁。

`shortCommit(s)` 把 commit 截到 7 hex（[prompt.go:349-354]）：`s[:7]` 或原样。

## `Service.RunPrompt` 装配

[internal/app/prompt.go:129-141] 把 wctx 转成 Snapshot：

```go
Snapshot: prompt.Snapshot{
    ProjectStateVersion: projectStateVersion(md),
    WorkitemVersion:     wi.Version,
    ArtifactVersions:    artifactVersions(wctx.Artifacts),
    KnowledgeRevision:   wctx.Knowledge.Baseline,
    KnowledgePages:      knowledgePagePaths(wctx.Knowledge.Pages),
    DecisionIDs:         decisionIDs(wctx.Decisions),
    WorkspaceHead:       r.Claim.HeadSHA,
    KnowledgeBehind:     knowledgeBehind(r.Claim.HeadSHA, wctx.Knowledge.Baseline),
    KnowledgeDegraded:   wctx.Knowledge.Degraded,
},
```

辅助函数（[internal/app/prompt.go:361-404]）：

- `projectStateVersion(md)`：把 `md.Project.UpdatedAt` 序列化为 RFC3339；
- `artifactVersions(refs)` / `decisionIDs(refs)`：list → list of refs；
- `knowledgePagePaths(pages)`：list → list of paths；
- `knowledgeBehind(workspaceHead, knowledgeRevision)`：`bool` —— 双方都不空且不等。

**注意 `KnowledgePages` 是路径列表而不是 refs**：prompt 里的「相关知识页」section 已经包含 ref/description，此处再独立存路径是为了**快照可索引**——事后能按路径快速定位 round 记录。

## `contextSnapshot` —— run.json 上的快照

[internal/app/runstream.go:56-68]：

```go
type contextSnapshot struct {
    ProjectStateVersion string   `json:"project_state_version,omitempty"`
    WorkitemVersion     string   `json:"workitem_version,omitempty"`
    ArtifactVersions    []string `json:"artifact_versions,omitempty"`
    KnowledgeRevision   string   `json:"knowledge_revision,omitempty"`
    KnowledgePages      []string `json:"knowledge_pages,omitempty"`
    DecisionIDs         []string `json:"decision_ids,omitempty"`
    WorkspaceHead       string   `json:"workspace_head,omitempty"`
    KnowledgeBehind     bool     `json:"knowledge_behind,omitempty"`
    KnowledgeDegraded   bool     `json:"knowledge_degraded,omitempty"`
}

// snapshotRecord converts a prompt snapshot for the stream; an empty snapshot
// stays absent rather than becoming an empty object.
func snapshotRecord(snapshot prompt.Snapshot) *contextSnapshot {
    if snapshot.Empty() {
        return nil
    }
    return &contextSnapshot{...}   // 逐字段复制
}
```

**为何不直接复用 `prompt.Snapshot`**：`streamRecord`（[runstream.go:24-51]）是 on-disk 契约——流记录的字段名一旦定下来就是稳定的外部 API；`prompt.Snapshot` 是 Go 内部类型，可以继续演进而受 Go 工具链保护。两者字段名一致（逐字段手动复制），但分两个类型避免「改 prompt 内字段名就破坏历史 run.json」的连带风险。

`streamRecord.Context *contextSnapshot`（[runstream.go:48-50]）—— `*` 而不是值类型：`Empty()` 时不写字段，避免 `context: {}` 这种无意义字段撑大 jsonl。
