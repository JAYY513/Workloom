# 知识层 · 人工保护

本卡描述 M5 知识层**人工保护**（`internal/knowledge/protection.go`）：当刷新想把页面交给生成器重写时，哪些页面必须被拦下来——以及「`--force` 强制覆盖」在协议层的语义。

## 两闸

`Skips`（[protection.go:57-92](../知识层/架构设计.md)）枚举候选页面，对每个返回：

| 闸 | 触发条件 | `Skip.Reason` |
|---|---|---|
| `protected: true` | `page.Protected`（front matter `protected: true` 标量） | `protected: true：页面被锁定，不重新生成` |
| 手改 | `recorded != actual`（生成器记录的 `content_hash` 与磁盘文件 hash 不一致） | `手工修改：内容哈希与记录不一致，不覆盖` |

两者互斥：先匹配 `protected`；不匹配再看 `recorded != actual`。两闸都未命中 → 该页**不**在 `Skips` 里，进 `candidates` 走生成器。

## `content_hash` 的口径

`HashFile`（[protection.go:16-27](../知识层/架构设计.md)）对**整文件**（含 front matter 与 body）计算 sha256 hex（小写）。这与生成器记录的 `content_hash` 字段对齐——参考生成器（RepoWiki）也用同样的口径。

`Page.Hash()`（[page.go:118-121](../知识层/架构设计.md)）只对 `Body` 计算 sha256——口径**不同**。理由：「`Body`」是「这次写了什么」的身份（用在生成器比对中），「整文件」是「磁盘上现在是什么」的身份（用在保护中）。本卡只关心后者。

## `Recorded` 与 `Actual`

`Skip` 结构（[protection.go:36-46](../知识层/架构设计.md)）：

```go
type Skip struct {
    Path       string `json:"path"`
    Reason     string `json:"reason"`
    Recorded   string `json:"recorded_hash,omitempty"`  // 生成器记录的 hash
    Actual     string `json:"actual_hash,omitempty"`    // 磁盘文件 hash
    Overridden bool   `json:"overridden,omitempty"`     // --force 时为 true
}
```

`Recorded` 的来源优先级：

1. 页面 front matter 的 `content_hash`（`page.ContentHash`）；
2. 若空，回退到 `state.Mapping(page.Path).ContentHash`；
3. 都空 → `Recorded == ""` → **不**视为手改（没东西可比对）→ 不进 `Skips`。

`Actual` 仅在 `Recorded != ""` 时计算——避免对「没记录过 hash」的页面白白做 hash：

```go
if recorded != "" {
    actual, err = HashFile(filepath.Join(root, filepath.FromSlash(page.Path)))
    ...
}
```

## `--force` 的覆盖语义

`Skips(root, pages, state, force bool)` 接受 `force` 参数：

- `force=false`：返回的 `Skips[]` 是**真正被排除**的页——`internal/app.KnowledgeRefresh` 把它们从 `candidates` 里剔除，剩下的才交给生成器；
- `force=true`：**所有**命中保护的页面**仍**进 `Skips`，但 `Skip.Overridden=true` 标记。生成器拿到的是完整 `candidates`（包括保护页），但报告里能看到「这次跳过了哪些 + 是被 `--force` 覆盖跳过的」。

**强制覆盖也留痕**：审计可见 `Overridden=true` 的记录——管理员主动覆盖与自动化覆盖的语义区别明确。

## 报告里的 Skipped 形态

`KnowledgeRefreshView.Skipped`（[internal/app/knowledge.go:178-180](../知识层/架构设计.md)）就是把 `Skips` 的输出原样放到 view 字段。CLI `reportRefresh` 在 `--quiet` 下**仍**打印：

```text
skipped: <path>  (<reason>)
```

理由：`Skipped` 是「这次为什么没全跑」的答案——hook 与审计靠它判定「管理员是不是真的同意覆盖」。

## 与生成器契约的边界

保护**不**拦截生成器的「写」动作——它只是**不把页面塞给生成器**。如果你绕过 `knowledge refresh` 直接调用生成器（带同样的 `--scope-file`），保护机制无从生效。`scripts/smoke-m5.sh` 的 `STUB_GENERATOR_WRITE` 演示了这种情况：绕过 `devsys`，让 stub 自己写 `docs/repowiki/knowledge/手改.md`，刷新后再 `echo "\n人工补充。" >> 手改.md`——下次 refresh 时 `content_hash` 不一致，手改保护就拦下来。

## 不保护的情况

- **没有 recorded hash 的页**（首次生成或老格式）——保护机制**主动**放行，没有东西可比对；
- **`generated: false` 的页**——不视为「机器写的」，由人拥有；`protected` 字段仍有效（手动的 lock）但 `content_hash` 校验**不**触发（页面前端没有 recorded hash）；
- **`Degraded` 状态**（无页面层）——根本没有页面可保护；`Skips` 不被调用。

## 边界与不做的事

- **不做 diff 合并**：被跳过的页面与新生成的内容**互不通信**；保护就是「不替换」。
- **不实现「自动解决冲突」**：人改了的页面如果被 `--force` 覆盖，原文就丢了——这是 `--force` 的字面语义。
- **不锁定文件**：层不把磁盘文件设成只读；保护**只**在 refresh 路径生效。
