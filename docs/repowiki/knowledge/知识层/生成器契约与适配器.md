# 知识层 · 生成器契约与适配器

本卡描述 M5 知识层**生成器契约**（`internal/knowledge/generator.go`）：层与外部生成器（首选 RepoWiki）之间的输入协议——生成器是什么、它接受哪些参数、Scope 怎么落地、为什么**不**走 shell。

## 契约形状

`Scope`（[internal/knowledge/generator.go:30-37](../知识层/架构设计.md)）：

```go
type Scope struct {
    FormatVersion int      `json:"format_version"`     // 恒 1（生成器必须按此版本解析）
    Project       string   `json:"project"`            // 项目根（绝对路径）
    Mode          string   `json:"mode"`               // "full" / "affected"
    Baseline      string   `json:"baseline,omitempty"` // state.Baseline.Commit
    Head          string   `json:"head,omitempty"`     // 当前 HEAD commit
    Pages         []string `json:"pages"`              // 需要生成的页面路径（项目内）
}
```

`FormatVersion = 1`（[generator.go:15](../知识层/架构设计.md)）是契约版本。升到 2 时 Generator 必须先读 `format_version`，不接受旧版 scope 才往下走——这是契约**唯一**的版本信号。

## argv 的拼装

`GeneratorCommand(command, scopePath, projectRoot)`（[generator.go:43-53](../知识层/架构设计.md)）：

```go
argv := strings.Fields(command)                  // 切分用户配置
return append(argv,
    "--project", projectRoot,                    // 项目根（绝对路径）
    "--scope-file", scopePath,                   // scope 文件路径（绝对路径）
    "--format-version", strconv.Itoa(FormatVersion),
), nil
```

例：用户配置 `repowiki refresh`，`projectRoot=/repo`，`scopePath=/repo/.devsys/knowledge/refresh-scope.json`：

```text
repowiki refresh --project /repo --scope-file /repo/.devsys/knowledge/refresh-scope.json --format-version 1
```

`strings.Fields` 按 ASCII 空白切分——多空白会被合并；引号包裹的字段**不**保留空白（生成器配置应避免）。理由：避免第二套 shell 解析层（cmd.exe / sh / PowerShell 各自有 quoting 规则）。

## Scope 落地文件

`ScopeFile = Dir + "/refresh-scope.json" = ".devsys/knowledge/refresh-scope.json"`（[generator.go:26](../知识层/架构设计.md)）。

`WriteScope`（[generator.go:56-65](../知识层/架构设计.md)）走 `storage.AtomicWrite`（同源 transaction 原语）：

- 序列化（`json.MarshalIndent`，缩进 2）；
- 末尾换行；
- 写文件权限 0644；
- 失败时包成 `fmt.Errorf("write %s: %w", ScopeFile, err)`。

生成器启动时**总是**先读 scope 文件——这避免了：

- 超长 Pages 列表压爆 argv；
- scope 字段后续扩展（新的 `Mode`、`FormatVersion` 子字段）不影响 argv 形状；
- scope 在刷新失败后可作为审计材料被读取。

## 不走 shell 的语义

`exec.CommandContext(ctx, argv[0], argv[1:]...)` 直接调用 CreateProcess：

- **没有 shell 展开**：环境变量、`~`、`*`、`$(...)` 都不展开；
- **没有管道/重定向**：`<`、`>`、`|` 都不解析；
- **Windows 不走 `cmd /c`**：`CreateProcess` 直接接收程序路径。

副作用：

- Linux/macOS 上脚本必须可执行（`chmod +x`）+ shebang 行（`#!/usr/bin/env bash`）；
- Windows 上**生成器必须**是 `.exe` 或 `.cmd`（**不能**直接是 `.sh`）。`scripts/smoke-m5.sh` 演示了包装：

```bash
if [[ "$(uname -s)" == MINGW* || "$(uname -s)" == MSYS* ]]; then
    cat > "$stubs/generator.cmd" <<STUB
@echo off
bash "$workspace/generator" %*
STUB
    generator_cmd="$(cygpath -m "$stubs/generator.cmd")"
else
    generator_cmd="$workspace/generator"
fi
```

`cygpath -m` 把路径转成 Windows 形式（`C:\...`），避免 YAML scalar 需要转义反斜杠。

## 生成器的输出约定

`runGenerator`（[internal/app/knowledge.go:550-581](../知识层/架构设计.md)）把 stdout 与 stderr **合并**写进 `KnowledgeRefreshView.Output`：

- `cmd.Stdout = cmd.Stderr = out`（同一 `*limitWriter`）；
- `out` 上限 `generatorOutputLimit = 256 KiB`，超过截断并追加 `\n[输出超过 %d 字节，已截断]`；
- 一个进程退出非 0 → 整个 refresh 返回 `Preconditionf("knowledge refresh: generator %q failed: %v", view.Generator, err)`（exit 3）。

生成器**应该**在 stdout 打印简洁的状态（smoke 用 `echo "stub generator ran"`）；**不应该**写大段日志——那是 `Output` 字段的带宽极限。

## 配置项 `knowledge_generator`

`config.yaml` 的 `knowledge_generator` 字段（[internal/config/config.go:104-113](../项目接入与配置/Schema与错误契约.md)）：

- 类型：字符串；
- 空：层走 `Missing` 路径（exit 11），不报错（§12.6 的 degradation）；
- 解析：白名单 `kindString`（位置字段，无多余约束）。

CLI 的 `KnowledgeRefresh`（[internal/app/knowledge.go:170-280](../知识层/架构设计.md)）在以下两种情况下返回 `Missing=true`：

- `view.Pages == 0`（层就没页面可生成）；
- 有 `candidates` 但 `Generator == ""`（有活没工具——退化）。

## 与 M6 适配器的关系

生成器契约**只**在知识层用。M6 的 `internal/harness` 暴露的 `Adapter` / `Session` 接口（[执行层 · 适配器协议契约](../执行层/适配器协议契约.md)）是另一份契约——运行 harness 适配器：

- 不是生成器——它产生 Run 的**执行**（spwan agent、读 stream）；
- 适配器协议走 stdin 投递 + JSONL 流；
- 知识层不需要 stdin/stdout JSONL 协议（生成器是 one-shot）。

唯一交叉点是 M6 的 `workspace.RunHook` 走 `harness.Shell`——那是生命周期钩子（`after_create` 等），不是生成器。

## 边界与不做的事

- **不做插件沙箱**：生成器以 devsys 子进程身份运行，能读写整个项目根——管理员责任；
- **不校验生成器签名**：M5 没有签名机制，参考实现（RepoWiki）的真实性由项目配置决定；
- **不支持多生成器并行**：单次 refresh 调一个 generator，多次 refresh 可串行；层不调度并发。
