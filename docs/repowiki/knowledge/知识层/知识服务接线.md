## `Service.knowledgeState` —— load + import + merge 三步合一

```go
func (s *Service) knowledgeState(md *config.Metadata) (*knowledge.State, string, error) {
    local, err := knowledge.LoadState(s.Root)
    if err != nil && !knowledge.MissingState(err) {
        return nil, "", Invalidf(KindKnowledge, nil, "knowledge state: %v", err)
    }
    generator := ""
    if md != nil && md.Config != nil {
        generator = strings.TrimSpace(md.Config.KnowledgeGenerator)
    }
    adapter, ok := knowledge.AdapterByName(generator)
    if !ok {
        return local, "", nil               // 没适配器：返回本地 state
    }
    imported, err := adapter.Import(s.Root)
    if err != nil {
        return nil, "", Internalf("knowledge import (%s): %v", adapter.Name(), err)
    }
    return knowledge.MergeStates(local, imported), adapter.Name(), nil
}
```

设计点：

- **三个值**：merged state + 适配器名 + err——status 视图需要适配器名（用于 Probe + AdapterInstalled），validate 不需要但拿到也不亏；
- **缺失 state 不是错误**：`knowledge.MissingState(err)` → `local = nil` → 适配器 import 后填上；
- **没适配器或拼错** → `(local, "", nil)`：本地 state 原样返回，适配器名字段留空——退回到「无 Probe」旧路径；
- **适配器 import 失败** → `Internalf("knowledge import (%s): %v", adapter.Name(), err)`：exit 1 / MCP `internal`——这是配置 + 环境的真实问题，不能退。

## `Service.generate` —— argv 与 Adapter 的合流点

`Service.generate(ctx, adapterName, configured, argv, pages, view)`（[internal/app/knowledge.go:507-524](../知识层/架构设计.md)）：

```go
if adapterName == "" {
    return s.runGenerator(ctx, argv)             // 旧路径：直接 exec argv[0]
}
adapter, ok := knowledge.AdapterByName(adapterName)
if !ok {
    return "", Usagef("knowledge_generator %q names an unknown adapter", configured)
}
result, err := adapter.Generate(ctx, knowledge.GenerateRequest{Root: s.Root, ScopeFile: view.ScopeFile, Pages: pages})
view.Finalized = result.Finalized
view.AwaitingGeneration = result.AwaitingGeneration
if result.Note != "" { view.Reason = result.Note }
return result.Output, err
```

- `adapterName == ""`：兼容老配置（只配了「一条 shell 命令」，未指名「哪个适配器」）；
- `AdapterByName` 找不到 → `Usagef` 走 CLI exit 2 / MCP `usage`，**不**静默 fallback；
- 输出继续走 256 KiB `limitWriter`——适配器的 stdout 也受同一上限保护；
- `view.Finalized` / `view.AwaitingGeneration` 写入 View——CLI `reportRefresh` 据此打印 `awaiting generation:` 行。

M5.6 把 `context get --task` / `context refresh --task` 升级为方案 §11.1 三层装配（[internal/cli/records.go:812-824](../项目接入与配置/CLI渲染与交换协议.md)）：

`splitPaths(list string) []string`（[records.go:964-972](../项目接入与配置/CLI渲染与交换协议.md)）：按 `,` 切，每项 trim，空串剔除；`--path a,,b` 与 `--path a,b` 等价。

`runContextTask(stdout, opts, svc, ctx, id, paths, limit, refresh)`（[records.go:919-961](../项目接入与配置/CLI渲染与交换协议.md)）调 `svc.TaskContext(ctx, id, paths, limit, refresh)`，按 4 行块渲染：`project:` / `task:` / 各类 ref / `notice:` / `knowledge:` 行；`[stale]` 标签贴到 `page.Stale=true` 的页。`--json` 模式直接 encode `app.TaskContext` 信封。

`context workitem --id <id> [--path a,b]`（[records.go:876-917](../项目接入与配置/CLI渲染与交换协议.md)）是单工作项视图：`--path` 把 paths 传给 `svc.ContextForWorkitem(ctx, id, paths)`——`internal/app` 用它走 `MatchSources`。`--id` 缺/空 → `errUsage` exit 2。

## 错误翻译

| 场景 | `*app.Error` | CLI exit | MCP tool |
|---|---|---|---|
| `KnowledgeStatus` git 不可用 | `Preconditionf`（exit 3） | 3 | `precondition` |
| `KnowledgeValidate` 有 errors | `Invalidf(KindKnowledge, problems, ...)`（exit 4） | 4 | `invalid` |
| `KnowledgeRefresh` 已有 holder | `Preconditionf("another refresh is already running")`（exit 3） | 3 | `precondition` |
| `KnowledgeRefresh` generator 失败 | `Preconditionf("generator %q failed: %v", ...)`（exit 3） | 3 | `precondition` |
| `KnowledgeRefresh` 没生成器 | `view.Missing = true`（exit 11 由 CLI codedExit 触发） | 11 | 工具成功，调用方按 `view.Missing` |
| `KnowledgeStatus` 页解析 error | `Invalidf(KindKnowledge, problems, ...)`（exit 4） | 4 | `invalid` |
| 未知子命令 | `errUsage`（exit 2） | 2 | `usage` |

MCP 客户端**不会**用工具返回的 `isError` 字段表示 10/11——`isError` 只表示 `*app.Error`；`KnowledgeStale` / `KnowledgeMissing` 是 `view.Status` 字段，由调用方分支。

## 边界与不做的事

- **不在 CLI 二次校验 page**：CLI 把工作交给 `app`；`pageRoots` / `checkPageRoot` / 解析都在 `internal/app` + `internal/knowledge` 完成。
- **不在 MCP 解析 prompt**：`paths` 是结构化字段；MCP 客户端用 `extractJsonOrFallback` 等 SDK 工具自己解析。
- **不在 `KnowledgeStatus` 内做变更**：status 是只读。
