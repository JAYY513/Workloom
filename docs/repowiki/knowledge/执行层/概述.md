# 执行层

本模块是 M6 里程碑的**执行层**：把 .devsys/ 中的领域记录（WorkItem/Run/Policy）与真实进程执行打通——为每一次 attempt 提供一个**适配器抽象**（Adapter）、一个**隔离执行目录**（Workspace）、一份**派发计划**（Plan）、一条**可复现的重试退避**（Delay）、一段**可复现的提示词文本**（Prompt），并在 `internal/app` 统一接线到 CLI/MCP 入口。

## 模块定位

- **做什么**：在 `internal/harness` 暴露 §9.2 的 `Adapter` 接口与 `Session` 接口（Capabilities / Availability / Workspace / Request / Command / Line / Result）+ Shell 基线适配器 + 三个 CLI 适配器（codex / opencode / claude），统一流式输出、行缓冲、stdin 投递、进程树终止与超时取消；在 `internal/workspace` 提供 Key/Path/Git/Hook + Ensure/Remove/List + RunHook（生命周期钩子通过 shell 适配器执行，保留相同流/超时/进程树语义）+ HookEnv；在 `internal/dispatch` 暴露 §4.8/§7.4 的纯函数 `Plan`（priority 降序 → created_at 升序 → id 决胜 + 状态白名单 + blocked_by + 全局/状态并发）+ `ResolveCaps`；在 `internal/retry` 给出 §15.4 的 `Delay(base, max, attempt, seed)`——指数增长 + 派生抖动（不随机、可复现）；在 `internal/prompt` 给出 `Assemble(Input)`——首轮全 brief，续轮 delta + remaining，sectioned 渲染，hash 稳定。
- **不做什么**：不写 .devsys/ 状态（由 `internal/app` 调 `storage.Store.Write`）；不实现审批/门禁/工作流策略（属 [可靠文本存储](../可靠文本存储/概述.md)）；不实现 MCP 工具族（属 [共享应用与 MCP](../共享应用与MCP/概述.md)）；不暴露 CLI 子命令（`internal/cli` 调用 `internal/app`）。

- M8.4 Contrabass 作为可选执行后端：`scripts/contrabass/export.py`（九态→六态，幂等重跑同字节） + `import.py`（保守子集回流，只调 `workloom workitem transition|comment`）；`.devsys/` 是唯一事实来源，看板卡片是投递副本——没有第二事实来源，字段名 [UNVERIFIED]，细节见 `scripts/contrabass/README.md`。

- **目录工作区**：非 Git 项目下 `Ensure` 只 `os.MkdirAll(path)` + 跑 `after_create`（失败即 `os.RemoveAll` 回退），返回 `Workspace{Key, Path}`——`Branch` 为空（[internal/workspace/workspace.go:147-177](file://internal/workspace/workspace.go#L147-L177)）；`Workspace.Branch` 的语义注释即「git worktree 有、目录工作区为空」（[internal/workspace/workspace.go:26-35](file://internal/workspace/workspace.go#L26-L35)）。分支前缀 `devsys/<key>` 与 `workloom worktree …` 命令名**均未变**。

## 本批（d07638c→9d7ed6c）：git 调用统一超时 + 汇报协议细化

本模块 scope 内只有两个文件变更（`internal/prompt/prompt.go`、`internal/workspace/git.go`），但两处都改的是**对外可见的执行语义**。

- **git 调用统一 10 秒超时**（`internal/workspace/git.go`）：新增 `const gitCommandTimeout = 10 * time.Second`（[internal/workspace/git.go:50](file://internal/workspace/git.go#L50)），`gitOutput` 从 `exec.Command` 改为 `context.WithTimeout` + `exec.CommandContext`（[internal/workspace/git.go:55-70](file://internal/workspace/git.go#L55-L70)）。**收敛点只有一个**——`GitProject` / `headSHA` / `branchSHA` / `currentBranch` / `commonDir` / `sameRepo` / `branchExists` / `addWorktree` / `removeWorktree` / `pruneWorktrees` / `deleteBranch` / `worktreeBranches` 全部经 `gitOutput` 发起，因此一次改动就让整个 workspace 包的 git 面获得上限。超时不是静默降级：`cmd.Run()` 返回错误后仍走原路径包成 `&GitError{Args, Output, Err}`，调用方看到的是带 `exec` 超时错误的 `GitError`，不会被误判成「git 不存在」（后者是 `requireGit` 的 `ErrGitMissing`，两条路径不合并）。此前挂死的 git（如网络文件系统上的 `rev-parse`、交互式 credential 提示）会无限期占住 attempt，现在上限 10 秒。
- **汇报协议的产物归属改为「主归属 + 关联」双写**（`internal/prompt/prompt.go:156`）：`artifact register` 的示例从单一 `--related` 改为 `--workitem $DEVSYS_WORKITEM` 记主归属（`workitem_id`）、已有主归属时用 `--related $DEVSYS_WORKITEM` 追加 `related_workitems`；并明确**门禁认名称，主归属或关联任一命中即算证据**。类型清单新增 `finding-report`。这与 `internal/app` 本轮新增的跟进任务能力（`followup.go`）是同一件事的两端：协议告诉 agent 产物挂在哪，app 层提供派生任务的入口。
- **汇报协议新增「发现」行**（`internal/prompt/prompt.go:157`）：发现先记录为当前 Run 的 timeline event；**需要行动时创建 follow-up work item，需要长期保留时登记 `finding-report` Artifact**——把「记录」与「行动」分开，避免 agent 把发现直接当结论用。

`protocol` 常量的行范围（154-160）与 `Assemble` 的行范围（164-229）本轮**未位移**，变更是行内字符串内容。
