# 执行层

本模块是 M6 里程碑的**执行层**：把 .devsys/ 中的领域记录（WorkItem/Run/Policy）与真实进程执行打通——为每一次 attempt 提供一个**适配器抽象**（Adapter）、一个**隔离执行目录**（Workspace）、一份**派发计划**（Plan）、一条**可复现的重试退避**（Delay）、一段**可复现的提示词文本**（Prompt），并在 `internal/app` 统一接线到 CLI/MCP 入口。

## 模块定位

- **做什么**：在 `internal/harness` 暴露 §9.2 的 `Adapter` 接口与 `Session` 接口（Capabilities / Availability / Workspace / Request / Command / Line / Result）+ Shell 基线适配器 + 三个 CLI 适配器（codex / opencode / claude），统一流式输出、行缓冲、stdin 投递、进程树终止与超时取消；在 `internal/workspace` 提供 Key/Path/Git/Hook + Ensure/Remove/List + RunHook（生命周期钩子通过 shell 适配器执行，保留相同流/超时/进程树语义）+ HookEnv；在 `internal/dispatch` 暴露 §4.8/§7.4 的纯函数 `Plan`（priority 降序 → created_at 升序 → id 决胜 + 状态白名单 + blocked_by + 全局/状态并发）+ `ResolveCaps`；在 `internal/retry` 给出 §15.4 的 `Delay(base, max, attempt, seed)`——指数增长 + 派生抖动（不随机、可复现）；在 `internal/prompt` 给出 `Assemble(Input)`——首轮全 brief，续轮 delta + remaining，sectioned 渲染，hash 稳定。
- **不做什么**：不写 .devsys/ 状态（由 `internal/app` 调 `storage.Store.Write`）；不实现审批/门禁/工作流策略（属 [可靠文本存储](../可靠文本存储/概述.md)）；不实现 MCP 工具族（属 [共享应用与 MCP](../共享应用与MCP/概述.md)）；不暴露 CLI 子命令（`internal/cli` 调用 `internal/app`）。

## 职责边界

| 子包 | 目录 | 职责 |
|---|---|---|
| Harness 适配器 | `internal/harness/` | `Adapter` / `Session` / `Capabilities` / `Availability` / `Workspace` / `Request` / `Command` / `Line` / `Result` 抽象；Shell 适配器（argv + 流式 + 进程树终止）；三个 CLI 适配器（codex / opencode / claude）；`Names()` / `ByName(name)` 注册表 |
| Workspace | `internal/workspace/` | `Key`（净化 + 哈希后缀，§4.8）；`Root` / `Validate`（路径净化与根内不变量，含 symlink 逃逸）；`Ensure` / `Remove` / `List`（工作区生命周期：Git 项目用 linked worktree，非 Git 项目用目录工作区——`GitProject` 分派，见 [internal/workspace/workspace.go:73-77](file://internal/workspace/workspace.go#L73-L77)）；`Hook` / `RunHook` / `HookEnv`（after_create/before_run/after_run/before_remove 通过 harness shell 执行） |
| 派发 | `internal/dispatch/` | 纯函数 `Plan(in Input) Report`（§4.8/§7.4 排序 + 门禁 + 并发 + blocked_by）；`ResolveCaps(policies []Caps) Caps`（最严合并 + 缺失即默认 1）；常量 `DefaultGlobalCap = 1` |
| 重试退避 | `internal/retry/` | `Delay(base, max, attempt, seed)` 指数 + 派生抖动（jitter 取 seed+attempt 派生 ≤ 20% × delay，clamp 至 max）；常量 `DefaultBase = 30s` / `DefaultMax = 1h` / `DefaultStallThreshold = 30m` |
| 提示词组装 | `internal/prompt/` | `Assemble(in Input) (Prompt, error)` 首轮全 brief / 续轮 delta + remaining；首轮无挂载工作流策略时写入 `noPolicyBody` 兜底文案、`len(Remaining)>0` 时附加「工作流步骤」section；`Prompt.Text` + `Hash` + `Refs`；常量 `protocol` 报告契约（workloom CLI/MCP 路径统一，含 `--by` / `workitem block` / `approval request`，见 [internal/prompt/prompt.go:154-160](file://internal/prompt/prompt.go#L154-L160)） |

五个子包**全部纯函数 / 纯执行**——`internal/harness` 不知道 .devsys/、Run、事件；`internal/workspace` 不知道 WorkItem 状态机；`internal/dispatch` 不写不发起；`internal/retry` 无状态；`internal/prompt` 无副作用。**接线由 `internal/app`** 完成：Service 把 plan → claim → workspace → spawn → prompt → stream → finish 串成一次 attempt，再把每一步落到 storage 与事件流。

**M8 新增**：
- M8.2 `internal/app.Dispatch` tick 顶端 `mergeConflict(root)` 门控（`PorcelainStatus` 找 unmerged 路径 + `MergeHeads` 找未完成 merge，recover 前 + dry-run 同门，blocked 走 exit 3 precondition；探针失败降级为 notice，不伪装为 conflict）。
- M8.4 Contrabass 作为可选执行后端：`scripts/contrabass/export.py`（九态→六态，幂等重跑同字节） + `import.py`（保守子集回流，只调 `workloom workitem transition|comment`）；`.devsys/` 是唯一事实来源，看板卡片是投递副本——没有第二事实来源，字段名 [UNVERIFIED]，细节见 `scripts/contrabass/README.md`。

## 本批（v0.1.9，ca58d27→19b9149）：Git 可选能力 + 主命令改名

- **Git 从入场券改为可选能力**（`cc5de1f`）：`Ensure` 顶层不再 `requireGit`，改为按 `GitProject(opts.ProjectRoot)` 分派 `ensureWorktree` / `ensureDirectory`（[internal/workspace/workspace.go:73-77](file://internal/workspace/workspace.go#L73-L77)）。`GitProject` = git 在 PATH 且 `git rev-parse --is-inside-work-tree` 为 true（[internal/workspace/git.go:38-46](file://internal/workspace/git.go#L38-L46)）。
- **目录工作区**：非 Git 项目下 `Ensure` 只 `os.MkdirAll(path)` + 跑 `after_create`（失败即 `os.RemoveAll` 回退），返回 `Workspace{Key, Path}`——`Branch` 为空（[internal/workspace/workspace.go:147-177](file://internal/workspace/workspace.go#L147-L177)）；`Workspace.Branch` 的语义注释即「git worktree 有、目录工作区为空」（[internal/workspace/workspace.go:26-35](file://internal/workspace/workspace.go#L26-L35)）。分支前缀 `devsys/<key>` 与 `workloom worktree …` 命令名**均未变**。
- **完成校验新增 `Skipped`**：`CompletionCheck` 增 `Skipped bool` + reason `git completion check is not applicable`（[internal/app/runverify.go:15-55](file://internal/app/runverify.go#L15-L55)）；`RunFinish` 把 `check.Skipped` 与 `check.Advanced` / `req.Force` 并列放行（[internal/app/run.go:317-347](file://internal/app/run.go#L317-L347)），事件类型仍是 `run_finished`、verdict 为 `git check not applicable`（[internal/app/run.go:358-376](file://internal/app/run.go#L358-L376)）——**跳过不等于验证通过**，`Advanced` 记录为 false。
- **主命令改名**：shell 适配器 stdin 写失败的行文本前缀改为 `workloom:`（[internal/harness/shell.go:173-178](file://internal/harness/shell.go#L173-L178)）；round prompt 的 `protocol` 常量全部改用 `workloom ...` 命令（[internal/prompt/prompt.go:151-160](file://internal/prompt/prompt.go#L151-L160)），续轮「沿用首轮协议」同样改为 `workloom run update` / `workloom run complete`（[internal/prompt/prompt.go:214](file://internal/prompt/prompt.go#L214)）。
