# 执行层 · 特殊配置与命令

本卡描述执行层落到 CLI / config / 脚本的全部入口。所有写命令都要求 `--actor` 与 `--reason`（审计事件）；attempt 级操作额外要求 `--expect <64-hex>`（来自 `run get` 的 `version` 字段）。

## 配置文件：`config.yaml` 新增字段

```yaml
schema_version: 1
workspace_root: /var/workloom/workspaces    # 可选；默认 <project>/.devsys/workspaces
dispatch_command: "devsys run exec --id {run_id} --actor dispatch --reason tick"  # 可选；M6.4 默认；M6.7 后由 harness 取代
```

| 字段 | 类型 | 必填？ | 默认 | 备注 |
|---|---|---|---|---|
| `workspace_root` | `string` | 否 | `<project>/.devsys/workspaces` | 绝对路径或相对项目根；存在但不是目录 → 拒绝（exit 3） |
| `dispatch_command` | `string` | 否 | 见上文 | 每个 attempt 的 argv 模板；M6.7 起由 per-workitem `assigned_harness` 取代 |

变更点：

- 字段加入 `internal/config/currentFields` 白名单（[internal/config/validate.go:60-66](file://internal/config/validate.go#L60-L66)）。
- `internal/config.config` struct 增 `WorkspaceRoot` / `DispatchCommand`（[internal/config/config.go:85-92](file://internal/config/config.go#L85-L92)）。
- `init` 在写 `config.yaml` 时不主动写这两个字段（占位文件保持 `schema_version: 1` 唯一键）；用户按需追加。

## `HookEnv`（[internal/workspace/workspace.go:319-334](file://internal/workspace/workspace.go#L319-L334)）

工作区钩子与 attempt 通过 `harness.HookEnv(projectRoot, workspacePath, branch, identifier, hookName)` 拿到环境：

| 变量 | 含义 |
|---|---|
| `DEVSYS_PROJECT_ROOT` | 项目根（= agent 报告目标，避免写入 worktree 自带的 `.devsys/`） |
| `DEVSYS_WORKSPACE` | 当前 worktree 路径 |
| `DEVSYS_WORKSPACE_BRANCH` | `devsys/<key>` 分支名 |
| `DEVSYS_WORKSPACE_IDENTIFIER` | 工作项标识符 |

## CLI 命令族

### `devsys worktree`

工作区生命周期：

```sh
# 创建（idempotent：存在即复用，不重跑 after_create）
bin/devsys.exe worktree prepare --workitem WLM-1 \
    --actor me --reason "start dispatch" [--run run-id] [--branch devsys/my-key]

# 列出（read-only）
bin/devsys.exe worktree list [--workitem WLM-1]

# 删除（before_remove 失败仅记录）
bin/devsys.exe worktree remove --workitem WLM-1 --actor me --reason cleanup [--force]
bin/devsys.exe worktree remove --path /abs/path --actor me --reason cleanup [--force]
```

- `prepare` 把 worktree 路径写到 run 记录（在 `--run` 给出时），并把当前分支 head 记为 `claim_head`——这是 `run verify` 的对照点。
- `remove --path` 强制走 `internal/workspace.Validate(root, path)`——越界路径 exit 3（`smoke-m6` 第一段 PASS）。
- `--force` 用于丢弃工作区本地修改（git worktree `remove --force`）。

### `devsys dispatch`

一次调度 tick（§4.8）：

```sh
# 一次性 tick（默认）
bin/devsys.exe dispatch --once --actor ops --reason tick

# 循环（Ctrl-C 退出 0）
bin/devsys.exe dispatch --watch --interval 30s --actor ops --reason tick

# 预览：不 recover / 不 claim / 不启动；只打印 plan
bin/devsys.exe dispatch --dry-run --actor ops --reason preview

# 限制本 tick 启动数
bin/devsys.exe dispatch --once --max 2 --actor ops --reason tick
```

- tick 顺序：recover（事务恢复）→ sweep（失败/超时/停滞 attempt 收尾）→ plan → claim → prepare workspace → spawn → mark running。
- 每步都有 notice 写入；一次 broken candidate 不阻塞队列。
- `--dry-run` 必须**不**创建任何 `.devsys/runs/*.yaml`（`smoke-m6` 第 3 段 PASS）。
- 本层与 `internal/app`/`internal/cli` 交界处的 `--latest`（CAS 重读 / 与 `--expect` 互斥）与并发冲突提示在 `run exec|prompt|complete|fail|cancel` 上落地，细节见 [共享应用与 MCP](../共享应用与MCP/概述.md)。

### `devsys run exec`

启动一次 attempt：

```sh
# 任意命令（Shell 适配器）
bin/devsys.exe run exec --id run-... --actor me --reason "smoke test" -- -- sh -c "echo hi"

# Harness 适配器（assigned harness）
bin/devsys.exe run exec --id run-... --harness codex --model gpt-5 \
    --actor ops --reason "acceptance" --timeout 120s
```

- `--harness ∈ {shell, codex, opencode, claude}`：未声明时按 shell 跑 `--` 后的命令；声明后 `Request.Harness` / `Request.Model` 进入适配器，shell 路径被拒绝。
- `--timeout` 终止**整棵进程树**（POSIX 进程组 / Windows Job）。
- 输出经 sink 镜像到 stdout/stderr；`--json` 模式 sink 全部进 stderr，stdout 只携带 envelope。
- Ctrl-C 取消 attempt（`signal.NotifyContext`）——不会留下孤儿进程。

### `devsys run prompt`

提示词组装预览（不发起 attempt）：

```sh
bin/devsys.exe run prompt --id run-... [--round N] [--write]
```

- `--round` 默认取下一个 round；0 = 由 `app.nextRound` 从 run 事件流推断。
- `--write` 把文本落到 `.devsys/local/runs/<id>/round-<N>.md`（不提交、可重建）。
- `--json` 输出 `{Round, Mode, Hash, Text, Refs, Path?}`；`Hash` 是 sha256(text)，可用于离线复算。
- 续轮（Round>1）只含 `# 任务`（任务行）+ `# 上一轮以来的变化` + `# 未完成项` + `# 汇报协议`（沿用首轮协议缩略版）；首轮无挂载策略时 `# 工作流策略正文` 渲染 `noPolicyBody` 中文兜底文案（[internal/prompt/prompt.go:149](file://internal/prompt/prompt.go#L149)），hash 仍按 [internal/prompt/prompt.go:164-229](file://internal/prompt/prompt.go#L164-L229) 既定规则产出。

### `devsys run verify`

完成校验（只读）：

```sh
bin/devsys.exe run verify --id run-...
# advanced | not advanced [+ reason]
```

- 比较 `claim_head`（claim 时记录的分支 head）与 `current_head`（`git rev-parse refs/heads/<branch>`）。
- 任一项缺失 → `Advanced=false` + reason（"no claim head" / "no workspace" / git 失败原因）。
- 失败时不修改任何状态；CLI 退出码 0。

### `devsys run complete | fail | cancel`

完成一次 attempt：

```sh
bin/devsys.exe run complete --id run-... --actor me --reason "acceptance" \
    [--expect <hash>] [--note "evidence"] [--force --by reviewer]

bin/devsys.exe run fail --id run-... --actor me --reason "tests failed" \
    [--expect <hash>] [--note "exit 9"]

bin/devsys.exe run cancel --id run-... --actor me --reason "stop" \
    [--expect <hash>]
```

- `complete` 默认走 `RunVerify` 守卫：未 advance → exit 4 + "cannot be marked succeeded" + run 进 `failed`、`workitem` 进 `review`（`smoke-m6` 第 5 段 PASS）。
- `--force --by <reviewer>` 让 reviewer 接受 verify 拒绝的 attempt（仅 `complete`）。
- `fail` / `cancel` 不走 verify；它们写终态 + reason/note 到 run 记录。
- 终态（succeeded/failed/canceled/timeout/stalled）再次 finish → exit 4（不让两个 actor 都声称结果）。

## MCP 工具族

```text
run_list / run_get / run_log / run_create / run_update / run_heartbeat
run_prompt                  # Session profile
run_exec                    # Executor profile
run_verify                  # Session profile（只读）
run_complete / run_fail / run_cancel   # Executor profile
```

- `run_prompt` / `run_verify` 是 `Session` profile（agent 可读），与 §15.5「读路径与写路径分 profile」一致。
- `run_exec` 与 `run_complete / run_fail / run_cancel` 是 `Executor` profile（仅 dispatch / reviewer 可写）。
- 错误通过 `toolError{Code, Message, Problems, Notice}` 翻译——`complete` 在 verify 拒绝时 `Notice="completion check refused; routed to review"`。

## 端到端验证

`scripts/smoke-m6.{sh,ps1}`（与 M1–M5 同款）覆盖九段：

```sh
bash scripts/smoke-m6.sh --keep
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke-m6.ps1 -Keep
```

1. **Workspace invariants**：`worktree list` 空状态；越界 `worktree remove --path` 被拒绝。
2. **Dispatch tick（cap 1, ordered）**：高优先级先起、第二个被 cap 阻塞；二次 tick `in flight: 1` 不重复起；`--dry-run` 不创建 run。
3. **Harness adapter chain（stub codex）**：走 stdin 投递 + 工作区 cwd + 提交 → `run verify` advanced → `run complete` succeeded。
4. **Completion check refuses**：`run complete` 验证未 advance → exit 4 + workitem 进 review；`--force --by reviewer` 接受。
5. **Retry sweep**：失败的 attempt 被 sweep → `retry_queued`。
6. **Unavailable harness**：`run exec --harness claude`（未安装）→ exit 3。
7. **Read-only commands never dispatch**：`next` / `doctor` / `project status` 不创建任何 `.devsys/runs/*.yaml`。
8. **§17 SPEC 一致性自检**（[docs/M6-一致性自检.md](../../../docs/M6-一致性自检.md)）：每条都有证据与通过/替换/偏离/不适用结论。
9. **真实集成画像**：codex / opencode 各启动一次（命令行被接受、JSONL 入流）；后端不可用如实记录；确定性链路用 stub harness 覆盖。
