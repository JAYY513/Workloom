# 执行层 · 特殊配置与命令

本卡描述执行层落到 CLI / config / 脚本的全部入口。所有写命令都要求 `--actor` 与 `--reason`（审计事件）；attempt 级操作额外要求 `--expect <64-hex>`（来自 `run get` 的 `version` 字段）。

## 配置文件：`config.yaml` 新增字段

```yaml
schema_version: 1
workspace_root: /var/workloom/workspaces    # 可选；默认 <project>/.devsys/workspaces
dispatch_command: "workloom run exec --id {run_id} --actor dispatch --reason tick"  # 可选；M6.4 默认；M6.7 后由 harness 取代
```

| 字段 | 类型 | 必填？ | 默认 | 备注 |
|---|---|---|---|---|
| `workspace_root` | `string` | 否 | `<project>/.devsys/workspaces` | 绝对路径或相对项目根；存在但不是目录 → 拒绝（exit 3） |
| `dispatch_command` | `string` | 否 | 见上文 | 每个 attempt 的 argv 模板；M6.7 起由 per-workitem `assigned_harness` 取代 |

## `HookEnv`（[internal/workspace/workspace.go:354-370](file://internal/workspace/workspace.go#L354-L370)）

工作区钩子与 attempt 通过 `workspace.HookEnv(projectRoot, workspacePath, branch, identifier, hookName)` 拿到环境：

| 变量 | 含义 |
|---|---|
| `DEVSYS_PROJECT_ROOT` | 项目根（= agent 报告目标，避免写入 workspace 自带的 `.devsys/`） |
| `DEVSYS_WORKSPACE` | 当前 workspace 路径（git worktree 或目录工作区） |

## CLI 命令族

### `workloom worktree`

工作区生命周期：

```sh
# 创建（idempotent：存在即复用，不重跑 after_create）
bin/workloom.exe worktree prepare --workitem WLM-1 \
    --actor me --reason "start dispatch" [--run run-id] [--branch devsys/my-key]

# 列出（read-only）
bin/workloom.exe worktree list [--workitem WLM-1]

# 删除（before_remove 失败仅记录）
bin/workloom.exe worktree remove --workitem WLM-1 --actor me --reason cleanup [--force]
bin/workloom.exe worktree remove --path /abs/path --actor me --reason cleanup [--force]
```

- `prepare` 把工作区路径写到 run 记录（在 `--run` 给出时）：Git 项目下同时把当前分支 head 记为 `claim_head`（`run verify` 的对照点）；**目录工作区没有分支也没有 HEAD**，记录的是空 claim head，而不是编一个（[internal/app/workspace.go:111-136](file://internal/app/workspace.go#L111-L136)）。
- `remove --path` 强制走 `internal/workspace.Validate(root, path)`——越界路径 exit 3（`smoke-m6` 第一段 PASS）。
- `--force` 只在 Git 项目里有意义：丢弃 worktree 本地修改（`git worktree remove --force`）；非 Git 目录工作区直接 `os.RemoveAll`，不需要 `--force`（[internal/workspace/workspace.go:288-303](file://internal/workspace/workspace.go#L288-L303)）。
- `list` 对目录工作区只列 key + 路径：`Registered` / 分支列只在 Git 项目里有值（[internal/workspace/workspace.go:316-351](file://internal/workspace/workspace.go#L316-L351)）。

### `workloom dispatch`

一次调度 tick（§4.8）：

```sh
# 一次性 tick（默认）
bin/workloom.exe dispatch --once --actor ops --reason tick

# 循环（Ctrl-C 退出 0）
bin/workloom.exe dispatch --watch --interval 30s --actor ops --reason tick

# 预览：不 recover / 不 claim / 不启动；只打印 plan
bin/workloom.exe dispatch --dry-run --actor ops --reason preview

# 限制本 tick 启动数
bin/workloom.exe dispatch --once --max 2 --actor ops --reason tick
```

- tick 顺序：recover（事务恢复）→ sweep（失败/超时/停滞 attempt 收尾）→ plan → claim → prepare workspace → spawn → mark running。
- 每步都有 notice 写入；一次 broken candidate 不阻塞队列。
- `--dry-run` 必须**不**创建任何 `.devsys/runs/*.yaml`（`smoke-m6` 第 3 段 PASS）。
- 本层与 `internal/app`/`internal/cli` 交界处的 `--latest`（CAS 重读 / 与 `--expect` 互斥）与并发冲突提示在 `run exec|prompt|complete|fail|cancel` 上落地，细节见 [共享应用与 MCP](../共享应用与MCP/概述.md)。

### `workloom run exec`

启动一次 attempt：

```sh
# 任意命令（Shell 适配器）
bin/workloom.exe run exec --id run-... --actor me --reason "smoke test" -- -- sh -c "echo hi"

# Harness 适配器（assigned harness）
bin/workloom.exe run exec --id run-... --harness codex --model gpt-5 \
    --actor ops --reason "acceptance" --timeout 120s
```

- `--harness ∈ {shell, codex, opencode, claude}`：未声明时按 shell 跑 `--` 后的命令；声明后 `RunExecRequest.Harness`（及 `--model`）被翻译进 `harness.Request{Model, Prompt}`，显式传 `--harness shell` 反而被拒（`the shell adapter runs an explicit command: pass one after --, or set dispatch_command for dispatched attempts`）。
- `--timeout` 终止**整棵进程树**（POSIX 进程组 / Windows `taskkill /T /F /PID`）。
- 输出经 sink 镜像到 stdout/stderr；`--json` 模式 sink 全部进 stderr，stdout 只携带 envelope。
- Ctrl-C 取消 attempt（`signal.NotifyContext`）——不会留下孤儿进程。

### `workloom run prompt`

提示词组装预览（不发起 attempt）：

```sh
bin/workloom.exe run prompt --id run-... [--round N] [--write]
```

- `--round` 默认取下一个 round；0 = 由 `app.nextRound` 从 run 事件流推断。
- `--write` 把文本落到 `.devsys/local/runs/<id>/round-<N>.md`（不提交、可重建）。
- `--json` 输出 `{Round, Mode, Hash, Text, Refs, Path?}`；`Hash` 是 sha256(text)，可用于离线复算。
- 续轮（Round>1）只含 `# 任务`（任务行）+ `# 上一轮以来的变化` + `# 未完成项` + `# 汇报协议`（沿用首轮协议缩略版）；首轮无挂载策略时 `# 工作流策略正文` 渲染 `noPolicyBody` 中文兜底文案（[internal/prompt/prompt.go:149](file://internal/prompt/prompt.go#L149)），hash 仍按 [internal/prompt/prompt.go:164-229](file://internal/prompt/prompt.go#L164-L229) 既定规则产出。

### `workloom run verify`

完成校验（只读）：

```sh
bin/workloom.exe run verify --id run-...
# advanced | not advanced [+ reason]
```

- Git 项目 + 已绑定 worktree：比较 `claim_head`（claim 时记录的分支 head）与 `current_head`（`workspace.BranchSHA(path, branch)`）。
- 非 Git 项目或目录工作区：**跳过** Git 校验——`Skipped=true`、`Reason="git completion check is not applicable"`，`Advanced` 保持 false（[internal/app/runverify.go:45-55](file://internal/app/runverify.go#L45-L55)）。人类输出仍是 `not advanced` + `reason: git completion check is not applicable`（[internal/cli/records.go:707-724](file://internal/cli/records.go#L707-L724)），`--json` 里多一个 `"skipped": true`。
- git-bound 路径上任一项缺失 → `Advanced=false` + reason（`the attempt has no claim head…` / `the attempt has no workspace…` / git 失败原因）（[internal/app/runverify.go:56-79](file://internal/app/runverify.go#L56-L79)）。
- 失败或跳过都不修改任何状态；CLI 退出码 0。

### `workloom run complete | fail | cancel`

完成一次 attempt：

```sh
bin/workloom.exe run complete --id run-... --actor me --reason "acceptance" \
    [--expect <hash>] [--note "evidence"] [--force --by reviewer]

bin/workloom.exe run fail --id run-... --actor me --reason "tests failed" \
    [--expect <hash>] [--note "exit 9"]

bin/workloom.exe run cancel --id run-... --actor me --reason "stop" \
    [--expect <hash>]
```

- `complete` 默认走 `RunVerify` 守卫：**git-bound worktree** 上未 advance → exit 4 + `run … cannot be marked succeeded: …` + run 进 `failed`、`workitem` 进 `review`（`smoke-m6` 第 5 段 PASS）；**非 Git 项目 / 目录工作区**上 `check.Skipped` 与 `advanced`、`--force` 并列放行——不报错、不路由 review，事件类型仍是 `run_finished`、verdict 写 `git check not applicable`（[internal/app/run.go:317-376](file://internal/app/run.go#L317-L376)）。
- `--force --by <reviewer>` 让 reviewer 接受 verify 拒绝的 attempt（仅 `complete`）；skip 路径不需要它，跳过时 `Verification.Advanced` 被写为 `false`（skip 不是 verified）。
- `fail` / `cancel` 不走 verify；它们写终态 + reason/note 到 run 记录。
- 终态（succeeded/failed/canceled/timeout/stalled）再次 finish → exit 4（不让两个 actor 都声称结果）。

## MCP 工具族

`internal/mcp/tools.go` 的 spec 表里 run 家族只有**记录面**（[internal/mcp/tools.go:94-103](file://internal/mcp/tools.go#L94-L103)）：

```text
run_list / run_get / run_log          # Session profile
run_create / run_update / run_heartbeat  # Executor profile
run_verify                            # Session profile（只读，TierCore）
run_complete                          # Executor profile（TierCore）
run_fail / run_cancel                 # Executor profile
```

- 读路径（`run_list` / `run_get` / `run_log` / `run_verify`）是 `Session` profile，写路径（`run_create` / `run_update` / `run_heartbeat` / `run_complete` / `run_fail` / `run_cancel`）是 `Executor` profile，与 §15.5「读路径与写路径分 profile」一致。
- **没有** `run_exec` / `run_prompt` 这两个 MCP 工具：真正启动 attempt 与预览提示词是 CLI 侧 `workloom run exec` / `workloom run prompt`（`internal/app.RunExec` / `RunPrompt`）。
- 错误通过 `toolError{Code, Message, Problems, Notice}` 翻译（[internal/mcp/tools.go:120-128](file://internal/mcp/tools.go#L120-L128)）；`run_complete` 被 completion check 拒绝时拿到的是同一条 `Message`——`run <id> cannot be marked succeeded: <reason> (claim head …, current head …); …`，工具描述本身写明「without an advance it is refused and the work item goes to review — pass force with by to accept it as a reviewer」（[internal/mcp/tools_run.go:182](file://internal/mcp/tools_run.go#L182)）。

## 端到端验证

`scripts/smoke-m6.{sh,ps1}`（与 M1–M5 同款）覆盖九段：

```sh
bash scripts/smoke-m6.sh --keep
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke-m6.ps1 -Keep
```

1. **Workspace invariants**：`worktree list` 空状态；越界 `worktree remove --path` 被拒绝。
2. **Dispatch tick（cap 1, ordered）**：高优先级先起、第二个被 cap 阻塞；二次 tick `in flight: 1` 不重复起；`--dry-run` 不创建 run。
3. **Harness adapter chain（stub codex）**：走 stdin 投递 + 工作区 cwd + 提交 → `run verify` advanced → `run complete` succeeded。
4. **Completion check refuses**：`run complete` 验证未 advance → exit 4 + workitem 进 review；`--force --by reviewer` 接受。
5. **Retry sweep**：失败的 attempt 被 sweep → `retry_queued`。
6. **Unavailable harness**：`run exec --harness claude`（未安装）→ exit 3。
7. **Read-only commands never dispatch**：`next` / `doctor` / `project status` 不创建任何 `.devsys/runs/*.yaml`。
8. **§17 SPEC 一致性自检**：每条都有证据与通过/替换/偏离/不适用结论（原文档 docs/M6-一致性自检.md 已移出 HEAD，见 git 历史）。
9. **真实集成画像**：codex / opencode 各启动一次（命令行被接受、JSONL 入流）；后端不可用如实记录；确定性链路用 stub harness 覆盖。
