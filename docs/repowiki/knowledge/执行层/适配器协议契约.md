# 适配器协议契约

`internal/harness` 的导出类型与方法是 §9.2/§9.3 适配器契约的 Go 形态。CLI 与 MCP 入口都通过 `internal/app.RunExec` 调它；任何新 harness 必须实现下列接口并经 `Names()` / `ByName` 注册。

## 类型总览（[internal/harness/harness.go](file://internal/harness/harness.go)）

```go
type Capabilities struct {
    NonInteractive bool `json:"supports_non_interactive"`
    JSONOutput     bool `json:"supports_json_output"`
    SessionResume  bool `json:"supports_session_resume"`
    MCP            bool `json:"supports_mcp"`
    Worktree       bool `json:"supports_worktree"`
    Streaming      bool `json:"supports_streaming"`
    ModelSelection bool `json:"supports_model_selection"`
    Approval       bool `json:"supports_approval"`
}

type Availability struct {
    Installed bool   `json:"installed"`
    Version   string `json:"version,omitempty"`
    Detail    string `json:"detail,omitempty"`
}

type Workspace struct {
    Path     string `json:"path"`
    Branch   string `json:"branch,omitempty"`   // 目录工作区为空
    Worktree string `json:"worktree,omitempty"` // 工作区 key
}

type Request struct {
    Command   []string      // shell 路径的整段 argv；harness 路径留空
    Dir       string        // 执行目录（= 工作区路径）
    Env       []string      // 叠加在 os.Environ() 之上
    Timeout   time.Duration // 0 = 不限时
    Stdin     []byte        // 投递到子进程 stdin 的 payload
    Prompt    string        // harness 请求：本轮提示词全文（codex/claude 走 stdin）
    Model     string        // 拼进各自 argv 的 model 参数
    SessionID string        // 续 session（codex resume / opencode --session / claude --resume）
}

type Command struct {
    Argv    []string
    Dir     string
    Env     []string
    Timeout time.Duration
    Stdin   []byte
}

type Line struct {
    Stream string // "stdout" | "stderr"
    Text   string // 无行终止符（CRLF 的 CR 已剥）
    Time   time.Time
}

type Result struct {
    ExitCode  int       // -1 = killed by signal / never started
    TimedOut  bool
    Canceled  bool
    StartedAt time.Time
    EndedAt   time.Time
    Err       string    // 非空 = spawn/wait 失败；spawn 失败是 error，见 Start 契约
}

func (r Result) Duration() time.Duration { return r.EndedAt.Sub(r.StartedAt) }

type Session interface {
    Lines() <-chan Line
    Wait(ctx context.Context) (Result, error)
    Stop(ctx context.Context) error
}

type Adapter interface {
    Name() string
    Probe(ctx context.Context) (Availability, error)
    Capabilities() Capabilities
    Prepare(ctx context.Context, ws Workspace) error
    Command(req Request) (Command, error)
    Start(ctx context.Context, cmd Command) (Session, error)
}
```

## Shell 适配器（[internal/harness/shell.go](file://internal/harness/shell.go)）

最小、最通用、所有 CLI 适配器的委托对象。

```go
type Shell struct{}

func NewShell() *Shell { return &Shell{} }

func (s *Shell) Name() string { return "shell" }
func (s *Shell) Capabilities() Capabilities { return Capabilities{NonInteractive: true, Streaming: true, Worktree: true} }

// Probe：总是 Installed=true（argv 直通不依赖 shell）；Detail 报告宿主
// goos 与 hint，Version 是 sh/cmd 的解析路径。
func (s *Shell) Probe(ctx context.Context) (Availability, error) { … }

// Prepare：ws.Path 必填、存在且为目录；根内不变量由 workspace.Validate 在更外层保证。
func (s *Shell) Prepare(ctx context.Context, ws Workspace) error { … }

// Command：校验 req.Command 非空、Dir 存在且为目录（缺省取 os.Getwd），
// 拷贝 argv/Env/Stdin 冻结成 Command（适配器内不调 workspace.Validate）。
func (s *Shell) Command(req Request) (Command, error) { … }

// Start：spawn → 行级流 → stdin 投递 → 进程树终止在 kill()。
func (s *Shell) Start(ctx context.Context, cmd Command) (Session, error) { … }
```

- **Constants**：`lineBuffer = 64 << 10`（64 KiB chunk），`waitDelay = 2 * time.Second`（进程退出后 os/exec 再等 2s 让流关闭，避免继承流的下游进程把 attempt 挂住）。
- **`feedStdin(pipe, payload, sess)`**：单独 goroutine 写 stdin 并 `Close()`；写失败**不是** spawn 错误，而是往 stderr 流发一行 `workloom: stdin write failed: <err>`（[internal/harness/shell.go:170-178](file://internal/harness/shell.go#L170-L178)）。
- **`shellSession`**：持有 `lines chan Line`（buffer=256）、`discard chan struct{}`、`stopOnce sync.Once`、`proc *exec.Cmd`、`timer *time.Timer`、`res Result`、`timedOut` / `canceled`。
- **`lineWriter`**：把字节流切成 `Line{Stream, Text}`；`\n` 切行、行尾 `\r` 剥掉；超长行按 rune 边界切 chunk（`incompleteTail` 决定切点）；UTF-8 安全。
- **输出不经 pipe 手读**：`proc.Stdout` / `proc.Stderr` 直接挂 `&lineWriter{}`，复制交给 os/exec，`Wait` 返回时两路流已 drain（[internal/harness/shell.go:130-137](file://internal/harness/shell.go#L130-L137)）。

## 三种 CLI 适配器（[internal/harness/cli.go](file://internal/harness/cli.go)）

```go
type cliAdapter struct {
    name  string
    bin   string   // argv[0]：codex / opencode / claude
    caps  Capabilities
    build func(req Request) (argv []string, stdin []byte, err error)
    shell *Shell
}
```

三种实现（argv 均为 **bin 之后的参数**；`cliAdapter.Command` 把 `bin` 前置，见 [internal/harness/cli.go:57-69](file://internal/harness/cli.go#L57-L69)）：

| Harness | `Name()` / `bin` | `Capabilities` | 参数形态 | stdin |
|---|---|---|---|---|
| `Codex()` | `"codex"` | 八项全 true（`NonInteractive` / `JSONOutput` / `SessionResume` / `MCP` / `Worktree` / `Streaming` / `ModelSelection` / `Approval`） | `exec --json -s workspace-write -C <dir>` + 可选 `-m <model>` + `resume <session>`（有 session）或 `-`（无 session） | **prompt → stdin**（`-` 分支） |
| `OpenCode()` | `"opencode"` | `NonInteractive` / `JSONOutput` / `SessionResume` / `Worktree` / `Streaming` / `ModelSelection`（**无** `MCP` / `Approval`） | `run --format json --dir <dir>` + 可选 `-m <model>` + 可选 `--session <id>` + prompt 作为**最后一个 positional** | **无 stdin**（文档化的 argv 长度限制） |
| `ClaudeCode()` | `"claude"` | 同 OpenCode 六项 | `-p --output-format stream-json --dangerously-skip-permissions` + 可选 `--model <m>` + 可选 `--resume <id>` | **prompt → stdin**（`-p`） |

三种都要求 `req.Prompt` 非空，否则 `build` 返回 error（`codex needs a prompt` / `opencode needs a prompt` / `claude needs a prompt`）。

构造器签名：

```go
func Codex() Adapter       // = &cliAdapter{name: "codex",  bin: "codex",  caps: …, shell: NewShell(), build: codexArgs}
func OpenCode() Adapter    // = &cliAdapter{name: "opencode", bin: "opencode", …}
func ClaudeCode() Adapter  // = &cliAdapter{name: "claude",  bin: "claude",  …}
```

`Codex` / `ClaudeCode` 走 stdin——`build` 返回 argv 与 stdin payload；`OpenCode` 没有 stdin 入口，prompt 必须是 positional 参数，超出 argv 长度限制时 caller 负责截短。

`Acceptance run` 的关键回归：argv 必须包含 binary 名 `codex` / `opencode` / `claude`——M6.7 早期版本曾漏写，attempt 跑成 `exec ...` 而非 `codex exec ...`（[internal/harness/cli.go:57-59](file://internal/harness/cli.go#L57-L59)）。

## Probe 契约

```go
const probeTimeout = 10 * time.Second   // internal/harness/cli.go:12-14

func (a *cliAdapter) Probe(ctx context.Context) (Availability, error) {
    // 1) exec.LookPath(a.bin)：不在 PATH → Availability{Installed:false, Detail:"<bin> is not on PATH"} + nil error
    // 2) exec.CommandContext(ctx, path, "--version").Output()（10s 超时）
    //    成功 → Installed:true, Version: 输出的 trim 结果, Detail: 解析到的路径
    //    失败 → Installed:true, Detail:"<name> found at <path> but --version failed: <err>"
    // 不静默替换为其它 harness（CLI/MCP 走 Name 显式选）。
}
```

错误语义（与源码逐条对应，[internal/harness/cli.go:41-55](file://internal/harness/cli.go#L41-L55)）：

- binary 不在 PATH → `Availability{Installed: false, Detail: "<bin> is not on PATH"}`，**不**返回 error；CLI 用 `Installed=false` 给用户提示（`workloom run exec --harness <name>` 报 precondition，exit 3，[internal/app/runexec.go:187-193](file://internal/app/runexec.go#L187-L193)）。
- `--version` 非零退出或超时 → `Availability{Installed: true, Detail: "<name> found at <path> but --version failed: <err>"}`，同样不返回 error——**可用性不降级**，「装是装了但探针失败」写在 Detail 里，不替代成别的 harness。
- `Shell.Probe` 与之无关：它永远 `Installed: true`，只是报告 `argv passthrough on <goos> (POSIX|Windows)` 与 `sh` / `cmd` 的解析路径（[internal/harness/shell.go:46-61](file://internal/harness/shell.go#L46-L61)）。

## Prepare 契约

- `Shell.Prepare`：`ws.Path` 必须非空（否则 error `workspace path is required`），随后 `os.Stat` 必须成功且 `IsDir()`（[internal/harness/shell.go:63-78](file://internal/harness/shell.go#L63-L78)）。
- `cliAdapter.Prepare`：直接 `a.shell.Prepare(ctx, ws)`——根内不变量不由适配器负责，`workspace.Validate(root, path)` 在 `internal/workspace.Ensure` / `Remove` 里执行（[internal/app/runexec.go:196-198](file://internal/app/runexec.go#L196-L198)、[internal/workspace/path.go:48-86](file://internal/workspace/path.go#L48-L86)）。
- 适配器只拿到 `Workspace{Path, Branch, Worktree}`：`Branch` 在目录工作区为空、`Worktree` 是工作区 key（[internal/app/runexec.go:196](file://internal/app/runexec.go#L196)）。

## Command 契约

```go
// Request 的真实字段见上文「类型总览」：Command / Dir / Env / Timeout /
// Stdin / Prompt / Model / SessionID。没有 Argv / Harness / Workdir 这些字段。
```

- `Shell.Command`：`req.Command` 非空且 `Command[0]` 非空白（否则 error `command is required`）；`Dir` 为空时取 `os.Getwd()`；`Dir` 必须存在且为目录。argv / Env / Stdin 全部**拷贝**后冻结进 `Command{Argv, Dir, Env, Timeout, Stdin}`（[internal/harness/shell.go:80-107](file://internal/harness/shell.go#L80-L107)）。
- `cliAdapter.Command`：先 `build(req)` 得到 `(argv, stdin, err)`，再把 `bin` 前置成 `shellReq.Command = append([a.bin], argv...)`、`Stdin = stdin`，最后交给 `shell.Command` 做同一套校验。harness 模式与 shell 模式的差别只有 `RunExec` 填了 `Prompt` 还是 `Command`（[internal/app/runexec.go:208-220](file://internal/app/runexec.go#L208-L220)）。
- 校验/构建失败 → `error`；`RunExec` 把它包成 `Preconditionf` → **CLI exit 3**（不是 exit 4），并在落账前先经 `refuseAttempt`（[internal/app/runexec.go:218-220](file://internal/app/runexec.go#L218-L220)）。
- `Command` 冻结后 `shell.Start` 不再改它。

## Start 契约

- `Cmd.Dir = Command.Dir`；`Cmd.Env = append(os.Environ(), Command.Env...)`（仅在 Env 非空时设置）。
- POSIX：`configureProcessGroup` 设 `SysProcAttr.Setpgid = true`，让子进程成为进程组 leader。
- Windows：`configureProcessGroup` 是 no-op；终止时改用 `taskkill /T /F /PID`。
- 输出：`proc.Stdout = &lineWriter{…stream:"stdout"}`、`proc.Stderr = &lineWriter{…stream:"stderr"}`，`proc.WaitDelay = waitDelay`；**不**用 `StdoutPipe` 自己读。
- stdin：仅当 `len(cmd.Stdin) > 0` 时 `proc.StdinPipe()` 并起 `go feedStdin(pipe, cmd.Stdin, sess)`。
- 启动顺序：配置进程组 → 挂两个 lineWriter → （可选）stdin pipe → `proc.Start()` → `go sess.reap()` → （可选）`time.AfterFunc(cmd.Timeout, …)` → ctx 取消监听 goroutine（[internal/harness/shell.go:111-168](file://internal/harness/shell.go#L111-L168)）。
- `proc.Start()` 失败 → 返回 `error`（`start <argv0>: …`）；`RunExec` 把失败记成 `command failed to start: <err> (<argv>)`、run 落 `failed`，再以 `Preconditionf` 返回 → **CLI exit 3**（[internal/app/runexec.go:287-304](file://internal/app/runexec.go#L287-L304)）。

`Start` 返回的 `Session` 在 adapter 内部实现（`*shellSession`）；用户**不**直接构造。

## Stop 契约

- `Stop` 先看 `done`：已结束 → 直接返回 nil（重复 Stop 是 no-op）。否则 `markCanceled()` + `kill()`，然后**等** `Wait(ctx)` 返回——Stop 不是 fire-and-forget（[internal/harness/shell.go:210-223](file://internal/harness/shell.go#L210-L223)）。
- `kill()` 由 `stopOnce sync.Once` 保护：关闭 `discard`（丢弃尚未发出的 line）并 `killTree(proc.Process)`；POSIX 是 `SIGKILL` 整组，Windows 是 `taskkill /T /F`（[internal/harness/shell.go:237-248](file://internal/harness/shell.go#L237-L248)）。
- `RunExec` 用 `context.WithTimeout(background, stopGrace=10s)` 兜住 Stop 的等待，所以被放弃的 attempt 不会把调用方吊死（[internal/app/runexec.go:27-29](file://internal/app/runexec.go#L27-L29)、[internal/app/runexec.go:308-312](file://internal/app/runexec.go#L308-L312)）。

## Wait 契约

- 阻塞直到子进程退出 + 两路 stdout/stderr 都 drain 完（os/exec 负责 drain）。
- 收集 `Result{ExitCode, TimedOut, Canceled, StartedAt, EndedAt, Err}`；ctx 在结束前被取消时返回 `Result{}, ctx.Err()`。
- `ExitCode = -1` 表示被信号杀死或从未启动；`Err` 是**字符串**：只有 `exec.ErrWaitDelay`（`"output streams stayed open after the command exited"`）或非 `*exec.ExitError` 的 wait 失败才非空——普通非零退出只体现在 `ExitCode`（[internal/harness/shell.go:250-284](file://internal/harness/shell.go#L250-L284)）。

## Line 契约

- `Text` 不带 `\n`；调用方按需补。
- `Stream ∈ {"stdout", "stderr"}`；MCP / CLI sink 据此分流。
- 超长单行按 rune 边界切成多 chunk 连续发出；agent 收到的是 `text` 字段多行（按 chunk 拼接）——不丢字节。
