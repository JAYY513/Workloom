# 适配器协议契约

`internal/harness` 的导出类型与方法是 §9.2/§9.3 适配器契约的 Go 形态。CLI 与 MCP 入口都通过 `internal/app.RunExec` 调它；任何新 harness 必须实现下列接口并经 `Names()` / `ByName` 注册。

## 类型总览（[internal/harness/harness.go](file://internal/harness/harness.go)）

```go
type Capabilities struct {
    NonInteractive bool   // false 时调用方不能假设行为
    Streaming      bool   // 是否支持 Line-level 流式
    Worktree       bool   // 是否必须在 workspace 内执行
}

type Availability struct {
    Installed bool
    Version   string
    Detail    string
}

type Workspace struct {
    Path   string
    Branch string
}

type Request struct {
    Argv      []string      // shell 适配器用
    Harness   string        // M6.7：assigned harness name
    Model     string        // M6.7：assigned model name
    SessionID string        // M6.7：续 session（保留）
    Prompt    []byte        // 投递到 stdin；codex/claude 用
    Workdir   string        // 相对 Workspace.Path
    Timeout   time.Duration // 0 = 不限时
    Env       []string      // 注入到子进程
}

type Command struct {
    Argv []string
    Dir  string
    Env  []string
}

type Line struct {
    Stream string  // "stdout" | "stderr"
    Text   string  // 无行终止符
    Time   time.Time
}

type Result struct {
    ExitCode   int      // -1 = killed by signal / never started
    StartedAt  time.Time
    EndedAt    time.Time
    TimedOut   bool
    Canceled   bool
    Err        error    // 非 nil = spawn/wait 失败
}

func (r Result) Duration() time.Duration { return r.EndedAt.Sub(r.StartedAt) }

type Session interface {
    Lines() <-chan Line
    Wait(ctx context.Context) (Result, error)
    Stop(ctx context.Context) error
}

type Adapter interface {
    Name() string
    Capabilities() Capabilities
    Probe(ctx context.Context) (Availability, error)
    Prepare(ctx context.Context, ws Workspace) error
    Command(req Request) (Command, error)
    Start(ctx context.Context, cmd Command) (Session, error)
}
```

## Shell 适配器（[internal/harness/shell.go](file://internal/harness/shell.go)）

最小、最通用、所有 CLI 适配器的委托对象。

```go
type Shell struct{}

func NewShell() *Shell { return &Shell{} }

func (s *Shell) Name() string { return "shell" }
func (s *Shell) Capabilities() Capabilities { return Capabilities{NonInteractive: true, Streaming: true, Worktree: true} }

// Probe：永远 available；Detail 报告 host shell（/bin/sh 或 sh.exe）。
func (s *Shell) Probe(ctx context.Context) (Availability, error) { … }

// Prepare：执行目录存在且为目录；workspace invariants 由 M6.2 引入。
func (s *Shell) Prepare(ctx context.Context, ws Workspace) error { … }

// Command：校验 argv 非空、Workdir 存在（适配器内不调 workspace.Validate）。
func (s *Shell) Command(req Request) (Command, error) { … }

// Start：spawn → 行级流 → stdin 投递 → 进程树终止在 kill()。
func (s *Shell) Start(ctx context.Context, cmd Command) (Session, error) { … }
```

- **Constants**：`lineBuffer = 64 << 10`（64 KiB chunk），`waitDelay = 2 * time.Second`（进程退出后再等 2s 让 stdin 写完）。
- **`feedStdin(pipe, payload, sess)`**：单独 goroutine 写 stdin，写失败 → `sess.stdinErr`（不是 spawn 错误）。
- **`shellSession`**：持有 `lines chan Line`（buffer=64）、`killOnce sync.Once`、`markTimedOut/markCanceled`。
- **`lineWriter`**：把字节流切成 `Line{Stream, Text}`；超长行按 rune 边界切 chunk；UTF-8 安全。

## 三种 CLI 适配器（[internal/harness/cli.go](file://internal/harness/cli.go)）

```go
type cliAdapter struct {
    name  string
    caps  Capabilities
    shell *Shell
    build func(req Request) ([]string, error) // → argv (binary prepended)
}
```

三种实现：

| Harness | `Name()` | `Capabilities` | argv 形态 | stdin |
|---|---|---|---|---|
| `Codex()` | `"codex"` | `NonInteractive=true, Streaming=true, Worktree=true` | `["codex", "exec", "-C", dir, "-", model?, session_id?]`，model/session 拼到 argv 末尾 | **prompt → stdin**（`-`） |
| `OpenCode()` | `"opencode"` | 同上 | `["opencode", "run", dir, model?]` positional；prompt 只能塞 argv | **无 stdin**（agent 文档化的长度限制） |
| `ClaudeCode()` | `"claude"` | 同上 | `["claude", "-p", "-C", dir, "--model", model?, session_id?]`，prompt → stdin | **prompt → stdin**（`-p`） |

构造器签名：

```go
func Codex() Adapter       // = cliAdapter{"codex", caps, shell, codexArgs}
func OpenCode() Adapter    // = cliAdapter{"opencode", caps, shell, opencodeArgs}
func ClaudeCode() Adapter  // = cliAdapter{"claude", caps, shell, claudeArgs}
```

`Codex` / `ClaudeCode` 走 stdin——`build` 完成后 argv 末尾带 `-` / `-p`；shell.Start 时把 prompt payload 灌入 `Cmd.Stdin`。`OpenCode` 没 stdin，prompt 必须是 positional 第一参数；超出 argv 长度限制时 caller 负责截短。

`Acceptance run` 的关键回归：argv 必须包含 binary 名 `codex` / `opencode` / `claude`——M6.7 早期版本曾漏写，attempt 跑成 `exec ...` 而非 `codex exec ...`。

## Probe 契约

```go
const probeTimeout = 10 * time.Second

func (a *cliAdapter) Probe(ctx context.Context) (Availability, error) {
    // 用 cliAdapter.name 作为 argv[0]，跑 --version；超时 10s；
    // 不识别 → Availability{Installed:false} + nil（不是错误）。
    // 不静默替换为其它 harness（CLI/MCP 走 Name 显式选）。
}
```

错误语义：

- binary 不在 PATH → `Availability{Installed: false, Detail: "codex: executable not found"}`，**不**返回 error——CLI 用 `Installed=false` 给用户提示（exit 3）。
- 探针超时 → 返回 error（CLI 把它升 exit 3）；不替代为别的 harness。
- 探针非零退出 → `Availability{Installed: false, Detail: stderr tail}`；同不返回 error。

## Prepare 契约

- `Shell.Prepare`：`os.Stat(dir)` 存在 + IsDir；不存在 → exit 3。
- `cliAdapter.Prepare`：直接 `a.shell.Prepare(ctx, ws)`——M6.2 起 `internal/app.RunExec` 在 spawn 前额外跑 `workspace.Validate(root, path)`。

## Command 契约

```go
type Request struct {
    Argv      []string   // shell: 整段 argv；harness: 忽略
    Harness   string     // 期望 harness name；cliAdapter 校验匹配
    Model     string     // 拼到 argv 末尾（codex -m / opencode positional / claude --model）
    SessionID string     // 续 session（codex resume / claude -c）
    Prompt    []byte     // stdin payload
    Workdir   string     // 必填；Command.Dir = Workdir
    Timeout   time.Duration
    Env       []string
}
```

校验失败 → `error`（CLI exit 4，**不是** exit 3）。`Command{Argv, Dir, Env}` 冻结；之后 shell.Start 不能改。

## Start 契约

- `Cmd.Dir = Command.Dir`；`Cmd.Env = Command.Env`（在 `os.Environ()` 之上叠加）。
- POSIX：`SysProcAttr.Setpgid = true` 让子进程成为进程组 leader。
- Windows：起 `JobObject` + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，把子进程 assign 到 Job。
- 启动顺序：`StdoutPipe` / `StderrPipe` → `Stdin`（`io.WriteCloser`）→ `Start`。
- `os/exec.Start` 失败 → 返回 `error`（CLI exit 1）。

`Start` 返回的 `Session` 在 adapter 内部实现；用户**不**直接构造。

## Stop 契约

- 调用 `(*shellSession).kill()`（`sync.Once` 保护）；POSIX 发 `SIGTERM`，`stopGrace=10s` 后再 `SIGKILL`；Windows 立即 `TerminateJobObject`。
- 重复 Stop 是 no-op；attempt 结束后 Stop 仍安全（什么都不做）。
- `Stop(ctx)` 不等结果；`Wait(ctx)` 阻塞到 attempt 真正结束。

## Wait 契约

- 阻塞直到子进程退出 + 两路 stdout/stderr 都 drain 完。
- 收集 `Result{ExitCode, StartedAt, EndedAt, TimedOut, Canceled, Err}`。
- `ExitCode=-1` 表示被信号杀死或从未启动；`Err != nil` 是 spawn/wait 失败，与 `ExitCode != 0` 是**不同**的事。

## Line 契约

- `Text` 不带 `\n`；调用方按需补。
- `Stream ∈ {"stdout", "stderr"}`；MCP / CLI sink 据此分流。
- 超长单行按 rune 边界切成多 chunk 连续发出；agent 收到的是 `text` 字段多行（按 chunk 拼接）——不丢字节。

## 注册表

```go
func Names() []string { return []string{"shell", "codex", "opencode", "claude"} }

func ByName(name string) (Adapter, bool) {
    switch name {
    case "shell":   return NewShell(), true
    case "codex":   return Codex(), true
    case "opencode": return OpenCode(), true
    case "claude":  return ClaudeCode(), true
    }
    return nil, false
}
```

未知名字 → `ByName` 返回 `(nil, false)`；caller 升 exit 2（`CodeUsage`）。
