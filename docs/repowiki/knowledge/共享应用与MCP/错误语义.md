# 错误语义 · 共享应用与 MCP

M4 把 CLI 与 MCP 共用的错误模型收口到 `internal/app/app.go`，让任意入口的「失败描述」都来自同一份分类。

## `*app.Error` 结构

`internal/app/app.go:33-46`：

```go
type Error struct {
    Kind     string            // 展示类型（usage / precondition / internal / invalid / workflow / gate / quality / workitem / approval）
    Message  string            // 人类可读消息
    Problems []config.Problem // 定位问题（仅 invalid / workflow 等结构化失败）
}

func (e *Error) Error() string { return e.Message }
```

## `Class()` 归一

`internal/app/app.go:47-55`：

```go
func (e *Error) Class() string {
    switch e.Kind {
    case KindUsage, KindPrecondition, KindInternal:
        return e.Kind
    }
    return KindInvalid
}
```

归一到 4 类：`usage / precondition / internal / invalid`。CLI 把这四类映射到退出码 `2 / 3 / 1 / 4`；MCP 把这四类映射到工具错误码（同名）。

## 构造器

| 函数 | 形态 | 触发 |
|---|---|---|
| `Usagef(format, ...)` | `*Error{Kind: usage}` | 参数错误、未知子命令、缺 `--expect` 等 |
| `Preconditionf(format, ...)` | `*Error{Kind: precondition}` | `.devsys/` 缺失、版本哈希不符、未初始化 |
| `Internalf(format, ...)` | `*Error{Kind: internal}` | 写入/读取 IO 失败、未在控制内的错误 |
| `Invalidf(kind, problems, format, ...)` | `*Error{Kind: <kind>, Problems: problems}` | 受管状态不可信；`kind` 选 `KindInvalid / KindWorkflow / KindGate / KindQuality / KindWorkitem / KindApproval` 中的一种 |
| `Classify(err)` | 已分类 → 透传；否则包成 `Internalf("%v", err)` | 跨层包装不丢失分类 |

func toCoded(err error) *codedError {
    var ae *app.Error
    if errors.As(err, &ae) {
        code := CodeInvalid
        switch ae.Class() {
        case app.KindUsage:
            code = CodeUsage
        case app.KindPrecondition:
            code = CodePrecondition
        case app.KindInternal:
            code = CodeInternal
        }
        return &codedError{code: code, kind: ae.Kind, msg: ae.Message, problems: ae.Problems}
    }

}

## MCP 翻译：`toolError` + `fail` / `failNotice` / `usageFail`

`internal/mcp/tools.go:108-156`：

```go
type toolError struct {
    Code     string           `json:"code"`
    Message  string           `json:"message"`
    Problems []config.Problem `json:"problems,omitempty"`
    Notice   string           `json:"notice,omitempty"`
}
```

| 函数 | 行为 |
|---|---|
| `fail[Out any](err error) (*mcpsdk.CallToolResult, Out, error)` | 把 `error` 翻译为 `isError=true` 的 tool result；`*app.Error` → `toolError{code: Class()}`；其它 → `toolError{code:"internal"}` |
| `failNotice[Out any](err error, notice string)` | 同上，并附 `notice`（用于 last-known-good fallback） |
| `usageFail[Out any](format, ...)` | 构造 `app.Usagef` 并调用 `fail`，用于「参数错误」 |

返回结构通过 SDK 的 `StructuredContent` 暴露给客户端——调用方按 `code` 分支时无需关心入口是 CLI 还是 MCP。

## 调用脚本分支约定

脚本与客户端**只信 `code` 字段**：

- `usage` (CLI exit 2)：修正参数。
- `precondition` (CLI exit 3)：运行 `devsys init` / `devsys recover` / 重新 `get` 取新 version。
- `internal` (CLI exit 1)：重试或上报。
- `invalid` (CLI exit 4)：按 `problems[]` 修复受管状态，或按 `message` 处理拒绝原因（门禁未满足、审批失效等）。

`kind` 字段是给人看的（让 stderr 更易读），**不是**分支依据。
