# 共享应用与 MCP · 概述

本模块是 M4 里程碑的接入层：把 CLI 与 MCP 两类入口共用的业务规则（输入校验、门禁、质量门、审批、版本守卫、事务、AGENTS.md 写入）收敛到**同一份 Go 应用服务** `internal/app`，让任意入口都不能绕过其它入口已经强制的不变量。`internal/mcp` 在该服务之上以官方 Go SDK 暴露 profile 过滤的工具族。两层都不引入新的锁或新的存储后端——它们都是 `可靠文本存储` 与 `项目接入与配置` 既有原语的薄适配。

## 模块定位

- **做什么**：
  - `internal/app.Service` 提供 30 余个业务方法，涵盖 `Session` / `Context` / `Project` / `Workitem` / `Workflow` / `Approval` / `Decision` / `Finding` / `Artifact` / `Event` / `Run` / `Next` / `Wire` / `KnowledgeStatus` 等领域；写方法统一接收 `expect`（来自对应 `Get*` 的 `Version`）并通过 `Tx` 走 `Store.Write` 的乐观并发。
  - `internal/mcp` 把每个工具方法映射到 SDK server 的注册项，按 profile 过滤暴露；工具处理器是 4–6 行的薄适配——业务规则全在 `internal/app`。
  - CLI（`internal/cli`）在 M4 后只做 flag 解析、`render`、`toCoded` 把 `app.Error` 翻译为退出码，并把业务分发迁出到 `internal/app`。
- **不做什么**：
  - 不实现业务规则（门禁、审批消费、传播、状态机、读取守卫、记录版本链）——这些都在 `internal/{workflow,approval,workitem,record,run,...}`，由 `app.Service` 调用。
  - 不引入新锁或新事务形态——所有写路径走 `storage.Store.Write`、所有读路径走 `Store.Read`。
  - 不实现知识层（`knowledge_status` 始终返回 `unavailable`，因为 M5 才是知识层的到达里程碑）。

## 职责边界

| 层 | 目录 | 职责 |
|---|---|---|
| 错误分类 | `internal/app/app.go` | `Kind`（展示类型：usage / precondition / internal / invalid / workflow / gate / quality / workitem / approval）+ `Class()`（归一到四类，对应退出码与 MCP 工具错误码）+ `Usagef / Preconditionf / Internalf / Invalidf` 构造器；`Classify` 把任意 error 包装为 `*Error` |
| 服务骨架 | `internal/app/app.go` | `Service{Root, Now}`、`New(root)`、`metadata` / `project` / `items` / `now` 私有助手 |
| 会话 | `internal/app/session.go` | `SessionStart(SessionRequest) SessionView`：单次返回项目身份、`CurrentState`、在飞工作项（limit 收口）、`RecommendedNextAction`（与 `next.Evaluate` 同源）、近期记录引用、`Notices` |
| 上下文 | `internal/app/context.go` | `ContextGet / ContextForWorkitem / ContextRefresh / ContextCompact`：项目 + 计数 + 判决 + 近期 decision/finding/artifact/event 引用（compact 模式裁短） |
| 项目 | `internal/app/project.go` | `ProjectGet / ProjectUpdate / ProjectStateGet / ProjectStateUpdate / ProjectList / ProjectStatus / ProjectBlueprint` |
| 工作项 | `internal/app/workitem.go` | 14 个方法覆盖 `List / Get / Create / Update / Transition / Claim / Release / Start / Block / Complete / Comment / AddDependency / RemoveDependency / Next`；写方法均带 `Expect`（来自 `Get`） |
| 工作流 | `internal/app/workflow.go` | `WorkflowList / Get / Start / StepNext / StepComplete / Pause / Resume / Cancel` |
| 审批 | `internal/app/approval.go` | `ApprovalList / Get / Request / Approve / Reject`（`approve` / `reject` 合并为 `Decide(approve bool)`） |
| 记录 | `internal/app/record.go` | `DecisionList/Get/Create/Approve` + `FindingList/Get/Create/Resolve` + `EventList/Record` + `ArtifactList/Get/Register/Update/History` |
| 运行 | `internal/app/run.go` | `RunList / Get / Create / Update / Heartbeat / Log` |
| 就绪 | `internal/app/next.go` | `Next() (next.Report, []*WorkItem, error)`：内部调 `reconcile.Doctor` + `next.Evaluate`，不可信状态（`!InspectionOK || len(PendingTransactions) > 0`）不返回业务事实 |
| Wire | `internal/app/wire.go` | `Wire(dryRun bool) WireView`：把 devsys 纪律块注入 `AGENTS.md` 的 `<!-- devsys:begin/end -->` 区间；幂等（三次运行字节一致）；区段外字节保留（含其它工具的管理块） |
| 知识状态 | `internal/app/knowledge.go` | `KnowledgeStatus() KnowledgeStatusView`：M4 永远返回 `unavailable`，提示「M5 §12.6 到达」 |
| MCP 服务 | `internal/mcp/server.go` | `DefaultProfiles / ParseProfiles / NewServer / Run`；Profile 常量 `session / executor / reviewer / admin`，未知名字解析失败（拼错不能静默放行） |
| MCP 工具表 | `internal/mcp/tools.go` | `allTools()` 列 60+ 工具的 `name + profiles + register`，注册期按 profile 过滤（未注册的无法以名称调用） |
| 工具实现 | `internal/mcp/tools_*.go` | 13 个文件，每文件一族；处理器都是 `(ctx, req, in) (out, toolResult, error)` 签名，错误统一通过 `fail` 渲染为 `{code,message,problems,notice?}` 结构化工具错误 |
| 工具错误 | `internal/mcp/tools.go` | `toolError` 结构 + `fail / failNotice / usageFail`：把 `*app.Error` 翻译为 SDK 的 `isError=true` tool result；保留 `notice` 用于 last-known-good 上下文 |
