# 共享应用与 MCP · 概述

本模块是 M4 里程碑的接入层：把 CLI 与 MCP 两类入口共用的业务规则（输入校验、门禁、质量门、审批、版本守卫、事务、AGENTS.md 写入）收敛到**同一份 Go 应用服务** `internal/app`，让任意入口都不能绕过其它入口已经强制的不变量。`internal/mcp` 在该服务之上以官方 Go SDK 暴露 profile 过滤的工具族。两层都不引入新的锁或新的存储后端——它们都是 `可靠文本存储` 与 `项目接入与配置` 既有原语的薄适配。

## 模块定位

- **做什么**：
  - `internal/app.Service` 提供 30 余个业务方法，涵盖 `Session` / `Context` / `Project` / `Workitem` / `Workflow` / `Approval` / `Decision` / `Finding` / `Artifact` / `Event` / `Run` / `Next` / `Wire` / `KnowledgeStatus` 等领域；写方法统一接收 `expect`（来自对应 `Get*` 的 `Version`）并通过 `Tx` 走 `Store.Write` 的乐观并发。
  - `internal/mcp` 把每个工具方法映射到 SDK server 的注册项，按 profile 过滤暴露；工具处理器是 4–6 行的薄适配——业务规则全在 `internal/app`。
  - CLI（`internal/cli`）在 M4 后只做 flag 解析、`render`、`toCoded` 把 `app.Error` 翻译为退出码，并把业务分发迁出到 `internal/app`。
- **不做什么**：
  - 不实现业务规则（门禁、审批消费、传播、状态机、读取守卫、记录版本链）——这些都在 `internal/{workflow,approval,workitem,record,run,...}`，由 `app.Service` 调用。
  - 不引入新锁或新事务形态——所有写路径走 `storage.Store.Write`、所有读路径走 `Store.Read`。
  - 不实现知识层（`knowledge_status` 始终返回 `unavailable`，因为 M5 才是知识层的到达里程碑）。


  - **M8 新增**：`Dispatch` tick 顶端走 `mergeConflict(root)` 门控（recover 前 + dry-run 同门；blocked 走 precondition / CLI exit 3；探针失败降级 notice，不伪装为 conflict）；`readRunStream` 在活流缺失时回落到 `.devsys/archive/runs/<id>.jsonl`（归档只收终态 run，live-wins-or-fallback 严格）。**本批（#300/#301）**：next 走与 claim 同源的质量门（`next.QualityBlocks` 用 `workflow.Load` 的 plain read 拿 policy 体；ready 项被门挡下的标 `quality_blocked` 风险 + 推荐 `workitem update` 补救命令），工作项 `retry_queued` 也参与门判，新增 `retry_pending` 风险种类；`workitem create` 接受 `--acceptance a,b` 把验收标准在 create 阶段一并落库（避免满足质量门时再发 update）。
  - **本批接入层**：`internal/app/skill.go`（`WriteSkill` 写 `.agents/skills/devsys/SKILL.md` + `references/cli.md` + `references/troubleshooting.md`，全部以 `<!-- devsys-skill -->` marker 标定，hand-written 不覆盖）；`internal/app/wirecheck.go`（`WireCheck` 只读报 go/git/.devsys/registry/AGENTS.md 块/skill/MCP 配置 8 行，**不**写）；`internal/app/mcpsnippets.go`（`MCPSnippet(codex|claude|opencode)` 拼 stdio 命令片段，文件形态 [UNVERIFIED]）；`internal/app/wire.go` 把 `<!-- devsys:begin/end -->` 块末尾「结构化输出」一行换成指向 `SKILL.md`，让 wire 注入的纪律块与本批技能目录形成单一源。
