# 完成校验与人工复核

M6 把 "agent 报告 done" 与 "attempt 真的产出了证据" **分开**：

- `workloom run verify` 只读：claim head 与 current head 是否一致——回答 "attempt 跑了吗"。
- `workloom run complete` 默认走 verify 守卫：未 advance → run **保留证据**（`Verification.Advanced=false`）、写 `completion_refused` 事件、workitem 进 `review`（事件名不是 `review_routed`）——**不是**一次拒绝，而是结构化的 "需人介入" 状态。
- `workloom run complete --force --by <reviewer>`：reviewer 显式接受 verify 拒绝——把人工复核作为最后一道闸门。
- **本轮（cc5de1f）新增例外**：非 Git 项目或目录工作区里 Git 证据**不适用**（`CompletionCheck.Skipped=true`）——`run complete` 不再被拒绝，但 `Advanced` 也不会被标 true。

## 完成校验契约（[internal/app/runverify.go](file://internal/app/runverify.go)）

```go
type CompletionCheck struct {
    RunID       string `json:"run_id"`
    Workspace   string `json:"workspace,omitempty"`
    Branch      string `json:"branch,omitempty"`
    ClaimHead   string `json:"claim_head,omitempty"`
    CurrentHead string `json:"current_head,omitempty"`
    Advanced    bool   `json:"advanced"`
    Skipped     bool   `json:"skipped,omitempty"` // 本轮新增：Git 证据不适用
    Reason      string `json:"reason,omitempty"`
}
```

`Service.RunVerify(ctx, runID)`（[internal/app/runverify.go:32-38](file://internal/app/runverify.go#L32-L38)）：

1. `readRun(ctx, s, id)` 取 run + version bytes（同 atomic 读，避免 version 与记录撕裂）。
2. `verifyCompletion(r)` 比较 `claim_head` 与 `current_head`（通过 `git rev-parse refs/heads/<branch>`）。
3. 任一缺失或 git 失败 → `Advanced=false` + `Reason`。
4. 不修改任何状态；CLI 退出码 0。

`verifyCompletion` 捕获所有失败并降级为 `Advanced=false`——**永不**返回 error；理由：

- "没有 claim head" 可能是 attempt 启动时还没绑 workspace（启动前崩溃）。
- "git 命令失败" 可能是 worktree 已删除或分支已 force-push。
- "workspace 是空" 是 fixture 或编辑痕迹。

每一种都让 agent 看到 "需要复核" 的明确信号，而不是把 Git 异常冒泡为运行错误。

### Git 证据不适用（本轮新增，cc5de1f）

`verifyCompletion`（[internal/app/runverify.go:45-80](file://internal/app/runverify.go#L45-L80)）在比较 head 之前先判：

```go
directoryWorkspace := r.Workspace.Path != "" && r.Workspace.Branch == ""
if directoryWorkspace || !workspace.GitProject(s.Root) {
    check.Skipped = true
    check.Reason = "git completion check is not applicable"
```

- **非 Git 项目**（项目身份是「含 `.devsys/` 的目录」，`init` 不再要求 git 根）与**目录工作区**（`Path != ""` 且 `Branch == ""`，非 worktree）都走这条：`Skipped=true` + Reason 固定文案，`Advanced` 保持 false——**skip 不是 verified advance**。
- 原先「the attempt has no workspace branch」这条 `Reason` 分支已被删除；真正没有 workspace（`Path == ""`）仍报 `the attempt has no workspace, so there is no evidence it advanced anything`。
- `RunFinish` 对 `Outcome=RunSucceeded` 把 `check.Skipped` 与 `Advanced` / `Force` 并列为通过条件（[internal/app/run.go:321](file://internal/app/run.go#L321)）：非 Git 项目里 `run complete` 正常成功，事件走 `run_finished`，正文 verdict 写 `git check not applicable`（[:362](file://internal/app/run.go#L362)、[:371](file://internal/app/run.go#L371)）。
- 覆盖面：`wire --check` 的 git 行（[internal/app/wirecheck.go:49-54](file://internal/app/wirecheck.go#L49-L54)）在 git 不在 PATH 时 `OK=true` + detail `not on PATH (optional: worktree, sync, knowledge freshness unavailable)`——能力缺失不把检查打成失败；单测 `TestCompletionSucceedsWithoutGit`（[internal/app/runverify_test.go:339](file://internal/app/runverify_test.go#L339)）守住这条路径。

## 拒绝完成（[internal/app/runverify.go:87-180](file://internal/app/runverify.go#L87-L180)）

`refuseCompletion`（[internal/app/runverify.go:87-114](file://internal/app/runverify.go#L87-L114)）：

1. 重读 run，把 `Verification.Advanced=false` + `Verification.HeadSHAAtComplete=check.CurrentHead` 写回（`run.New(s.Root).Update`，带版本守卫）。**run 的 `status` 不变、仍是非终态**——留给 reviewer 收尾；workspace binding 也不动，reviewer 仍能看到 attempt 的工作区路径。
2. 写事件 `completion_refused`（`subject_type=run`，Actor=调用者，Related 指向 workitem），content = `claim head <sha>, current head <sha>: <reason>`。
3. 调 `routeToReview`，并把它的 `routed bool` 交回调用方——调用方据此决定报错文案（见下）。

`routeToReview`（[internal/app/runverify.go:116-180](file://internal/app/runverify.go#L116-L180)）：

1. 先把**本 run 绑定的**租约还给 reviewer（`ReleaseOptions{ForRefused: true, BoundRunID: r.ID}`）——claimed 的工作项拒绝他人 transition，reviewer 不该需要 agent 的 token；别的 attempt 的 claim 不受影响。
2. 已经在 `review` → 直接返回 `true`；`IsTransitionLegal` 不成立（例如已 closed）→ 返回 `false`（拒绝仍记在 run 与事件流里）。
3. 自动路径**同样过 stage gate**（`checkTransitionGate`）——`require_comment` / `require_artifacts` 不能因为「系统送审」被绕过；门禁挡住时写 `review_gate_blocked` 事件并保持原状态，返回 `false`。
4. 通过则 transition 到 `review`（reason `completion refused: <reason>`），返回 `true`。

`RunFinish` 在拒绝分支返回 `Preconditionf("run %s cannot be marked succeeded: …")`（CLI exit 3 / MCP `code=precondition`），并按 `routed` 选文案：`routed=true` → "the work item is in review — review it and pass --force --by <reviewer> to accept, or fix the branch and retry"；`routed=false` → 指出去补 comment 的 `workloom workitem comment --id …` 命令。

**注意**：本卡涉及的事件名只有 `completion_refused`（拒绝）、`review_gate_blocked`（送审被门禁挡住）、`completion_verified` / `completion_overridden` / `run_finished`（成功与终态）——源码里**没有** `review_routed` 事件。


## 早期拒绝的 reviewer 可见性（本批 #336：`refuseAttempt`）

`internal/app/runexec.go:469-547` 的 `refuseAttempt` 把 `RunExec` 在 `openRunStream` 之前 Usage/Precondition 拒绝（典型：before_run 钩子失败、attach workspace 失败、prompt 装配错误）统一落账为：

```text
run.status=failed       ← tx.Write 在事务内
result.errors=<cause>   ← RunExecView.Errors 通过版本守卫落到 run 记录
finished_at=<now>       ← 与正常 terminal run 同一字段
event: run_failed       ← subject_type=run, content=cause
releaseFailedClaim(...) ← lease 释放（与 retrySweep 同语义）
```

这条路径把"agent 没跑起来但 run 记录存在"从「空 run finished」纠正为「run failed + 原因」——reviewer 通过：

1. `workloom run verify <id>` 仍可读 `CompletionCheck`（claim head vs current head = 未推进，run.status=failed）。
2. `workloom run log <id>` / `workloom event list` 看到 `run_failed` 事件 + 原因。
3. `workloom workitem review` 或 MCP `run_get` 的 `RunView.Status == failed` + `Errors[]`。
4. CLI 退出码仍由原 Usage/Precondition 决定（`2` / `3`），因为错误是 Usage/Precondition，不通过 workflow kind；但 storeError 已统一落账，reviewer 端看到的事实一致。

`abortAttempt`（仅 before_run 失败分支）改接入 `refuseAttempt`，**禁止**把空 run 标 `finished`——保留 attempt 上下文供 reviewer 看证据。这与 `RunFinish.refuseCompletion` 同族但触发面更早、范围更窄：`refuseAttempt` 写的是 `run.status=failed` + `run_failed` 事件 + 释放租约，**不**送 review（只落账）；`refuseCompletion` 保留 run 的非终态、写 `completion_refused` 事件，并把 workitem 送 `review`。

## 审批失效回执（`gateEvidence` 的 `ApprovalNote`，本批新增）

`internal/app/workitem.go:594-649` 的 `gateEvidence` 收集阶段门证据时，如果 `require_approval` 命中但 `approval.MatchingGate` 没有匹配的未消费审批，会再调一次 `approval.InvalidatedFor(ctx, s.Root, wi.ID, stage)` 看是否「曾经有过但被 §4.9 voided 了」。如果命中，把 `voided.Id` / `voided.InvalidatedAt`（RFC3339）/ `voided.RequestedStatus` 拼成一句话写进 `workflow.GateEvidence.ApprovalNote`：

```text
<approval-id> was invalidated at <rfc3339> when the work item left "<status>" (方案 §4.9); request a new approval with `workloom approval request`
```

语义：

- 当且仅当 `require_approval` 门禁**当前**仍未满足时，`ApprovalNote` 才有内容；已经匹配的审批走 `ApprovalReady=true`、不写 note。
- 若 `approval.InvalidatedFor` 返回 `ErrNotFound`（从未申请过），`ApprovalNote` 留空——`Problems[]` 里只列「缺审批」，让 reviewer 自己走 `workloom approval request`。
- 若 `approval.InvalidatedFor` 返回其它错误（IO / 损坏），按 `evidenceError` 包装成 `internal` 退出，不静默吞掉。
- 这条 note 同时出现在 `workitem_transition` / `checkTransitionGate` 与 `RunFinish` 拒绝完成两条路径上——CLI 走 stderr JSON envelope；MCP 走 `toolError.Problems[]` 或 notice 字段（视 call site 而定），reviewer 在 MCP 端也能拿到失效时间戳与重批命令。

## 人工复核（`--force --by reviewer`）

CLI `run complete --force --by <reviewer>` 与 MCP `run_complete {force: true, by: "<reviewer>"}` 路径：

```text
read Run                          # expected version 守卫（checkExpect；不符 → exit 4 invalid）
isTerminalRun(status)             # 已终态 → Preconditionf → exit 3（不让两个 actor 抢结果）
Outcome == RunSucceeded && Force:
  跳过 verify 守卫分支（switch 直接命中 req.Force）
  写 r.Verification.Advanced = check.Advanced
  写 r.Verification.HeadSHAAtComplete = check.CurrentHead
  写 r.Verification.VerifiedBy = &req.By      # 例外必须可归因
  r.Status = succeeded; r.FinishedAt = now    # 事务内 update
  写 completion_overridden 事件：
      content = "succeeded: <reason> (<advanced|not advanced>, head <sha>); accepted by <reviewer>"
  释放本 run 绑定的租约（ForCompleted）
```

**唯一**允许的强制接受语义：

- 仅 `Outcome=RunSucceeded`；
- 必须 `--by <reviewer>`（缺了报 `forcing an outcome requires --by <reviewer>: an exception has to be traceable`，exit 2）；
- `--expect <hash>` 仍强制（写锁 CAS）；
- 已终态 → `Preconditionf("run %s already ended as %s")`（exit 3，不让两个 actor 抢结果）。

事件（reviewer 接受时，注意没有 `review_accepted`）：

```text
completion_overridden   actor=<actor>, content="succeeded: <reason> (advanced/not advanced, head <sha>); accepted by <reviewer>"
```

不走 force 的成功路径写的是 `completion_verified`（content 里 verdict 为 `advanced`）；`failed` / `canceled` 与本轮的 Skipped 成功写 `run_finished`。

## Workitem `review` 状态与 `next.Evaluate` 对接

`review` 状态（domain.Workitem.Status）：

- 可派发？**否**——`dispatchableStatus` 仅 `ready` / `retry_queued`。
- 接受 transition？仅 `ready`（reviewer 决定 retry）或 `blocked` / `cancelled`。
- `next.Evaluate` 把 `review` / `verification` + `updated_at ≤ now - 24h` 标为 `stale_review` 风险（§17.4）。
