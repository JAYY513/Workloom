# 完成校验与人工复核

M6 把 "agent 报告 done" 与 "attempt 真的产出了证据" **分开**：

- `devsys run verify` 只读：claim head 与 current head 是否一致——回答 "attempt 跑了吗"。
- `devsys run complete` 默认走 verify 守卫：未 advance → run 进 `failed`、workitem 进 `review`、事件 `review_routed`——**不是** devsys 的拒绝，是结构化的 "需人介入" 状态。
- `devsys run complete --force --by <reviewer>`：reviewer 显式接受 verify 拒绝——把人工复核作为最后一道闸门。

## 完成校验契约（[internal/app/runverify.go](file://internal/app/runverify.go)）

```go
type CompletionCheck struct {
    RunID       string `json:"run_id"`
    Workspace   string `json:"workspace,omitempty"`
    Branch      string `json:"branch,omitempty"`
    ClaimHead   string `json:"claim_head,omitempty"`
    CurrentHead string `json:"current_head,omitempty"`
    Advanced    bool   `json:"advanced"`
    Reason      string `json:"reason,omitempty"`
}
```

`Service.RunVerify(ctx, runID)`（[internal/app/runverify.go:27-35](file://internal/app/runverify.go#L27-L35)）：

1. `readRun(ctx, s, id)` 取 run + version bytes（同 atomic 读，避免 version 与记录撕裂）。
2. `verifyCompletion(r)` 比较 `claim_head` 与 `current_head`（通过 `git rev-parse refs/heads/<branch>`）。
3. 任一缺失或 git 失败 → `Advanced=false` + `Reason`。
4. 不修改任何状态；CLI 退出码 0。

`verifyCompletion` 捕获所有失败并降级为 `Advanced=false`——**永不**返回 error；理由：

- "没有 claim head" 可能是 attempt 启动时还没绑 workspace（启动前崩溃）。
- "git 命令失败" 可能是 worktree 已删除或分支已 force-push。
- "workspace 是空" 是 fixture 或编辑痕迹。

每一种都让 agent 看到 "需要复核" 的明确信号，而不是把 Git 异常冒泡为运行错误。

## 拒绝完成（[internal/app/runverify.go:75-144](file://internal/app/runverify.go#L75-L144)）

`Service.RunFinish` 在 `Outcome == RunSucceeded` 且 `!req.Force` 时跑守卫：

```text
check = verifyCompletion(r)
if !check.Advanced:
    refuseCompletion(r, actor, reason, check) → 把 run 标记为 failed + 写 workspace_hook_failed / review_routed 事件
    routeToReview(r, actor, reason)           → 把 workitem 推到 review 状态
    return *app.Error{Kind: workflow}        → CLI exit 4 + MCP isError=true
```

`refuseCompletion`：

1. 用 `runUpdateRaw` 把 run 记录更新为 `status=failed` + `finished_at` + `summary=completion check refused: <reason>`。
2. **不**改 workspace binding（让 reviewer 仍能看到 attempt 的工作区路径）。
3. 写 `workspace_hook_failed`（如果是 before_run 失败）或 `run_finished` 事件，记录 reason。

`routeToReview`：

1. workitem transition 到 `review` 状态，保留 `previous_status`。
2. 写 `review_routed` 事件：`subject_type=workitem, content={run_id, reason, check_summary}`。
3. **不**写 approval / decision / finding——人工复核是独立的流程。

## 人工复核（`--force --by reviewer`）

CLI `run complete --force --by <reviewer>` 与 MCP `run_complete {force: true, by: "<reviewer>"}` 路径：

```text
read Run                          # expected version 守卫
isTerminalRun(status)             # 已终态 → exit 4
Outcome == RunSucceeded && Force:
  跳过 verifyCompletion
  写 review_accepted 事件（actor=reviewer, force=true）
  写 run_finished 事件（status=succeeded, summary="forced by <reviewer>"）
  finishAttempt(...)              # 写 succeeded + finished_at
```

**唯一**允许的强制接受语义：

- 仅 `Outcome=RunSucceeded`；
- 必须 `--by <reviewer>`（reviewer 身份字符串）；
- `--expect <hash>` 仍强制（写锁 CAS）；
- 已终态 → exit 4（不让两个 actor 抢结果）。

事件序列（reviewer 接受时）：

```text
review_accepted     actor=<reviewer>, by=<reviewer>, force=true
run_finished        status=succeeded, summary="forced by <reviewer>"
```

## CLI / MCP 退出语义

| 命令 | 守卫未通过 | `--force` 接受 |
|---|---|---|
| `devsys run verify` | exit 0（always） | 不适用 |
| `devsys run complete` | exit 4（kind="workflow"）| exit 0，run.status=succeeded |
| `devsys run fail` | exit 0，run.status=failed | 不适用（不走 verify） |
| `devsys run cancel` | exit 0，run.status=canceled | 不适用 |
| MCP `run_verify` | `isError=false`（仍返回 check） | 不适用 |
| MCP `run_complete` | `isError=true`，`toolError{code: invalid, message: ...}`，`Notice="completion check refused; routed to review"` | `isError=false`，`RunView` 含 status=succeeded |
| MCP `run_fail` / `run_cancel` | `isError=false` | 不适用 |

## Workitem `review` 状态与 `next.Evaluate` 对接

`review` 状态（domain.Workitem.Status）：

- 可派发？**否**——`dispatchableStatus` 仅 `ready` / `retry_queued`。
- 接受 transition？仅 `ready`（reviewer 决定 retry）或 `blocked` / `cancelled`。
- `next.Evaluate` 把 `review` / `verification` + `updated_at ≤ now - 24h` 标为 `stale_review` 风险（§17.4）。

`run complete` 拒绝 → `review` 状态这条路径把 "agent 报告 done 但 git 没动" 转化为 "reviewer 该看一眼" 的明确信号——而不是让 workitem 留在 `verification` 等 stale。
