## 环境要求

- Go 1.26 工具链（`go.mod` 固定 `go 1.26`）和可在 PATH 调用的 Git。
- 唯一外部 Go 依赖是 `gopkg.in/yaml.v3`，已 `go mod vendor` 并提交 `vendor/`；离线构建时设 `GOPROXY=off` 或在 PowerShell 中设 `$env:GOPROXY='off'`。
- 不需要数据库服务；项目状态保存在 `.devsys/`，随 Git 同步。

## 构建

在仓库根构建 `devsys` 二进制：

```sh
# PowerShell / cmd
go build -o bin/devsys.exe ./cmd/devsys
# Bash / Git Bash（路径与产物按平台调整）
go build -o bin/devsys ./cmd/devsys

bin/devsys.exe --version    # devsys 0.1.0-dev
bin/devsys.exe --help
bin/devsys.exe bogus; echo $?   # 2
```

`.exe` 是此仓库 Windows 示例的产物名；其他平台可改为 `bin/devsys`。发布构建需注入版本与短 SHA：

```sh
go build -ldflags "-X workloom/internal/version.Version=0.1.0 -X workloom/internal/version.Commit=$(git rev-parse --short HEAD)" -o bin/devsys.exe ./cmd/devsys
```

## init

`devsys init` 是唯一允许修改受管文件的写命令。它把 `.devsys/` 布局落到 Git 仓库根目录、写入 4 份占位元数据、注册项目路径到用户级注册表，并保证 `.devsys/.gitignore` 至少覆盖 `local/` 与 `.cache/`。子目录不是仓库根时会拒绝执行。

```sh
cd /path/to/your/git-repo
devsys --json init
devsys --quiet init
devsys config check
```

文本模式报告初始化目录、项目名称与 ID、实际创建的路径数量及注册表路径；数量取决于已有布局。JSON 模式返回实际创建路径与登记结果。参见下方 CLI 源码引用；不要把示例数量当成固定契约。

幂等行为：
- 缺失的 `.devsys/`、子目录和占位文件会被补建；现存占位元数据不重写。
- `.devsys/.gitignore` 若已存在，只追加缺失的 `local/`、`.cache/` 行，原有内容不变。
- 落盘前先校验现有受管元数据；若已存在的 `project.yaml` / `config.yaml` / `state/*.yaml` 出现未知 `schema_version`、未知键或类型错误，`init` 拒绝改动并报退出码 4。
- 当前目录不在 Git 仓库或 `git` 不可用 → 退出码 3（前置条件），无任何写入。

## config check

`devsys config check` 是只读诊断：不加锁、不写盘、不恢复事务。它遍历四份受管元数据文件，逐条定位问题，并按 `文件:行号: 字段: 原因` 格式化输出。

```sh
devsys config check             # 通过：config ok: 4 files checked
devsys --json config check      # {ok,root,checked,project?,config?}
devsys config check; echo $?    # 0 / 4 / 3
```

四份受管文件（顺序固定）：`project.yaml`、`config.yaml`、`state/current.yaml`、`state/milestones.yaml`。问题示例：

```
project.yaml:5: unknown_field: unknown key
project.yaml:2: schema_version: unsupported version 99 (...)
config.yaml:2: timeout: unknown key
```

`--json` 模式下问题进入 `error.problems` 数组（`code=4`、`kind=invalid`）；通过时返回完整 `project`、`config` 解析结果。`init` 之前的项目目录 → 退出码 3。

## search

`devsys search <keyword>` 在 `.devsys/` 下做无索引文本扫描：大小写不敏感子串匹配，单文件最多 5 条命中行，行内容截断 200 字节（UTF-8 安全），排除 `.cache/` 与 `local/`。缺少关键字参数或多于一个位置参数 → 退出码 2。

```sh
devsys search 密码
devsys --json search WLM-2
devsys search no-such-keyword; echo $?   # 0（零命中仍成功）
```

文本输出：`<相对路径>:<行号>: <行内容>`，末尾汇总 `<N> match(es) in .devsys/ for "<keyword>"`。

`--json` 字段：`ok`、`root`、`query`、`matches[]`（`path`、`line`、`text`）、`total`。零命中时 `matches` 是空数组、`total=0`，退出码仍为 0。

初始化与日常只读查询路径：

1. 隔离测试时把 `DEVSYS_CONFIG_DIR` 指向临时目录，避免污染用户级注册表（PowerShell：`$env:DEVSYS_CONFIG_DIR = 'C:/Temp/workloom-registry'`）。
2. 在目标仓库根执行 `devsys --json init`，确认 `created[]` 反映实际补建内容。
3. 执行 `devsys --json config check`，确认 `ok=true`；若 `error.problems` 非空，按 `文件:行号: 字段: 原因` 修复受管文件。
4. 关键字检索：`devsys --json search <keyword>`；M1 域层记录（WorkItem / Decision / Finding / Artifact / Run / Event）落入 `workitems/`、`decisions/`、`findings/`、`artifacts/`、`runs/`、`events/`，都参与扫描。

## 退出码与输出约定

| 退出码 | 含义 | 触发示例 |
|---|---|---|
| 0 | 成功（含 `search` 零命中） | `init` 幂等完成、`config check` 通过、`search` 命中或空 |
| 1 | 内部错误 | 读取/写入系统调用失败 |
| 2 | 用法错误 | 未知命令/选项、`search` 缺关键字或多参数、`config` 缺子命令 |
| 3 | 前置条件错误 | 不在 Git 仓库、`git` 不在 PATH、未初始化 `.devsys/` |
| 4 | 受管元数据无效 | 未知键、类型错误、缺必填项、`schema_version` 不支持（未知版本仍可只读诊断） |

全局开关（`--json`、`--quiet`、`--version`、`--help`）必须放在子命令之前；解析器遇到第一个非选项参数即停止收集开关。`init` 与 `config check` 拒绝多余位置参数。

JSON 模式：成功输出走 stdout（带 `ok:true`），错误信封走 stderr（`{ok:false, error:{code,kind,message,problems?}}`）。`config check` 不加锁、不写盘；它不替代并发业务读取，只做只读诊断。
