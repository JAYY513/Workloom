## 环境要求

需要 Go 1.26 工具链与可在 PATH 中调用的 Git。当前唯一外部 Go 依赖是已提交至 `vendor/` 的 `gopkg.in/yaml.v3`。离线构建的前提是本地已安装匹配工具链且 checkout 包含 vendor 内容；不需要另建数据库服务。

## 安装

当前使用从源码构建的 `devsys` 二进制。进入 Workloom 源码根目录构建，然后把二进制绝对路径用于目标项目，或自行放到 PATH；不要把它误认为已有公开包管理器安装流程。

章节来源：[README.md:22-34](file://README.md#L22-L34)。

## 构建

在源码根目录执行：

```sh
go build -mod=vendor -o bin/devsys.exe ./cmd/devsys
bin/devsys.exe --version
bin/devsys.exe --help
```

`.exe` 是此仓库 Windows 示例的产物名。其他平台可改为 `bin/devsys`。要强制验证离线依赖，在 PowerShell 中设置 `$env:GOPROXY='off'`，或在 POSIX shell 中使用 `GOPROXY=off go build -mod=vendor ./...`。

章节来源：[README.md:24-27](file://README.md#L24-L27)、[README.md:82-85](file://README.md#L82-L85)。

## 运行

切换到**要管理的 Git 仓库根目录**，以下假定 `devsys` 已在 PATH：

```sh
devsys --json init
devsys --json config check
devsys --quiet init
```

全局参数放在子命令前：正确写法为 `devsys --json init`，不是 `devsys init --json`。解析器在第一个非选项参数停止解析全局参数；`init` 拒绝剩余参数。

`init` 会补建 `.devsys/` 结构和缺失元数据，登记用户级项目路径；再次运行不会重写已有占位文件。已有 `.devsys/.gitignore` 若缺少受管忽略项则会被追加，不应把幂等理解成任何文件都绝不变化。已有受管元数据无效时，初始化在改动前拒绝继续。

## 典型工作流

1. 在独立测试 Git 仓库试运行时，先将 `DEVSYS_CONFIG_DIR` 指向临时目录，隔离用户级注册表。PowerShell 示例：`$env:DEVSYS_CONFIG_DIR = 'C:/Temp/workloom-registry'`。
2. 在目标根执行 `devsys --json init`，查看创建路径。
3. 执行 `devsys --json config check`，确认元数据可解析。缺失文件在诊断中报错，但 `init` 可以补建；无效的已有文件需要先处理具体问题。
4. 将允许提交的项目文本通过 Git 管理；不要把 `.devsys/local/` 中的锁和恢复材料当成跨设备共享状态。设备交接前停止写入。

| 退出码 | 含义与处理 |
|---|---|
| 0 | 成功 |
| 1 | 内部错误；保留错误信息排查 |
| 2 | 用法错误；先检查命令名与参数顺序 |
| 3 | 前置条件问题；检查 Git、所在目录或初始化状态 |
| 4 | 受管元数据无效；读取具体文件、行号、字段与原因 |

JSON 成功输出在 stdout，错误信封在 stderr。`config check` 是不加锁、不恢复事务的只读诊断，不能作为并发业务读取的一致性接口。
