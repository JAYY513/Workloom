**领域存储（M1）。** WorkItem/Run/记录三类采用「一记录一文件 + CAS 分配 + 乐观并发更新」；事件流按月分片 JSONL 追加；Artifact 版本为不可变文件链（`previous_id` 回链）；`workloom search` 对 `.devsys/` 大小写不敏感扫描，排除 `local/`/`.cache/`/`archive`。


**状态机与调度（M2 新增）。** 状态写入只经 `Transition`/`ApplyRepair`：actor+reason 必填、旧快照拒绝、状态与事件（`status_changed`/`repair_applied`）同一事务；调度态与业务状态分离，领取用 `.devsys/scheduling/<id>.yaml` 租约与随机 token fencing，并发领取恰好一个胜者并在同一事务创建 Run。

**对账与修复（M2 新增）。** `workloom doctor` 只读（不建锁、不自动恢复；待恢复事务优先报告且不输出业务事实）；`workloom recover` 先确定性恢复事务，再释放过期/孤儿领取并留事件；`workloom repair --dry-run/--apply` 以无墙钟摘要与写事务内证据复核执行「推断→确认→重写」。

**工作流策略、门禁与质量门（M3 新增）。** `.devsys/workflows/<id>.md` 解析为 `Policy`：front matter 行号定位、未知键 warning、结构/类型/必填/交叉引用 error；步骤序列、转换条件白名单（7 字段）、门禁（artifact 名集、最小数量、comment、approval）、质量门（满分 100）、hook 名枚举、`on_reject` ∈ {`block`, `regress:<status>`}、`quality_gate.min_score` 0–100；M3.7 起 `RequireApproval` 由 `approval.MatchingGate` 复核。详见[状态机与调度](../knowledge/可靠文本存储/状态机与调度.md)「M3 工作流实例操作」与[架构设计](../knowledge/可靠文本存储/架构设计.md)。

**记录传播（M3 新增）。** 完成（进入 `done`）事务内 `propagateRecordsTx` 扫描 `decisions/` 与 `findings/` 中 `RelatedWorkItems` 命中的记录，把 `decision://<id>` / `finding://<id>` 追加到父与直接兄弟的 `context_refs`（同事务 CAS、不改对方状态、已存在则跳过 → 幂等）；无 parent 不广播；父子自环拒绝并回滚。`record_propagated` 事件与 `status_changed` 同批 `events.AppendBatchTx` 提交。

**last-known-good 策略缓存（M3 新增）。** `workflow.Resolve(ctx, root, id)` 是工作流读取统一入口：每次重新 `Parse`（不信 mtime），成功后 `refreshLastKnownGood` best-effort 写 `.devsys/.cache/workflows/<id>.md`（同字节不写）；失败回退快照并携带当前 `Issue`；无快照或快照损坏 fail closed。`workflow check` 只读走 `Load`；`claim` 拒绝在策略非法/缺失时执行；`transition` 门禁允许用快照评估既有任务并打印 `warning: … using last-known-good`；`next` 增 `invalid_policy` 只读风险（含「工作项引用缺失策略」交叉核对）。

**工作流实例与 fencing（M3 新增）。** `workflow_instance.go` 五类操作（`start` / `step-complete` / `pause` / `resume` / `cancel`）共用 `workflowWrite`：写事务内 `ReadForExpect` → `bytes.Equal` 校验 `--expect` → 租约活跃时要求 `Owner` + `Token` → `mutate` 重写 `wi.Workflow` → `PutYAML(ExpectHash)` + `AppendTx` 事件。**不**写工作项状态、不写调度态/租约/`scheduling/` 目录；目标步骤声明 `status` 时当前状态不匹配即拒绝；显式 `--to` 必须命中声明转换且条件成立，自环拒绝；`paused` 拒绝推进。

**审批服务（M3 新增）。** `.devsys/approvals/approval-<N>.yaml`，ID `^approval-[0-9]+$`。`Request` 写事务内 `findOpenApproval` 防重复请求 → `nextNumber` → `PutYAML(ExpectAbsent)`。`DecideTx` 重读 + `ExpectHash`，pending → approved/rejected。`ConsumeTx` 仅在调用方写事务 Guard 内调用，校验 approved + 未消费 + 同 work item + 同 stage + 当前状态 = `requested_status`，任一不符 abort 整单，写 `consumed_at` + 返回 `approval_consumed` 事件。`InvalidateForStatusTx` 在 `changeStatus` 离开 `from` 状态时把同源未消费审批标记为 `invalidated_at`，通过 `Tx.Staged(rel)` 跳过本事务已暂存文件。`scope=stage_gate` 拒绝走 `rejectStageGate` 在 `Transition` Guard 内同时完成 `DecideTx(rejected)` 与状态变更（默认 `blocked`，`regress:<status>` 回退），失败整单回滚。

**就绪判定与 next（M3 新增）。** 纯函数 `next.Evaluate(Input)`：FAIL = 有待恢复事务（不输出业务事实、附 `workloom recover` 修复项）；CONCERNS = 任一风险信号；PASS = 无。风险八类顺序：过期租约 → 孤儿领取 → 不可读调度文件 → 滞留审查（review/verification 且 `updated_at ≤ now − 24h`）→ 阻塞 → 元数据非法 → 策略非法 → 待决审批。推荐六优先级：recover_claim → review → start → start_backlog → milestone_review → report_done。CLI `workloom next` 只读组装 Input（先 `reconcile.Doctor`，再 workitems / pending approvals / 策略与元数据问题），exit 恒 0。

**共享应用服务（M4 新增）。** `internal/app.Service` 是 M4 起所有业务规则的统一持有者。写方法统一接收 `expect`（来自对应 `Get*` 的 64-hex `Version` 字段）→ 写锁内 `Tx.ReadForExpect` + `bytes.Equal(raw, expected)` 守卫；读方法走 `storage.Store.Read` 共享锁；只读聚合走 `reconcile.Doctor` + `workflow.Load` + `next.Evaluate` 组合，不创建锁、不触发恢复、不可信状态不输出业务事实（§15.4）。错误模型 `*app.Error{Kind, Message, Problems}`：9 种 Kind 由 `Class()` 归一到 4 类，CLI 与 MCP 共用——`toCoded` 与 `fail` 都从 `*app.Error` 出发。构造器 `Usagef/Preconditionf/Internalf/Invalidf`；`Classify(err)` 包装任意 error。

**MCP 服务（M4 新增）。** `internal/mcp` 基于官方 Go SDK `github.com/modelcontextprotocol/go-sdk v1.8.0`（[go.mod](file://go.mod)）：`Config{Root, Profiles, ServerVersion, Instructions, Log}` 由 CLI 通过 `workloom mcp serve --profile <list>` 构造。`ParseProfiles(list)` 拒绝未知名字；`DefaultProfiles = [session, executor]`；`allTools()` 是唯一工具注册表，`NewServer` 注册期 `visible(spec.profiles, cfg.Profiles)` 过滤——未注册工具既不出现在 `tools/list`，也无法以名称调用。工具处理器是 4–6 行薄适配，业务规则全在 `internal/app`。错误通过 `toolError{Code, Message, Problems, Notice}` 翻译；`Instructions` 与 `app.Wire` 注入内容、`mcpInstructions` 常量**完全一致**——同一事实，三个入口。

**CLI 渲染层（M4 新增）。** `internal/cli` 在 M4 后薄化为三层：flag 解析 → `appService()` + `requireProjectRoot()` → `svc.Xxx(...)` → `render`。**写方法**统一抛 `*app.Error`；`toCoded`（[internal/cli/cli.go:101-119](file://internal/cli/cli.go#L101-L119)）翻译为 `codedError{code, kind, msg, problems}`。**列表输出**支持 `--jsonl`：`writeJSONL[T]`（[internal/cli/cli.go:126-135](file://internal/cli/cli.go#L126-L135)）逐行 encode 列表项，字段名与 `--json` 信封内同名数组一致。**M4 新增命令族**：`project list|get|status|blueprint|update|state-update` / `decision list|get|create|approve` / `finding list|get|create|resolve` / `event list|record` / `artifact list|get|register|update|history` / `run list|get|create|update|heartbeat|log` / `context get|workitem|refresh|compact` / `knowledge status` / `session start` / `wire` / `mcp serve`。**仍保留 CLI-only**：`search / config check / doctor / recover / repair`（无 MCP对应）；`wire`（operator 工具，`方案 §8.2` 无对应）。

**AGENTS.md 写入（M4 新增）。** `workloom wire` 把 devsys 纪律块以 `<!-- devsys:begin ... -->` / `<!-- devsys:end -->` 标记注入 `AGENTS.md`；`app.Wire(dryRun bool)`（[internal/app/wire.go:44-77](file://internal/app/wire.go#L44-L77)）保证：①三次运行字节级一致（幂等），②区段外字节保留（含其它工具的管理块与手写内容），③`--dry-run` 预览 diff 不写盘，④块破损拒绝并升 `CodePrecondition = 3`。纪律描述与 MCP `Instructions`、`app.Wire` 注入内容、`mcpInstructions` 常量**完全一致**——同一事实，三个入口。

**读快照与守卫更新（M4 新增）。** `internal/record/update.go` 把「读 + 守卫写」显式化为可重用 API：`readSnapshot[T]` 泛型共享 `ReadDecision / ReadFinding / ReadArtifact`，返回解码对象与原 YAML 字节；`UpdateDecision / UpdateFinding` 在写锁内 `tx.ReadForExpect` + `ExpectHash(HashBytes(expected))` 守卫；`AppendArtifactVersion` 拒绝**并发分叉**——若 `currentID` 已有子版本，立即返回 `ErrSuperseded` 要求 re-read head 再 append。`internal/run.ReadSnapshot` 同形单态实现支撑 `app.RunUpdate` 的 `expect` 守卫。CLI `--expect <64-hex>` 与 MCP 工具 `expect` 字段在 `internal/app` 内被反解码为同一原字节给 storage 层。

**可靠文本存储。** `Store.Read` 在共享锁下执行回调；发现未完成事务时释放共享锁、恢复后重试。`Store.Write` 在独占锁下先恢复，再提交回调收集的操作。`Tx.AppendJSONLRaw` 把多行 JSONL payload 一次 append（同 shard 多个事件合并提交）；`tx.Staged(rel)` 查询本事务是否已暂存 `rel`，供 `InvalidateForStatusTx` 跳过本事务已写的审批。
