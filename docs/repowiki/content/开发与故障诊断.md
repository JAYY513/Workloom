## 开发环境

Go 1.26 与 Git 是当前命令面所需环境。依赖副本随仓库提交；升级 YAML 依赖时同步更新 `go.mod`、`go.sum` 和 vendor，而不是只修改本机模块缓存。仓库 README 给出了本机网络受限时的代理方案，代理不是所有环境的强制前置。

## 编码规范

### 配置字段扩展是跨模块变更

当前 `project.yaml` 白名单仅包括 `schema_version/id/name/created_at`；`config.yaml` 只认 `schema_version`。新增字段时同步修改配置类型、字段白名单、初始化占位及相关说明，不能直接把完整规划模型写进文件后期待旧解析器接受。状态文件目前只严格校验版本，不能套用项目头的全部字段规则。

章节来源：[internal/config/config.go:80-95](file://internal/config/config.go#L80-L95)、[docs/开发记录.md:41-49](file://docs/开发记录.md#L41-L49)。

### 分清有效状态读取与诊断

业务一致性读取使用 `Store.Read`，跨文件提交使用 `Store.Write`：读取遇到待恢复事务先恢复，写入先取得独占锁并恢复。`config.Diagnose` 故意直接读取、不加锁、不恢复，适用于报告无效或未知版本元数据，不能用它替代有效状态查询。

`init` 先调用 `config.Load` 校验，再补建目录并用单文件原子写生成占位；它没有把整个初始化过程包装为 `Store.Write`。调用者不要推导出未实现的全局事务保证。

章节来源：[internal/storage/store.go:140-190](file://internal/storage/store.go#L140-L190)、[internal/config/config.go:104-113](file://internal/config/config.go#L104-L113)、[internal/project/init.go:63-109](file://internal/project/init.go#L63-L109)。

### 并发更新保留版本守卫

通过 `Reader.Expect` 取得不存在或内容 hash 守卫，使后续更新能识别两次操作之间的变更。文件锁解决协作进程的本机访问协调，不等于 Git 跨设备同时领取仲裁。设备交接前停写；不要根据租约时间或本机文件状态自行宣布跨设备赢家。

## 测试

仓库既有验收命令：

```sh
gofmt -l cmd internal

go test ./...
```

隔离初始化冒烟的注册表：将 `DEVSYS_CONFIG_DIR` 指向临时目录，在单独 Git 测试仓库运行二进制，避免污染真实用户配置。修改配置后应关注多错定位、未知版本拒写与缺失文件补建；修改存储协议后应关注崩溃恢复、重复重放、版本竞争和锁冲突，而不只检查序列化结果。

## 调试

| 现象 | 检查路径 |
|---|---|
| `init --json` 返回用法错误 | 全局参数必须前置，改为 `--json init` |
| 非 Git 目录或仓库子目录不能初始化 | 到 Git 根目录执行；不要手动绕过根目录前置条件 |
| 配置问题一次输出多条 | 按文件、行号、字段处理，保留未识别版本文件原样 |
| 未知 `schema_version` | 只读诊断仍可运行；当前没有可用迁移命令 |
| 恢复失败 | 保留 `.devsys/local/txn/` 中日志与 payload；它们不是可随意清理的缓存 |
| Windows 原子替换被目标句柄占用 | 检查长时间持有的读取句柄；实现已有有限重试，不代表可以无限等待 |

## 发布

构建时以 `-ldflags` 注入 `workloom/internal/version.Version` 与 `workloom/internal/version.Commit`。PowerShell 示例：

```powershell
$commit = git rev-parse --short HEAD
go build -mod=vendor -ldflags "-X workloom/internal/version.Version=0.1.0 -X workloom/internal/version.Commit=$commit" -o bin/devsys.exe ./cmd/devsys
bin/devsys.exe --version
```

未注入版本的本地构建保留 `0.1.0-dev`；Commit 为 `unknown` 或空时只显示版本。这是构建标识能力，不表示当前已有自动发布流水线。
