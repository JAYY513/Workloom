# Workloom 知识库

Workloom 当前实现到 **M9 + 发布自动化 + 外部审查两批修复**（正式 tag `v0.1.9`；主命令 `workloom`——`cmd/workloom` 为唯一主入口，`devsys` 是**同一二进制的兼容别名**，install 脚本同时装入两个名字）：`init`、`setup`（一条命令接入：init → 起手工作流 → wire → config check → wire --check → prime → 蓝图检查 → doctor；**不注册 MCP**）、`config check`、`search`、`workitem`（含 `create --acceptance`；非法 id 归用法错误）、`doctor`、`recover`、`repair`、`workflow check/start/next/step-complete/pause/resume/cancel`、`approval list/request/approve/reject`（列表第二列为有效状态）、`decision / finding / event / artifact / run` 完整记录族、`context get/workitem/refresh/compact`、`context get --task <id>`（M5 叠加 `KnowledgeContext`）、`knowledge status/scan/validate/refresh`、`prime`（= `session start --compact`）与 `session start`、`wire [--check|--skill|--print-mcp]`（`--check` 含技能内容比对）、`mcp serve [--profile …] [--tier core|standard]`（官方 Go SDK、profile×tier 过滤的 66 项工具）、`mcp install [--scope user|project] [--client codex|claude|opencode] [--apply|--force]`（**默认只预览**，`--apply` 才写；注册名保持 `devsys`）、`worktree prepare/remove/list`、`dispatch --once|--watch|--dry-run`、`run exec|prompt|verify|complete|fail|cancel`、`sync status`（M8.1 只读接力判定）、`repair --dry-run|apply` 接 `note_unmerged_paths`（M8.2 人工标注 + dispatch 门控）、`archive events --before|runs --id`（M8.3 保守归档）、`scripts/contrabass/{export,import}.py`（M8.4 可选看板后端）、`workspace view/build/serve` + 新鲜度提示（M7 只读视图）、`project state-update|blueprint`（未声明蓝图 exit 0）、以及发布链 `scripts/build-release.{sh,ps1}` + `scripts/install.{sh,ps1}`（公开仓库默认**匿名下载**、不设 `GOPRIVATE`；`gh` 已登录时优先用它下载以覆盖私有 fork 与匿名限流；校验和容忍 GNU / shasum 两种方言）与 `.github/workflows/release.yml`——**Release 资产名自 `v0.1.9` 起是 `workloom-*`**（`v0.1.8` 及更早仍是 `devsys-*`）。门禁口径：策略来源 = 工作项绑定的实例，或 `.devsys/config.yaml` 的 `default_policy`；`next` 与 `claim` 使用同一质量门判定。
