## 偏离 / 遗留汇总

1. **§11 clone 后必须 `devsys init` 一次**：`local/` 在 `.gitignore` 内，git clone 不会恢复。clone 后第一次读写会因 `local/lock` 缺失报错；补一次幂等的 `devsys init`（只补目录，不动元数据）即恢复。
2. **§4 blocked 恢复须指名原状态**：`blocked → previous_status` 才合法；CLI 无 `--previous-status` 参数，直接 `--to <原状态>`（如 `in_progress`）即可，`blocked → ready`（原状态非 ready 时）拒绝。这是保守图的正常裁剪，不是缺漏。
3. **§15 refresh 在无 generator 时降级报告（不假装成功）** —— 当前内置二进制未配置真实生成器；保护 / 手改 skip / `--force` override 语义由 Go 测试锁定。
4. **§9 devsys 自身不分发 skill 目录**；唯一提到 "skill" 的源码注释把 RepoWiki 视作**外部 page 生成器**，与“per-harness skill”无关。
5. **§17 tick 要求 git 有 HEAD 且 `dispatch_command` 为字符串**：未 commit 的项目 tick 会 notice 拒绝（不是静默成功）；数组形态的 `dispatch_command` 直接 exit 4。均为 fail-closed 形态。
6. **Windows shell 取 token 的坑**：`workitem claim --json` 的 token 经 Git Bash `$()` + python 抓取时 CR 混入导致 `lease token mismatch`；从 `.devsys/scheduling/<id>.yaml` 的 `^token:` 行直读最稳。本报告 §4/§8 链路均用此法。
