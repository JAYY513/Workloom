## 1. 计划原则

1. **一步 = 一个工作项 = 一次会话**：任何步骤都应能在单次会话内完成并独立验收；做不到就继续拆。
2. **每一步都有可执行的验收**：命令、退出码、可观察的文件内容；不接受「看起来对」。
3. **严格自下而上**：存储 → 领域 → 状态与调度 → 门禁 → 接入 → 知识 → 执行 → 视图 → 同步。上层只依赖已完成的下层。
4. **里程碑边界可交付**：每个里程碑结束时代码可用、可跑剧本、可打 tag 回退。
5. **不写时间估算**：与方案 §7.4 一致，用「依赖 + 产出 + 验收」度量进度。
6. **不提前优化**：未到对应里程碑的机制不写进代码（如执行层之前不实现工作区）。

## 4. 详细步骤

### M0 仓库骨架与存储基元

**M0.1 语言与工程骨架**
- 目标：定语言（D1），建仓库结构、构建脚本、格式化与静态检查。
- 产出：可编译/可运行的 `devsys --version`；`README.md`；CI 跑构建与检查。
- 验收：干净机器上按 README 一条命令跑通构建并输出版本号。
- 不含：任何业务逻辑。

**M0.2 CLI 骨架与 `devsys init`**
- 目标：命令注册、`--json`/`--quiet` 全局开关、统一退出码（0 成功 / 非 0 分类错误）。
- 产出：`devsys init` 创建 `.devsys/{project.yaml,config.yaml,state/{current.yaml,milestones.yaml},workitems/,specs/,workflows/,runs/,decisions/,findings/,approvals/,events/,artifacts/,context/,knowledge/,local/,` `.cache/}`；`state/` 下两个初始文件为最小合法占位（严格解析归 M0.4）；同时在用户级注册表登记项目路径与标识（方案 §14.4）。
- 验收：重复执行 `init` 幂等（不覆盖已有内容，注册表按路径去重更新）；目录与方案 §14.3 完全一致；在非 Git 目录执行报错并给出 `git init` 指引（方案 §14.1、D6）。
- 依赖：M0.1。

**M0.3 文本存储基元**
- 目标：实现原子写（临时文件 + 替换）、JSONL 追加、稳定键序序列化（YAML/JSON），以及项目级短时写锁、版本校验和跨文件事务日志/恢复基元（无数据库）。
- 产出：内部存储模块 + 单元测试；明确事务提交点、读者隔离、日志持久化与幂等恢复协议。锁和恢复材料放 `.devsys/local/`，未完成事务不得按临时文件清理；此步骤不实现任务状态机。
- 验收：空文件和写入中断可正确处理；并发写者互斥，基于同一旧版本的竞争更新仅一个成功；在跨文件事务各落盘阶段中断进程，重启恢复后只呈现完整一致状态，重放不重复追加事件，恢复失败拒绝有效状态查询/写入并允许诊断。覆盖 Windows/macOS/Linux 锁与文件替换行为；进程中断测试不得宣称已证明断电持久性。
- 依赖：M0.2；对应方案 §15.2。

**M0.4 严格配置解析**
- 目标：解析 `project.yaml` 与 `config.yaml`，未知键、类型错误、缺必填项都要报错并给出位置；校验受管状态文件的 `schema_version`（方案 §14.1）。
- 产出：解析器 + 错误信息规范（文件、行号、字段、原因）+ 版本检查（未知版本拒绝写入、允许只读诊断）。
- 验收：故意写错三个字段，报错信息逐条可定位；把 `schema_version` 改为未知值，写操作被拒绝且提示迁移。
- 依赖：M0.3。

### M1 领域模型与项目内存储

**M1.1 领域类型与序列化**
- 目标：定义 Project / WorkItem / Run / Decision / Finding / Event / Artifact / Approval 类型（对应方案 §5，含 §5.2 新增字段：数值 `priority`、`created_from` 来源字段、`workflow` 实例引用；§5.8 Approval），并实现往返序列化。
- 产出：类型定义 + 往返测试（写入再读出，字段完全一致；所有受管文件含 `schema_version`）。
- 验收：所有类型的往返测试通过，键序稳定（两次写入字节一致）。
- 依赖：M0.3。

**M1.2 WorkItem 读写与 ID 分配**
- 目标：一任务一文件（`.devsys/workitems/<id>.yaml`）；ID 形如 `<前缀>-<序号>`，序号在写入时校验唯一。
- 产出：读写接口 + 冲突时重新分配的逻辑 + 测试。
- 验收：同一 ID 并发创建只有一次成功；列表按 ID 排序稳定。
- 依赖：M1.1。

**M1.3 事件流（JSONL 按月分片）**
- 目标：`.devsys/events/<YYYY-MM>.jsonl` 追加写；事件包含类型、主体、时间（RFC 3339 UTC）、操作者、关联对象；事件类型含 `comment`（支持一级 `reply_to`，方案 §4.6）。
- 产出：追加接口 + 读取/过滤接口。
- 验收：写入 100 条事件后可按时间与主体过滤；分片跨月自动切换；`comment` 事件可按主体聚合且回复关系可还原。
- 依赖：M0.3。

**M1.4 Run 记录与上下文快照**
- 目标：实现方案 §5.4 的 Run 结构（含 `attempt`、`phase`、`claim`、`verification` 字段占位）与 §11.3 上下文快照。
- 产出：Run 读写 + 快照写入（记录当时引用的知识版本与工件版本）。
- 验收：`run get` 可还原「Agent 当时看到了什么」。
- 依赖：M1.1。

**M1.5 记录（Decision / Finding / Artifact）**
- 目标：一记录一文件；Artifact 支持版本号与前一版本链接。
- 产出：写入/查询接口 + 版本追加规则。
- 验收：同一 Artifact 连写三版后能回溯历史。
- 依赖：M1.1。

**M1.6 检索（文本扫描）**
- 目标：不引入数据库，直接扫描 `.devsys/` 文本实现关键字检索与过滤。
- 产出：`devsys search <keyword>`（含 `--json`）；扫描排除 `.cache/`、`local/`。
- 验收：1000 个文件规模下响应可接受（记录实测数字到文档）。
- 依赖：M1.2–M1.5；对应方案 §14.1「不使用数据库」。

**M1.7 里程碑剧本与快照**
- 目标：跑通「创建项目 → 建任务 → 记录决策 → 完成」的手工剧本。
- 产出：`scripts/smoke-m1.*`（可重复执行）+ 一份示例 `.devsys/`（可作为模板）。
- 验收：剧本在干净目录一次跑通；`git status` 显示的状态文件全部是文本。
- 依赖：M1.1–M1.6。

### M2 状态机、调度态与对账

**M2.1 工作项状态机**
- 目标：实现方案 §6.1–§6.3 的基础状态与合法转换；转换必须带原因与操作者。
- 产出：状态转换接口 + 非法转换拒绝 + 事件记录。
- 验收：非法转换（如 `draft → done`）被拒绝并给出允许的下一步列表；旧版本更新被拒绝，状态与对应事件通过 M0.3 事务一致提交。
- 依赖：M1.2。

**M2.2 调度态与文件级领取**
- 目标：实现 `unclaimed/claimed/running/retry_queued/released`（方案 §6.4）与租约文件、心跳。
- 产出：`workitem claim/release/heartbeat` 接口 + 领取状态映射（§6.4 映射表）。
- 验收：并发领取同一任务仅一个成功；领取、关联 Run 与事件不得对外呈现半提交状态；租约过期经恢复释放后可再领取，旧领取者的后续写入被拒绝；锁不跨越 Agent 执行期。
- 依赖：M2.1。

**M2.3 孤儿恢复与对账**
- 目标：打开项目时先检查 M0.3 未完成事务，再检测「已领取但无运行记录」「租约过期」「状态与产物不一致」（方案 §15.4），不把半提交状态误判成业务孤儿。
- 产出：`devsys doctor`（只报告）与恢复动作（事务恢复、按策略释放孤儿领取）+ 事件记录；确定性事务恢复与 M2.4 业务推断修复分离。
- 验收：人为制造孤儿状态，`doctor` 报告并可通过显式命令修复；待恢复事务不作为有效业务状态返回；`doctor` 与 `repair --dry-run` 不改写文件，恢复重复执行不重复产生事件。
- 依赖：M2.2。

**M2.4 状态修复（推断 → 确认 → 重写）**
- 目标：按方案 §15.4 实现修复流程；只有该路径允许降低任务完成度。
- 产出：`devsys repair --dry-run`（列出提议表）与 `--apply`（确认后重写并校验）。
- 验收：dry-run 不写入任何文件；apply 后状态自洽且有事件留痕。
- 依赖：M2.3。

**M2.5 里程碑剧本与快照**
- 目标：验证中断-恢复链路。
- 产出：`scripts/smoke-m2.*`：领取 → 模拟进程被杀 → `doctor` → 恢复 → 重新领取。
- 验收：剧本一次跑通，事件流完整可读。
- 依赖：M2.1–M2.4。

### M3 策略文件、实例与审批

**M3.1 策略文件格式与解析**
- 目标：`.devsys/workflows/<id>.md`（front matter + 提示词正文），严格校验，错误可定位（方案 §5.3）。
- 产出：解析器 + 校验规则 + 示例策略（快修 / 功能 / 架构变更三份）。
- 验收：非法 front matter 报错明确；未知键按方案策略处理（记录但不崩）。
- 依赖：M0.4。

**M3.2 模板渲染与变量引用**
- 目标：严格变量检查渲染提示词；`$VAR` 环境变量引用不入库。
- 产出：渲染器 + 渲染失败的错误分类。
- 验收：拼错变量名必须渲染失败（不得静默变空）。
- 依赖：M3.1。

**M3.3 门禁、钩子与限额字段**
- 目标：实现 `gates / hooks / concurrency / limits / quality_gate / on_reject`（方案 §4.7、§4.8、§5.3）。
- 产出：门禁检查函数（产物、数量、评论事件、审批、豁免阶段；审批的请求与消费逻辑在 M3.7）+ 领取质量门（确定性评分与阈值，被拦返回缺失项清单）+ 记录传播（完成时把 `decision`/`learning` 以引用形式传播到父任务与直接兄弟任务）+ 钩子声明解析（执行在 M6）。
- 验收：缺少必需产物时推进被拒绝并返回缺失清单；低质量任务被领取质量门拦截且返回改进项；完成任务后父任务与兄弟任务出现引用与事件，双方状态不变。
- 依赖：M3.1。

**M3.4 就绪门与下一步优先级**
- 目标：实现 `PASS/CONCERNS/FAIL` 就绪判定与固定的 next 顺序（方案 §7.4）。
- 产出：`devsys next`（含风险信号：过期、孤儿、滞留审查、未解决阻塞）。
- 验收：构造四类风险各一例，`next` 输出与优先级表一致，且不含时间估算。
- 依赖：M2.1、M3.3。

**M3.5 策略热载入与 last-known-good**
- 目标：每次读取时校验策略；解析失败保留上一份有效配置，只阻塞派发不阻塞只读操作。
- 产出：配置缓存 + 失败回退 + 操作者可见的错误。
- 验收：写入坏策略后 `next` 仍可用；派发类操作被拒绝并提示原因。
- 依赖：M3.1。

**M3.6 工作流实例与步骤推进**
- 目标：实现方案 §5.3 的实例语义：实例状态存于工作项文件 `workflow` 字段、步骤历史走事件流；步骤推进、声明式条件求值与策略校验期错误；步骤 `status` 与工作项状态映射。
- 产出：实例模型 + 工作流领域实现（`workflow_start / workflow_step_next / workflow_step_complete / workflow_pause / workflow_resume / workflow_cancel` 的领域层，MCP 工具面在 M4.2）+ 条件求值器（`== != < > in exists`，白名单字段）+ 校验（未知字段或操作符=策略错误）。
- 验收：两步流程按 `when` 条件正确分支；非法推进（跳步、条件不满足）被拒绝并给出允许的下一步；未知条件字段在策略加载期报错；步骤推进产生的状态与事件一致，且不写调度态。
- 依赖：M3.1、M2.1。

**M3.7 审批服务**
- 目标：实现方案 §4.9/§5.8：Approval 模型与存储（`.devsys/approvals/`）、请求-决定-消费流程、门禁联动、拒绝语义（默认 `block`，可配 `regress:<status>`）。
- 产出：审批服务（request/decide/consume/查询）+ CLI（`devsys approval list/request/approve/reject`）+ 与 `require_approval` 门禁的联动 + 事件记录。
- 验收：未批准时门禁拒绝推进；批准后可推进一次且写入 `consumed_at`；离开阶段后批准失效、再次进入需重新请求；拒绝后工作项转 `blocked` 且理由与引用完整；审批写入走版本校验与事务路径，无法绕过。
- 依赖：M3.3、M2.1。

### M4 接入层（CLI 完整 + MCP + 文件协议）

**M4.1 MCP Server 骨架**

### M5 上下文与知识层

**M5.1 知识页面格式与校验**
- 目标：页面 front matter（`status/type/triggers/description/source_commit/sources`）+ 校验命令。
- 产出：格式定义 + `knowledge validate`（错误/告警分类）。
- 验收：缺 triggers 的页面被拒绝；校验输出可用于 CI（非 0 退出码）。
- 依赖：M1.6。

**M5.2 扫描与快照**
- 目标：扫描项目、指纹每个文件（路径/大小/哈希/语言），排除密钥、>1MB、`.gitignore` 与自定义忽略文件。
- 产出：`.repowiki` 等价物 —— `.devsys/knowledge/snapshot.json`（本地缓存）。
- 验收：示例仓库扫描结果与实测文件数一致；密钥与大文件出现在排除清单。
- 依赖：M5.1。

**M5.3 新鲜度与增量**
- 目标：基线 commit + `affected_pages` + 退出码 0/10/11（方案 §12.5）。
- 产出：`knowledge status`、`knowledge refresh --affected`。
- 验收：改一个源文件后，status 只报受影响的页面为过期。
- 依赖：M5.2。

**M5.4 人工保护**
- 目标：`content_hash` 检测手工编辑；`protected: true` 锁定；只有 `--force` 可覆盖。
- 产出：保护判定 + 跳过报告。
- 验收：手工修改过的页面在 refresh 后被跳过，且明确列出跳过原因。
- 依赖：M5.3。

**M5.5 断点续跑与互斥**
- 目标：`run.json` 检查点 + pid 互斥，中断后可续跑。
- 产出：`knowledge refresh` 的续跑流程。
- 验收：中途杀掉进程，重启后从断点继续，不重写已完成页面。
- 依赖：M5.4。

**M5.6 上下文装配、生成器契约与降级**
- 目标：按任务装配分层上下文（方案 §11.1）；实现生成器契约与 repowiki 适配（方案 §12.6、D4）；无生成器时降级为索引层。
- 产出：`context get --task`、上下文快照写入（含 `workspace_head` 差异标注，方案 §11.3）、生成器契约（输入/输出/幂等与保护规则）、repowiki 适配层、降级行为（页面层缺失时 `knowledge status` 报 11 语义且不报错）。
- 验收：同一任务两次装配结果稳定；更换生成器不影响上下文接口；未安装生成器时全部查询与装配可用；若环境可用，用 repowiki 真实生成一页并通过校验与保鲜检查。
- 依赖：M5.5、M4.4。

### M6 执行编排与 Harness 适配

**M6.1 Harness Adapter 接口与 Shell Adapter**
- 目标：统一执行接口（方案 §9.2）+ 最小可用 Shell Adapter。
- 产出：接口定义 + Shell 实现（可跑任意命令并按行流式输出）。
- 验收：跑一条命令，事件流实时可见并落盘。
- 依赖：M1.4。

**M6.2 工作区管理与不变量**
- 目标：git worktree 工作区、路径不变量、目录名净化 + 哈希后缀、生命周期钩子（方案 §4.8）。
- 产出：工作区模块 + 四个钩子的执行与失败语义。
- 验收：越界路径被拒绝；`after_create` 失败时工作区不残留半成品。
- 依赖：M6.1、M3.3。

**M6.3 Run 生命周期与多轮续跑**
- 目标：尝试阶段（§4.8）、首轮全量提示词、后续续跑指引、轮数上限。
- 产出：Run 状态推进 + 事件记录。
- 验收：单任务跨多轮完成，续跑轮次不重复发送完整提示词。
- 依赖：M6.2、M3.2。

**M6.4 调度 tick、派发与阻塞**
- 目标：`devsys dispatch --once` 一次性 tick（可选 `--watch` 前台循环）：事务校验与恢复 → 租约/孤儿对账 → 到期重试 → 停滞评估 → 按排序（`priority` 降序 → 创建时间 → 标识符）与全局/按状态并发上限派发；`blocked_by` 先决（方案 §4.8、§7.4）。
- 产出：tick 实现 + 并发闸门 + 只读对账与执行推进的分离。
- 验收：同一状态重复 tick 不重复派发（幂等）；超额派发被拒绝；阻塞任务不进入队列；`status`/`next` 不启动执行。
- 依赖：M6.3、M3.3。

**M6.5 重试、退避与停滞检测**
- 目标：确定性退避 + 可复现抖动 + 停滞检测（方案 §15.4）。

- 验收：相同任务与尝试次数在重启后产生相同重试时刻（到期判定在 tick 时求值）。
- 依赖：M6.4。

**M6.6 完成校验与人工复核**
- 目标：claim head SHA 记录与 `git rev-parse <branch>` 比对（方案 §4.8）；无推进不放行。
- 产出：校验逻辑 + 人工复核队列 + 事件。

- 依赖：M6.5、M2.2。

**M6.7 Harness 适配：Codex / OpenCode / Claude Code**

- 产出：适配器实现 + 能力探测 + 启动参数模板。

- 依赖：M6.6。

**M6.8 一致性自检**

## 5. 关键路径与可并行项

- **关键路径**：M0 → M1 → M2 → M3 → M4 → M6 → M8 → M9。
- **可并行**（在依赖满足后）：
  - M5（知识层）与 M6（执行层）可在 M4 完成后并行推进，二者只共享上下文接口；
  - M7（视图）的静态构建可与 M8 并行；
  - M6.7 的三个 Harness 适配器之间互相独立，可分别推进；
  - M3.6（工作流实例）与 M3.7（审批）相互独立，可并行。
- **禁止并行**：M1/M2 与 M3 的存储格式调整（会造成反复迁移）；M6.2 与 M6.6 的工作区/校验字段（同一批文件）。

## 6. 回退与风险管理

| 风险 | 触发信号 | 应对 |
|---|---|---|
| 状态文件格式频繁变更 | 同一文件在相邻两个步骤里两次改结构 | 格式定版前不进入 M4；变更必须带迁移脚本 |
| 门禁过严拖慢 Agent | Agent 大量时间补材料 | 通过策略文件的 `exempt_stages` 调低要求，不改代码 |
| 文件数量增长超预期 | 单项目状态文件超过约定阈值 | 启用 M8.3 归档；评估分片策略 |
| 规范漂移（Symphony SPEC） | 上游 SPEC 语义变化 | 按方案 §20.8：比对差异 → 记录偏离 → 只在核心清单内验收 |
| 生成器契约漂移（repowiki） | 页面 front matter 字段或状态文件变化 | 适配层隔离格式差异；升级前比对 `.repowiki/state.json` 与页面契约，先改适配层再升级（方案 §12.6） |
| 执行层与真实 Harness 不兼容 | 适配器启动失败或协议变化 | 适配器放最后一批（M6.7），并保留 Shell Adapter 兜底 |

每个里程碑结束：打 tag、跑对应 `scripts/smoke-mN.*`、更新方案文档中受影响章节。
