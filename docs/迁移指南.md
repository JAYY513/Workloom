# Workloom 迁移指南（schema_version 与版本升级）

> 基线 `1ac4d56`。当前全系 `schema_version: 1`
> （`internal/domain/models.go: SchemaVersion`、`internal/config: SupportedSchemaVersion`、
> 受管四文件 `project.yaml / config.yaml / state/current.yaml / state/milestones.yaml`）。
> 规则一句话：**未知版本拒绝一切写入、只读诊断可用**（M0.4 落地，M9.1 §11/§15 已验收）。

## 1. 触发与现象（真实输出）

把某受管文件的 `schema_version` 改成 `99` 后：

```
$ devsys config check
devsys: invalid managed state (1 problem)
  project.yaml:2: schema_version: unsupported version 99 (this build supports 1); refusing to write, migration must be explicit
EXIT=4
$ devsys --json config check
{"ok":false,"error":{"code":4,"kind":"invalid","problems":[{"file":"project.yaml","line":2,"field":"schema_version","reason":"unsupported version 99 (this build supports 1); …"}]}}
$ devsys init
devsys: invalid managed state (1 problems)
  project.yaml:2: schema_version: … migration must be explicit
```

要点：`config check`（只读，不加锁不恢复）**仍可运行**并逐条定位；
`init`（及一切写路径）在**任何改动前**拒绝，未知版本的文件**零改写**
（改前改后 sha256 不一致仅因你手工改了版本号，命令本身零写入）。

## 2. 升级流程（同版本 / 小版本二进制替换）

```sh
devsys config check                     # 先绿（exit 0）
git add -A && git commit -m "chore(devsys): pre-upgrade snapshot"   # 快照 .devsys/
cp bin/devsys.exe bin/devsys.exe.bak    # 留旧二进制（回退用）
# 换新二进制后：
devsys config check                     # 复验（exit 0）
devsys init                             # 幂等补齐新增目录/占位（不动已有元数据）
devsys --json config check              # 结构化复核
```

clone 到新机器：`git clone` 后补一次 `devsys init`（重建被 gitignore 的 `local/lock`，
`created: 12 paths`），再按上表复验。

## 3. 跨版本迁移（v1 → v2 模板，未来用）

1. 发版说明给出**逐文件对照表**（字段增删改 + 语义变化 + 是否可自动迁移）。
2. 迁移命令（如未来 `devsys migrate --to 2 --dry-run/--apply`）必须满足：
  逐文件备份 → 转换 → `config check` 全绿 → git 提交（`chore(devsys): migrate v1→v2`）；
   `--dry-run` 先报计划，`--apply` 要求工作区干净。
3. 验证命令：`config check`（exit 0）+ `workitem list` + `project status` + `context get`
   + `knowledge status`（按页基线复核）全过。
4. 当前 v1 时代：**没有自动迁移**，任何未知版本都按 §1 拒绝并提示等迁移指引——
   不要手工改 `schema_version` 数字“骗过”校验（解码形状会对不上）。

## 4. 回退（版本回退不破坏状态文件）

```sh
cp bin/devsys.exe.bak bin/devsys.exe     # 或重建同 commit 二进制
git stash list; git status --short -- .devsys/   # 确认无半截写入
git checkout <上一tag> -- .devsys/ 2>/dev/null || git restore --source=<上一tag> .devsys/
devsys config check && devsys project status && devsys workitem list
```

`.devsys/` 全文本 + 原子写 + 事务恢复：旧版二进制读旧版状态即回退，
演练验收见 M9.3（从上一 tag 回退后项目仍可读写）。

## 5. FAQ

- **Q: `dispatch_command` 写成数组被拒？** A: 该键是字符串（shell 片段），数组即
  `config.yaml:3: dispatch_command: expected string, got !!seq`（exit 4）。
- **Q: `knowledge refresh` 说无生成器？** A: 未配置 `knowledge_generator` 时只报告
  不伪造（方案 §12.6 降级），配桩/真生成器后再跑（见 smoke-m5）。
- **Q: 锁文件缺失？** A: clone/拷目录后补 `devsys init`（§2）。
